## 5. 단계

1. **대조표를 먼저 만든다.** `ui.ts`의 관리자 콘솔 코드를 처음부터 끝까지 읽고, 화면에 보이는 것과 누를 수 있는 것을 하나도 빼지 않고 적는다(보기 7개, 상세 패널, 대화상자, 사이드바의 개수·점, 명령 팔레트, 단축키, 자동 갱신, 테마, 로그아웃, 관리자 아님·연결 실패 화면, 목록을 못 불러올 때의 대체 표시). 형식:
   ```markdown
   | # | 옛 콘솔 기능 | 옛 요청 (메서드 경로) | 새 화면 | e2e 이름 | 상태 |
   |---|---|---|---|---|---|
   | 1 | 개요: 멤버 수(활성·대기·정지) | GET /api/admin/overview | /app/admin | admin "overview cards" | 있음 |
   ```
   상태는 `있음`, `없음`, `일부러 뺌(사유)` 중 하나다. P5-12가 덮은 행은 그 화면과 e2e 이름(`e2e/admin.e2e.ts`)을, 이 작업이 덮는 행은 6절의 이름을 적는다. P5-13 몫의 행은 새 화면 `P5-13`, e2e 이름 `—`, 상태 `없음`.
2. `api/admin.ts`
   - `AdminUser`에 `UserCrmRow`의 `can_ingest`, `can_share`, `can_use_server_key`, `memo`, `public_count`를 더한다. 개요 응답의 `settings`에서 새 사용자 기본값(`default_user_role`, `default_can_use_server_key`, `default_quota_mb`)을 읽는다(그 밖의 설정 키는 P5-13이 더한다).
   - `AdminUserPatch`를 옛 콘솔이 보내는 키 전부로 넓힌다: `displayName`, `role`, `status`, `canIngest`, `canShare`, `canUseServerKey`, `quotaMb`, `memo`, `newPassword`, `revokeSessions`. 비밀번호 칸이 비면 `newPassword` 키를 보내지 않는다.
   - 메서드를 더한다. 메서드·경로·본문·응답 모양은 서버 코드 그대로다.
     ```ts
     createUser(body: AdminNewUser): Promise<void>;                       // POST /api/admin/users
     lectures(q: { status?: string; q?: string; owner?: string; limit?: number; offset?: number }): Promise<AdminLecturePage>;  // GET /api/admin/lectures
     lecture(id: string): Promise<AdminLectureDetail>;                     // GET /api/admin/lectures/:id
     retryLecture(id: string): Promise<void>;                              // POST /api/lectures/:id/retry (409 = 이미 처리 중)
     compactLectures(ids: string[]): Promise<{ queued: number; estimatedSavedBytes: number }>;   // POST /api/admin/storage/compact {ids}
     deleteLectureAudio(id: string): Promise<{ reclaimedBytes: number }>;  // DELETE /api/lectures/:id/audio
     deleteLecture(id: string): Promise<void>;                             // DELETE /api/lectures/:id
     ```
   - `AdminTransport.v1`이 `POST`도 받게 한다.
3. 화면
   - **사용자** `/admin/users`: 역할 필터(전체·소유자·관리자·멤버·보기 전용, 개수), 상태 필터(활성·승인 대기·정지, 개수), 검색(이름·이메일·메모). 셋 다 주소에 남는다. 버튼 `새 사용자` → 대화상자(이메일, 표시 이름, 초기 비밀번호 6자 이상, 역할, 상태 활성·승인 대기, 녹음·업로드 허용, 공개 공유 링크 허용, 서버 AI 키 사용, 오디오 한도(MB, 0 = 무제한), 메모). 기본값은 개요의 `settings`. 서버 오류는 대화상자 안 `role="alert"`. 줄의 이름은 상세로 가는 링크다.
   - **사용자 상세** `/admin/users/$userId`: 옛 상세 패널의 속성(상태, 역할, 녹음·공개·오류 수, 오디오/한도 막대, 세션 수, 최근 로그인, 가입, ID)과 링크 `이 사용자의 녹음`(→ `/admin/recordings?owner=<id>`). 편집 폼: 표시 이름, 역할, 상태, 세 권한, 한도(MB), 메모, 새 비밀번호(비우면 그대로, 6자 미만이면 폼 안 오류), `저장할 때 모든 세션 로그아웃`. 저장 토스트 `사용자 정보를 저장했습니다.` 서버 규칙은 P5-12와 같다(자기 자신의 역할·상태, 소유자는 소유자만). 삭제는 P5-12의 대화상자를 쓴다.
   - **녹음** `/admin/recordings`(새 탭 `녹음`): 상태 필터(전체·처리 중·오류·완료, 응답의 `counts`), 검색(250ms 뒤 요청), 소유자 필터(주소의 `owner`, 칩으로 해제). 모두 주소에 남는다. 표(상태, 제목과 과목, 소유자, 길이, 오디오 크기와 `압축됨`·`오디오 없음`, 만든 시각), 50개씩 `더 보기`(`offset`). 줄을 누르면 상세(줄 안 링크가 같은 일).
   - **녹음 상세** `/admin/recordings/$lectureId`: 옛 상세 패널의 속성(상태와 진행률, 단계, 소유자(사용자 상세 링크), 길이, 오디오(크기·형식·압축됨, 압축 전후와 줄어든 비율, 압축 시각, 보관 위치), 업로드 경로, 모델(요청과 다르면 둘 다), 노트 글자 수, 공개, 생성·수정 시각, ID, 오류 메시지, 요약). 동작은 옛 콘솔과 같은 조건으로: `재시도`(오디오가 있고 오류이거나 처리 중), `지금 압축`(완료, 압축 전, `audio_compact_state`가 `skipped`가 아님, 업로드 폴더 안), `오디오 삭제`, `녹음 삭제`. 재시도 409는 토스트 `이미 처리 중입니다.`
4. 되돌릴 수 없는 동작(오디오 삭제, 녹음 삭제, 사용자 삭제)은 확인 대화상자를 거친다. 실행 중에는 버튼이 꺼지고 `실행 중…`으로 바뀐다. 같은 요청을 두 번 보내지 않는다.
5. fixture: 강의 55개(5명에게 나눔, 처리 중·오류·완료 섞음, 압축됨·오디오 없음 포함)로 `더 보기`가 한 번 나온다. 사용자 5명은 P5-12 그대로이고 권한·메모를 더한다. 서버 규칙(자기 자신, 소유자, 6자 비밀번호, 이메일 중복 409)을 따른다.

| 종류 | 테스트 이름 | 준비 | 기대 |
|---|---|---|---|

| e2e | "user filters stay in the address" | 역할·상태·검색 | 주소에 남고, 새로고침해도 같은 줄 |

| e2e | "recording actions ask first" | `오디오 삭제` → 취소 → 다시 → 확인 | 취소 뒤 그대로, 확인 뒤 토스트와 `오디오 없음` |

## 10. 명세 작성자 메모

- 옛 콘솔의 `앱에서 열기`(`/?lecture=<id>`)는 새 앱 주소가 v2 녹음 id를 쓰는데 관리자 강의 DTO에 그 id가 없다. 운영자는 남의 녹음을 새 앱에서 열 수도 없다. 대조표에서 `일부러 뺌(사유)`으로 두거나, 서버 코드에서 열 수 있는 경로를 찾으면 그것을 쓴다.
- S-22: `LECTERN_V1_BLOCK`을 켜면 `/api/lectures*`가 막혀 녹음 상세의 재시도·삭제·오디오 삭제가 실패한다. 보고의 `NEEDS`에 적는다(v2 관리자 라우트가 생기거나 차단 대상에서 그 경로를 빼야 한다).
- 사용자 목록은 여전히 개요 응답의 `users`다(GET 사용자 목록 경로가 없다, P5-12).
