# P1-14 여러 오디오 파트

> 등급: `basic` · 게이트: `full` · 의존: `P1-12` · 소유: `apps/server/`, `packages/media/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

`LECTERN_PIPELINE=v2`일 때 `createUpload`가 오디오 파일 여러 개(1부/2부)를 받는다. 완료하면 파트마다 `asset`(`kind = 'audio'`, `part_index` 0, 1, …)이 생기고, `process` 작업이 파트를 순서대로 ffmpeg로 하나로 이어 붙인 뒤 전사 파이프라인에 넣는다. 전사 시각은 이어 붙인 타임라인이다. `LECTERN_PIPELINE=v1`에서는 지금의 400 문구가 그대로 나온다.

## 5. 단계

1. `packages/media/src/concat.ts`:
   ```ts
   import type { RunOptions } from "./ffmpeg.ts";
   export interface ConcatResult { duration_ms: number; parts: Array<{ path: string; duration_ms: number }> }
   /** Joins audio files end to end into one lossless 16 kHz mono file at `outPath`. Original time of part n starts where the parts before it end. */
   export async function concatAudio(inputs: readonly string[], outPath: string, options?: RunOptions): Promise<ConcatResult>
   ```
   - `inputs`가 비면 `MediaError("empty", "이어 붙일 오디오가 없습니다.")`.
   - 각 입력의 길이는 `readStreamInfo(path, options).duration_ms`(`probe.ts`)로 구한다(없는 오디오 트랙이면 그 함수가 던진다).
   - 명령 인자: `["-y", ...inputs.flatMap((p) => ["-i", p]), "-filter_complex", graph, "-map", "[out]", ...encodingArgs(WORK_ENCODING), part]`. `graph`는 입력 `i`마다 `[i:a:0]aresample=16000,aformat=channel_layouts=mono[a<i>]`를 `;`로 잇고, 끝에 `[a0][a1]…concat=n=<N>:v=0:a=1[out]`을 붙인 문자열이다(라벨은 입력 순서).
   - 실행은 `writeAtomically(outPath, (part) => runFfmpeg(args(part), "오디오 이어 붙이기", options))`.
   - 반환 `duration_ms`는 `readStreamInfo(outPath)`의 값, `parts`는 입력 순서대로의 길이.
2. `uploads.ts` `createUpload`:
   - 상수 `MAX_AUDIO_PARTS = 8`.
   - `audio.length !== 1` 검사를 바꾼다: `audio.length === 0`이면 지금 문구로 400. `audio.length > 1`이고 `config().pipeline !== "v2"`이면 **지금과 똑같은 문구** `"새 녹음에는 오디오 파일이 하나 있어야 합니다."`로 400. `audio.length > MAX_AUDIO_PARTS`이면 400 `"오디오는 최대 8개까지 올릴 수 있습니다."`. `config`는 `@lectern/config`에서 가져온다.
   - `body.recording_id`가 있을 때 오디오 거부는 그대로.
3. `uploads.ts` `completeUpload`: 
   - `const audios = stored.filter((s) => s.file.kind === "audio")`, `const audio = audios[0]`. 중복 검사 키는 `audios.length === 1 ? audio.sha256 : sha256Hex(audios.map(a => a.sha256).join("\n"))`(`@lectern/db`의 `sha256Hex`). 이 값을 `getLectureByAudioSha256`과 `createRecordingForAudio`의 `dedupeKey`에 쓴다(`sha256` 필드는 첫 파트의 것).
   - 중복(`existing`)이면 `audios` 전부를 `rmSync`로 지운다(지금은 첫 파일만).
   - 새 녹음이면 `createRecordingForAudio`는 첫 파트로 그대로 부르고, 이어서 `transact(() => insertAudioPartAssets(recording, audios.slice(1), now))`를 부른다. 새 비공개 함수:
     ```ts
     // part_index 1.. in upload order; durations come from the process job (concatAudio)
     INSERT INTO asset (id, workspace_id, recording_id, kind, part_index, blob_key, sha256, bytes, mime, duration_ms, page_count, meta_json, created_at)
     VALUES (uuidv7(now), ?, ?, 'audio', ?, 'file:' || ?, ?, ?, ?, NULL, NULL, ?, ?)   -- meta_json = {"filename": ..., "path": ...}
     ```
     `mime`은 `AUDIO_MIME_BY_EXT[extname(path)] ?? "application/octet-stream"`.
   - `enqueueDistillation` → (P1-12가 바꾼) `enqueueRecordingProcessing`의 인자는 첫 파트 경로 그대로.
4. `process-job.ts` `runProcessJob`: 전사 파이프라인 호출 직전에 오디오 입력을 정한다.
   - `const parts = db.query("SELECT id, blob_key, meta_json FROM asset WHERE recording_id = ? AND kind = 'audio' ORDER BY part_index").all(recordingId)`; 각 경로는 `assetPath(row)`(`api/v2/store.ts`). 하나라도 `null`이면 `{ ok: false, error: "오디오 파트 파일을 찾을 수 없습니다." }`.
   - 파트가 하나면 지금 그대로(`audioPath = sourceAudio(lectureId)`).
   - 둘 이상이면 `const joined = join(DATA_DIR, "work", `${job.id}-joined.flac`)`; 파일이 없으면 `concatAudio(paths, joined, { signal })`. 있으면 다시 만들지 않는다(재개). 이어 `UPDATE asset SET duration_ms = ? WHERE id = ?`를 파트마다 실행한다. 이 `audioPath = joined`를 전사 입력으로 쓴다. `checkSource()`의 기준(강의의 `audio_path`)은 그대로 첫 파트 경로다.
   - 작업이 `ok`이거나 취소/원본 삭제로 끝나면 `joined` 파일을 지운다(`rmSync(…, { force: true })`). 실패하면 남긴다(재시도 때 재사용).
   - `concatAudio`가 던진 `MediaError`는 기존 오류 경로(한국어 메시지, `failLectureRecord`)로 처리한다.
5. `db.ts` `deleteLectureById`: 강의를 지우기 전에 `SELECT blob_key, meta_json FROM asset WHERE recording_id = ? AND kind = 'audio' AND blob_key LIKE 'file:%'`(`recording.id` = `lectureRecordingId(id)`)의 파일을, 경로가 `join(DATA_DIR, "uploads")`로 시작할 때만 `unlinkSync`(실패 무시)한다. 첫 파트 파일을 지우는 기존 코드는 그대로 둔다.

## 10. 명세 작성자 메모

- 충돌: `packages/db/src/legacy.ts`의 `projectAudio`는 첫 오디오 asset의 `duration_ms`를 강의 전체 길이로 덮는다. 파트가 둘이면 웹의 `createAudioClock`(첫 파트 길이로 둘째 시작 위치를 정한다)이 틀어진다. 이 파일은 `P1-11` 소유라서 `P1-11` 명세에 "녹음에 오디오 asset이 둘 이상이면 `projectAudio`가 `duration_ms`를 덮지 않는다"를 넣었다. `P1-11`이 병합돼 있어야 위 타임라인 테스트의 `asset.duration_ms` 단언이 통과한다.
- `deleteLectureById`의 추가 파트 파일 삭제는 `db.ts`(소유 안)에서 한다. PDF·이미지 asset 파일은 지금도 삭제되지 않는 것으로 보인다(확인 못 함). 이 패키지는 오디오만 다룬다.
- v1 클라이언트는 첫 파트만 본다(`lectures.audio_path`). 의도된 제한이다.
- `concatAudio`의 필터 문자열은 ffmpeg 버전에 따라 조정이 필요할 수 있다. 위 테스트(혼합 포맷 포함)가 통과하는 형태를 쓴다.
