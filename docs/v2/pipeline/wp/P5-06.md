## 1. 목표

팀 워크스페이스에 사람을 이메일로 초대하고, 받은 사람이 로그인한 뒤 수락하면 멤버가 된다. owner·admin이 멤버의 역할을 바꾸고 내보낼 수 있다. owner는 항상 한 명 이상 남는다. 팀 워크스페이스에 녹음을 올릴 수 있다. 전부 `LECTERN_TEAMS=1`일 때만 동작하고 꺼져 있으면 501이다.

## 5. 단계

1. `access.ts`: `Action`에 `"member:manage"`를 더하고 `can`에서 `MANAGERS`(owner, admin)만 허용한다.
2. `invites.ts`
   ```ts
   export const INVITE_TTL_MS = 7 * 24 * 60 * 60 * 1000;
   export function createInvite(p: { workspaceId: string; email: string; role: "admin" | "member" | "viewer"; invitedBy: string }): { id: string; token: string; expiresAt: number }
   export function findInviteByToken(token: string): InviteRow | null       // by sha256Hex(token)
   export function acceptInvite(token: string, user: { id: string; email: string }): { workspaceId: string; role: string } | { error: "invalid" | "expired" | "revoked" | "used" | "email_mismatch" }
   export function inviteMail(p: { workspaceName: string; inviterName: string; role: string; token: string }): { subject: string; html: string }
   ```
   - 토큰: `randomBytes(32).toString("base64url")`, 저장은 `sha256Hex`. 이메일은 소문자·trim으로 정규화해 저장한다.
   - `acceptInvite` 순서: 없음 → `invalid`. `revoked_at` → `revoked`. `accepted_at` → `used`. `expires_at <= now` → `expired`. 초대의 이메일과 사용자의 이메일(둘 다 정규화)이 다르면 `email_mismatch`. 이미 멤버면 역할은 바꾸지 않고 초대만 수락 처리한다. 아니면 `membership` 행을 넣는다. 한 트랜잭션에서 `accepted_at`, `accepted_by`를 채운다.
   - 메일: 제목 `[Lectern] <초대한 사람>님이 "<워크스페이스 이름>" 워크스페이스에 초대했습니다`. 본문: `<초대한 사람>님이 Lectern의 "<이름>" 워크스페이스에 <역할 표기>(으)로 초대했습니다.`, 버튼 링크 `${config().baseUrl}/app/invite?token=<token>`(문구 `초대 수락하기`), `이 초대는 7일 동안 유효합니다. 초대를 받은 이메일 주소로 로그인해야 수락할 수 있습니다.`, `초대를 요청한 적이 없다면 이 메일을 무시해 주세요.` 역할 표기: `admin` → `관리자`, `member` → `멤버`, `viewer` → `보기 전용`. 값은 `escapeHtml`.
3. `workspaces.ts` — 여섯 핸들러 모두 맨 앞에서 `config().teams`가 거짓이면 `notImplemented(req)`.
   - `createInvite`: `requireWorkspace(req, id, "member:manage")`. 개인 워크스페이스면 `409 conflict`, `개인 워크스페이스에는 초대할 수 없습니다.` 이미 멤버인 이메일이면 `409`, `이미 이 워크스페이스의 멤버입니다.` 같은 이메일의 살아 있는 초대가 있으면 그것을 회수하고 새로 만든다. 대기 중 초대는 워크스페이스당 50개까지(`409`, `대기 중인 초대가 너무 많습니다.`). admin은 `admin` 역할로 초대할 수 없다(owner만. `403`). 메일은 `await sendMail(…)`; 실패하면 초대 행을 지우고 `503 unavailable`, `초대 메일을 보내지 못했습니다. 잠시 뒤 다시 시도해 주세요.` 응답 201 `InviteDto`(토큰은 응답에 없다).
   - `listInvites`: `member:manage`. 수락·회수·만료되지 않은 것만, 최신순.
   - `revokeInvite`: `member:manage`. `revoked_at = now`. 없으면 404. 204.
   - `acceptInvite`: 로그인 필요. 사용자당 15분에 10번까지(넘으면 `429 rate_limited`). 오류 매핑: `invalid`·`revoked`·`used` → `404 not_found`, `초대를 찾을 수 없습니다. 이미 사용했거나 취소된 초대입니다.` / `expired` → `409 conflict`, `만료된 초대입니다. 다시 초대해 달라고 요청해 주세요.` / `email_mismatch` → `403 forbidden`, `이 초대는 다른 이메일 주소로 보낸 것입니다. 초대받은 주소로 로그인해 주세요.` 성공 200 `{ workspace, role }`.
   - `updateMember`: `member:manage`. 대상이 멤버가 아니면 404. 규칙: ① admin은 owner의 역할을 바꿀 수 없고 누구도 owner·admin으로 올릴 수 없다(`403`) ② owner만 owner를 만들거나 내릴 수 있다 ③ **마지막 owner의 역할을 내리면 `409 conflict`, `owner가 한 명은 있어야 합니다. 다른 멤버를 먼저 owner로 지정해 주세요.`** 응답은 `WorkspaceMember`.
   - `removeMember`: 자기 자신이면 누구나 가능(나가기), 남이면 `member:manage`. admin은 owner·admin을 내보낼 수 없다(`403`). 마지막 owner는 위와 같은 409. 내보낸 사람의 녹음은 워크스페이스에 남는다(`created_by`는 그대로). 204.
   - 마지막 owner 검사와 변경은 한 트랜잭션 안에서 한다.
4. `uploads.ts`: 팀 워크스페이스의 `createUpload`를 `config().teams`가 참이고 `can(caller, "recording:create")`이면 허용한다(viewer는 403). 플래그가 꺼져 있으면 지금 동작 그대로다. 팀 녹음의 기본 `visibility`는 `workspace`다(요청이 `private`를 주면 그대로).
5. 권한 표 테스트(`api-v2-access.test.ts`): 역할 4개(owner, admin, member, viewer)와 비멤버 × 아래 행동을 표 하나로 돌린다. 리소스는 팀 워크스페이스의 `workspace` 공개 녹음, 남의 `private` 녹음, 자기 `private` 녹음이다.

   | 행동 | owner | admin | member | viewer | 비멤버 |
   |---|---|---|---|---|---|
   | 워크스페이스 보기 | 200 | 200 | 200 | 200 | 403 |
   | 워크스페이스 설정 변경 | 200 | 200 | 403 | 403 | 403 |
   | 초대 만들기(member) | 201 | 201 | 403 | 403 | 403 |
   | 초대 만들기(admin) | 201 | 403 | 403 | 403 | 403 |
   | 업로드 | 201 | 201 | 201 | 403 | 403 |
   | `workspace` 녹음 읽기 | 200 | 200 | 200 | 200 | 404 |
   | 남의 `private` 녹음 읽기 | 404 | 404 | 404 | 404 | 404 |
   | 자기 `private` 녹음 읽기 | 200 | 200 | 200 | — | — |
   | 남의 `workspace` 녹음 수정 | 200 | 200 | 403 | 403 | 404 |
   | 남의 `workspace` 녹음 삭제 | 204 | 204 | 403 | 403 | 404 |
   | 폴더 만들기 | 201 | 201 | 201 | 403 | 403 |

   기존 `can`의 동작이 이 표와 다르면 **`can`을 고치지 말고** 표의 기대값을 실제 동작에 맞춘 뒤 다른 칸을 `DEVIATIONS`에 적는다(권한 규칙 변경은 이 작업의 범위가 아니다).

## 6. 테스트

`invites.test.ts` (`LECTERN_TEAMS=1`, 가짜 Resend)

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| "invite sends one mail with the link" | `createInvite` | 201, 메일 1통, 본문에 `/app/invite?token=`, 응답과 DB에 토큰 원문 없음 |
| "accept creates the membership" | 초대받은 이메일의 사용자가 수락 | 200, `listWorkspaceMembers`에 그 역할로 |
| "wrong e-mail is refused" | 다른 이메일의 사용자 | 403 |
| "expired" | `expires_at`을 과거로 | 409 |
| "revoked" / "used twice" | 회수 뒤 / 두 번 | 404 |
| "re-invite replaces the old link" | 같은 이메일로 두 번 | 첫 토큰 404, 둘째 200 |
| "already a member" | 멤버의 이메일로 초대 | 409 |
| "personal workspace" | 개인 워크스페이스에 초대 | 409 |
| "mail failure rolls back" | 가짜 Resend 500 | 503, 초대 행 없음 |
| "last owner cannot be demoted or removed" | owner 한 명 | `updateMember`·`removeMember` 409 |
| "owner hands over" | 다른 멤버를 owner로 → 자신을 member로 | 둘 다 200 |
| "admin cannot touch owners or admins" | admin이 owner 역할 변경, admin 제거 | 403 |
| "member leaves" | member가 자기 자신 제거 | 204 |
| "viewer cannot upload" | viewer의 `createUpload` | 403 |
| "member uploads into the team" | member의 `createUpload` | 201, `workspace_id`가 팀 |
| "accept is rate limited" | 틀린 토큰 11번 | 11번째 429 |
| "flag off" | `LECTERN_TEAMS=0` | 6개 라우트 501, 팀 업로드는 이전 동작 |

## 10. 명세 작성자 메모

- `pipeline.json`과 CATALOG의 의존에 `P4-05`를 더했다(`mail.ts`).
