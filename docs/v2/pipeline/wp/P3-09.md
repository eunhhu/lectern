# P3-09 웹: 전역 검색

> 등급: `basic` · 게이트: `full` · 의존: `P3-06` · 소유: `apps/web/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

`/app/search` 화면이 생기고 ⌘K의 내용 검색이 하이브리드 `GET /search`(P3-06)의 결과를 종류별(녹음 제목, 전사, 문서, PDF)로 묶어 보여 준다. 결과를 누르면 그 위치로 간다(전사·문서는 시각, PDF는 그 쪽). 한글 조합(IME) 중에는 요청을 보내지 않는다. 결과가 0건이면 안내 문구가 나온다.

## 5. 단계

1. **`lib/ime-query.ts`.**
```ts
/** The committed query: it follows `raw` except while an IME composition is in progress. */
export function nextCommitted(prev: string, raw: string, composing: boolean): string { return composing ? prev : raw; }
export function useImeSafeQuery(initial = "", delayMs = 250): {
  raw: string; setRaw: (v: string) => void; committed: string;
  inputProps: { onCompositionStart: () => void; onCompositionEnd: (e: { currentTarget: { value: string } }) => void };
};
```
   `committed`는 `raw.trim()`이 `delayMs` 동안 안 바뀐 뒤 갱신된다. 조합 중에는 갱신하지 않는다. 조합이 끝나면(`onCompositionEnd`) `raw`를 `e.currentTarget.value`로 맞추고 다시 타이머를 시작한다. `inputProps`는 `<Input>`에 펼쳐 넣는다.
2. **`lib/search-hits.ts`에 추가.**
```ts
export function cleanSnippet(parts: SnippetPart[]): SnippetPart[];   // per part: same cleanups as hitText; drop empty parts; trim the ends
export function hitPdfTarget(hit: SearchHit): { assetId: string; page: number } | undefined;  // only kind "pdf_page"
export type HitGroupKey = "recording" | "transcript" | "document" | "pdf_page";
export const HIT_GROUP_LABEL: Record<HitGroupKey, string> = { recording: "녹음", transcript: "전사", document: "문서", pdf_page: "PDF" };
export function groupHits(hits: SearchHit[]): Array<{ key: HitGroupKey; label: string; hits: SearchHit[] }>;  // fixed order recording, transcript, document, pdf_page; empty groups omitted; unknown kinds skipped; order inside a group unchanged
```
   `hitTime`은 `pdf_page`에 `undefined`(지금 코드가 이미 그렇게 동작한다).
3. **라우트.** `router.tsx`: `searchRoute = createRoute({ getParentRoute: () => authedRoute, path: "/search", validateSearch: (s) => ({ q: str(s.q), kind: s.kind === "transcript" || s.kind === "document" || s.kind === "pdf_page" ? s.kind : undefined }), component: SearchPage })`, `authedRoute.addChildren`에 추가. `recordingRoute`의 `validateSearch`에 `pdf`를 더한다: `^[A-Za-z0-9_-]{1,64}:\d{1,5}$`에 맞는 문자열만 통과, 아니면 생략. 사이드바 내비게이션(`NAV_ITEMS`)과 `G` 단축키는 **바꾸지 않는다**(화면은 ⌘K와 헤더 검색 아이콘 흐름에서 도달한다).
4. **`RecordingPage.tsx`.** `PlaybackProvider` 안쪽에 작은 컴포넌트 `PdfDeepLink({ pdf })`를 렌더한다: `useEffect`에서 `pdf`가 있으면 `const [assetId, page] = pdf.split(":")`, `showPdfPage(assetId, Number(page))`를 한 번 부른다. 부른 뒤 `navigate({ ..., search: { ...(t !== undefined ? { t } : {}) }, replace: true })`로 `pdf` 인자를 지운다(`ask` 처리와 같은 방식).
5. **`queries.ts`.** `queryKeys.search = (ws, q, kind) => ["search", ws, q, kind ?? null] as const`; `useSearchHits(ws, q, kind)`: `useQuery({ queryKey, queryFn: () => api.search({ workspace_id: ws, q, kind, limit: 50 }), enabled: q.length >= 2, staleTime: 60_000 })`.
6. **`SearchPage.tsx`** (`usePageTitle("검색")`, `layout.page`/`layout.pageTitle`):
   - `useSearch({ from: "/_authed/search" })`로 `q` 초기값. `useImeSafeQuery(q ?? "")`. 입력은 `ui/controls.tsx`의 텍스트 입력(없으면 `react-aria-components`의 `TextField`/`Input`), `aria-label="내용 검색"`, `inputProps` 펼침. `committed`가 바뀌면 `navigate({ to: "/search", search: { q: committed || undefined, kind }, replace: true })`.
   - 종류 필터 칩 4개(전체/전사/문서/PDF; `ToggleButton` 또는 `Button`, `aria-pressed`).
   - `committed.length < 2`: 안내 "두 글자 이상 입력하면 전사, 문서, PDF에서 찾습니다."(요청 없음). 로딩: "찾는 중…". 오류: `ErrorBox`. 0건: `EmptyState icon="search"` 제목 "‘{committed}’에 맞는 결과가 없습니다." 본문 "다른 단어로 찾거나 물어보기를 써 보세요."와 "물어보기" 버튼(`/ask?q=…`).
   - 결과: `groupHits(items)`를 `<section aria-label="{label} 결과">` + `<h2>{label} {개수}</h2>` + 목록으로. 항목은 링크(`<Link>` 또는 `Button`로 `navigate`), 내용은 `cleanSnippet(hit.snippet)`을 `<mark>`(highlight) / 평문으로 렌더(`dangerouslySetInnerHTML` 금지), 보조줄 `"{recording_title}"` + 시각(`formatTimestamp(hitTime)`) 또는 `"p.{page}"`.
   - 이동: 전사·문서 → `/recordings/$recordingId`, `search: t !== undefined ? { t } : {}`; PDF → `search: { pdf: "${assetId}:${page}" }`; 녹음 제목 → 인자 없음.
   - 스타일은 토큰만(`styles.test.ts` 규칙). `mark`는 `background: var(--color-bg-hover)`처럼 기존 토큰을 쓴다(없는 토큰 금지).
7. **`CommandPalette.tsx`.**
   - 입력 `<Input>`에 `useImeSafeQuery`의 `inputProps`를 펼치고, 요청에 쓰는 `q`를 `committed`(180 → 기본 250ms 대신 이 훅에 `delayMs=180`)로 바꾼다. 항목 필터링(이동·명령 순위)은 지금처럼 `query`(raw)로 한다.
   - `search` 쿼리 `limit`을 8로. 적중 항목: `h.kind === "pdf_page"`이면 아이콘 `pdf`, `detail`에 `"{제목} · p.{page}"`, 이동은 `search: { pdf: … }`. 나머지는 지금 그대로.
   - `search:all` 항목의 이동을 `/library?q=`에서 `/search?q=`로 바꾸고 라벨을 "‘{질의}’ 모든 결과 보기"로.
8. **픽스처.** `fixtures/index.ts`에 `export const PDF_PAGE_TEXTS: Array<{ recordingId: string; assetId: string; page: number; text: string }>`: `rec_os07`/`rec_os07_pdf`의 `12쪽 "라운드 로빈 타임 퀀텀 표: 퀀텀이 너무 크면 FCFS와 같아진다"`, `16쪽 "다단계 피드백 큐 레벨별 퀀텀 슬라이드"`, 3쪽 `"프로세스 상태 다이어그램 슬라이드"`. `fixture/client.ts`의 `search`에서 `!q.kind || q.kind === "pdf_page"`이면 이 배열을 부분 문자열(소문자)로 훑어 `{ kind: "pdf_page", recording_id, recording_title, snippet: snippet(text, needle), asset_id, page }` 적중을 더한다(해당 녹음이 `q.workspace_id` 안에 있을 때만).
9. `a11y.e2e.ts`의 `SCREENS`에 `{ path: "/app/search?q=퀀텀", label: "검색", ready: "PDF" }`.

## 10. 명세 작성자 메모

- 한글 조합 중 요청 금지를 e2e로 보려면 Chromium의 CDP `Input.imeSetComposition`이 필요하다(Playwright `context.newCDPSession(page)`). fixture 프로젝트는 네트워크 없이 메모리 클라이언트라 요청 대신 **결과가 나타나지 않음**으로 확인한다. Playwright 프로젝트가 Chromium이 아니면 이 테스트는 만들 수 없어 `BLOCKED`로 보고한다(미확인).
- `RecordingView`에서 `PlaybackProvider`가 어디에 있는지 확인하지 못했다(`RecordingPage.tsx` 일부만 읽음). 4단계는 "Provider 안쪽"이라는 조건만 정했다.
- 문서 적중이 블록 위치로 이동하지 않는 것은 현 `RecordingPage`가 `?t=`만 받기 때문이다(범위 밖).
- 헤더 검색 아이콘은 현재 ⌘K 팔레트를 연다(`RootLayout.tsx`). `/search`로 가는 길은 팔레트의 "모든 결과 보기"뿐이다.
