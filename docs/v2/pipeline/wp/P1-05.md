## 1. 목표

"다음 주 화요일 수업 전까지", "내일 오전 9시 반" 같은 한국어 상대 날짜 표현을 녹음 시각과 시간대 기준의 실제 날짜·시각으로 바꾸는 순수 함수 `resolveKoreanDate`를 만든다. 못 읽으면 `null`이다(추측 금지). 사용자가 보는 변화는 없다(`verify`가 쓴다).

## 5. 단계

1. 타입과 시그니처.
   ```ts
   export interface KoreanDateBase { recordedAtMs: number; tz: string }
   export interface ResolvedDate {
     date: string;            // "YYYY-MM-DD"
     time: string | null;     // "HH:MM"
     end_time: string | null; // "HH:MM"
     all_day: boolean;        // time === null
     rule: string;
     flags?: string[];        // only present when non-empty; the only value used here: "weekday_mismatch"
   }
   export function resolveKoreanDate(raw: string, base: KoreanDateBase): ResolvedDate | null;
   ```
2. 날짜 산술 도우미(모듈 안 비공개).
   - `localParts(ms, tz)`: `new Intl.DateTimeFormat("en-US", { timeZone: tz, year: "numeric", month: "numeric", day: "numeric", hour: "numeric", minute: "numeric", hourCycle: "h23" }).formatToParts(new Date(ms))`에서 `{ y, m, d }`를 뽑는다. 잘못된 `tz`면 `RangeError`가 그대로 나가게 둔다.
   - 날짜는 **일 번호**로 계산한다: `dayNumber(y, m, d) = Math.floor(Date.UTC(y, m - 1, d) / 86400000)`. 문자열 변환 `fmt(dn)`은 `new Date(dn * 86400000).toISOString().slice(0, 10)`.
   - 요일(월=0 … 일=6): `(dn + 3) % 7` (1970-01-01이 목요일이므로). 그 주의 월요일: `dn - weekday(dn)`.
   - 존재하지 않는 날짜(2월 30일, 13월)는 `null`. 확인: `fmt(dayNumber(y,m,d))`을 다시 파싱해 월·일이 같은지 본다.
3. 전처리: `raw.normalize("NFKC")`, 앞뒤 공백 제거, 연속 공백 하나로. 빈 문자열이면 `null`.
4. 시각 추출(먼저, 날짜와 독립).
   - 범위: `/(오전|오후)?\s*(\d{1,2})\s*시(?:\s*(?:(\d{1,2})\s*분|(반)))?\s*(?:부터|~|-)\s*(오전|오후)?\s*(\d{1,2})\s*시(?:\s*(?:(\d{1,2})\s*분|(반)))?/`. 맞으면 `time`, `end_time` 둘 다 얻는다. 끝 시각에 오전/오후가 없으면 첫 시각의 것을 이어받는다. 끝 ≤ 시작이면 12시간을 더하고, 그래도 24시 이상이면 `end_time = null`.
   - 단일: `/(오전|오후)?\s*(\d{1,2})\s*시(?:\s*(?:(\d{1,2})\s*분|(반)))?/`.
   - 변환: `오후`이고 시<12면 +12, `오전 12시`는 0시, `오후 12시`는 12시, 표시 없으면 24시간제로 그대로. `반`은 30분. 시 ≥ 24 또는 분 ≥ 60이면 전체 `null`. 형식 `HH:MM`(0채움).
   - 맞은 부분은 문자열에서 **지운다**. 남은 문자열을 `rest`라 한다.
5. 날짜 규칙(`rest`에서 **이 순서로** 처음 맞는 것 하나, 정규식은 부분 일치). `B` = 기준일(`localParts(recordedAtMs, tz)`의 일 번호), `Y`·`M` = 기준 연·월.
   | 순서 | 정규식 | 날짜 | rule |
   |---|---|---|---|
   | 1 | `/이번\s*달\s*말\|이달\s*말\|월말/` | `Y-M`의 마지막 날 | `end_of_month` |
   | 2 | `/다음\s*달\s*(\d{1,2})\s*일/` | `M+1`월(12월이면 다음 해 1월) N일 | `next_month_day` |
   | 3 | `/(\d{1,2})\s*월\s*(\d{1,2})\s*일/` | 아래 "연도 규칙" | `month_day` |
   | 4 | `/(이번\|다음)\s*주\s*([월화수목금토일])요일/` | 주 시작은 **월요일**. `이번`=0주, `다음`=1주. 날짜 = (기준일이 속한 주의 월요일) + 주수×7 + 요일 번호(월0…일6) | `this_week_weekday` / `next_week_weekday` |
   | 5 | `/(\d+)\s*주\s*(?:뒤\|후)/`, `/일주일\s*(?:뒤\|후)/` | `B + N×7` (일주일=1) | `weeks_later` |
   | 6 | `/(\d+)\s*일\s*(?:뒤\|후)/` | `B + N` | `days_later` |
   | 7 | `글피` → `B+3` `three_days_later`; `모레` → `B+2` `day_after_tomorrow`; `내일` → `B+1` `tomorrow`; `오늘` → `B` `today` (이 순서로 검사) | | |
   | 8 | `/([월화수목금토일])요일/` | 기준일 **다음에 오는** 그 요일(기준일이 그 요일이면 +7) | `weekday` |
   - 어느 것도 안 맞으면: `time`이 있으면 날짜 = `B`, rule `time_only`. 시각도 없으면 `null`.
   - 연도 규칙(3번): 후보 = 기준 연의 M월 D일(존재하지 않으면 `null`). 후보가 `B`보다 **31일을 넘게** 과거면(`B - 후보 > 31`) 다음 해로 한다(정확히 31일 전이면 그대로). 같은 `rest`에 `([월화수목금토일])요일`이 있고 결과 날짜의 실제 요일과 다르면 날짜는 그대로 두고 `flags: ["weekday_mismatch"]`를 단다.
   - "다음 주"만 있고 요일이 없는 경우, `5일까지`처럼 월 없는 일자, "학기 말쯤", "나중에" 등은 어느 규칙에도 안 맞아 `null`.
6. 결과: `{ date, time, end_time, all_day: time === null, rule }` (+ `flags`는 비어 있지 않을 때만 키를 둔다). `end_time`이 없으면 `null`.
7. `src/index.ts`에 export를 더한다.

**C. 시간대**: `recordedAtMs = Date.UTC(2026, 9, 19, 20, 0, 0)`(= 서울 10월 20일 05:00 = 뉴욕 10월 19일 16:00).
- `tz: "America/New_York"`: `오늘` → 2026-10-19, `내일` → 2026-10-20.
- `tz: "Asia/Seoul"`: `오늘` → 2026-10-20.

**D. 시각 범위·표기**: `오후 2시부터 4시까지` → time 14:00, end_time 16:00, date 2026-10-19, rule `time_only`; `오전 11시부터 1시까지` → 11:00, end 13:00; `내일 오후 3시 30분` → 2026-10-20 15:30; `오전 12시` → 00:00; `오후 12시` → 12:00; `내일 오후 25시` → `null`.

**E. 읽지 못함 → `null`(5개 이상)**: `""`, `"다음 주"`, `"5일까지"`, `"나중에"`, `"2월 30일"`, `"13월 1일"`.

**F. 부가**: `flags` 키는 `weekday_mismatch`가 없는 결과에는 **없다**(`"flags" in result === false`); 같은 입력은 항상 같은 결과(두 번 호출 `toEqual`); 입력 앞뒤 공백·여러 공백(`"  이번   주  금요일 "`)도 같은 결과; 전각 숫자는 NFKC 전처리로 반각이 되므로 `"３일 뒤"`의 결과가 `3일 뒤`와 같다.

## 10. 명세 작성자 메모

- 계약의 `ResolvedDate`에는 `flags`가 없지만 표의 "`month_day` (+ `weekday_mismatch`)"를 담을 곳이 필요해서 선택 필드 `flags?: string[]`를 더했다. 계약 필드는 그대로이고 값이 있을 때만 키가 생긴다.
- 계약은 `이번 주 월요일`처럼 오늘이나 과거인 요일, 시각만 있는 표현의 날짜, 시각 범위, 24시간제 표기를 정하지 않았다. 위 규칙(오늘 날짜로 `time_only`, 범위는 `end_time`)은 명세 작성자가 정했다.
- `다다음 주`, `이틀 뒤`, `N개월 후`, `지난 주`는 계약 목록에 없어 `null`이다.
- 5번 표의 규칙 5·6은 계약 표의 `weeks_later`/`days_later`를 따른다. 정규식 순서는 `일주일 후`가 `N일 뒤`에 걸리지 않게(숫자가 필요하므로 안 걸린다) 확인했다.
