# P4-01 ICS 구독

> 등급: `basic` · 게이트: `full` · 의존: `P4-C` · 소유: `apps/server/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

사용자가 캘린더 앱에 구독 주소 하나를 넣으면 확정한 일정이 보인다. 설정에서 주소를 만들고(`createCalendarFeed`), 있는지 보고(`getCalendarFeed`), 없앤다(`deleteCalendarFeed`). 주소 `GET /cal/<토큰>.ics`는 인증 없이 열리는 비밀 주소다. `LECTERN_CALENDAR=0`이면 feed 라우트는 501, `/cal/…`은 404다.

## 5. 단계

1. `calendar/ics.ts`
   ```ts
   export interface IcsEvent { id: string; title: string; startAt: number; endAt: number | null; allDay: boolean; tz: string; updatedAt: number; recordingTitle: string | null }
   export function escapeIcsText(text: string): string   // \ → \\ , ; → \; , "," → \, , newline → \n (order: backslash first)
   export function foldLine(line: string): string         // fold to <= 75 octets; continuation lines start with one space; never split a UTF-8 character
   export function renderIcs(events: IcsEvent[]): string  // lines joined with CRLF, ends with CRLF
   ```
   규칙
   - 머리: `BEGIN:VCALENDAR`, `VERSION:2.0`, `PRODID:-//Lectern//Calendar//KO`, `CALSCALE:GREGORIAN`, `METHOD:PUBLISH`, `X-WR-CALNAME:Lectern`. 꼬리: `END:VCALENDAR`.
   - 일정마다 `BEGIN:VEVENT`, `UID:<id>@lectern`, `DTSTAMP:<updatedAt, UTC>`, 시작, 끝, `SUMMARY:<escape(title)>`, (녹음 제목이 있으면) `DESCRIPTION:<escape("녹음: " + recordingTitle)>`, `END:VEVENT`.
   - 시각 형식은 UTC `YYYYMMDDTHHMMSSZ`다. `DTSTAMP`는 `updatedAt`이다(지금 시각을 쓰지 않는다. 출력이 결정적이어야 한다).
   - 시간 일정: `DTSTART:<startAt>`, `DTEND:<endAt ?? startAt + 3600000>`.
   - 하루 종일: `DTSTART;VALUE=DATE:<tz 기준 startAt의 날짜 YYYYMMDD>`, `DTEND;VALUE=DATE:<끝 날짜 + 1일>`(끝이 없으면 시작 날짜 + 1일). 날짜는 `Intl.DateTimeFormat("en-CA", { timeZone: tz })`로 구한다.
   - 모든 줄에 `foldLine`을 적용한다. 일정은 `startAt` 오름차순, 같으면 `id` 순이다.
2. `calendar/feed.ts`
   - `createFeed(userId, workspaceId): { url: string; createdAt: number }`: 그 사용자·워크스페이스의 활성 행(`revoked_at IS NULL`)에 `revoked_at = now`를 넣고, 토큰 `randomBytes(32).toString("base64url")`을 만들어 `token_hash = sha256Hex(token)`으로 새 행을 넣는다. URL은 `` `${config().baseUrl}/cal/${token}.ics` ``다. 한 트랜잭션이다. 토큰 원문은 저장하지도 로그에 남기지도 않는다.
   - `getFeed(userId, workspaceId): { exists: boolean; createdAt: number | null }`.
   - `deleteFeed(userId, workspaceId): void` (`revoked_at = now`).
   - `feedByToken(token): { userId; workspaceId } | null` (해시로 찾고 `revoked_at IS NULL`).
   - `feedEvents(userId, workspaceId): IcsEvent[]`: `event_candidate`에서 `workspace_id`가 같고 `status IN ('accepted','synced')`이며, 그 녹음이 `visibility = 'workspace'`이거나 `created_by = userId`인 것. 사용자가 그 워크스페이스의 멤버가 아니게 됐으면 빈 배열이다.
3. `api/v2/calendar.ts`: 세 핸들러를 구현한다. 맨 앞에서 `config().calendar`가 거짓이면 `notImplemented`와 같은 501을 돌려준다. `requireWorkspace`로 멤버인지 본다. `getCalendarFeed`의 `url`은 항상 `null`이다. `createCalendarFeed`는 `{ url, created_at }`, `deleteCalendarFeed`는 204다.
4. `http.ts`: v2 앱을 붙인 줄 뒤, 레거시로 넘기는 `app.all("*")` 앞에 넣는다.
   ```ts
   app.get("/cal/:file", (c) => { /* 404 unless config().calendar and :file matches /^([A-Za-z0-9_-]{20,128})\.ics$/ and feedByToken() finds a feed */ });
   ```
   성공 응답 헤더: `Content-Type: text/calendar; charset=utf-8`, `Cache-Control: private, max-age=300`, `X-Robots-Tag: noindex`. 실패는 모두 같은 404(본문 `Not found`)다. 토큰이 틀린 것과 회수된 것을 구별해 알려 주지 않는다. 요청 로그에 경로가 남는다면 `/cal/` 뒤를 `***`로 가린다(`redactUrlForLog`가 있으면 그것을 쓴다).
5. `api-v2.test.ts`의 `NOT_YET`에서 `getCalendarFeed`, `createCalendarFeed`, `deleteCalendarFeed`를 뺀다(P4-C가 넣은 것). README 표를 고친다.

## 6. 테스트

`calendar-ics.test.ts` (순수 함수)

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| "renders a timed and an all-day event" | 아래 두 일정 | 아래 문자열과 정확히 같다 |
| "escapes text" | `escapeIcsText("a,b;c\\d\ne")` | `a\,b\;c\\d\ne` (마지막은 글자 `\`와 `n`) |
| "folds long lines without splitting characters" | 제목이 `가` 60자 | 모든 줄이 75옥텟 이하, 둘째 줄부터 공백으로 시작, `CRLF+공백`을 지우면 원래 줄 |
| "end defaults to one hour" | `endAt: null`, 시간 일정 | `DTEND`가 시작 + 1시간 |
| "sorted by start then id" | 순서를 섞어 넣음 | `UID` 순서가 시작 시각 순 |

입력: `{ id: "evc_1", title: "과제 제출, 3장", startAt: Date.UTC(2026,9,27,6,0,0), endAt: Date.UTC(2026,9,27,7,0,0), allDay: false, tz: "Asia/Seoul", updatedAt: Date.UTC(2026,9,19,5,0,0), recordingTitle: "자료구조 7주차" }`, `{ id: "evc_2", title: "중간고사", startAt: Date.UTC(2026,10,2,15,0,0), endAt: null, allDay: true, tz: "Asia/Seoul", updatedAt: Date.UTC(2026,9,19,5,0,0), recordingTitle: null }`.

기대(각 줄 끝은 CRLF):
```
BEGIN:VCALENDAR
VERSION:2.0
PRODID:-//Lectern//Calendar//KO
CALSCALE:GREGORIAN
METHOD:PUBLISH
X-WR-CALNAME:Lectern
BEGIN:VEVENT
UID:evc_1@lectern
DTSTAMP:20261019T050000Z
DTSTART:20261027T060000Z
DTEND:20261027T070000Z
SUMMARY:과제 제출\, 3장
DESCRIPTION:녹음: 자료구조 7주차
END:VEVENT
BEGIN:VEVENT
UID:evc_2@lectern
DTSTAMP:20261019T050000Z
DTSTART;VALUE=DATE:20261103
DTEND;VALUE=DATE:20261104
SUMMARY:중간고사
END:VEVENT
END:VCALENDAR
```

`calendar-feed.test.ts` (`api-v2-data.test.ts`의 서버 준비 방식을 본뜬다. `LECTERN_CALENDAR=1`)

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| "create then fetch" | `createCalendarFeed` → 받은 URL의 경로로 `GET` | 200, `text/calendar`, 본문에 수락한 일정의 `UID` |
| "only accepted and synced" | `suggested`·`dismissed` 일정도 넣음 | 본문에 없다 |
| "get never returns the url" | 만든 뒤 `getCalendarFeed` | `{ exists: true, url: null }` |
| "recreate revokes the old url" | 두 번 만듦 | 옛 URL 404, 새 URL 200 |
| "delete" | `deleteCalendarFeed` 뒤 | URL 404, `getCalendarFeed`가 `exists: false` |
| "private recordings stay private" | 사용자 B의 비공개 녹음 일정, 사용자 A의 feed | A의 본문에 없다 |
| "no plaintext token in the database" | 만든 뒤 `calendar_feed` 전체를 문자열로 | 토큰 원문이 없다 |
| "flag off" | `LECTERN_CALENDAR=0` | feed 라우트 501, `/cal/x.ics` 404 |
| "bad file name" | `/cal/abc`, `/cal/..%2f.ics` | 404 |

## 10. 명세 작성자 메모

- 테스트에서 설정을 켜는 방법(환경 변수를 준 뒤 설정을 다시 읽는 방법)은 `LECTERN_ASK`를 켜는 기존 테스트(`apps/server/test/ask-api.test.ts`)를 본뜬다. 확인 필요: 그 테스트의 방식이 이 플래그에도 그대로 되는지.
- `/cal/` 경로의 로그 가림은 요청 로그가 경로를 남길 때만 필요하다. `LECTERN_LOG_REQUESTS`의 로그 형식을 보고 정한다.
