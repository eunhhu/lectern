# P3-08 웹: PDF 뷰어

> 등급: `careful` · 게이트: `full` · 의존: `P3-C`, `P3-03` · 소유: `apps/web/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

녹음 상세의 "파일" 패널에 pdf.js 뷰어가 생긴다. 한 번에 한 쪽만 canvas로 그리고(큰 PDF도 가볍다), 쪽 이동(버튼·키보드·쪽 번호 입력)과 확대/축소, 글자 선택(투명 text layer)이 된다. 문서의 `p.4` 칩과 물어보기의 PDF 인용을 누르면 그 쪽이 열린다. 스캔본이면 "글자 인식(OCR)" 버튼이 비용 확인 대화상자를 연다. pdf.js 워커 파일은 같은 오리진의 `/app/assets/`로 번들되고, CSP 위반이 0건이다.

## 5. 단계

1. **빌드(`build.ts`).** `Bun.build` **앞에** 워커를 따로 번들한다: 진입점 `require.resolve("pdfjs-dist/build/pdf.worker.mjs")`(또는 `import.meta.resolve`), `target: "browser"`, `format: "esm"`, `minify: !dev`, `naming: { entry: "pdf-worker-[hash].[ext]" }`, `outdir: assetsDir`. 결과 파일 URL을 `ASSET_PATH + 이름`으로 만든다(`scripts`·`styles` 계산은 이 결과를 쓰지 않는다 → `index.html`에 워커 `<script>`가 생기면 안 된다). `pdfjs-dist/cmaps`와 `pdfjs-dist/standard_fonts` 디렉터리를 `assetsDir/pdfjs/cmaps`, `assetsDir/pdfjs/standard_fonts`로 복사한다(`cpSync`). 메인 `Bun.build`의 `define`에 `"process.env.LECTERN_PDF_WORKER": JSON.stringify(workerUrl)`, `"process.env.LECTERN_PDF_DATA": JSON.stringify(ASSET_PATH + "pdfjs/")`를 더한다. `dist-fixture` 빌드(`--api fixture --out`)도 같은 코드를 탄다.
2. **pdf.js 설정(`pdf/pdfjs.ts`).** pdf.js는 **지연 로드**한다(초기 JS를 키우지 않는다).
```ts
export async function loadPdfjs(): Promise<typeof import("pdfjs-dist")> {
  const pdfjs = await import("pdfjs-dist/build/pdf.mjs");
  pdfjs.GlobalWorkerOptions.workerSrc = process.env.LECTERN_PDF_WORKER!;
  return pdfjs;
}
export const PDF_OPEN_OPTIONS = { isEvalSupported: false, enableXfa: false, useWorkerFetch: false,
  cMapUrl: `${process.env.LECTERN_PDF_DATA}cmaps/`, cMapPacked: true,
  standardFontDataUrl: `${process.env.LECTERN_PDF_DATA}standard_fonts/` } as const;
```
   `Bun.build`가 `pdfjs-dist/build/pdf.mjs`의 `node:*`/`canvas` 참조로 실패하면 `pdfjs-dist/legacy/build/pdf.mjs`와 `pdf.worker.mjs`(legacy)로 **둘 다** 바꾸고 보고의 DEVIATIONS에 적는다. 그래도 안 되면 `BLOCKED`.
3. **API(R8).** `types.ts`에 `AssetPages`, `OcrAssetRequest`, `OcrAssetResponse` 재수출. `ApiClient`에 `listAssetPages(assetId: string): Promise<AssetPages>`와 `ocrAsset(assetId: string, body: OcrAssetRequest): Promise<OcrAssetResponse>`. http: `call("listAssetPages", { params: { asset_id: assetId } })`, `call("ocrAsset", { params: { asset_id: assetId }, body })`. fixture: `listAssetPages`는 자산의 `page_count`쪽 모두 `has_text_layer: true`, `char_count: 800`, `scanned: false`(스캔본 경우는 e2e에서 `page.route`로 응답을 바꾼다); `ocrAsset`은 `dry_run`이면 `{ pages_to_ocr: page_count, estimated_cost_microusd: 2818 * page_count, job_id: null }`, 아니면 같은 값에 `job_id: "job_fixture_ocr"`. 픽스처 `assetContentUrl`은 id가 `_pdf`로 끝나면 `/api/v2/assets/${id}/content`, 아니면 `null`(오디오는 지금처럼). `queries.ts`에 `queryKeys.assetPages(id)`, `useAssetPages(assetId)`, `useOcrAsset()`(성공하면 `assetPages`와 해당 녹음 상세를 무효화).
4. **순수 함수(`lib/pdf-view.ts`).**
```ts
export const ZOOM_STEPS = [0.5, 0.75, 1, 1.25, 1.5, 2, 3] as const;
export function clampPage(page: number, pageCount: number): number;   // NaN/<1 -> 1, >pageCount -> pageCount
export function nextZoom(current: number, dir: 1 | -1): number;        // moves along ZOOM_STEPS, saturates at both ends
export function formatCostUsd(microusd: number): string;               // "$0.0028": microusd/1e6, 4 decimals; 0 -> "$0"
```
5. **뷰어(`PdfViewer.tsx`).** props `{ assetId: string; name: string; pageCount: number; targetPage: { page: number; token: number } | null }`.
   - `loadPdfjs()` 뒤 `pdfjs.getDocument({ url: api.assetContentUrl(assetId)!, ...PDF_OPEN_OPTIONS })`(쿠키 인증은 같은 오리진 기본값으로 충분). `useEffect` 정리에서 `task.destroy()`와 진행 중 `RenderTask.cancel()`.
   - 상태: `page`(1부터), `zoom`(기본 1). 쪽이 바뀔 때마다 `doc.getPage(page)`, `viewport = pg.getViewport({ scale: zoom * 1.25 })`(기본 배율 기준), 한 개의 `<canvas>`에 `devicePixelRatio`를 곱해 그린다(`canvas.width/height`는 속성으로, CSS 크기는 `style.setProperty`가 아니라 **CSS 클래스 + `width`/`height` 속성**: 인라인 `style` 속성을 쓰지 않는다. 캔버스 표시 크기는 canvas 요소의 `width`·`height` 속성과 CSS `max-width: 100%; height: auto`로 맞춘다).
   - text layer: 같은 쪽에 `new pdfjs.TextLayer({ textContentSource: pg.streamTextContent(), container: layerRef.current, viewport }).render()`. 컨테이너에 `layerRef.current.style.setProperty("--scale-factor", String(viewport.scale))`(CSSOM만 쓴다. `setAttribute("style")` 금지). 쪽을 바꾸기 전에 `layer.replaceChildren()`. 주석 레이어·XFA는 만들지 않는다.
   - 이동: 이전/다음 버튼(`aria-label="이전 쪽"`, `"다음 쪽"`), 쪽 번호 입력(`aria-label="쪽 번호"`, Enter에 `clampPage`), 표시 `"{page} / {pageCount}"`(`aria-live="polite"`), 확대/축소 버튼(`aria-label="축소"`, `"확대"`, 현재 배율 `"{zoom*100}%"`). 뷰어 영역(`tabIndex=0`, `role="group"`, `aria-label="{name} 뷰어"`)에서 `ArrowLeft`/`PageUp` 이전, `ArrowRight`/`PageDown` 다음, `+`/`-` 확대·축소, `Home`/`End` 처음·끝. 쪽 번호 입력 칸에서는 이 키를 가로채지 않는다. 한글 조합 중에는 무시(`lib/keyboard.ts`의 `isImeComposing`).
   - `targetPage`가 바뀌면(토큰 비교) `setPage(clampPage(targetPage.page, pageCount))`.
   - 오류(문서 열기 실패)는 `ErrorBox`로 "PDF를 열지 못했습니다. 원본을 다시 올려 주세요.", 로딩은 "PDF를 불러오는 중…".
   - 색은 토큰만(`var(--color-…)`; 리터럴 금지). text layer: `.textLayer { position: absolute; inset: 0; overflow: hidden; line-height: 1; } .textLayer span { position: absolute; white-space: pre; color: transparent; transform-origin: 0 0; cursor: text; } .textLayer ::selection { background: var(--color-bg-hover); }`.
6. **OCR(`OcrDialog.tsx`).** `useAssetPages(assetId)`가 `scanned: true`면 뷰어 머리에 `Badge`("스캔본")와 버튼 "글자 인식(OCR)…". 누르면 `Dialog`가 열리고 열릴 때 `ocrAsset(assetId, { dry_run: true })`를 한 번 부른다. 본문: `"{pages_to_ocr}쪽을 AI로 읽습니다. 예상 비용 약 {formatCostUsd(...)}이며 실제 비용은 다를 수 있습니다."`. 푸터: "취소", "OCR 시작". "OCR 시작"만 `dry_run: false`를 보내고 성공하면 토스트 "글자 인식을 시작했습니다." 후 닫는다. `pages_to_ocr === 0`이면 "이미 모든 쪽의 글자를 읽었습니다."와 "닫기"만. 오류 코드가 `not_implemented`(501)면 버튼 자체를 숨긴다. 확인 없이 `dry_run: false`가 나가는 경로가 없어야 한다.
7. **SidePane.** `Files`의 PDF 카드에서 `.pdfPage` 자리 표시(`<div className={s.pdfPage}>…`)를 `<PdfViewer assetId={pdf.id} name={name(pdf)} pageCount={pdf.page_count ?? 0} targetPage={target !== null ? { page: target, token: pdfTarget!.token } : null} />`로 바꾼다. `page_count`가 0/null이면 뷰어 대신 기존 안내 문구. 쪽 칩(`showPdfPage`)·`AskPanel`의 PDF 인용은 이미 `showPdfPage`를 부르므로 코드를 바꾸지 않는다. 사용하지 않게 된 `.pdfPage`·`.pdfPageNumber` CSS는 지운다.
8. 접근성: 모든 버튼에 이름, 키 조작 후 포커스가 뷰어 영역에 남는다. 새 화면 경로가 없으므로 `a11y.e2e.ts`의 `SCREENS`에 `{ path: "/app/recordings/rec_os07", label: "녹음 상세(PDF 뷰어)", ready: "1 / 24" }`를 더하되, e2e 안에서 PDF 응답을 가로챈 뒤에만 준비된다(`pdf.e2e.ts`에 axe를 넣고 이 항목은 더하지 않아도 된다).

## 8. 하지 않는 것

- 서버 변경(CSP 포함: `default-src 'self'`가 같은 오리진 워커를 이미 허용한다), `packages/*` 변경, 새 의존성(`pdfjs-dist`는 `P3-C`가 넣었다).
- 서버 e2e에 PDF 시나리오 추가. 주석 레이어·양식(XFA)·인쇄·다운로드 버튼. 여러 쪽 연속 스크롤.
- 확인 없는 OCR 요청. `localStorage`, 인라인 `<script>`/`<style>`/`style=` 속성, `blob:` 워커, 외부 CDN.

## 10. 명세 작성자 메모

- `Bun.build`가 pdf.js(`pdf.mjs`)를 브라우저용으로 묶을 수 있는지, 그리고 워커·cmaps 복사 구조가 `web-shell.ts`의 정적 서빙(`assets/` 아래 하위 디렉터리, 미등록 확장자는 `application/octet-stream`)에서 동작하는지는 **작성 시점에 실행해 보지 못했다.** 2단계에 대체 경로(legacy 빌드)를 적었다. `.bcmap`·`.pfb`를 `octet-stream`으로 주는 것이 pdf.js에 문제인지도 미확인이다.
- `apps/web`은 `pdf-lib`를 의존성으로 선언하지 않는다(P3-C는 `packages/pdf`에만 넣었다). e2e가 `pdf-lib`를 루트 `node_modules` 호이스팅으로 import한다. 호이스팅이 안 되면 `BLOCKED`(의존성은 P3-C 소관).
- 쪽 연속 스크롤 대신 한 쪽 보기로 정했다. "큰 PDF에서 보이는 쪽만 그림"을 가장 단순하게 만족한다.
- 스캔본 픽스처를 만들지 않고 e2e에서 응답을 가로챈다(픽스처 데이터 수정을 줄이려는 선택). 픽스처에 스캔본 자산이 필요하면 `src/fixtures/index.ts`를 고쳐도 소유 범위 안이다.
- 문서 칩(`p.N`) 클릭이 이미 `showPdfPage`로 연결돼 있고 물어보기 PDF 인용도 `AskPanel.tsx`가 `showPdfPage`를 부른다는 것은 코드로 확인했다. 물어보기 PDF 인용을 띄우는 fixture 흐름이 있는지는 확인하지 못했다.
- 쪽 번호 `$0.0676`은 fixture 단가(`2818 × 24`)이며 실제 서버 추정과 무관하다.
