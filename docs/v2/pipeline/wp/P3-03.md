# P3-03 pdf_ingest 단계와 쪽 저장

> 등급: `basic` · 게이트: `full` · 의존: `P3-01`, `P3-02`, `P1-12` · 소유: `packages/harness/`, `apps/server/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

`LECTERN_PDF=1`에서 `process` 작업이 녹음의 PDF asset마다 `pdf_ingest` 단계를 돌려 쪽 글자를 `pdf_page` 행으로 저장하고, asset의 `page_count`와 `meta_json.scanned`를 채운다. `GET /assets/{id}/pages`(`listAssetPages`)가 그 결과를 돌려준다. 같은 PDF를 다시 올리면 추출을 다시 하지 않는다(메모 적중). PDF 처리가 실패해도 녹음 전체는 실패하지 않고 `partial`이 된다. 스캔본이라도 OCR은 돌지 않는다(P3-05).

## 5. 단계

1. `packages/harness/src/pdf/ingest.ts` (하네스는 `@lectern/pdf`를 import하지 않는다. 추출 함수를 주입받는다):
```ts
export const PdfIngestPage = z.object({ page_no: z.int().min(1), text: z.string(), char_count: z.int().nonnegative(), has_text_layer: z.boolean() });
export const PdfIngestOutput = z.object({ page_count: z.int().nonnegative(), scanned: z.boolean(), pages: z.array(PdfIngestPage) });
export type PdfIngestOutput = z.infer<typeof PdfIngestOutput>;
export interface PdfIngestInput { path: string }
export type PdfExtractor = (path: string) => Promise<{ pageCount: number; scanned: boolean; pages: { pageNo: number; text: string; charCount: number; hasTextLayer: boolean }[] }>;
export const pdfIngestStage = (extract: PdfExtractor): StageDefinition<PdfIngestInput, PdfIngestOutput> => defineStage({
  name: "pdf_ingest", version: 1, output: PdfIngestOutput, memo: "shared",
  retry: { maxAttempts: 1, repairs: 0 },
  async key(input) { return { inputs: [await hashFile(input.path)], config: { extractor: 1, min_chars: 20, max_pages: 500 } }; },
  async run(input) { /* call extract; map camelCase -> snake_case */ },
});
```
   `run`은 추출기가 던진 오류가 `err?.name === "PdfError"`이면 `new HarnessError("input", err.message, { code: err.code })`로 바꿔 던진다(그 밖의 오류는 그대로). 파일이 없으면 `key`가 `HarnessError("input", ...)`를 던진다(`ingestStage`와 같은 방식).
2. `index.ts`에 내보내기 한 줄.
3. `apps/server/src/pdf-publish.ts`:
```ts
export interface PdfIngestSummary { ingested: number; failed: number; scannedAssets: string[]; cacheHits: number }
export function savePdfPages(args: { assetId: string; recordingId: string; workspaceId: string; out: PdfIngestOutput }): void;
export async function ingestRecordingPdfs(args: { run: JobRun; recordingId: string; workspaceId: string; extract?: PdfExtractor }): Promise<PdfIngestSummary>;
```
   - `savePdfPages`: `transact(...)`(`api/v2/store.ts`) 한 번으로 `DELETE FROM pdf_page WHERE asset_id = ?` 뒤 쪽마다 `INSERT INTO pdf_page (asset_id, page_no, workspace_id, recording_id, text, char_count, has_text_layer, ocr_source) VALUES (?,?,?,?,?,?,?,NULL)`(`has_text_layer`는 0/1). 이어서 `UPDATE asset SET page_count = ?, meta_json = ? WHERE id = ?`: `meta_json`은 기존 JSON에 `scanned`(boolean)를 합치고 `pdf_error`를 지운다. 멱등이어야 한다.
   - `ingestRecordingPdfs`: `SELECT * FROM asset WHERE recording_id = ? AND kind = 'pdf' ORDER BY part_index, created_at`. 각 asset의 파일 경로는 `assetPath(asset)`; `null`이면 실패로 센다. `extract` 기본값은 `@lectern/pdf`의 `extractPdfPages`. `await run.run(pdfIngestStage(extract), { path })`, 성공하면 `savePdfPages`, `value.scanned`이면 `scannedAssets`에 asset id, `cacheHit`이면 `cacheHits++`.
   - 오류: `HarnessError`의 `kind === "canceled"`는 다시 던진다(작업 취소). 그 밖의 오류는 잡아서 `failed++`, `UPDATE asset SET meta_json = json_set(meta_json, '$.pdf_error', ?)`에 `err.code ?? "unreadable"`를 기록, `logger.warn("pdf ingest failed", { asset_id, recording_id, code })`(본문·경로 로그 금지, R17). 다음 asset으로 계속한다.
   - 이 함수는 OCR을 호출하지 않는다.
4. `process-job.ts`: `config().pdf`가 참이고 `publishTranscript`가 끝난 뒤, `runNotesPipeline` 호출 앞에 `const pdf = await ingestRecordingPdfs({ run, recordingId, workspaceId })`를 한 번 부른다(`run`은 그 작업의 `JobRun`; 변수 이름은 파일에서 확인). `pdf.failed > 0`이면 최종 상태 판정에서 `partial`로 취급한다(D-P1-2, 이미 있는 "노트 단계 실패 → partial"과 같은 변수·경로를 쓴다). `pdf_ingest` 단계 이벤트는 기존 `onEvent` 경로를 그대로 쓴다(웹 라벨 `pdf_ingest`는 이미 있다). 이 호출 외에 `process-job.ts`를 바꾸지 않는다.
5. `assets.ts`의 `listAssetPages`:
   - `config().pdf`가 거짓이면 `notImplemented(req)`를 반환(501).
   - asset을 읽고 없거나 `kind !== 'pdf'`이면 `notFound(req, "파일")`; `loadRecording(req, asset.recording_id)`가 `Response`면 `notFound`.
   - `SELECT page_no, has_text_layer, char_count FROM pdf_page WHERE asset_id = ? ORDER BY page_no`로 `pages`를 만든다. `page_count = asset.page_count ?? pages.length`, `scanned = meta_json.scanned === true`. `ok(req, { page_count, scanned, pages })`.
6. `db.ts`의 `deleteLectureById`에서 `deleteRecordingIndex(db, workspaceId, id)` 바로 뒤에 `db.query("DELETE FROM pdf_page WHERE recording_id = ?").run(id)`를 더한다. `recordings.ts`의 `deleteRecording`의 v2 전용 분기(`deleteRecordingRows` 앞)에도 같은 한 줄을 더한다(`recording.id`).
7. `README.md` 표에서 `listAssetPages`를 `실제`로 고치고 `api-v2.test.ts`의 `NOT_YET`에서 `"listAssetPages"`를 지운다.

|---|---|---|
| upload then listAssetPages | `LECTERN_PDF=1`. 사용자·녹음·pdf asset 행(`kind 'pdf'`, 파일 `%PDF-fake`)을 만들고 `ingestRecordingPdfs`(가짜 3쪽: 글자 있음, 없음, 글자 있음) → `GET /assets/{id}/pages` | 200, `page_count 3`, `scanned false`, `pages[1].has_text_layer false`, `pdf_page` 행 3개, `asset.page_count 3` |
| scanned pdf is flagged and nothing else runs | 가짜 추출기가 3쪽 모두 `hasTextLayer false`, `scanned true` | `pages` 응답 `scanned true`, `summary.scannedAssets`에 asset id, 모델(가짜 `fetch`) 호출 0회, `ai_call` 행 0개 |
| re-upload of the same pdf hits the memo | 같은 내용의 파일을 가진 두 번째 asset(같은 녹음)으로 다시 실행 | `summary.cacheHits === 1`, 추출기 호출 합계 1, 두 asset 모두 `pdf_page` 행이 있음 |
| rerun is idempotent | 같은 asset에 두 번 실행 | `pdf_page` 행 수가 늘지 않음(3) |
| failure does not throw | 추출기가 `PdfError(corrupt)`를 던짐 | 함수가 reject하지 않음, `failed 1`, `asset.meta_json`의 `pdf_error === "corrupt"`, `pdf_page` 0행, 응답 `pages: []` |
| canceled run rethrows | `HarnessError("canceled")`를 던지는 추출기 | 함수가 reject |
| process job: pdf failure makes recording partial | `P1-12`의 `process-job.test.ts`를 본떠 가짜 전사·LLM 공급자로 `process` 실행, PDF asset 1개와 `corrupt` 추출기 | 녹음 `status === "partial"`, 전사 행은 남음 |
| process job without pdf skips the step | PDF 없는 녹음 | `stage_run`에 `pdf_ingest` 없음 |
| flag off: pages route is 501 | `LECTERN_PDF=0` | `GET /assets/{id}/pages` 501 `not_implemented` |
| other user cannot list pages | 다른 사용자 토큰 | 404 |
| deleting the recording deletes pages | 녹음 삭제 API(`DELETE /recordings/{id}`) | `pdf_page` 행 0개 |
| non-pdf asset is 404 | 오디오 asset id | 404 |

## 10. 명세 작성자 메모

- `process-job.ts`는 `P1-12`가 만든다. 이 명세 작성 시점에는 파일이 없어 호출 지점·변수 이름(`run`, `partial` 판정)을 확인하지 못했다. 3절의 `git grep`으로 찾고, 계약 §1.1 흐름(2 `publishTranscript` 뒤, 4 `runNotesPipeline` 앞)과 맞지 않으면 `BLOCKED`.
- 하네스가 `@lectern/pdf`를 직접 import하지 못하는 이유: `packages/harness/package.json`은 `P3-C`의 소유가 아니다. 그래서 추출기 주입 방식으로 했다(CATALOG의 "하네스 `pdf_ingest` 단계"와 호환).
- `asset.page_count` 채우기는 `P3-01`에서 이 패키지로 옮겨 왔다(`P3-01` 10절).
- `deleteLectureById`는 `packages/db`의 투영을 거치므로 `pdf_page` 삭제를 `db.ts`에 직접 넣었다(`packages/db`는 소유 밖).
