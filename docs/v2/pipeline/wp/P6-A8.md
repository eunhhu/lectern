# P6-A8 iOS 공유 확장

> 등급: `basic` · 게이트: `apple` · 의존: `P6-A6` · 소유: `apps/apple/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

다른 앱(음성 메모, 파일, 메일)에서 오디오나 PDF를 "공유 → Lectern"으로 보낸다. 오디오와 PDF를 함께 보내면 웹과 **같은 규칙**으로 짝지어 PDF가 그 녹음의 참고 자료가 된다. 파일은 App Group 폴더의 업로드 대기열에 들어가고, 실제 업로드는 본 앱의 대기열이 한다. 녹음 시각은 파일의 메타데이터에서 읽는다.

## 5. 단계

1. `Pairing.swift` — `pairing.ts`를 **한 함수씩 그대로** 옮긴다. 이름도 맞춘다.
   ```swift
   public enum PairFileKind: Sendable { case audio, pdf }
   public struct PairFile: Sendable, Equatable { public var name: String; public var type: String?; public var lastModified: Date?; public var size: Int64; public var id: String }
   public func extensionOf(_ name: String) -> String
   public func classifyFile(name: String, type: String?) -> PairFileKind?
   public func parseFileName(_ name: String) -> ParsedName
   public func pairFiles(_ files: [PairFile], timeZone: TimeZone) -> PairingResult
   public func assignPdf(_ result: PairingResult, fileID: String, groupID: String?) -> PairingResult
   ```
   - `ParsedName`, `PairingResult`(그룹, 짝 없는 PDF, 무시된 파일)의 필드는 TypeScript의 타입과 같은 뜻으로 둔다.
   - 웹 코드가 쓰는 정규식, 확장자 목록, 시간대 기본값, 정렬 순서를 **바꾸지 않는다.** 한글 파일 이름은 비교 전에 NFC로 정규화한다(iOS 파일 이름은 NFD일 수 있다). 웹이 정규화하지 않더라도 Swift 쪽은 입력을 NFC로 바꾼 뒤 같은 규칙을 적용한다.
   - 이 파일 맨 위에 주석: `// Port of apps/web/src/lib/pairing.ts. Keep the two in step; PairingTests mirrors apps/web/test/pairing.test.ts.`
2. `MediaDate.swift`
   ```swift
   public func recordedDate(of url: URL) async -> Date?
   ```
   순서: ① `AVURLAsset`의 `creationDate` 메타데이터 ② 파일의 `creationDate` 리소스 값 ③ `nil`. 미래 시각이거나 2000년 이전이면 버린다.
3. `SharedInbox.swift`
   ```swift
   public struct SharedInbox: Sendable {
       public init(containerURL: URL, store: UploadQueueStore)
       public func importFiles(_ urls: [URL], workspaceID: String, folderID: String?, timeZone: TimeZone, now: Date) async throws -> ImportSummary
   }
   public struct ImportSummary: Sendable, Equatable { public var recordings: Int; public var pdfsPaired: Int; public var pdfsUnpaired: Int; public var ignored: [String] }
   ```
   - 파일을 `<컨테이너>/Inbox/<uuid>/<원래 이름>`으로 **복사한다**(공유 확장이 받은 URL은 확장이 끝나면 못 쓴다). 이름에서 경로 구분자를 뺀다.
   - `pairFiles`로 묶은 뒤 오디오 그룹마다 `UploadJob` 하나를 만들어 저장한다. 짝지어진 PDF는 `pdfRelativePaths`에. `recordedAt`은 `recordedDate(of:)`, 없으면 파일 이름에서 읽힌 날짜, 그것도 없으면 `nil`.
   - 오디오 없이 PDF만 온 경우: 대기열에 넣지 않고 `pdfsUnpaired`로 센다(이 단계의 앱은 PDF만 올리는 흐름이 없다).
   - 오디오 하나의 크기 한도는 2GB다. 넘으면 `ignored`에 이름을 넣는다.
   - 컨테이너 여유 공간이 가져올 크기 + 200MB보다 적으면 아무것도 복사하지 않고 `SharedInboxError.noSpace`(`"기기의 저장 공간이 부족합니다."`).
4. 확장 화면(`ShareViewController`가 SwiftUI `ShareView`를 띄운다)
   - 로그인하지 않았으면(App Group `UserDefaults`에 `default_workspace_id` 없음) `Lectern 앱을 열어 로그인한 뒤 다시 시도해 주세요.`와 버튼 `닫기`.
   - 받은 항목에서 파일 URL을 꺼낸다(`NSItemProvider`의 `public.audio`, `com.adobe.pdf`, `public.file-url`. `loadFileRepresentation`).
   - 요약을 보인다: `녹음 <n>개`, 짝지어진 PDF가 있으면 `PDF <n>개를 녹음에 붙입니다`, 짝 없는 PDF `PDF <n>개는 올리지 않습니다(함께 보낸 녹음이 없습니다)`, 무시된 파일 이름들. 버튼 `Lectern에 추가` / `취소`.
   - 추가하면 `importFiles` → 성공 문구 `추가했습니다. Lectern 앱에서 업로드가 이어집니다.` → 1초 뒤 `completeRequest`. 확장은 업로드를 직접 하지 않는다(메모리 제한). 본 앱이 다음에 열리거나 백그라운드 세션이 깨울 때 대기열이 돈다.
   - `Info.plist`의 활성화 규칙을 조인다: `NSExtensionActivationRule`을 술어 문자열로 바꿔 오디오(`public.audio`)와 PDF(`com.adobe.pdf`)만 받게 한다(최대 10개).
5. 본 앱: 앱이 앞으로 올 때(`scenePhase == .active`) `UploadQueue.run()`을 부른다(이미 그렇게 돼 있으면 그대로).
6. `MANUAL_CHECKS.md`에 행: "음성 메모 앱에서 공유 → Lectern → 앱을 열면 업로드된다", "파일 앱에서 오디오 1개와 PDF 1개를 함께 공유하면 한 녹음으로 묶인다", "1GB 오디오를 공유해도 확장이 죽지 않는다".

## 6. 테스트

`PairingTests` — `apps/web/test/pairing.test.ts`의 **모든 테스트를 같은 이름(영어 그대로, camelCase로)과 같은 입력·기대값으로** 옮긴다. 웹 테스트가 19개면 Swift도 19개다. 하나라도 옮길 수 없으면(예: 브라우저 `File` 전용 동작) 그 이유를 테스트 파일 주석과 `DEVIATIONS`에 적는다. 추가로:

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| `testNfdFileNamesPairLikeNfc` | 같은 한글 이름의 NFD 오디오와 NFC PDF | 한 그룹으로 묶인다 |

`SharedInboxTests`(임시 폴더)

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| `testAudioBecomesOneJob` | 오디오 1개 | 대기열 1개, 파일이 `Inbox/` 아래에 복사됨, 원본은 그대로 |
| `testAudioAndPdfArePaired` | 이름이 맞는 오디오와 PDF | 항목 1개, `pdfRelativePaths` 1개, `pdfsPaired == 1` |
| `testPdfAloneIsNotQueued` | PDF만 | 대기열 0개, `pdfsUnpaired == 1` |
| `testUnsupportedFilesAreIgnored` | `.txt` | `ignored`에 이름 |
| `testRecordedAtFromFileName` | 이름에 날짜가 있는 오디오(메타데이터 없음) | `recordedAt`이 그 날짜 |
| `testNameIsSanitised` | 이름 `../a/b.m4a` | 저장 경로가 `Inbox/<uuid>/` 안, 이름에 `/` 없음 |
| `testNoSpace` | 여유 공간 함수를 주입해 부족하게 | `noSpace`, 복사된 파일 없음 |
| `testOversizedAudioIsIgnored` | 크기 3GB로 보고되는 파일(크기 함수를 주입) | `ignored` |
