# P7-02 복원·장애 리허설

> 등급: `basic` · 게이트: `full` · 의존: `P1-12`, `P1-16` · 소유: `scripts/rehearse/`, `docs/runbooks/`, `apps/server/test/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

두 가지를 "실제로 해 본 것"으로 만든다.

1. **복원 리허설**: 백업 파일 하나를 받아 임시 디렉터리에 복원하고, 원본 백업과 건수·체크섬이 같은지, 그 사본으로 서버가 뜨는지(마이그레이션 포함) 확인하는 스크립트. 사본에서만 돈다. 운영 데이터 디렉터리를 작업 디렉터리로 주면 거절한다.
2. **공급자 장애 리허설**: Gemini가 계속 5xx를 주거나, 응답하지 않거나(타임아웃), 429를 줄 때 `process` 작업이 **끝난다**는 것(녹음이 `processing`에 영원히 남지 않는다)을 테스트로 고정한다.

런북 두 개(`backup-restore.md`, `incident-response.md`)에 리허설 절과 결과 읽는 법을 더한다.

## 5. 단계

### 5.1 복원 리허설 스크립트

1. `scripts/rehearse/lib.ts`
   ```ts
   export function assertWorkDir(workDir: string, backupFile: string, env?: Record<string, string | undefined>): string
   export interface TableDigest { table: string; rows: number; sha256: string }
   export function digestDatabase(path: string): TableDigest[]                       // opens read-only
   export function compareDigests(a: TableDigest[], b: TableDigest[]): string[]      // human-readable differences; [] when equal
   export function integrity(path: string): { integrity: string; foreignKeyViolations: number }
   ```
   - `assertWorkDir`가 거절하는 경우(메시지 `rehearse: refused — <이유>`): 작업 디렉터리가 `<repo>/data`이거나 그 안 / `env.LECTERN_DATA_DIR`와 같거나 그 안이거나 그것을 포함 / 백업 파일이 들어 있는 데이터 디렉터리(`backupFile`이 `<X>/backups/<파일>`이면 `<X>`)와 같거나 그 안 / `lectern.sqlite`가 이미 있다 / 있고 비어 있지 않다 / `/`·홈·저장소 루트. 통과하면 만들고 절대 경로를 돌려준다.
   - `digestDatabase`: `new Database(path, { readonly: true })`. `sqlite_master`에서 `type = 'table'`이고 이름이 `sqlite_`로 시작하지 않는 테이블을 이름순으로. 각 테이블마다 `SELECT COUNT(*)`와, `SELECT * FROM "<t>" ORDER BY rowid`(rowid가 없는 테이블은 `ORDER BY 1`)의 행을 차례로 읽어 `sha256`에 넣는다. 한 행은 열 값을 `JSON.stringify`(`Uint8Array`는 16진수 문자열로, `bigint`는 문자열로)한 줄. **행을 배열로 모으지 않는다**(`query.iterate()`로 하나씩). FTS5의 그림자 테이블(`<이름>_data`, `_idx`, `_content`, `_docsize`, `_config`)과 가상 테이블은 건수만 세고 체크섬은 `"-"`.
   - `compareDigests`: 테이블 목록, 건수, 체크섬의 차이를 한 줄씩(`table recording: rows 12 != 11`).
   - `integrity`: `PRAGMA integrity_check`의 첫 행과 `PRAGMA foreign_key_check`의 행 수.
2. `scripts/rehearse/restore.ts` — 인자 `--backup <파일>`(필수), `--work <디렉터리>`(없으면 `mkdtemp`), `--uploads <디렉터리>`(선택), `--keep`(끝나고 작업 디렉터리를 남긴다), `--out <파일>`
   1. 백업 파일이 없으면 종료 코드 2. `assertWorkDir`.
   2. `before = digestDatabase(backup)`(읽기 전용. **백업 파일에 쓰지 않는다**).
   3. `<work>/data/lectern.sqlite`로 복사(`copyFileSync`). `-wal`·`-shm`은 만들지 않는다.
   4. `after = digestDatabase(<사본>)`, `compareDigests(before, after)`가 비어야 한다. `integrity(<사본>)`가 `ok`, 외래 키 위반 0.
   5. 그 사본으로 서버를 띄운다: `Bun.spawn(["bun", "apps/server/src/index.ts"], { env })`. `env`는 샌드박스 묶음만(부모 환경을 넘기지 않는다): `LECTERN_DATA_DIR=<work>/data`, `LECTERN_LECTURES_DIR=<work>/lectures`, `HOME=<work>/home`, `LECTERN_RESEND_CREDENTIALS_FILE=<work>/no-credentials.json`, `PORT=<빈 포트>`, `LECTERN_BASE_URL=http://127.0.0.1:<port>`, `LECTERN_WORKER_MODE=external`, `LECTERN_LOG_REQUESTS=0`, `PATH`. 오너 환경 변수는 주지 않는다(사본의 계정을 그대로 쓴다).
   6. `/api/health`가 200이 될 때까지 최대 90초(마이그레이션 시간 포함). 응답의 `checks.database`가 `ok`여야 한다. 그다음 서버를 내린다(`SIGTERM`, 10초 뒤 `SIGKILL`).
   7. `migrated = digestDatabase(<사본>)`. **마이그레이션 뒤에 줄어든 테이블이 없어야 한다**: `before`에 있던 테이블마다 `migrated`의 건수 ≥ `before`의 건수. 단, 서버가 부팅 때 정리하는 테이블은 예외로 둔다 — `sessions`, `job`, `job_event`, `rate_limit`으로 시작하는 이름, 그리고 실제로 줄어든 테이블이 더 있으면 그 이름을 `notes`에 적고 워커가 원인을 확인한다(부팅 정리면 예외 목록에 더하고 이유를 주석으로 남긴다. 사용자 데이터 테이블이면 `BLOCKED`).
   8. `--uploads`가 있으면: 사본 DB의 `lectures.audio_path`(비어 있지 않은 것)마다 파일 이름(`basename`)이 `--uploads` 디렉터리에 있는지 센다. 요약에 `audio: { referenced, present, missing: [<이름> 최대 20개] }`. 파일을 읽거나 옮기지 않는다.
   9. 요약 JSON(표준 출력, `--out`): `{ backup: { file, bytes, mtime }, tables: <n>, rows_total, digest_equal, integrity, foreign_key_violations, server: { started, health, migration_ms }, shrunk_tables: [], audio?, ok, notes }`. `ok` = 4·6·7이 모두 통과. 종료 코드 `ok ? 0 : 1`.
   10. `--keep`이 없으면 작업 디렉터리를 지운다(스크립트가 만든 것이든 사용자가 준 빈 디렉터리든, 안의 내용은 이 스크립트가 만든 것뿐이다). **요약과 로그에 행 내용·이메일·제목을 내지 않는다**(건수와 해시만).
3. `scripts/rehearse/README.md`(30줄 이내): 명령 예, 요약 필드, 안전 규칙, "운영 호스트에서 돌릴 때는 런북 §7을 본다".

### 5.2 공급자 장애 테스트

4. `apps/server/test/provider-failure.test.ts` — `process-job.test.ts`의 준비 코드를 본떠 쓴다(공유 도우미가 있으면 import, 없으면 이 파일 안에 다시 쓴다). 실제 어댑터(`GeminiTranscriptionProvider`, `GeminiLlmProvider`)에 **가짜 `fetch`**를 넣어 네트워크 경계에서 장애를 만든다.
   ```ts
   type Fault = "5xx" | "429" | "hang" | "ok";
   /** A fetch that answers Gemini URLs by script; any other URL throws (nothing leaves the machine). */
   function faultyFetch(plan: { transcribe: Fault; llm: Fault }): { fetch: typeof fetch; calls: { transcribe: number; llm: number } }
   ```
   - `5xx`: `503`과 `{ "error": { "code": 503, "message": "unavailable", "status": "UNAVAILABLE" } }`.
   - `429`: `429`와 `{ "error": { "code": 429, "message": "quota", "status": "RESOURCE_EXHAUSTED" } }`. `Retry-After`는 주지 않는다.
   - `hang`: 요청의 `signal`이 중단될 때까지 풀리지 않는 Promise(중단되면 `signal.reason`으로 거절). 타이머로 스스로 풀지 않는다.
   - `ok`: 전사 요청(본문 `contents[0].parts`에 `inlineData`가 있다)에는 어댑터의 파서가 받는 JSON, LLM 요청에는 단계별 JSON. 모양은 `apps/web/e2e/server/start.ts`의 가짜 Gemini(P1-16. 이 작업의 의존이다)에서 **복사한다**(`packages/harness/test`의 어댑터 테스트 픽스처가 같은 모양이면 그것을 써도 된다). 복사한 응답으로 전사·노트가 끝까지 가지 않으면 `skip`으로 두지 말고 `BLOCKED`로 보고한다.
   - 어댑터 옵션: `apiKey: "test-key"`(보내지 않는다. 가짜 fetch가 가로챈다), `timeoutMs: 300`, 재시도 대기를 줄이는 옵션이 있으면 가장 작게(`gemini-http.ts`·`gemini-transcribe.ts`의 옵션 이름을 그대로 쓴다. 없으면 그냥 둔다 — 그 경우 테스트의 시간 제한을 넉넉히 잡는다).
   - 각 테스트는 `runProcessJob(directJob(...), { transcription, llm, pipeline: <작은 청크> })`를 **시간 제한(테스트 타임아웃 60초) 안에** 끝내야 한다.
5. 테스트가 서버 코드의 결함을 찾으면(예: `hang`에서 작업이 끝나지 않는다) **서버를 고치지 않는다**(소유는 `apps/server/test/`뿐이다). 그 테스트를 `test.failing` 또는 `test.skip`으로 두지 말고 그대로 실패하게 둔 채 `RESULT: BLOCKED`로 보고한다. `NEEDS`에 어느 장애에서 무엇이 남았는지(작업 상태, 녹음 상태) 적는다.

## 6. 테스트

### 6.1 `scripts/rehearse/rehearse.test.ts`

임시 디렉터리에 `bun:sqlite`로 작은 DB(테이블 2개, 행 몇 개, BLOB 열 하나)를 만들어 쓴다.

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| refuses the repository data dir | `--work <repo>/data/x` | 던진다 |
| refuses the configured data dir | `env.LECTERN_DATA_DIR`와 같은·안쪽·바깥쪽 경로 | 셋 다 던진다 |
| refuses the backup's own data dir | 백업 `<X>/backups/a.sqlite`, 작업 `<X>`, `<X>/restore` | 둘 다 던진다 |
| refuses a dir that has a database | `lectern.sqlite`가 있는 디렉터리 | 던진다 |
| accepts a fresh dir | 새 임시 경로 | 만들어진다 |
| digest is stable | 같은 DB를 두 번 | 같다 |
| digest sees a changed row | 사본에서 한 행의 값을 바꾼다 | 그 테이블의 체크섬만 다르다, `compareDigests`가 한 줄 |
| digest sees a missing row | 사본에서 한 행 삭제 | `rows` 차이가 보고된다 |
| digest handles blobs and bigints | BLOB·큰 정수 열 | 던지지 않는다 |
| digest does not write | 읽기 전용 파일(`chmod 0444`)로 | 통과, 파일 mtime이 그대로다 |
| integrity reports ok | 정상 DB | `integrity === "ok"`, 위반 0 |
| restore end to end | 서버로 만든 샌드박스 DB의 `VACUUM INTO` 사본을 백업으로(R12의 샌드박스 환경에서 `apps/server/src/db.ts`를 import해 계정 1개를 만든 뒤) `restore.ts`를 자식 프로세스로 실행 | 종료 코드 0, 요약 `ok: true`, `digest_equal: true`, `server.health === "ok"`. 작업 디렉터리가 지워졌다 |
| restore refuses the live dir | 위 샌드박스의 데이터 디렉터리를 `--work`로 | 종료 코드 ≠ 0, `rehearse: refused`, 샌드박스 DB의 mtime이 그대로다 |

### 6.2 `apps/server/test/provider-failure.test.ts`

모두 `describe.skipIf(!isFfmpegAvailable())`. `LECTERN_PIPELINE=v2`. 합성 오디오는 `process-job.test.ts`와 같은 길이. †는 가짜 fetch의 `ok` 응답이 필요한 행이다.

| 테스트 이름 | 장애 | 기대 |
|---|---|---|
| transcription 5xx on every call ends as failed | 전사 `5xx`, LLM 호출 안 됨 | 60초 안에 끝난다. 작업 `failed`, 녹음 `failed`, 오류 메시지가 한국어, `job` 테이블에 이 녹음의 `queued`·`running` 행 0 |
| transcription that never answers ends as failed | 전사 `hang` | 위와 같다. 걸린 시간 < 60초(어댑터의 `timeoutMs`가 실제로 끊는다) |
| transcription 429 ends as failed | 전사 `429` | 위와 같다 |
| notes 5xx keeps the transcript † | 전사 `ok`, LLM `5xx` | 작업 `succeeded`, 녹음 `partial`, `failure_code = 'notes_failed'`, 전사 행 > 0 |
| notes that never answer keep the transcript † | 전사 `ok`, LLM `hang` | 위와 같다. 60초 안 |
| notes 429 keeps the transcript † | 전사 `ok`, LLM `429` | 위와 같다 |
| nothing is retried forever | 전사 `5xx` | `calls.transcribe`가 유한하다: 청크 수 × (어댑터의 최대 시도 횟수) 이하. 숫자를 요약 주석에 적는다 |
| recording can be retried after a failure † | 전사 `5xx`로 실패 → 같은 녹음에 `ok` fetch로 다시 `runProcessJob` | `ready` |
| no outbound request | 모든 테스트 | 가짜 fetch가 Gemini 밖의 URL을 받으면 던진다(0회) |

## 10. 명세 작성자 메모

- ROADMAP은 "공급자 장애 시 전환 리허설"이라고 적었다. 이 프로젝트는 Gemini만 쓴다(다른 공급자 어댑터를 만들지 않는다는 사용자 결정). 그래서 "전환"을 "장애가 났을 때 작업이 끝나고, 장애가 끝난 뒤 다시 시도하면 된다"로 좁혔다.
- 전사 실패가 `failed`인지 `partial`인지는 P1-12의 규칙(모든 청크 실패 → `failed`)을 따랐다. 실제 구현이 다르게(예: 일부 청크만 실패 → `partial`) 끝나면 표의 기대를 구현이 아니라 **CONTRACTS D-P1-2**에 맞춘다. 둘이 어긋나면 `BLOCKED`.
- 어댑터의 재시도 횟수·대기 옵션 이름은 확인하지 못했다. 테스트가 60초를 넘기면 옵션으로 줄일 수 있는지 먼저 보고, 없으면 테스트 타임아웃을 늘리되 결과 보고에 실제 걸린 시간을 적는다.
- 마이그레이션 뒤 "줄어도 되는 테이블" 목록은 추정이다. 실제로 줄어드는 테이블을 보고 정한다.
- 운영 백업으로 하는 리허설은 사용자 몫이다(STATUS "실측 필요"). 운영 데이터를 개발 기계로 가져오지 않는다.
