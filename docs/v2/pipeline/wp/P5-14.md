# P5-14 옛 관리자 콘솔 HTML 삭제

> 등급: `careful` · 게이트: `full` · 의존: `P5-13`, `P2-10` · 소유: `apps/server/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

**사용자 승인이 필요하다.** `pipeline.json`에 `needs_user`가 남아 있으면 시작하지 않는다. 사용자가 새 관리자 콘솔(`/app/admin`)을 운영에서 써 보고, `PARITY-ADMIN.md`의 `일부러 뺌` 행을 읽고, 옛 콘솔 삭제를 말로 승인한 뒤에만 한다.

## 1. 목표

서버가 그리던 옛 관리자 콘솔(HTML과 스크립트)을 지운다. `/admin`은 `/app/admin`으로 간다. 관리자 API(`/api/admin/*`)는 그대로다. 이 작업 뒤 `ui.ts`에는 사용자 화면도 관리자 화면도 남지 않는다.

## 2. 먼저 읽을 것

- 계약: `CONTRACTS.md` D-P5-10, D-0-3
- 문서: `docs/v2/pipeline/PARITY-ADMIN.md` (P5-13)
- 코드: `apps/server/src/ui.ts` — `renderAdminPageHtml`, `PAGE_SCRIPTS`
- 코드: `apps/server/src/index.ts` — `/admin` 처리, `/assets/*` 서빙
- 코드: `apps/server/src/http.ts` — `/` 처리(P2-10이 고쳤다), 웹 셸이 꺼졌을 때의 응답
- 코드: `apps/server/src/preflight-checks.ts` — `buildPreflightChecks`
- 코드: `apps/server/src/share-page.ts`, 법적 페이지 서빙 — `ui.ts`에 기대지 않는지 확인
- 테스트: `apps/server/test/ui.test.ts`, `server.test.ts`, `web-shell.test.ts`, `preflight-checks.test.ts`

## 4. 만들 파일과 고칠 파일

| 경로 | 새로/수정 | 무엇 |
|---|---|---|
| `apps/server/src/ui.ts` | 삭제 또는 수정 | 관리자 콘솔 삭제. 남는 export가 없으면 파일을 지운다 |
| `apps/server/src/index.ts` | 수정 | `/admin` 처리 삭제, 옛 화면 전용 `/assets/*` 항목 삭제 |

| `apps/server/test/ui.test.ts`, `server.test.ts`, `web-shell.test.ts`, `preflight-checks.test.ts` | 수정·삭제 | 지운 화면의 테스트 삭제, 새 동작 테스트 |

## 5. 단계

1. `ui.ts`에서 `renderAdminPageHtml`과 그 함수만 쓰는 도우미·CSS·스크립트를 지운다. 이름마다 `git grep -n "<이름>" -- apps/server/src`로 다른 곳에서 쓰는지 확인하고, 쓰이는 것(예: 공유 페이지나 법적 페이지가 함께 쓰는 이스케이프 함수)은 그것을 쓰는 모듈 쪽으로 옮긴다. 파일에 export가 하나도 안 남으면 파일을 지운다.
2. `index.ts`: `/admin`(과 `/admin/…` 하위 경로가 있으면 그것도)에 HTML을 주던 분기를 지운다. `PAGE_SCRIPTS`가 비면 그 서빙 코드도 지운다. **`/api/admin/*`는 한 줄도 건드리지 않는다.**
3. `http.ts`: 레거시로 넘기기 전에 다음을 넣는다.
   - 웹 셸이 켜져 있으면: `GET /admin`과 `GET /admin/*` → `302 /app/admin`(쿼리 문자열은 버린다).
   - 웹 셸이 꺼져 있으면: `/`와 같은 `503` 응답(P2-10이 정한 본문 `웹 앱이 꺼져 있습니다. 관리자에게 문의해 주세요.`).
4. `preflight-checks.ts`: `/admin`을 검사하던 항목의 기대 상태를 302(웹 셸 켬)·503(끔)으로 바꾼다. 로그인하지 않은 `/admin`이 200 HTML이던 것을 기대하는 검사가 있으면 지운다.
5. 테스트
   - `ui.test.ts`: 관리자 콘솔 HTML만 검사하던 테스트를 지운다(지운 코드의 테스트라서 명세가 지시한 삭제다). 파일에 테스트가 남지 않으면 파일을 지운다. 다른 모듈로 옮긴 함수의 테스트는 그 모듈의 테스트 파일로 옮긴다.
   - `web-shell.test.ts`에 6절의 테스트를 더한다.
   - `server.test.ts`에서 `/admin`이 HTML이라고 기대하던 곳을 고친다.
6. `git grep -n "renderAdminPageHtml\|PAGE_SCRIPTS" -- apps/server`가 아무것도 내지 않는지 본다.
7. CSP: `http.ts`의 CSP에 옛 화면의 인라인 스크립트·스타일을 위한 예외(해시, nonce, `unsafe-inline`)가 남아 있고 다른 곳(공유 페이지, 법적 페이지)이 그것을 쓰지 않으면 지운다. 쓰는 곳이 있으면 그대로 두고 `DEVIATIONS`에 적는다.

## 6. 테스트

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| web-shell "/admin redirects to the new console" | 웹 셸 켬, `GET /admin` | 302, `Location: /app/admin` |
| web-shell "/admin subpaths redirect too" | `GET /admin/users?x=1` | 302, `Location: /app/admin` |
| web-shell "/admin answers 503 when the web app is off" | 웹 셸 끔 | 503 |
| server "admin API still answers" (기존) | 운영자로 `GET /api/admin/overview` | 200 |
| server "admin API still refuses non-admins" (기존) | 일반 사용자 | 기존과 같은 상태 코드 |
| v1-contract (기존 전체) | — | 통과 |
| "share and legal pages still render" | `GET /privacy`, `GET /terms`, 공유 페이지 | 200 |
| preflight-checks "admin expects a redirect" | `buildPreflightChecks` | `/admin`의 기대가 302(켬)·503(끔) |

## 10. 명세 작성자 메모

- 이 작업 뒤에는 웹 셸을 끄면(`LECTERN_WEB_SHELL=0`) 사용자 화면도 관리자 화면도 없다. 롤백 수단이 "웹 셸 끄기"에서 "이전 릴리스로 되돌리기"로 바뀐다. 사용자가 승인할 때 알아야 하는 점이라 STATUS에 적었다.
- `ui.ts`가 다른 모듈과 무엇을 함께 쓰는지는 확인하지 않았다. 5절 1단계의 참조 확인으로 정한다.
