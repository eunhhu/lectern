# P5-02 개인 액세스 토큰(PAT)

> 등급: `careful` · 게이트: `full` · 의존: `P5-C` · 소유: `apps/server/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

사용자가 설정에서 이름·범위·만료가 있는 액세스 토큰을 만들고 회수한다. 그 토큰으로 API v2를 부를 수 있다. 읽기 전용 토큰은 쓰지 못한다. 토큰 원문은 만들 때 한 번만 보이고 서버에는 해시만 남는다. 기존 v1 API 토큰은 그대로 동작한다.

- 계약: `CONTRACTS.md` D-0-7, D-P5-3, §5 DB(`access_token`)

## 5. 단계

1. `access-tokens.ts`
   ```ts
   export const PAT_PREFIX = "lct_pat_";
   export interface PatRow { id: string; userId: string; workspaceId: string; name: string; scopes: string[]; tokenPrefix: string; expiresAt: number | null; lastUsedAt: number | null; createdAt: number; revokedAt: number | null }
   export function createPat(p: { userId: string; workspaceId: string; name: string; scopes: string[]; expiresAt: number | null }): { row: PatRow; secret: string }
   export function findActivePat(secret: string, now?: number): PatRow | null    // by sha256Hex(secret); null when revoked or expired
   export function listPats(userId: string): PatRow[]                            // not revoked, newest first
   export function revokePat(userId: string, id: string): boolean
   export function touchPat(id: string, now?: number): void                      // last_used_at, at most once per 5 minutes per token
   ```
   - 원문: `PAT_PREFIX + randomBytes(32).toString("base64url")`. 저장: `token_hash = sha256Hex(secret)`, `token_prefix = secret.slice(0, 12)`(`lct_pat_` + 4자). 원문은 저장도 로그도 하지 않는다.
   - `access_token` 테이블에 `workspace_id` 열이 없다(계약 DDL). 토큰의 워크스페이스는 `scopes_json`에 함께 둔다: `{ "scopes": [...], "workspace_id": "…" }`. 읽을 때 배열이면(옛 형식) `workspace_id`는 사용자의 개인 워크스페이스다.
2. `api/v2/authn.ts`
   ```ts
   export interface V2Auth { user: UserRecord; via: "session" | "api_token" | "pat"; pat?: PatRow }
   export function authenticateV2(req: Request): V2Auth | null
   ```
   - `extractAuthToken`으로 토큰을 꺼낸다. `PAT_PREFIX`로 시작하면 `findActivePat` → 사용자(`getUserById`, 비활성 사용자는 `null`) → `touchPat`. 그 밖에는 지금의 `authenticateRequest`와 같은 결과다(`via`는 쿠키면 `"session"`, 아니면 `"api_token"`. 구별하기 어려우면 둘 다 `"session"`으로 두어도 된다).
   - **`auth.ts`의 `authenticateRequest`는 고치지 않는다.** 그래서 PAT는 v1 엔드포인트(`/api/lectures` 등)에서 401이다. v1에는 범위 검사가 없으므로 일부러 막는다.
3. `common.ts`: 인증 줄을 `authenticateV2`로 바꾸고 `V2Request`에 `pat?: PatRow`를 더한다. 핸들러를 부르기 전에 PAT 검사를 한다.
   - PAT로 부를 수 없는 라우트: `tag`가 `me`(단, `getMe`는 허용), `admin`, `auth`인 것, 그리고 `createShareLink`·`updateShareLink`·`revokeShareLink`·`startGoogleIntegration`·`disconnectIntegration` → `403 forbidden`, 문구 `개인 액세스 토큰으로는 이 작업을 할 수 없습니다.`
   - 메서드가 `GET`·`HEAD`면 `recordings:read`가, 그 밖에는 `recordings:write`가 범위에 있어야 한다. 없으면 `403 forbidden`, 문구 `이 토큰에는 필요한 권한이 없습니다.`
4. `access.ts` `callerIn(req, workspaceId)`: `req.pat`이 있고 `req.pat.workspaceId !== workspaceId`면 `role: null`인 `Caller`를 돌려준다(그 워크스페이스의 멤버가 아닌 것처럼 동작한다).
5. `me.ts`
   - `createAccessToken`: `requireWorkspace(req, body.workspace_id)`. `expires_at`이 과거면 400. 사용자당 살아 있는 토큰은 20개까지(넘으면 `409 conflict`, `액세스 토큰은 20개까지 만들 수 있습니다.`). 201 `{ token: <AccessTokenDto>, secret }`.
   - `listAccessTokens`: 지금의 v1 토큰 항목을 맨 앞에 그대로 두고, 뒤에 `listPats` 결과를 잇는다.
   - `revokeAccessToken`: `revokePat` → 204. 없거나 남의 것이면 404. v1 토큰 항목의 id(`tok_…`)가 오면 `409 conflict`, `이 토큰은 여기서 회수할 수 없습니다. 예전 설정 화면에서 다시 발급해 주세요.`

| 테스트 이름 | 준비 | 기대 |

## 10. 명세 작성자 메모

- 계약은 "저장은 해시와 앞 8자"라고 했다. `lct_pat_`가 정확히 8자라서 앞 8자는 모든 토큰이 같다. 그래서 앞 12자를 저장한다(계약과 다른 점. CONTRACTS 보충 절에 적었다).
- `access_token`에 `workspace_id` 열이 없어서 `scopes_json` 안에 넣었다. 열을 더하려면 계약 WP가 필요하다.
- SSE(`streamEvents`)를 PAT로 여는 것은 허용된다(`GET`, `recordings:read`).
- `authenticateV2`는 `P5-03`이 네이티브 access 토큰을 더할 자리다.
