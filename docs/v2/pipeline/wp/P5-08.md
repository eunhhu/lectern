# P5-08 데이터 내보내기

> 등급: `basic` · 게이트: `full` · 의존: `P5-C` · 소유: `apps/server/`, `apps/worker/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

사용자가 워크스페이스의 데이터를 zip 파일 하나로 내려받는다. 녹음 목록, 문서(Markdown과 JSON), 전사, 일정·할 일이 들어가고, 고르면 오디오 원본도 들어간다. 만드는 일은 백그라운드 작업이 하고, 파일은 7일 뒤 지워진다. 요청한 사람만 내려받을 수 있다.

## 5. 단계

1. `export/zip.ts` — 의존성 없이 zip을 쓴다. 압축하지 않는다(method 0, "stored"). 오디오는 이미 압축돼 있고, 구현이 단순해야 한다.
   ```ts
   export interface ZipEntry { name: string; size: number; open(): AsyncIterable<Uint8Array> | Uint8Array }
   export async function writeZip(path: string, entries: AsyncIterable<ZipEntry> | Iterable<ZipEntry>): Promise<{ bytes: number; files: number }>
   export function crc32(chunk: Uint8Array, seed?: number): number
   ```
   - 파일마다: 로컬 헤더(시그니처 `0x04034b50`, 버전 20, 플래그 `0x0808` = 데이터 디스크립터 사용 + UTF-8 이름, method 0, CRC·크기는 0) → 내용을 조각 단위로 쓰며 CRC-32를 누적 → 데이터 디스크립터(`0x08074b50`, CRC, 크기, 크기).
   - 끝에 중앙 디렉터리(파일마다 `0x02014b50`, 같은 플래그, 실제 CRC·크기, 로컬 헤더 오프셋)와 끝 레코드(`0x06054b50`).
   - **4GiB 이상의 파일이나 전체 크기, 65,535개를 넘는 항목은 지원하지 않는다.** 넘으면 `Error("export too large")`를 던진다(작업이 `failed`로 끝나고 사용자에게 안내한다).
   - 이름은 `/`로 구분한 상대 경로만 받는다. `..`, 절대 경로, 역슬래시가 있으면 던진다. 시각 필드는 고정값(1980-01-01)이다.
   - 메모리에 파일 전체를 올리지 않는다. `Bun.file(path).writer()`로 쓴다. 임시 파일 권한은 0600이다.
2. `export/build.ts`
   ```ts
   export function* exportEntries(p: { userId: string; workspaceId: string; includeAudio: boolean }): Iterable<ZipEntry>
   export function safeName(title: string): string   // NFC, replace / \ : * ? " < > | and control chars with "_", trim, max 80 chars, "제목 없음" when empty
   ```
   대상은 그 사용자가 볼 수 있는 녹음이다(`VISIBLE_RECORDING_SQL`과 같은 조건). zip 안의 구조:
   ```
   README.txt                                  설명(아래 문구)
   export.json                                 { "format": 1, "exported_at": ISO, "workspace": {id, name}, "recordings": <개수>, "include_audio": bool }
   recordings.json                             녹음 목록(API의 Recording DTO 배열)
   recordings/<번호>-<제목>/recording.json      녹음 상세
   recordings/<번호>-<제목>/document.md         현재 문서의 Markdown (문서가 있을 때)
   recordings/<번호>-<제목>/document.json       현재 문서 버전 JSON (문서가 있을 때)
   recordings/<번호>-<제목>/transcript.json     전사 (있을 때. API의 Transcript 모양)
   recordings/<번호>-<제목>/events.json         일정
   recordings/<번호>-<제목>/action-items.json   할 일
   recordings/<번호>-<제목>/audio/<part>.<확장자>   오디오 원본 (include_audio일 때)
   recordings/<번호>-<제목>/pdf/<파일 이름>        PDF 원본 (include_audio일 때, PDF가 있으면)
   ```
   `<번호>`는 만든 순서의 4자리(`0001`…), `<제목>`은 `safeName`. JSON은 2칸 들여쓰기 UTF-8이다. `README.txt`: `Lectern 데이터 내보내기\n\n이 파일에는 워크스페이스 "<이름>"의 녹음과 노트가 들어 있습니다.\nrecordings/ 아래 폴더 하나가 녹음 하나입니다.\ndocument.md는 사람이 읽는 노트, *.json은 프로그램이 읽는 원본 데이터입니다.\n`
3. `export/job.ts`
   ```ts
   export const EXPORT_JOB_KIND = "export";
   export const EXPORT_TTL_MS = 7 * 24 * 60 * 60 * 1000;
   export function exportDir(): string                       // <data dir>/exports, created with mode 0700
   export async function runExportJob(exportId: string): Promise<void>
   export function expireExports(now?: number): number       // deletes files past expires_at, sets state 'expired'
   ```
   - `runExportJob`: 행을 `running`으로 → `<exportDir>/<id>.zip.tmp`에 쓰고 → `rename`으로 `<id>.zip` → `state = 'ready'`, `blob_key = "exports/<id>.zip"`, `bytes`, `ready_at = now`, `expires_at = now + EXPORT_TTL_MS`. 실패하면 임시 파일을 지우고 `state = 'failed'`, `error`에 짧은 사유(`export too large`면 `내보낼 데이터가 너무 큽니다. 오디오를 빼고 다시 시도해 주세요.`, 그 밖에는 `내보내기를 만들지 못했습니다.`). 큐에는 성공으로 답한다(재시도하지 않는다).
   - `registerJobHandler(EXPORT_JOB_KIND, …, { concurrency: 1 })`.
   - `expireExports`: `state = 'ready' AND expires_at <= now` → 파일 삭제 → `state = 'expired'`, `blob_key = NULL`. 서버가 죽어서 남은 `.zip.tmp`(1일 넘은 것)도 지운다. `maintenance.ts`에 단계로 더한다.
4. `me.ts`
   - `createExport`: `requireWorkspace`. 그 사용자의 `queued`·`running` 내보내기가 이미 있으면 `409 conflict`, `이미 만들고 있는 내보내기가 있습니다.` 24시간 안에 만든 것이 5개 이상이면 `409`, `내보내기는 하루에 5번까지 만들 수 있습니다.` 행을 넣고(`state = 'queued'`) `enqueueJob`(subject = export id). 202 `DataExportDto`.
   - `listExports`: 자기 것, 최신순, 최대 20개.
   - `getExportContent`: 자기 것이 아니면 404. `ready`가 아니면 `409 conflict`, `아직 준비되지 않았거나 만료된 내보내기입니다.` 파일이 없으면 404. 응답: 스트림, `Content-Type: application/zip`, `Content-Length`, `Content-Disposition: attachment; filename="lectern-export-<YYYYMMDD>.zip"`, `Cache-Control: private, no-store`.

## 8. 하지 않는 것

- 가져오기(import)는 만들지 않는다.
- 물어보기 대화, 감사 로그, 다른 멤버의 비공개 녹음은 넣지 않는다.
- zip 압축(deflate), ZIP64.
- 웹 화면(`P5-10`).

## 10. 명세 작성자 메모

- zip을 직접 쓰는 것은 새 의존성을 피하려는 결정이다. 4GiB 제한 때문에 오디오가 많은 워크스페이스는 "오디오 포함" 내보내기가 실패할 수 있다. 그때의 안내 문구를 넣었다. ZIP64가 필요해지면 별도 작업이다(STATUS에 적는다).
- PDF 원본을 `include_audio`에 묶은 것은 이 명세의 결정이다(용량이 큰 원본 파일을 한 스위치로 다룬다).
- `apps/worker/`를 고칠 일은 없을 것으로 본다(워커는 서버의 핸들러 등록을 import한다).
