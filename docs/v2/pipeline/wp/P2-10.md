# P2-10 ui.ts 사용자 앱 화면 삭제

> 등급: `careful` · 게이트: `full` · 의존: `P2-09` · 소유: `apps/server/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

**사용자 승인이 필요하다.** `pipeline.json`에 `needs_user`가 남아 있으면 시작하지 않는다. 사용자가 운영에서 새 웹 앱을 확인하고 옛 화면 삭제를 말로 승인한 뒤에만 한다.

## 1. 목표

옛 사용자 앱 화면(서버가 그리던 HTML과 그 스크립트)을 지운다. `/`는 항상 `/app`으로 간다. `?legacy=1`은 없어진다. 관리자 콘솔 HTML, 공유 페이지, 법적 페이지, v1 API는 그대로다.

## 2. 먼저 읽을 것

- 계약: `CONTRACTS.md` D-P2-6 ②, D-P5-10
- 코드: `apps/server/src/ui.ts` — `renderAppHtml`, `renderAdminPageHtml`, `PAGE_SCRIPTS`
- 코드: `apps/server/src/index.ts` — `renderAppHtml`을 부르는 곳과 `/assets/*` 서빙
- 코드: `apps/server/src/http.ts` — `/` 리다이렉트와 `legacy=1` 분기
- 코드: `apps/server/src/preflight-checks.ts` — `buildPreflightChecks` (P0-01이 만든다)
- 코드: `apps/server/src/share-page.ts` (P2-02가 만든다. 공유 페이지가 `ui.ts`에 기대지 않는지 확인)
- 테스트: `apps/server/test/ui.test.ts`, `server.test.ts`, `web-shell.test.ts`

## 3. 사전 점검

```bash
bun run pipeline show P2-10 | grep -c needs_user
git grep -n "renderAppHtml" -- apps/server/src
git grep -n "renderAdminPageHtml" -- apps/server/src
git grep -n "legacy" -- apps/server/src/http.ts
git grep -n "from \"./ui.ts\"\|from \"../ui.ts\"" -- apps/server/src
```

첫 명령이 `1`이면(승인 전) 멈춘다. 마지막 명령으로 `ui.ts`를 쓰는 모듈을 모두 적어 둔다.

## 4. 만들 파일과 고칠 파일

| 경로 | 새로/수정 | 무엇 |
|---|---|---|
| `apps/server/src/ui.ts` | 수정 | 사용자 앱 화면과 그 스크립트·스타일 삭제. 관리자 콘솔은 남긴다 |
| `apps/server/src/index.ts` | 수정 | `/`가 옛 화면을 그리던 분기 삭제 |
| `apps/server/src/http.ts` | 수정 | `legacy=1` 분기 삭제, 웹 셸이 꺼졌을 때의 `/` |
| `apps/server/src/preflight-checks.ts` | 수정 | `/?legacy=1` 점검 삭제 |
| `apps/server/test/ui.test.ts`, `server.test.ts`, `web-shell.test.ts`, `preflight-checks.test.ts` | 수정 | 지운 화면의 테스트 삭제, 새 동작 테스트 |

## 5. 단계

1. `ui.ts`에서 `renderAppHtml`과, **그 함수만** 쓰는 도우미·CSS·페이지 스크립트를 지운다. `PAGE_SCRIPTS`에서는 사용자 앱 전용 항목만 뺀다. 판단 기준: `renderAdminPageHtml`이나 다른 남는 함수가 참조하면 남긴다. 지우기 전에 이름마다 `git grep -n "<이름>" -- apps/server/src`로 참조를 확인한다.
2. `index.ts`: `/` 요청에 `renderAppHtml`을 부르던 분기를 지운다. 레거시 라우터에서 `/`는 3단계의 응답을 준다.
3. `http.ts`: `/` 처리를 다음으로 바꾼다.
   - 웹 셸이 켜져 있으면: 쿼리와 상관없이 `302 /app` (기존 쿼리 문자열은 붙여 보낸다. `legacy` 파라미터는 뺀다).
   - 웹 셸이 꺼져 있으면: `503`, `Content-Type: text/plain; charset=utf-8`, 본문 `웹 앱이 꺼져 있습니다. 관리자에게 문의해 주세요.`
4. `preflight-checks.ts`: `/?legacy=1` 점검을 지운다. 웹 셸이 꺼진 구성의 `/` 기대 상태를 503으로 바꾼다.
5. 테스트를 고친다.
   - `ui.test.ts`: 사용자 앱 화면만 검사하던 테스트를 지운다(지운 코드의 테스트라서 명세가 지시한 삭제다). 관리자 콘솔·이스케이프·CSP 검사는 남긴다.
   - `web-shell.test.ts`: `?legacy=1` 테스트를 "`/?legacy=1`도 302 `/app`"으로 바꾼다. 웹 셸 꺼짐에서 `/`가 503인 테스트를 더한다.
   - `server.test.ts` 등에서 `/`가 200 HTML이라고 기대하던 곳을 위 동작으로 바꾼다.
6. `git grep -n "renderAppHtml\|legacy=1" -- apps/server`가 아무것도 내지 않는지 본다.
7. `apps/server/src/api/v2/README.md`와 `AGENTS.md`는 건드리지 않는다(소유 밖이거나 범위 밖). 저장소 지도 수정이 필요하면 보고의 `NEEDS`에 적는다.

## 6. 테스트

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| web-shell "/ always redirects to /app" | 웹 셸 켬, `GET /` | 302, `Location: /app` |
| web-shell "legacy query is ignored" | 웹 셸 켬, `GET /?legacy=1&x=1` | 302, `Location: /app?x=1` |
| web-shell "/ answers 503 when the web app is off" | 웹 셸 끔, `GET /` | 503, 본문에 `웹 앱이 꺼져 있습니다` |
| ui "admin console still renders" (기존) | `GET /admin` | 200 |
| v1-contract (기존 전체) | — | 통과 |
| preflight-checks "no legacy check" | `buildPreflightChecks` 결과 | `/?legacy=1` 경로가 없다 |

## 8. 하지 않는 것

- 관리자 콘솔 HTML을 지우지 않는다(`P5-14`).
- v1 API(`/api/lectures`, `/api/auth/*`, `/api/ingest/*`)를 건드리지 않는다.
- `apps/web`을 고치지 않는다.

## 9. 끝났다는 기준

- [ ] 사용자 승인이 `pipeline.json`에 반영돼 있다(`needs_user` 없음)
- [ ] `renderAppHtml`과 `legacy=1`이 코드에 없다
- [ ] 관리자 콘솔, `/s/:token`, `/privacy`, `/terms`가 그대로 열린다(테스트)
- [ ] v1 계약 테스트가 통과한다
- [ ] 게이트가 통과한다

## 10. 명세 작성자 메모

- `ui.ts` 안에서 사용자 앱과 관리자 콘솔이 무엇을 함께 쓰는지는 확인하지 않았다. 5단계 1번의 참조 확인으로 정한다. 함께 쓰는 것이 많아 깔끔히 나누기 어려우면 멈추고 보고한다.
- 로그인하지 않은 방문자가 보던 공개 소개(로그인 카드 옆 소개, Google OAuth 검증용)가 새 앱의 로그인 화면에 있는지는 `PARITY.md`가 확인한다. 그 행이 없으면 이 작업을 시작하지 말고 보고한다.
- 웹 셸이 꺼졌을 때의 503 응답은 계약에 없는 이 명세의 결정이다.
