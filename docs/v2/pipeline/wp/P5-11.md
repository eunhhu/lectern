# P5-11 웹: 멤버, 초대, 사용량

> 등급: `basic` · 게이트: `full` · 의존: `P5-06`, `P5-07` · 소유: `apps/web/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

설정 "워크스페이스"에서 owner·admin이 멤버의 역할을 바꾸고 내보내고, 이메일로 초대하고 초대를 회수한다. 초대 메일의 링크(`/app/invite?token=…`)를 열면 수락 화면이 나온다. 모든 멤버가 이번 달 사용량과 한도를 본다.

## 5. 단계

1. API 클라이언트
   ```ts
   updateMember(workspaceId: WorkspaceId, userId: string, role: MembershipRole): Promise<WorkspaceMember>;
   removeMember(workspaceId: WorkspaceId, userId: string): Promise<void>;
   listInvites(workspaceId: WorkspaceId): Promise<InvitePage>;
   createInvite(workspaceId: WorkspaceId, body: CreateInviteRequest): Promise<Invite>;
   revokeInvite(workspaceId: WorkspaceId, inviteId: string): Promise<void>;
   acceptInvite(token: string): Promise<AcceptInviteResponse>;
   getWorkspaceUsage(workspaceId: WorkspaceId): Promise<WorkspaceUsage>;
   ```
   fixture: 팀 워크스페이스 하나(멤버 4명: owner·admin·member·viewer)와 초대 1개를 가진다. `?fixture-role=<역할>`로 내 역할을 바꾼다.
2. 역할 표기: `owner` → `소유자`, `admin` → `관리자`, `member` → `멤버`, `viewer` → `보기 전용`.
3. `Members.tsx` — 제목 "멤버". 개인 워크스페이스에서는 `개인 워크스페이스에는 다른 멤버가 없습니다.`만 보인다.
   - 표: 이름, 이메일, 역할, 동작. 내 줄에는 `나` 표시.
   - 역할 선택(`SelectField`)은 내가 owner·admin일 때만 켜진다. admin에게는 owner·admin 줄의 선택이 꺼져 있고, 선택지에 `소유자`·`관리자`가 없다.
   - 버튼 `내보내기`(남) / `나가기`(나). 확인: `<이름>님을 워크스페이스에서 내보낼까요? 이 사람이 올린 녹음은 워크스페이스에 남습니다.` / `이 워크스페이스에서 나갈까요?`
   - 409(마지막 owner): 서버 문구를 토스트로 보인다. owner가 한 명뿐이면 그 줄의 역할 선택과 `나가기` 아래에 `소유자가 한 명은 있어야 합니다.`를 보이고 둘을 끈다.
   - 501이면 `준비 중입니다.`
4. `Invites.tsx` — 제목 "초대". owner·admin에게만 보인다.
   - 폼: 이메일, 역할(`멤버` 기본, `보기 전용`, owner에게만 `관리자`), 버튼 `초대 보내기`. 성공 토스트 `<이메일>(으)로 초대를 보냈습니다.` 오류는 서버 문구 그대로.
   - 대기 중 목록: 이메일, 역할, 만료일, 버튼 `초대 취소`(확인 없음, 토스트 `초대를 취소했습니다.`).
5. `InvitePage.tsx` — `/app/invite?token=…` (`authedRoute` 아래. 로그인하지 않았으면 기존 방식대로 로그인으로 갔다가 같은 주소로 돌아온다)
   - 토큰이 없으면 `초대 링크가 올바르지 않습니다.`
   - 화면: `워크스페이스 초대를 받았습니다.`, 내 이메일 표시 `<이메일>(으)로 로그인되어 있습니다.`, 버튼 `초대 수락`. **자동으로 수락하지 않는다**(링크 미리보기가 수락해 버리면 안 된다).
   - 성공: 그 워크스페이스로 전환하고 `/app`으로 이동, 토스트 `"<이름>" 워크스페이스에 참여했습니다.`
   - 오류: 404·409·403·429는 서버 문구를 화면 본문에 보이고, 403(이메일 불일치)에는 버튼 `다른 계정으로 로그인`(로그아웃 뒤 로그인 화면, 돌아올 경로는 같은 초대 주소).
   - 수락 뒤 주소에서 토큰을 지운다(`history.replaceState`).
6. `lib/usage.ts`와 `Usage.tsx` — 제목 "사용량".
   ```ts
   export function usageRows(u: WorkspaceUsage): { label: string; used: string; max: string | null; ratio: number | null }[]
   ```
   - 세 줄: `이번 달 녹음 시간`(`3시간 20분` 형식), `이번 달 AI 처리 비용`(`$1.23`. 마이크로달러 ÷ 1,000,000, 소수 둘째 자리), `저장 공간`(`1.2GB` 형식).
   - 한도가 있으면 `<사용> / <한도>`와 막대(`<progress>` 또는 `role="progressbar"` + `aria-valuenow`·`aria-valuemax`·`aria-label`). 한도가 없으면 사용량만 보이고 막대는 없다.
   - `ratio >= 1`이면 그 줄에 `한도를 모두 사용했습니다.`를 글자로 보인다(색만으로 알리지 않는다). `ratio >= 0.9`면 `한도에 가까워졌습니다.`
   - 맨 아래 `기간: <YYYY년 M월>`. 한도는 운영자가 정한다는 안내 `한도는 운영자가 설정합니다.`

## 6. 테스트

| 종류 | 테스트 이름 | 준비 | 기대 |
|---|---|---|---|
| unit | usage "formats" | `audio_ms: 12_000_000`, `ai_cost_microusd: 1_234_567`, `storage_bytes: 1_288_490_189` | `3시간 20분`, `$1.23`, `1.2GB` |
| unit | usage "ratio" | 한도 없음 / 절반 / 초과 | `null` / `0.5` / `1`(1을 넘지 않게 자른다) |
| e2e | "owner changes a role" | `fixture-role=owner`, member를 `보기 전용`으로 | 표가 바뀐다 |
| e2e | "admin cannot edit owners" | `fixture-role=admin` | owner 줄의 선택이 `disabled`, 선택지에 `소유자` 없음 |
| e2e | "member sees no invite form" | `fixture-role=member` | "초대" 구역 없음, 역할 선택 모두 꺼짐 |
| e2e | "last owner hint" | owner 한 명 | `소유자가 한 명은 있어야 합니다.` |
| e2e | "invite and cancel" | 초대 보내기 → 목록 → 취소 | 토스트 두 개, 목록에서 사라짐 |
| e2e | "accept needs a click" | `/app/invite?token=x` | 버튼을 누르기 전에는 `acceptInvite`가 불리지 않는다. 누르면 참여 토스트, 주소에 `token` 없음 |
| e2e | "accept with the wrong account" | fixture가 403 | 서버 문구와 `다른 계정으로 로그인` |
| e2e | "usage with a quota" | 한도 있는 fixture | `progressbar` 3개와 `aria-valuenow` |
| e2e | a11y "workspace settings", "invite page" | 각 화면 | axe 위반 0건 |

## 10. 명세 작성자 메모

- 로그인 화면이 "돌아올 경로"를 받는 방식은 `router.tsx`와 `LoginPage.tsx`를 읽고 따른다. 그런 기능이 없으면 초대 주소를 `sessionStorage`에 넣었다가 로그인 뒤 꺼내 이동한다(토큰이 URL 밖에 잠깐 남는다. 수락 뒤 지운다).
- 비용 표기를 달러로 한 것은 원장이 마이크로달러이기 때문이다. 환율 변환은 하지 않는다.
