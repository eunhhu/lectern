# P6-A12 배포: Sparkle과 공증 스크립트

> 등급: `careful` · 게이트: `apple` · 의존: `P6-A9` · 소유: `apps/apple/`, `docs/runbooks/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

**사용자가 필요하다.** 서명·공증·업데이트 서명은 Apple Developer ID와 사용자의 키가 있어야 확인된다. 이 작업이 만드는 것은 코드와 스크립트와 런북이다. `pipeline.json`에 `needs_user`가 남아 있어도 코드 부분은 진행할 수 있다는 것을 오케스트레이터가 사용자에게 확인한 뒤 시작한다.

## 1. 목표

새 macOS 앱을 Gatekeeper 경고 없이 설치하고 앱 안에서 업데이트할 수 있게 준비한다. Sparkle 2를 앱에 넣고(업데이트 확인 메뉴, 자동 확인 설정), 서명 → 공증 → 스테이플 → 압축 → 업데이트 서명을 하는 스크립트를 만들고, 런북에 절차를 적는다. 자격 증명이 없으면 스크립트는 무엇이 필요한지 알려 주고 끝난다. 서명 없이 하는 게이트 빌드는 그대로 통과한다.

## 5. 단계

1. Sparkle 넣기
   - `project.yml`의 `packages`에 `Sparkle: { url: https://github.com/sparkle-project/Sparkle, from: "2.6.0" }`(2.x의 실제 최신 태그로 맞춘다), `LecternMac`의 `dependencies`에 `- package: Sparkle`.
   - `Base.xcconfig`에 `LECTERN_SPARKLE_FEED_URL =`와 `LECTERN_SPARKLE_PUBLIC_KEY =`(빈 값). `Local.xcconfig.example`에 설명: 피드 주소(appcast.xml의 https 주소)와 EdDSA **공개** 키(`generate_keys`가 출력하는 값). 비공개 키는 로그인 키체인에만 있고 저장소·xcconfig에 넣지 않는다.
   - `Info.plist`: `SUFeedURL` = `$(LECTERN_SPARKLE_FEED_URL)`, `SUPublicEDKey` = `$(LECTERN_SPARKLE_PUBLIC_KEY)`, `SUEnableInstallerLauncherService` = true(샌드박스 앱).
   - entitlements: Sparkle 문서의 "Sandboxing" 절이 요구하는 `com.apple.security.temporary-exception.mach-lookup.global-name`(`$(PRODUCT_BUNDLE_IDENTIFIER)-spks`, `$(PRODUCT_BUNDLE_IDENTIFIER)-spki`)를 더한다. 문서의 현재 요구와 다르면 문서를 따른다.
2. `Updater.swift`
   ```swift
   @MainActor final class Updater: ObservableObject {
       static func isConfigured(feedURL: String?, publicKey: String?) -> Bool     // both non-empty, feed is https
       init()                                                                      // creates SPUStandardUpdaterController only when isConfigured
       var canCheckForUpdates: Bool { get }
       func checkForUpdates()
       var automaticallyChecks: Bool { get set }
   }
   ```
   - **피드나 공개 키가 비어 있으면 업데이터를 만들지 않는다**(개발 빌드와 게이트 빌드에서 Sparkle이 오류 창을 띄우지 않는다). 그때 메뉴 항목은 꺼져 있고 설정에는 `이 빌드는 자동 업데이트를 지원하지 않습니다.`가 보인다.
   - 메뉴: 앱 메뉴에 `업데이트 확인…`. 설정: 토글 `자동으로 업데이트 확인`.
   - `isConfigured`는 `LecternKit`이나 `LecternUI`에 순수 함수로 두고 SwiftPM 테스트를 한다(Sparkle에 의존하지 않는 곳).
3. `scripts/lib/release-checks.sh`(bash 함수. `set -u`에서 안전하게)
   ```bash
   require_env NAME "설명"          # prints "release: <NAME>가 필요합니다 — <설명>" to stderr, returns 1 when unset or empty
   require_tool NAME "설치 방법"
   check_release_prereqs            # runs every check below, prints all problems (not just the first), returns 1 when any failed
   ```
   필요한 것: 도구 `xcodebuild`, `xcodegen`, `xcrun`(와 `xcrun notarytool`, `xcrun stapler`), `ditto`, `codesign`. 환경 변수 `LECTERN_DEVELOPER_ID`(서명 신원 이름 `Developer ID Application: … (TEAMID)`), `LECTERN_NOTARY_PROFILE`(`notarytool store-credentials`로 만든 키체인 프로필 이름), 선택 `LECTERN_SPARKLE_SIGN`(Sparkle의 `sign_update` 경로. 없으면 업데이트 서명을 건너뛰고 경고). `Local.xcconfig`에 `DEVELOPMENT_TEAM`, `LECTERN_SPARKLE_FEED_URL`, `LECTERN_SPARKLE_PUBLIC_KEY`가 채워져 있는지(값은 출력하지 않는다).
4. `scripts/release-macos.sh <version>`
   1. `check_release_prereqs` — 실패하면 문제 목록 뒤에 `release: 자격 증명이 없어 중단합니다. docs/runbooks/apple-developer-notarization.md를 보세요.`를 내고 **종료 코드 2**. 아무것도 만들지 않는다.
   2. `<version>`이 `^[0-9]+\.[0-9]+\.[0-9]+$`가 아니면 종료 코드 2.
   3. `xcodegen generate` → `xcodebuild archive -scheme LecternMac -configuration Release -archivePath build/LecternMac.xcarchive MARKETING_VERSION=<version> CURRENT_PROJECT_VERSION=<날짜 기반 빌드 번호> CODE_SIGN_IDENTITY="$LECTERN_DEVELOPER_ID" CODE_SIGN_STYLE=Manual OTHER_CODE_SIGN_FLAGS="--timestamp --options=runtime"`.
   4. 아카이브에서 `Lectern.app`을 꺼내 `codesign --verify --deep --strict`와 `codesign -d --entitlements -`로 확인한다. Hardened Runtime이 켜져 있어야 한다.
   5. `ditto -c -k --keepParent Lectern.app Lectern-<version>.zip` → `xcrun notarytool submit … --keychain-profile "$LECTERN_NOTARY_PROFILE" --wait`. 결과가 `Accepted`가 아니면 `notarytool log`를 출력하고 종료 코드 1.
   6. `xcrun stapler staple Lectern.app` → `xcrun stapler validate` → `spctl --assess --type execute -vv Lectern.app`.
   7. 스테이플된 앱을 다시 zip → `build/release/Lectern-<version>.zip`. `LECTERN_SPARKLE_SIGN`이 있으면 `"$LECTERN_SPARKLE_SIGN" build/release/Lectern-<version>.zip`의 출력(`sparkle:edSignature`, `length`)을 `build/release/Lectern-<version>.sig.txt`에 쓴다.
   8. 마지막에 산출물 경로와 다음 할 일(`make-appcast.sh`, GitHub Release에 올리기)을 출력한다.
   - 스크립트는 `set -euo pipefail`. 비밀 값(프로필 이름은 비밀이 아니다)을 출력하지 않는다. `build/`는 `apps/apple/.gitignore`에 더한다.
   - **업로드·배포는 하지 않는다**(GitHub Release 만들기, appcast 게시는 사용자가 한다).
5. `scripts/make-appcast.sh <version> <zip-url> <sig-file> [notes-file]`: appcast `<item>` XML 한 덩어리를 표준 출력으로 낸다(제목 `Lectern <version>`, `sparkle:version`, `sparkle:shortVersionString`, `enclosure url/length/type="application/octet-stream"/sparkle:edSignature`, `sparkle:minimumSystemVersion` = `26.0`, `pubDate`). 인자가 모자라면 사용법과 종료 코드 2. 서명 파일이 없으면 종료 코드 2.
6. `scripts/test-release-checks.sh`: 임시 환경에서 6절의 경우를 돌리는 셸 테스트. `apps/apple/scripts/gate.sh`에 한 줄 더해 게이트에서 돈다(`bash scripts/test-release-checks.sh`).
7. 런북 `docs/runbooks/apple-developer-notarization.md`(없으면 새로, 있으면 새 앱 절을 더한다). 절:
   1. 한 번만 하는 준비: Developer ID Application 인증서 발급·키체인 설치 / 앱 전용 암호 발급 후 `xcrun notarytool store-credentials <프로필 이름>` / Sparkle 키 만들기(`generate_keys`. 공개 키를 `Local.xcconfig`에, 비공개 키는 키체인에만. **비공개 키를 잃으면 기존 사용자가 업데이트를 못 받는다**는 경고와 백업 방법) / `Local.xcconfig` 채우기
   2. 릴리스: 환경 변수 세 개를 내보내고 `bash apps/apple/scripts/release-macos.sh <버전>` → 산출물 확인 → GitHub Release에 zip 올리기 → `make-appcast.sh`로 항목을 만들어 appcast에 넣고 게시
   3. 확인: 다른 Mac에서 내려받아 실행(Gatekeeper 경고 없음), 이전 버전에서 `업데이트 확인…`으로 올라오는지
   4. 문제 해결: 공증 거부 로그 읽기, 스테이플 실패, 서명에 `--options=runtime` 누락, 샌드박스에서 Sparkle이 설치를 못 할 때
   5. 옛 앱(`apps/macos`)에서 넘어오기: 같은 번들 id와 같은 Developer ID로 서명해야 마이크 권한이 이어진다. 옛 앱은 Sparkle이 없으므로 사용자가 한 번 직접 내려받아야 한다
   명령에 실제 팀 id·이름·이메일을 넣지 않는다(자리 표시는 `<팀 ID>` 형식의 설명으로만 쓰고, 실행하는 명령 줄에는 환경 변수를 쓴다).
8. `MANUAL_CHECKS.md`에 행: "`release-macos.sh`가 공증까지 통과한다", "다른 Mac에서 Gatekeeper 경고 없이 열린다", "이전 버전에서 앱 안 업데이트가 된다", "업데이트 뒤 마이크·시스템 오디오 권한이 유지된다", "업데이트 서명이 틀린 zip은 Sparkle이 거부한다".

`test-release-checks.sh`(게이트에서 돈다)

| 경우 | 준비 | 기대 |
|---|---|---|
| 자격 증명 없음 | 환경 변수 없음 | `release-macos.sh 1.2.3`이 종료 코드 2, stderr에 `LECTERN_DEVELOPER_ID가 필요합니다`와 `LECTERN_NOTARY_PROFILE가 필요합니다` **둘 다**, 마지막 줄에 런북 경로. `build/`가 생기지 않는다 |
| 버전 형식 | `release-macos.sh v1` | 종료 코드 2 |
| `require_env` | 빈 문자열로 설정 | 실패로 본다 |
| `make-appcast.sh` 인자 부족 | 인자 2개 | 종료 코드 2, 사용법 |
| `make-appcast.sh` 정상 | 가짜 서명 파일(`sparkle:edSignature="AAA" length="123"`) | 출력에 `<enclosure`, `sparkle:edSignature="AAA"`, `length="123"`, `sparkle:shortVersionString>1.2.3<`. `xmllint --noout`이 통과 |
| 비밀 미출력 | 환경 변수에 가짜 값을 넣고 실패 경로 실행 | 출력에 `Local.xcconfig`의 값이 없다 |

SwiftPM: `testUpdaterIsConfigured` — (피드, 키) = (`nil`, `nil`) → false / (`"https://x/appcast.xml"`, `"KEY"`) → true / (`"http://x/appcast.xml"`, `"KEY"`) → false / (`""`, `"KEY"`) → false.

## 10. 명세 작성자 메모

- 샌드박스 앱에서의 Sparkle 설정(XPC 서비스, entitlements)은 Sparkle 문서가 버전마다 조금씩 바꿨다. 이 명세의 키 이름은 기억에 의존했다. 문서(sparkle-project.org/documentation/sandboxing)를 기준으로 한다.
- 공증된 빌드에서만 드러나는 문제(Hardened Runtime에서 시스템 오디오 탭, Sparkle 설치기)는 전부 사용자 확인 항목이다. 이 작업이 `DONE`이어도 "배포할 수 있다"는 뜻이 아니다(STATUS에 그렇게 적었다).
- 빌드 번호 규칙(날짜 기반)은 이 명세의 제안이다. 기존 CI의 번호 규칙이 있으면 그것을 따른다.
