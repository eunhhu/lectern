# P5-07 쿼터와 사용량

> 등급: `basic` · 게이트: `full` · 의존: `P5-C` · 소유: `apps/server/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

워크스페이스가 이번 달에 쓴 오디오 시간·AI 비용·저장 용량을 볼 수 있다. 운영자가 워크스페이스에 한도(쿼터)를 넣으면, 한도를 넘은 워크스페이스는 새 업로드와 물어보기가 한국어 안내와 함께 거절된다. 쿼터 행이 없으면 제한이 없다(지금과 같다).

## 2. 먼저 읽을 것

- 계약: `CONTRACTS.md` D-P5-7, §5 DB(`workspace_quota`), 라우트(`getWorkspaceUsage`, `adminSetQuota`)
- 레시피: `RECIPES.md` R3, R12
- 코드: `packages/db/src/schema.ts` — `usageLedger`(`workspace_id`, `period`, `audio_ms`, `ai_cost_microusd`, `storage_bytes`), `aiCall`(`workspace_id`, `cost_microusd`, `created_at`), `asset`(`workspace_id`, `bytes`), `recording`(`duration_ms`)
- 코드: `apps/server/src/api/v2/admin.ts` — `adminListUsage`(원장을 읽기만 한다. 지금은 원장을 쓰는 코드가 없다), `isAdminUser`로 운영자를 가르는 방법
- 코드: `apps/server/src/api/v2/uploads.ts` — `createUpload`; `apps/server/src/api/v2/ask.ts` — `askQuestion`(물어보기 월 한도 `budget_exceeded`를 주는 곳)
- 코드: `apps/server/src/maintenance.ts` — `runMaintenanceNow`(주기 작업에 한 단계를 더하는 방법)

## 5. 단계

1. `usage.ts`
   ```ts
   export function periodOf(now?: number): string                       // "YYYY-MM" in Asia/Seoul
   export function periodBounds(period: string): { from: number; to: number }   // epoch ms, [from, to)
   export function measureUsage(workspaceId: string, period?: string): { period: string; audio_ms: number; ai_cost_microusd: number; storage_bytes: number }
   export function refreshLedger(workspaceId: string, period?: string): void   // upsert the measured numbers into usage_ledger
   export function refreshAllLedgers(): number                                 // every workspace that has a recording; returns how many
   export function quotaOf(workspaceId: string): { audio_ms_month: number | null; ai_microusd_month: number | null; storage_bytes: number | null } | null
   export function setQuota(workspaceId: string, q: { audio_ms_month: number | null; ai_microusd_month: number | null; storage_bytes: number | null }, updatedBy: string): void
   export function quotaProblem(workspaceId: string, add?: { bytes?: number }): { code: "quota_exceeded"; message: string; details: { limit: string; used: number; max: number } } | null
   ```
   `measureUsage`는 원장이 아니라 **원본 행에서 센다**(원장은 그 결과를 보관하는 사본이다).
   - `audio_ms`: 그 워크스페이스에서 `created_at`이 기간 안인 녹음의 `duration_ms` 합(`NULL`은 0, 지워진 녹음은 세지 않는다).
   - `ai_cost_microusd`: `ai_call.workspace_id`가 같고 `created_at`이 기간 안인 `cost_microusd` 합.
   - `storage_bytes`: 그 워크스페이스 `asset.bytes` 합(기간과 상관없는 현재 값).
   `quotaProblem` — 쿼터 행이 없으면 `null`. 있으면 `measureUsage`와 비교해 처음 걸리는 것 하나를 돌려준다. `null`인 한도는 검사하지 않는다.
   - 오디오: `audio_ms >= audio_ms_month` → `이번 달 녹음 시간 한도를 모두 사용했습니다. 다음 달에 다시 올리거나 관리자에게 문의해 주세요.` (`limit: "audio_ms_month"`)
   - AI: `ai_cost_microusd >= ai_microusd_month` → `이번 달 AI 처리 한도를 모두 사용했습니다. 다음 달에 다시 시도하거나 관리자에게 문의해 주세요.` (`limit: "ai_microusd_month"`)
   - 저장: `storage_bytes + (add.bytes ?? 0) > storage_bytes 한도` → `저장 공간 한도를 넘습니다. 필요 없는 녹음이나 오디오를 지운 뒤 다시 시도해 주세요.` (`limit: "storage_bytes"`)
2. `getWorkspaceUsage`: `requireWorkspace`(멤버면 누구나). `{ ...measureUsage(id), quota: quotaOf(id) }`. 응답 직전에 `refreshLedger(id)`를 부른다(운영자 화면의 원장이 최신이 된다).
3. `adminSetQuota`: 운영자만(`admin.ts`의 다른 핸들러와 같은 검사. 운영자가 아니면 그 파일의 방식대로 403/404). 워크스페이스가 없으면 404. 본문의 세 값이 모두 `null`이면 행을 **지운다**(제한 없음으로 되돌림). 아니면 upsert. 응답은 저장된 값(지웠으면 세 값 `null`). `recordAuditLog`가 v2에서 쓰이고 있으면 같은 방식으로 감사 로그를 남긴다(`action: "workspace.quota.set"`).
4. 집행
   - `createUpload`: 워크스페이스 권한 검사 뒤, 업로드 세션을 만들기 전에 `quotaProblem(workspaceId, { bytes: 요청의 전체 크기 })`. 있으면 `apiError(c, 409, "quota_exceeded", message, details)`. 요청에 전체 크기 필드가 없으면 `bytes`는 0으로 둔다.
   - `askQuestion`: 기존 월 한도 검사 앞에서 `quotaProblem(workspaceId)`의 `limit`이 `ai_microusd_month`일 때만 같은 409를 준다(오디오·저장 한도는 물어보기를 막지 않는다). 스트리밍을 시작하기 전에 검사한다.
   - 이미 올라간 녹음의 처리(작업)는 막지 않는다. 받은 것은 끝까지 처리한다.
5. `maintenance.ts`: 유지보수 실행에 `refreshAllLedgers()` 단계를 더한다(실패해도 다른 단계는 계속).

## 6. 테스트

`usage.test.ts`

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| "period is the Seoul month" | `periodOf(Date.UTC(2026, 9, 31, 15, 30))`(서울 11월 1일 0시 30분) | `"2026-11"` |
| "measures from source rows" | 이번 달 녹음 2개(10분, 20분), 지난달 1개, `ai_call` 3행, `asset` 2개 | `audio_ms === 1_800_000`, 비용 합, 바이트 합 |
| "no quota row: unlimited" | 쿼터 없음, 큰 사용량 | `quotaProblem === null`, `createUpload` 201 |
| "audio quota blocks uploads" | `audio_ms_month: 600_000`, 사용 10분 | `createUpload` 409 `quota_exceeded`, 문구 `이번 달 녹음 시간 한도를 모두 사용했습니다.`로 시작, `details.limit === "audio_ms_month"` |
| "storage quota counts the new file" | 한도 100, 사용 60, 새 파일 50 | 409. 새 파일 40이면 201 |
| "ai quota blocks ask and uploads" | `ai_microusd_month`만 넘김 | `askQuestion` 409, `createUpload`도 409 |
| "audio quota does not block ask" | `audio_ms_month`만 넘김 | `askQuestion`은 평소대로 |
| "new month resets" | 지난달에 한도를 넘긴 워크스페이스 | 이번 달 `quotaProblem === null` |
| "getWorkspaceUsage" | 멤버 호출 | 200, `period`, 세 수치, `quota`(없으면 `null`). 비멤버 403 |
| "only the operator sets quotas" | 일반 사용자 `adminSetQuota` | 403(또는 그 파일의 방식대로 404) |
| "set then clear" | 값 설정 → 세 값 `null` | `workspace_quota` 행이 생겼다가 사라진다 |
| "ledger refresh" | `refreshAllLedgers()` | `usage_ledger`에 (워크스페이스, 기간) 행이 하나씩, 두 번 돌려도 행 수 그대로 |

AI 한도는 업로드도 막는다(D-P5-7: "월 오디오 시간과 월 AI 비용을 넘으면 `createUpload`가 … `409 quota_exceeded`").

## 10. 명세 작성자 메모

- 기간을 서울 시간의 달로 잡은 것은 이 명세의 결정이다. `adminListUsage`가 읽는 기존 원장 행(있다면)과 기간 표기(`YYYY-MM`)는 같다.
- 오디오 시간은 "그 달에 만든 녹음의 길이 합"이다. 처리 전인 녹음(`duration_ms`가 `NULL`)은 0으로 세므로, 처리가 끝나기 전에 연달아 올리면 한도를 조금 넘을 수 있다. 받아들인다.
- `createUpload` 요청에 전체 크기가 있는지는 확인하지 않았다(`CreateUploadRequest`를 읽는다).
