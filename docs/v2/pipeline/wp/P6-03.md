# P6-03 서버: apple-app-site-association, v1 사용량과 Sunset

> 등급: `basic` · 게이트: `full` · 의존: `P6-C` · 소유: `apps/server/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

세 가지를 넣는다. ① iOS·macOS 앱이 유니버설 링크를 쓰도록 `/.well-known/apple-app-site-association`을 서빙한다. ② 누가 아직 v1 API를 쓰는지 세어 운영자가 볼 수 있게 한다. ③ 폐기 날짜를 정하면 v1 응답에 `Deprecation`·`Sunset` 헤더가 붙고, 운영자가 차단을 켜면 날짜 뒤에 옛 엔드포인트가 410을 준다. 셋 다 변수가 없으면 지금과 똑같이 동작한다.

## 5. 단계

1. `apple-app-site-association.ts`
   ```ts
   export function aasaDocument(appIds: string[]): object | null   // null when the list is empty
   ```
   ```json
   { "applinks": { "details": [ { "appIDs": ["<id>", "…"], "components": [ { "/": "/app/*" }, { "/": "/s/*" } ] } ] },
     "webcredentials": { "apps": ["<id>", "…"] } }
   ```
   `http.ts`: `GET /.well-known/apple-app-site-association` — 문서가 `null`이면 404(본문 `Not found`). 있으면 200, `Content-Type: application/json`, `Cache-Control: public, max-age=3600`. 리다이렉트 없이 직접 답한다. 레거시로 넘기기 전에 등록한다.
2. `v1-sunset.ts`
   ```ts
   export function isV1ApiPath(pathname: string): boolean          // starts with "/api/" and not "/api/v2/" and not "/api/health"
   export function isRetiredV1Path(pathname: string): boolean       // the paths LECTERN_V1_BLOCK may close (see below)
   export function normalizeV1Route(method: string, pathname: string): string
   export function classifyV1Client(headers: Headers): string
   export function recordV1Usage(route: string, client: string, now?: number): void
   export function flushV1Usage(): void
   export function v1Headers(now?: number): Record<string, string>  // {} when no sunset date
   export function v1Blocked(pathname: string, now?: number): boolean
   export function pruneV1Usage(now?: number): number               // rows older than 400 days
   ```
   - **폐기 대상 경로**(`isRetiredV1Path`): `/api/lectures`와 그 하위, `/api/ingest/`, `/api/events`, `/api/clients/`. **대상이 아닌 것**: `/api/auth/`(새 웹 앱의 로그인·가입·재설정이 쓴다), `/api/admin/`(새 관리자 콘솔이 쓴다), `/api/cd/`, `/api/health`. 이 목록은 함수 안의 상수 배열 하나로 둔다.
   - `normalizeV1Route`: `"<METHOD> <경로>"`. 경로의 각 조각 중 id처럼 보이는 것(길이 16 이상, 또는 숫자만, 또는 `[0-9a-f-]{8,}`)을 `:id`로 바꾼다. 쿼리는 버린다. 전체 120자로 자른다. 예: `GET /api/lectures/:id/audio`.
   - `classifyV1Client`(위에서부터 처음 맞는 것)
     1. 헤더 `X-Client`(기존 클라이언트들이 이미 보낸다: `macos-native-menubar`, `android-share` 등)를 소문자로 바꾼 값이 `/^[a-z0-9-]{1,32}$/`에 맞으면 그 값
     2. `User-Agent`에 `LecternMenuBar` → `macos`
     3. `Shortcuts` 또는 `WorkflowKit` → `shortcuts`
     4. `Dalvik` 또는 `okhttp` → `android`
     5. `CFNetwork` → `apple-other`
     6. `Mozilla/`로 시작 → `browser`
     7. `User-Agent`가 없음 → `no-ua`
     8. 그 밖 → `other`
   - `recordV1Usage`: 요청마다 DB에 쓰지 않는다. 메모리의 `Map<"day|route|client", count>`에 더하고, 30초마다(타이머 `unref()`) 또는 키가 500개를 넘으면 `flushV1Usage`가 한 트랜잭션으로 `INSERT … ON CONFLICT(day, route, client) DO UPDATE SET count = count + excluded.count`를 한다. `day`는 `Asia/Seoul`의 `YYYY-MM-DD`다. 서버가 내려갈 때(`beforeExit` 또는 기존 종료 처리)도 한 번 flush한다. 실패해도 요청에는 영향이 없다.
   - `v1Headers`: `config().v1.sunset`이 있으면 `{ "Deprecation": "true", "Sunset": <그 날짜 00:00 Asia/Seoul의 HTTP 날짜(RFC 7231, GMT)>, "Link": "</api/v2/openapi.json>; rel=\"successor-version\"" }`.
   - `v1Blocked`: `config().v1.block`이 참이고 `sunset`이 있고 지금이 그 날짜 00:00(서울) 이후이고 `isRetiredV1Path`면 참.
3. `http.ts` 미들웨어(v2 앱을 붙인 뒤, 레거시로 넘기기 전)
   - `isV1ApiPath`가 아니면 그냥 지나간다.
   - `v1Blocked`면 레거시를 부르지 않고 `410`, JSON `{ "error": "이 API는 종료되었습니다. 앱을 최신 버전으로 업데이트해 주세요.", "code": "v1_gone" }`, `v1Headers()`. 이 요청도 집계한다(누가 아직 두드리는지 봐야 한다).
   - 아니면 레거시 응답을 받은 뒤 `v1Headers()`를 붙이고(스트림 응답 포함. 응답 본문은 건드리지 않는다) `recordV1Usage(normalizeV1Route(…), classifyV1Client(…))`.
   - SSE(`/api/events`)는 연결 한 번을 한 건으로 센다.
   - 변수가 둘 다 없으면 바뀌는 것은 집계뿐이다. **응답 헤더와 본문은 한 바이트도 달라지지 않는다**(`v1-contract.test.ts`).
4. `adminListV1Usage`: 운영자만. `from`·`to`(기본: 최근 30일, 서울 날짜)로 `day` 범위를 걸러 `day DESC, count DESC`로 최대 1,000행. 응답 전에 `flushV1Usage()`를 불러 방금 것까지 보이게 한다.
5. `maintenance.ts`에 `pruneV1Usage()` 단계.

`v1-sunset.test.ts`

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| "route normalisation" | `GET /api/lectures/0a1b2c3d-…/audio?x=1`, `POST /api/ingest/shortcut`, `GET /api/lectures` | `GET /api/lectures/:id/audio`, `POST /api/ingest/shortcut`, `GET /api/lectures` |
| "client classification" | 5절 2단계의 여덟 경우 | 각각의 값. `X-Client: macos-native-menubar` → `macos-native-menubar`. `X-Client: Bad Value!`는 무시되고 UA 규칙으로 간다 |
| "counts one row per day, route and client" | 같은 요청 3번 + flush | `v1_usage` 1행, `count === 3` |
| "v2 and health are not counted" | `/api/v2/me`, `/api/health` | 행 없음 |
| "no variables: responses unchanged" | 변수 없음 | 응답에 `Deprecation`·`Sunset` 없음. `v1-contract.test.ts` 통과 |
| "sunset adds headers" | `LECTERN_V1_SUNSET=2027-03-01` | v1 응답에 `Deprecation: true`, `Sunset: Sun, 28 Feb 2027 15:00:00 GMT`, `Link`. v2 응답에는 없다 |
| "block needs both the flag and the date" | ① 날짜 지남 + 플래그 끔 ② 플래그 켬 + 날짜 전 ③ 둘 다 | ①② 평소 응답 ③ `GET /api/lectures` 410 `v1_gone` |
| "auth and admin stay open when blocked" | ③에서 `POST /api/auth/login`, `GET /api/admin/overview` | 410이 아니다 |
| "v2 is never affected" | ③에서 `GET /api/v2/me` | 평소 응답 |
| "blocked requests are still counted" | ③에서 요청 + flush | 집계에 있다 |
| "admin list" | 운영자 / 일반 사용자 | 200과 행들 / 403(또는 그 파일의 방식) |
| "prune" | 401일 전 행, 399일 전 행 | 앞의 것만 삭제 |
| "flush failure does not break requests" | flush가 던지게 함 | 요청은 평소대로 |

## 8. 하지 않는 것

- `LECTERN_V1_BLOCK`을 켜는 것은 사용자가 사용량을 보고 정한다. 이 작업은 켜지 않는다.
- 관리자 화면(`P5-13`이 `adminListV1Usage`를 그린다).

## 10. 명세 작성자 메모

- 계약은 "모든 v1 응답 경로"라고만 했다. 차단 대상에서 `/api/auth/`와 `/api/admin/`을 뺀 것은 새 웹 앱과 새 관리자 콘솔이 그 경로를 쓰기 때문이다(CONTRACTS 보충 절). 집계에는 들어간다. 그래서 `browser` 클라이언트의 `/api/auth/*` 건수는 0이 되지 않는다. 차단을 켤 때 봐야 하는 것은 폐기 대상 경로의 건수다.
- macOS·Android 클라이언트는 업로드 요청에 `X-Client`를 보낸다. 목록 조회 같은 다른 요청에는 없어서 UA 규칙으로 잡힌다. Windows 앱은 `X-Client`도 `User-Agent`도 보내지 않아 `no-ua`다(P6-W1이 `X-Client: windows-native-tray`를 보내게 한다).
- `Sunset` 헤더의 시각을 서울 자정으로 잡았다(예: 3월 1일 00:00 KST = 2월 28일 15:00 GMT).
