# P6-A11 시스템 표면

> 등급: `careful` · 게이트: `apple` · 의존: `P6-A7`, `P6-02`, `P6-03` · 소유: `apps/apple/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

업로드한 뒤 앱을 열지 않아도 진행 상황과 결과가 사용자에게 온다. iPhone이 푸시를 받도록 기기를 서버에 등록하고, 처리 단계가 Live Activity에 보이고, 끝나면 "문서가 준비되었습니다" 알림이 온다. 그리고 문서를 Spotlight·Siri에서 찾고, 홈 화면 위젯에서 최근 문서와 처리 중인 녹음을 보고, 공유 링크와 `/app/…` 주소가 앱에서 열리고, 수락한 일정을 기기 캘린더에 넣는다.

## 5. 단계

1. 푸시 페이로드 모델(`PushPayloads.swift`) — 서버와 같은 모양
   ```swift
   public struct ProcessingContentState: Codable, Hashable, Sendable {      // D-P6-12
       public var stage: String
       public var stageLabel: String        // "stage_label"
       public var progress: Double?
       public var recordingID: String       // "recording_id"
       public var documentReady: Bool       // "document_ready"
   }
   public struct DocumentAlert: Decodable, Sendable { public let recordingID: String; public let url: URL; public let title: String; public let body: String }
   public func decodeAlert(userInfo: [AnyHashable: Any]) -> DocumentAlert?
   ```
   `CodingKeys`로 스네이크 표기를 맞춘다. 모르는 키는 무시한다. `stage`가 모르는 값이어도 디코드된다(문자열 그대로).
2. 처리 진행 Live Activity
   ```swift
   public struct ProcessingActivityAttributes: ActivityAttributes {   // the type name must stay: the server sends "attributes-type": "ProcessingActivityAttributes"
       public typealias ContentState = ProcessingContentState
       public var recordingID: String      // "recording_id"
       public var title: String
   }
   ```
   - `ProcessingActivityCoordinator`: 업로드가 `done(recordingID)`이 되면 `Activity.request(attributes:content:pushType: .token)`으로 활동을 시작하고, `pushTokenUpdates`에서 토큰이 오면 `setLiveActivity(recordingID, deviceID, pushToken)`을 서버에 보낸다(토큰이 바뀔 때마다 다시). 활동이 끝나면(`activityStateUpdates`가 `.ended`·`.dismissed`) `endLiveActivity`.
   - push-to-start: `Activity<ProcessingActivityAttributes>.pushToStartTokenUpdates`의 토큰을 기기 등록(`push_to_start_token`)에 실어 보낸다.
   - 화면(`ProcessingLiveActivity`): 제목, `stage_label`, 진행 막대(`progress`가 있으면 값, 없으면 불확정 표시). `document_ready`면 `문서 준비됨`과 열기 링크(`widgetURL`: `lectern://recordings/<id>`). Dynamic Island compact: 아이콘과 `stage_label`의 짧은 표기.
   - 한 번에 진행 활동은 5개까지. 넘으면 가장 오래된 것을 끝낸다.
3. 기기 등록(`PushRegistration`)
   - `DeviceIdentity`: 처음 실행 때 UUID를 만들어 Keychain(`device_id`)에 둔다. 앱을 지웠다 깔면 새 id다.
   - 알림 권한은 첫 업로드가 끝났을 때 묻는다. 허용되면 `registerForRemoteNotifications()`. 받은 APNs 토큰(16진수 문자열)으로 `upsertPushDevice(deviceID, { platform: "ios", apns_token, push_to_start_token?, name: <기기 이름>, app_version })`.
   - 토큰이나 push-to-start 토큰이 바뀌면 다시 보낸다. 같은 값을 연달아 보내지 않는다(마지막으로 보낸 값을 기억).
   - 로그아웃: `deletePushDevice(deviceID)`를 **토큰을 지우기 전에** 부른다(실패해도 로그아웃은 진행).
   - 서버가 501을 주면(플래그 꺼짐) 조용히 넘어간다.
4. 알림 처리: 알림을 누르면 `decodeAlert`로 `recording_id`를 꺼내 그 녹음 화면을 연다. 앱이 앞에 있을 때 온 알림은 배너로 보인다. 알림 카테고리 `DOCUMENT_READY`에 액션 `열기`.
5. 딥링크(`DeepLink.swift`)
   ```swift
   public enum DeepLink: Equatable, Sendable { case recording(id: String), library, settings, share(token: String), invite(token: String) }
   public func parseDeepLink(_ url: URL, serverHost: String?) -> DeepLink?
   ```
   - `lectern://recordings/<id>`, `lectern://library`, `lectern://settings`.
   - `https://<서버>/app/recordings/<id>`, `/app`, `/app/library`, `/app/settings`, `/app/invite?token=…`, `/s/<token>`. 호스트가 `serverHost`와 다르면 `nil`.
   - id와 토큰은 `[A-Za-z0-9_-]{1,128}`만 받는다. 그 밖의 경로는 `nil`(앱이 처리하지 않고 Safari에 맡긴다).
   - `share`와 `invite`는 이 단계의 앱에 화면이 없다. Safari로 그 주소를 연다.
   - entitlements에 `com.apple.developer.associated-domains` = `[applinks:$(LECTERN_ASSOCIATED_DOMAIN), webcredentials:$(LECTERN_ASSOCIATED_DOMAIN)]`. `Base.xcconfig`에 `LECTERN_ASSOCIATED_DOMAIN =`(빈 값)과 `Local.xcconfig.example`에 설명. `Info.plist`에 URL 스킴 `lectern`.
   - Handoff: 녹음 화면에서 `NSUserActivity`(`activityType: "com.qucord.lectern.recording"`, `webpageURL: <서버>/app/recordings/<id>`). 받는 쪽은 `parseDeepLink`로 연다.
6. App Entity와 Spotlight
   - `RecordingEntity: AppEntity, IndexedEntity`(id, 제목, 날짜, 폴더 이름). `EntityQuery`는 `WidgetSnapshot`의 캐시와 서버 목록에서 찾는다.
   - `OpenRecordingIntent`(`녹음 열기`, 파라미터 `RecordingEntity`, `openAppWhenRun = true`). `LecternShortcuts`에 문구 `"\(.applicationName)에서 \(\.$recording) 열기"`, `"\(.applicationName) 최근 문서 열기"`.
   - `SpotlightIndexer`: 목록을 새로 읽을 때마다 `CSSearchableIndex`에 녹음을 색인한다(제목, 날짜, 문서의 첫 300자). 로그아웃하면 색인을 모두 지운다. 한 번에 500개까지.
7. 위젯
   - `WidgetSnapshot`: `<App Group>/widgets.json`에 최근 문서 5개(id, 제목, 날짜)와 처리 중인 녹음(id, 제목, `stage_label`)을 쓴다. 앱이 목록을 읽을 때와 푸시를 받을 때 갱신하고 `WidgetCenter.shared.reloadAllTimelines()`. 위젯은 네트워크를 쓰지 않고 이 파일만 읽는다. 파일이 없거나 깨졌으면 빈 상태.
   - `RecentDocumentsWidget`(small, medium): 최근 문서 목록. 누르면 `lectern://recordings/<id>`. 빈 상태 `아직 문서가 없습니다`. 로그아웃 상태 `로그인이 필요합니다`.
   - `ProcessingWidget`(small): 처리 중인 녹음 수와 첫 항목의 단계. 없으면 `처리 중인 녹음이 없습니다`.
   - 로그아웃하면 스냅샷 파일을 지운다(잠금 화면에 제목이 남지 않게).
8. 캘린더 내보내기(쓰기 전용)
   ```swift
   public struct EventDraft: Equatable, Sendable { public var title: String; public var start: Date; public var end: Date; public var isAllDay: Bool; public var timeZone: TimeZone; public var notes: String; public var url: URL }
   public func eventDraft(from candidate: EventCandidateModel, serverURL: URL) -> EventDraft
   ```
   - 시간 일정: 끝이 없으면 시작 + 1시간. 하루 종일: 시작 날짜의 0시부터, 끝은 그 날(EventKit의 하루 종일 일정은 끝 날짜를 포함한다. ICS와 다르다).
   - `notes` = `Lectern 녹음에서 찾은 일정입니다.`, `url` = `<서버>/app/recordings/<recording_id>`.
   - `CalendarExporter`(iOS): `EKEventStore.requestWriteOnlyAccessToEvents()` → `EKEvent`를 기본 캘린더에 저장. 녹음 상세의 일정 줄에 버튼 `캘린더에 추가`. 성공 `캘린더에 추가했습니다.`, 거부 `캘린더 권한이 필요합니다. 설정에서 Lectern의 캘린더 접근을 켜 주세요.` `Info.plist`에 `NSCalendarsWriteOnlyAccessUsageDescription` = `수락한 일정을 캘린더에 넣으려면 캘린더에 추가할 수 있는 권한이 필요합니다.`
   - 같은 일정을 두 번 넣지 않게, 넣은 일정의 `event_candidate.id`를 App Group `UserDefaults`에 기억한다(쓰기 전용 권한이라 캘린더에서 찾아볼 수 없다).
9. `project.yml`·entitlements: iOS 앱에 `aps-environment` = `development`(배포 구성은 사용자가 서명할 때 정한다). 위젯 확장에 새 위젯 둘과 `ProcessingLiveActivity`를 더한다.
10. `MANUAL_CHECKS.md`에 행(실제 iPhone, 서버에 APNs 키 필요)
    - 알림 권한 허용 뒤 서버의 `push_device`에 기기가 생긴다
    - 업로드 뒤 Live Activity가 단계에 따라 바뀐다(앱을 닫은 상태)
    - Mac에서 올린 녹음이 push-to-start로 iPhone에 뜬다
    - 처리가 끝나면 알림이 오고, 누르면 그 문서가 열린다
    - Spotlight에서 녹음 제목으로 찾아 연다. Siri로 "Lectern에서 … 열기"
    - 위젯에 최근 문서가 보이고 누르면 열린다. 로그아웃하면 비워진다
    - `https://<서버>/app/recordings/<id>` 링크를 메모 앱에서 누르면 앱이 열린다(`APPLE_APP_IDS` 설정 필요)
    - Mac에서 보던 문서가 iPhone의 Handoff로 이어진다
    - `캘린더에 추가`가 캘린더 앱에 일정을 만든다. 같은 일정을 다시 눌러도 두 개가 되지 않는다

## 10. 명세 작성자 메모

- 이 작업은 크다. 워커가 한 번에 끝내기 어려우면 5절의 1~4단계(푸시와 Live Activity)만 하고 `RESULT: BLOCKED`, `NEEDS`에 "5~8단계 분리 요청"을 적는다. 오케스트레이터가 나눈다.
- 실제 푸시는 유료 Apple Developer 계정, APNs 키, 실제 기기가 있어야 확인된다. 전부 사용자 몫이다(STATUS "사용자 필요").
- App Intents의 `IndexedEntity`, ActivityKit의 `pushToStartTokenUpdates`의 정확한 모양은 SDK 선언을 따른다.
- 유니버설 링크는 서버의 `APPLE_APP_IDS`(팀 id 포함)와 앱의 Associated Domains가 맞아야 동작한다. 둘 다 저장소에 값이 없다.
