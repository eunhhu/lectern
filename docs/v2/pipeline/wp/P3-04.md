> 등급: `careful` · 게이트: `full` · 의존: `P3-03` · 소유: `packages/harness/`, `apps/server/`

## 1. 목표

전사와 PDF 쪽의 대응표를 모델 없이 만든다(`align`). 전사를 2분 창으로 나누고, 창마다 글자 2-gram BM25 점수로 상위 3쪽을 고른다. `structure`·`extract`는 그 쪽들(최대 12쪽, 쪽당 2,000자)을 문맥으로 받고, `verify`는 블록의 `pdf_pages`를 `PdfPageSourceRef`로 바꾸며 그 집합 밖 번호를 지운다. `GET /recordings/{id}/alignment`(`getRecordingAlignment`)가 결과를 돌려준다. PDF가 없는 녹음은 이 단계를 건너뛴다.

## 5. 단계

1. `align.ts` (순수, 모델 없음). 상수와 형태:
```ts
export const ALIGN_WINDOW_MS = 120_000;
export const ALIGN_TOP_PAGES = 3;
export interface AlignSegment { idx: number; start_ms: number; end_ms: number; text: string }
export interface AlignPage { asset_id: string; page_no: number; text: string }
export const AlignOutput = z.object({ windows: z.array(z.object({ start_ms: z.int().nonnegative(), end_ms: z.int().nonnegative(),
  pages: z.array(z.object({ asset_id: z.string(), page_no: z.int().min(1), score: z.number() })) })) });
export type AlignOutput = z.infer<typeof AlignOutput>;
export function alignWindows(segments: readonly AlignSegment[], pages: readonly AlignPage[]): AlignOutput;
export const alignStage: StageDefinition<{ segments: AlignSegment[]; pages: AlignPage[] }, AlignOutput>;
```
   `alignWindows` 규칙(이 순서 그대로):
   - 창 번호 = `Math.floor(start_ms / 120000)`. 같은 번호의 세그먼트 글을 공백으로 이어 한 창으로 한다. 글이 빈 세그먼트는 버린다. `start_ms` = 번호 × 120000, `end_ms` = 그 창 세그먼트 `end_ms`의 최댓값. 창은 번호 오름차순.
   - 토큰은 `indexTokens(text)`(`@lectern/ask`)다. 토큰 수가 0인 쪽은 코퍼스에서 뺀다.
   - BM25: `k1 = 1.2`, `b = 0.75`, 코퍼스 = 모든 PDF 쪽, `N` = 쪽 수, `avgdl` = 쪽 토큰 수 평균. `idf(t) = ln(1 + (N - n_t + 0.5) / (n_t + 0.5))`(`n_t` = 토큰 `t`가 있는 쪽 수). 점수 = 창의 **서로 다른** 토큰마다 `idf * f*(k1+1) / (f + k1*(1 - b + b*len/avgdl))`(`f` = 그 쪽에서의 토큰 빈도)의 합. 점수는 `Math.round(x * 10000) / 10000`.
   - 창마다 점수 > 0인 쪽을 점수 내림차순, 같으면 `asset_id`, `page_no` 오름차순으로 정렬해 앞 3개. 점수가 0인 쪽뿐이면 `pages: []`(창은 남긴다).
   - `alignStage`: `name: "align"`, `version: 1`, `memo: "shared"`, `retry: { maxAttempts: 1, repairs: 0 }`, `key`: `inputs: [sha256Hex(canonicalJson(segments.map(s => [s.idx, s.start_ms, s.end_ms, s.text]))), sha256Hex(canonicalJson(pages.map(p => [p.asset_id, p.page_no, p.text])))]`, `config: { window_ms: 120000, top: 3, k1: 1.2, b: 0.75, tokenizer: "ask.indexTokens" }`. `run`은 `alignWindows`를 부른다. 모델을 부르지 않으므로 `ctx.meter`를 쓰지 않는다.
2. `context.ts`:
```ts
export const PDF_CONTEXT_MAX_PAGES = 12;
export const PDF_CONTEXT_PAGE_CHARS = 2_000;
export interface PdfLabel { label: number; asset_id: string; page_no: number }
export interface PdfContext { text: string; labels: PdfLabel[] }
export function buildPdfContext(align: AlignOutput, pages: readonly AlignPage[], assetOrder: readonly string[]): PdfContext;
```
   - 쪽별 점수 = 모든 창에서의 점수 합. 합 내림차순(같으면 `assetOrder` 위치, `page_no` 오름차순)으로 최대 12쪽을 고른다. 고른 쪽을 `assetOrder` 위치, `page_no` 오름차순으로 다시 늘어놓고 라벨 1부터 붙인다.
   - `text`는 쪽마다 `"[PDF {label}] (자료 {assetOrder 위치+1}, {page_no}쪽)\n" + 쪽 글자 앞 2000자(코드포인트 기준)`를 빈 줄 하나로 잇는다. 고른 쪽이 없으면 `{ text: "", labels: [] }`.
3. `structure.ts`·`extract.ts`: 입력 타입에 선택 필드 `pdf?: PdfContext`를 더한다. `pdf?.text`가 비어 있지 않을 때만 프롬프트의 **전사 뒤, 단계 지시 앞**에 `"자료(PDF) 관련 쪽:\n" + pdf.text`를 넣고, `pdf_pages`에는 위 라벨 번호만 쓰라는 한 줄을 지시에 더한다. `pdf`가 없으면 프롬프트 문자열이 지금과 **바이트까지 같아야 한다**(P1 스냅샷 유지). 메모 키의 `inputs`에 `sha256Hex(pdf.text)`를 더하되 `pdf`가 없으면 더하지 않는다. `structure`와 `extract`가 같은 전사+PDF 접두부를 쓰는지(요청 본문 비교)는 기존 `extract` 테스트가 본다.
4. `verify.ts`: 입력에 선택 필드 `pdfLabels?: PdfLabel[]`를 더한다. 블록·항목의 `pdf_pages` 각 번호에 대해 (a) 번호가 `pdfLabels`에 있으면 `{ kind: "pdf_page", asset_id, page: page_no }`로 바꿔 그 블록의 `sources`에 더한다(같은 쪽 중복 제거), (b) 없으면 지우고 보고서 항목에 `outcome: "fixed"`, `reasons: ["pdf_page_out_of_set"]`. `pdfLabels`가 없으면(PDF 없는 녹음) 모든 `pdf_pages`를 같은 방식으로 지운다. 지운 뒤 출처가 0개가 된 블록의 처리는 기존 규칙(수리 → 탈락)을 그대로 쓴다.
5. `pipeline.ts`: `runNotesPipeline`의 `input`에 선택 필드 `pdf?: PdfContext`를 더해 `structure`·`extract`에 넘기고 `verify`에는 `pdf?.labels`를 `pdfLabels`로 넘긴다. 다른 동작은 바꾸지 않는다.
6. `pdf-align.ts`(서버):
```ts
export interface RecordingAlignmentFile { windows: AlignOutput["windows"] }
export function alignmentPath(recordingId: string): string; // join(DATA_DIR, "pdf-align", `${recordingId}.json`)
export function readAlignment(recordingId: string): RecordingAlignmentFile;   // missing file -> { windows: [] }
export function deleteAlignment(recordingId: string): void;
export async function alignRecording(args: { run: JobRun; recordingId: string; workspaceId: string }): Promise<PdfContext | null>;
```
   `alignRecording`: `SELECT idx, start_ms, end_ms, text FROM transcript_segment WHERE recording_id = ? ORDER BY idx`; 쪽은 `SELECT asset_id, page_no, text FROM pdf_page WHERE recording_id = ? AND char_count > 0 ORDER BY asset_id, page_no`. 세그먼트나 쪽이 0개면 `null`을 돌려주고 **단계를 실행하지 않는다**(`stage_run` 행이 생기지 않는다). 아니면 `run.run(alignStage, {...})` → 결과를 `ensurePrivateDir`된 `DATA_DIR/pdf-align/`에 JSON으로 쓰고(`.tmp`에 쓴 뒤 rename) `buildPdfContext`(assetOrder = PDF asset을 `part_index, created_at` 순으로 읽은 id 목록)를 돌려준다. 실패하면 `logger.warn("pdf align failed", { recording_id, err })` 후 `null`(녹음은 `partial`이 되지 않는다: 정렬은 보조 정보다).
7. `process-job.ts`: `config().pdf`가 참일 때 `ingestRecordingPdfs`(P3-03) 뒤, `runNotesPipeline` 앞에서 `const pdf = await alignRecording({...})`를 부르고 `pdf ?? undefined`를 `runNotesPipeline` 입력의 `pdf`로 넘긴다. 이 두 곳 외에 바꾸지 않는다.
8. `recordings.ts`: `getRecordingAlignment`: `config().pdf` 거짓이면 `notImplemented(req)`; `loadRecording(req, recording_id)`가 `Response`면 반환; `ok(req, readAlignment(id))`. `deleteRecording`의 v2 전용 분기와 `db.ts`의 `deleteLectureById`(P3-03이 `pdf_page` 삭제를 넣은 자리)에 `deleteAlignment(id)`를 더한다. `README.md` 표와 `NOT_YET`에서 `getRecordingAlignment`를 뺀다.

### `packages/harness/test/pdf-align.test.ts` (모델·네트워크 없음)
합성 데이터: 세그먼트 A(`idx 0, 0~60000ms`, "대칭키 암호의 운영 모드 ECB와 CBC를 설명합니다"), B(`idx 1, 130000~190000`, "해시 함수 SHA와 충돌 저항성을 봅니다"), C(`idx 2, 250000~300000`, "공개키 RSA 암호와 소인수분해 어려움"). 쪽: P1 "운영 모드 ECB CBC 블록 암호 대칭키", P2 "해시 함수 SHA 충돌 저항성 무결성", P3 "공개키 RSA 소인수분해 암호", P4 "점심 메뉴 김밥 라면 학생식당 안내"(모두 `asset_id "ast_a"`).

| 테스트 이름 | 준비 | 기대 |
|---|---|---|

## 10. 명세 작성자 메모

- `notes/*.ts`와 `process-job.ts`는 P1이 만든다. 작성 시점에 없어 입력 타입 이름과 호출 지점을 확인하지 못했다. 3절 `git grep`으로 찾고 계약 §1과 맞지 않으면 `BLOCKED`.
- **설계 보충**: CONTRACTS는 "align 결과는 단계 산출물(JSON)이고 `getRecordingAlignment`가 읽는다"고 하지만 하네스 산출물은 blob이고 작업이 끝나면 지워질 수 있다(`deleteArtifactsForJob`). 새 테이블도 계약에 없어서, 서버가 같은 JSON을 `DATA_DIR/pdf-align/<recording_id>.json`에 한 벌 더 쓰고 라우트가 그것을 읽는다.
- `pdf_pages` 라벨 규칙(1부터, 문맥 안 순서)은 `packages/domain/src/blocks.ts`의 설명을 따랐다. `[PDF n]` 머리 표기는 이 명세가 정했다.
- BM25 상수와 가중 방식은 이 명세가 정했다(CONTRACTS는 "2-gram BM25, 창마다 상위 3쪽"만 정한다). 토크나이저는 `@lectern/ask`의 `indexTokens`를 그대로 가져다 쓴다(하네스는 이미 `@lectern/ask`에 의존한다).
- 정렬 실패를 `partial`로 만들지 않기로 했다(보조 정보). 다르게 하려면 계약 결정이 필요하다.
