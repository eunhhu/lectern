# P2-03 웹: 회원가입, 이메일 인증, 비밀번호 재설정

> 등급: `basic` · 게이트: `full` · 의존: `P0-01` · 소유: `apps/web/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

`/app/signup`(회원가입 + 이메일 인증번호)과 `/app/reset`(비밀번호 재설정) 화면을 만든다(D-P2-1). 두 화면은 기존 v1 인증 엔드포인트를 그대로 쓴다. 로그인 화면 아래의 "기존 화면" 안내를 이 두 화면의 링크로 바꾼다. 마우스 없이 키보드만으로 가입 → 인증번호 입력 → 로그인이 된다.

### 서버 엔드포인트 (읽고 확인한 사실)

| 엔드포인트 | 요청 JSON | 성공 | 실패 본문 |
|---|---|---|---|
| `POST /api/auth/send-code` | `{ email, purpose: "signup" \| "reset" }` | 200 `{ ok, message }` | `{ error: "한국어 문구" }` (400/403/429) |
| `POST /api/auth/register` | `{ email, displayName, password, verificationCode }` | 201 `{ ok, token, user }` (로그인됨, 쿠키 설정) 또는 201 `{ ok, pendingApproval: true, message }` | `{ error }` |
| `POST /api/auth/reset-password` | `{ email, verificationCode, newPassword }` | 200 `{ ok, message }` | `{ error }` |

- 비밀번호는 6자 이상이다. 메일 키가 없는 환경(테스트)에서는 인증번호 없이도 가입된다. 키가 있으면 인증번호가 필수다(서버가 판단하고 문구를 돌려준다).

## 5. 단계

1. `client.ts` — 타입과 메서드 선언:
   ```ts
   export type RegisterResult = { kind: "signedIn"; user: SessionUser } | { kind: "pending"; message: string };
   // inside ApiClient:
   /** Mails a 6-digit code (POST /api/auth/send-code). Resolves with the server's sentence. */
   sendCode(email: string, purpose: "signup" | "reset"): Promise<string>;
   register(input: { email: string; displayName: string; password: string; verificationCode: string }): Promise<RegisterResult>;
   resetPassword(input: { email: string; verificationCode: string; newPassword: string }): Promise<string>;
   ```
2. `http/client.ts` — 반환 객체의 `logout` 아래에 구현. `auth()`로 JSON POST를 보내고 `!res.ok`면 `throw await errorFrom(res)`.
   - 본문 파서: `const V1MessageBody = z.object({ message: z.string().optional() });` 응답에서 `message ?? ""`.
   - `register`: 201 본문에 `pendingApproval === true`이면 `{ kind: "pending", message }`, 아니면 `{ kind: "signedIn", user: await sessionFrom(res) }`(본문의 `token`은 읽지 않는다).
   - 본문 키 이름은 서버 그대로: `email`, `displayName`, `password`, `verificationCode`, `newPassword`, `purpose`.
3. `fixture/client.ts` — 같은 이름의 메서드. `sendCode`는 `wait(() => "이메일로 6자리 인증번호를 발송했습니다. (10분간 유효)")`(`reset`은 `"가입된 계정이라면 이메일로 6자리 인증번호가 발송됩니다. (10분간 유효)"`). `register`: 이메일이 `data.me.email`이면 `ApiClientError(400, "bad_request", "이미 가입된 이메일 주소입니다.")`, 비밀번호가 6자 미만이면 `ApiClientError(400, "bad_request", "비밀번호는 최소 6자 이상이어야 합니다.")`, 인증번호가 `"000000"`이 아니면 `ApiClientError(400, "bad_request", "이메일 인증번호가 올바르지 않거나 만료되었습니다.")`, 아니면 `signedIn = true`로 두고 `{ kind: "signedIn", user: session() }`. `resetPassword`: 인증번호 `"000000"`이 아니면 `ApiClientError(400, "bad_request", "인증번호가 올바르지 않거나 만료되었습니다.")`, 새 비밀번호 6자 미만이면 위와 같은 6자 문구(`"새 비밀번호는 최소 6자 이상이어야 합니다."`), 아니면 `"비밀번호가 재설정되었습니다. 새 비밀번호로 로그인해주세요."`.
4. `router.tsx` — `loginRoute` 아래에 같은 모양으로 두 경로를 만들고(`getParentRoute: () => rootRoute`, `path: "/signup"`·`"/reset"`, `beforeLoad`는 세션이 있으면 `throw redirect({ href: "/" })`), `rootRoute.addChildren([loginRoute, signupRoute, resetRoute, authedRoute.addChildren(...)])`로 등록한다. 컴포넌트는 `SignupPage`, `ResetPage`.
5. `SignupPage.tsx` — `usePageTitle("회원가입")`. 구조는 `LoginPage`와 같다(`<main id="main" className={s.page}>` > `.card`). 보이는 문구:
   - `<h1>` `회원가입`, 안내 `이메일을 확인한 뒤 Lectern 계정을 만듭니다.`
   - 필드(`TextField` + `Label` + `Input`): `이메일`(`type="email"`, `autoComplete="username"`, `isRequired`, `autoFocus`), 같은 줄 버튼 `인증번호 받기`(`type="button"`), `인증번호`(`inputMode="numeric"`, `autoComplete="one-time-code"`, `maxLength=6`), `이름`(`autoComplete="name"`), `비밀번호`(`type="password"`, **`autoComplete="new-password"`**), `비밀번호 확인`(`autoComplete="new-password"`).
   - 제출 버튼 `가입하기`(진행 중 `가입하는 중…`), 아래 링크 `이미 계정이 있나요? 로그인`(`<Link to="/login">`).
   - 클라이언트 검사(서버 요청 전): 이메일 비었음 → `이메일을 입력하세요.`; 비밀번호 6자 미만 → `비밀번호는 6자 이상이어야 합니다.`; 두 비밀번호 다름 → `비밀번호가 서로 다릅니다.`. 인증번호는 비어 있어도 서버에 보낸다(메일 설정에 따라 서버가 판단).
   - `인증번호 받기`: 이메일이 비었으면 `이메일을 입력하세요.`, 아니면 `api.sendCode(email, "signup")`. 성공 문구는 서버가 준 문장을 `<p role="status">`로, 실패는 `<p className={s.error} role="alert">`(`errorMessage(err, "인증번호를 보내지 못했습니다. 잠시 뒤 다시 시도하세요.")`). 보내는 동안 버튼은 `isDisabled`, 성공 뒤 60초는 `다시 받기 (N초)`로 비활성(타이머는 `setInterval`, 정리 함수 필수).
   - 제출 성공: `kind === "signedIn"`이면 `queryClient.clear()`, `queryClient.setQueryData(queryKeys.session, user)`, `navigate({ href: "/", replace: true })`(LoginPage와 같은 순서). `kind === "pending"`이면 폼 자리에 `<p role="status">`로 서버 문구와 링크 `로그인 화면으로`.
   - 오류는 모두 `role="alert"` 한 곳(`.error`)에 `<Icon name="alert" />`와 함께. 서버 오류 문구는 그대로 보여 준다.
6. `ResetPage.tsx` — `usePageTitle("비밀번호 재설정")`. `<h1>` `비밀번호 재설정`, 안내 `가입한 이메일로 인증번호를 받아 새 비밀번호를 정합니다.` 필드: `이메일`, 버튼 `인증번호 받기`(`api.sendCode(email, "reset")`), `인증번호`, `새 비밀번호`(`autoComplete="new-password"`), `새 비밀번호 확인`(`autoComplete="new-password"`). 제출 `비밀번호 바꾸기`(진행 중 `바꾸는 중…`). 검사 문구는 가입 화면과 같되 비밀번호 칸은 `새 비밀번호는 6자 이상이어야 합니다.`. 인증번호가 비었으면 `인증번호를 입력하세요.`. 성공: 폼을 `<p role="status">`로 서버 문구(`비밀번호가 재설정되었습니다. 새 비밀번호로 로그인해주세요.`)와 `<Link to="/login">로그인하기</Link>`로 바꾸고 그 링크로 포커스를 옮긴다. 아래 링크 `로그인으로 돌아가기`.
7. `account.module.css` — `login.module.css`와 같은 클래스(`page`, `card`, `brand`, `title`, `lead`, `form`, `error`, `note`)에 `row`(이메일 칸 + 버튼, `display:flex; gap:var(--space-8); align-items:flex-end`), `status`(`color: var(--color-text-secondary)`)를 더한다. 토큰 변수만(`styles.test.ts`가 색 리터럴과 없는 변수를 막는다). 필요한 토큰 이름은 `login.module.css`에 있는 것만 쓴다.
8. `LoginPage.tsx` — `api.mode === "http"`일 때의 `.note`를 `<Link to="/signup">회원가입</Link> · <Link to="/reset">비밀번호를 잊으셨나요?</Link>`로 바꾼다(문구 `계정이 없거나 비밀번호를 잊었다면` 뒤에). `<a href="/?legacy=1">` 링크를 지운다. fixture 모드 문구는 그대로 두되 두 링크는 fixture에서도 보이게 한다.
9. 테스트 파일들을 6절대로 쓴다.

## 10. 명세 작성자 메모

- 서버 e2e에는 메일 키가 없어 인증번호 입력 경로를 끝까지 못 탄다. 인증번호 경로는 fixture e2e(`000000`)와 단위 테스트가 덮는다. 실제 메일 검증은 사용자가 한다.
- fixture 앱은 기본이 로그인 상태다. fixture e2e가 가입·재설정 화면에 가려면 먼저 로그아웃해야 한다(`organise.e2e.ts`에 로그아웃 절차가 있다. 정확한 버튼 이름은 거기서 복사한다).
- 가입 직후 계정이 승인 대기(`default_require_approval`)일 수 있다. 이 경우 `pending` 문구만 보여 준다.
