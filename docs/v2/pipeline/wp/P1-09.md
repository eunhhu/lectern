# P1-09 runNotesPipeline과 장애 주입

> 등급: `careful` · 게이트: `unit` · 의존: `P1-08` · 소유: `packages/harness/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

classify → structure → extract → verify → render를 한 작업(`JobRun`)으로 이어 붙이는 `runNotesPipeline`을 만든다. 같은 작업으로 다시 부르면 끝난 단계는 건너뛰고(재개), 단계가 실패해도 가능한 만큼의 결과(`partial`)를 돌려준다. 공급자 5xx·타임아웃, 프로세스 SIGKILL, 예산 초과, 취소를 주입하는 테스트로 동작을 못 박는다. 사용자가 보는 변화는 없다(서버 P1-11·P1-12가 쓴다).

## 5. 단계

1. `src/notes/pipeline.ts`.
   ```ts
   export interface NotesPipelineInput {
     transcript: Transcript;                       // harness Transcript (published form)
     filename: string | null;
     hint: { domain: RecordingDomain | null; folder_id: string | null };
     folders: { id: string; name: string }[];
     tags: string[];
     recordedAtMs: number;
     recordedAtSource: "client" | "media" | "upload";
     tz: string;
   }
   export type NotesStageName = "classify" | "structure" | "extract" | "verify" | "render";
   export interface NotesStageEvent { stage: NotesStageName; cacheHit: boolean; resumed: boolean; value: unknown }
   export interface NotesPipelineOptions {
     llm: LlmProvider; routing: Routing;
     onStage?: (event: NotesStageEvent) => void;
     templatesDir?: URL | string;                  // tests only; default TEMPLATES_DIR
   }
   export async function runNotesPipeline(run: JobRun, input: NotesPipelineInput, options: NotesPipelineOptions): Promise<NotesResult>;
   ```
2. 순서(각 단계 앞에서 `run.context.signal?.aborted`면 `HarnessError("canceled", "작업이 취소되었습니다.")`를 던진다. `run.run`도 같은 검사를 한다).
   1. `segments` = `transcript.segments`를 `CompactSegment`(`idx, start_ms, speaker, text`)로.
   2. **classify**: `run.run(classifyStage(llm, routing), { segments, filename, hint, folders, tags })`. `step` 도우미로 `onStage`를 부른다(`runTranscriptPipeline`과 같은 방식: `result.cacheHit`, `result.resumed`, `result.value`).
      - 실패하면: `kind`가 `config`/`canceled`/`budget`이면 그대로 던진다. 그 밖에는 **대체 분류**로 계속한다: `{ domain: hint.domain ?? "other", language: "ko", title: <파일명에서 마지막 확장자를 뗀 값을 60자까지, 없으면 "녹음">, participants: [], folder_suggestion: { folder_id: null, new_name: null }, tags: [], confidence: 0 }`.
   3. 템플릿: 대체 분류이면서 `hint.domain`이 있으면 `templateForDomain(hint.domain)`, 그 밖에는 `templateForDomain(classification.domain, classification.confidence)`. `loadTemplate(id, options.templatesDir)`.
   4. **structure**: `run.run(structureStage(llm, routing), { template, segments, language: classification.language })`. 실패는 **모두 던진다**(문서가 없다).
   5. **extract**: `run.run(extractStage(llm, routing), { template, segments, language, recordedAtMs, tz })`. 실패 중 `config`/`canceled`만 던진다. 나머지(`budget` 포함)는 `extract = {}`, `extractFailed = true`로 계속한다.
   6. **verify**: `run.run(verifyStage(llm, routing), { template, structure, extract, transcript: { segments: transcript.segments, gaps: transcript.gaps }, recordedAtMs, recordedAtSource, tz, language })`. 실패 중 `config`/`canceled`만 던진다. 나머지는 `verifyDocument(sameInput, null)`(수리 없이, 모델 호출 없이)을 직접 부른 결과를 쓰고 `verifyDegraded = true`.
   7. **render**(단계 아님, 순수): `renderDocumentMarkdown(verify.body, { title: classification.title, segments: transcript.segments.map(s => ({ idx: s.idx, start_ms: s.start_ms })) })`. `onStage({ stage: "render", cacheHit: false, resumed: false, value: markdown })`.
   8. 결과: `NotesResult.parse({ classification, template: { id: def.id, version: def.version }, body, markdown, events, action_items, report, partial: verify.partial || extractFailed || verifyDegraded })`.
3. `src/index.ts`에 export를 더한다.
4. 테스트 도우미 `test/notes-helpers.ts`(아래 값 그대로).
   ```ts
   export const RECORDED_AT_MS = Date.parse("2026-10-19T14:00:00+09:00");
   export function fixtureTranscript(): Transcript  // version 1, duration_ms 360000, failed_chunks [], gaps [],
   //   speakers [{label:"S1",confidence:1,basis:"single_chunk",segments:6,chars:60,members:[{chunk:0,label:"S1"}]}],

   //   ["오늘은 운영 모드를 봅니다","ECB는 위험합니다","다음 주 화요일까지 과제를 제출하세요","CBC는 IV가 필요합니다","시험에 나옵니다","수고하셨습니다"]

   export const classifyOut = { domain:"lecture", language:"ko", title:"암호 운영 모드", participants:[], folder_suggestion:{folder_id:null,new_name:null}, tags:["암호"], confidence:0.9 };
   export const structureOut = { sections: [
     { key:"summary", blocks:[{type:"paragraph",heading:null,text:"운영 모드를 다룬다",sources:["#1"],pdf_pages:[]}] },
     { key:"topics", blocks:[

       {type:"paragraph",heading:null,text:"CBC는 IV가 필요하다",sources:["#3"],pdf_pages:[]} ] } ] };
   export const extractOut = {
     events:[{title:"과제 제출",kind:"deadline",raw_expression:"다음 주 화요일까지",model_resolution:{date:"2026-10-27",time:null,end_time:null,all_day:true},evidence:["#2"],quote:"다음 주 화요일까지 과제를 제출하세요",confidence:0.9}],
     glossary:[{term:"IV",definition:"초기화 벡터",evidence:["#3"]}] };
   export function kindOf(req: LlmRequest<unknown>): "classify" | "structure" | "extract" | "repair"
   //   req.model === "gemini-3.5-flash-lite" → "classify"; req.instruction.includes("추출 항목:") → "extract"; req.instruction.includes("이유(issues)") → "repair"; else "structure"
   export function answerFor(req: LlmRequest<unknown>): unknown  // classifyOut / structureOut / extractOut by kindOf; repair → {fixes: []}
   ```
5. 자식 프로세스 `test/fixtures/notes-crash.ts`: 인자 `<dbPath> <blobDir> <jobId> <markerFile> <crashOn>`(`crashOn`은 `none|classify|structure|extract`). `Database`를 열고 `Harness({ db, blobDir, sleep: async () => {} })`, `ScriptedLlmProvider`의 답 함수에서 먼저 `appendFileSync(markerFile, kind[0])`(`c`/`s`/`e`) 한 다음 `kind === crashOn`이면 `process.kill(process.pid, "SIGKILL")`, 아니면 `answerFor(req)`. `runNotesPipeline`의 `onStage`로 모은 `{stage, cacheHit, resumed}` 목록과 `{ template: result.template, partial: result.partial }`를 `JSON.stringify`해 stdout에 쓴다. (`transcript-crash.ts`처럼 `scope: "ws"`.)

## 10. 명세 작성자 메모

- 계약은 "취소 `signal`"을 파이프라인 인자로 적었지만 실제 `JobRunContext.signal`이 이미 있고 `JobRun.run`이 검사하므로 별도 옵션을 두지 않았다.
- "단계 실패 시 어디까지 계속하나"는 계약에 없다(D-P1-2는 서버 상태만 정한다). 명세 작성자가 정했다: classify 실패는 대체 분류로 계속, structure 실패는 중단, extract·verify 실패는 `partial`로 계속, `config`/`canceled`는 항상 중단. 오케스트레이터가 다르게 정하면 5절 2번만 바꾸면 된다.
- 예산이 단계 **도중**(structure의 map 호출들 사이)에 바닥나는 경우는 막지 못한다(`JobRun.run`은 단계 시작에만 예산을 본다).
- 출력 `NotesResult`에는 render 입력(`transcript.segments`의 시각)이 쓰이지만 결과에 전사를 넣지 않는다.
- 크래시 테스트의 마지막 행 기대값은 `"csse"`다(structure를 죽이는 첫 실행의 marker는 `cs`, 재실행에서 structure `s`, extract `e`).
