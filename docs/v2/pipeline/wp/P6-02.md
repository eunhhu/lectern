# P6-02 서버: APNs 발송기

> 등급: `careful` · 게이트: `full` · 의존: `P6-01`, `P1-12` · 소유: `apps/server/`, `apps/worker/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

녹음을 처리하는 동안 iPhone의 Live Activity가 단계(전사 → 구조화 → 추출 → 검증)를 따라 바뀌고, 끝나면 "문서가 준비되었습니다" 알림이 온다. 서버는 단계가 바뀔 때와 끝났을 때만 보낸다. `LECTERN_APNS=0`이거나 키가 없으면 Apple에 연결하지 않는다. 테스트는 로컬 가짜 APNs만 쓴다.

## 5. 단계

1. `apns/jwt.ts`
   ```ts
   export interface ApnsAuth { teamId: string; keyId: string; keyFile: string }
   export function apnsAuth(): ApnsAuth | null                      // null when LECTERN_APNS is off or any value/file is missing
   export async function apnsProviderToken(auth: ApnsAuth, now?: number): Promise<string>   // cached per keyId; a new one after 50 minutes
   export function resetApnsTokenCache(): void                      // tests
   ```
   헤더 `{ alg: "ES256", kid: keyId }`, 클레임 `{ iss: teamId, iat: <초> }`. 키 파일은 처음 한 번만 읽는다. 키 내용과 토큰을 로그에 남기지 않는다.
2. `apns/payload.ts` (순수 함수. 스냅샷 테스트의 대상)
   ```ts
   export interface ContentState { stage: string; stage_label: string; progress: number | null; recording_id: string; document_ready: boolean }   // D-P6-12
   export const STAGE_LABEL: Record<string, string>
   export function liveActivityUpdate(state: ContentState, nowSec: number): object
   export function liveActivityEnd(state: ContentState, nowSec: number): object
   export function liveActivityStart(state: ContentState, attrs: { recording_id: string; title: string }, nowSec: number): object
   export function documentReadyAlert(p: { recordingId: string; title: string; url: string; partial: boolean }): object
   export function processingFailedAlert(p: { recordingId: string; title: string; url: string }): object
   ```
   - `STAGE_LABEL`: `ingest` → `준비 중`, `transcribe` → `전사 중`, `align`·`speakers` → `전사 정리 중`, `classify` → `분류 중`, `structure` → `노트 구성 중`, `extract` → `일정·할 일 찾는 중`, `verify` → `검증 중`, `publish` → `마무리 중`, 완료 → `문서 준비됨`, 실패 → `처리 실패`. `StageName`에 있는데 표에 없는 이름은 `처리 중`.
   - 업데이트: `{ "aps": { "timestamp": nowSec, "event": "update", "content-state": state } }`
   - 종료: `{ "aps": { "timestamp": nowSec, "event": "end", "content-state": state, "dismissal-date": nowSec + 3600 } }`
   - 시작(push-to-start): `{ "aps": { "timestamp": nowSec, "event": "start", "content-state": state, "attributes-type": "ProcessingActivityAttributes", "attributes": attrs, "alert": { "title": "녹음을 처리하고 있습니다", "body": attrs.title } } }`
   - 준비 알림: `{ "aps": { "alert": { "title": partial ? "전사가 준비되었습니다" : "문서가 준비되었습니다", "body": title }, "sound": "default", "thread-id": "recording-<id>", "interruption-level": "active" }, "recording_id": id, "url": url }`
   - 실패 알림: 제목 `녹음을 처리하지 못했습니다`, 나머지는 같은 모양.
   - 제목은 100자로 자른다. 페이로드가 4096바이트를 넘지 않는다(테스트).
3. `apns/client.ts`
   ```ts
   export interface ApnsResult { status: number; reason: string | null; apnsId: string | null }
   export interface ApnsClient { send(p: { token: string; topic: string; pushType: "liveactivity" | "alert"; priority: 5 | 10; expiration: number; payload: object; providerToken: string }): Promise<ApnsResult>; close(): void }
   export function createApnsClient(origin?: string): ApnsClient   // default by config().apns.env
   ```
   - 기본 호스트: `https://api.push.apple.com`(production), `https://api.sandbox.push.apple.com`(sandbox). `origin`은 테스트가 가짜 주소를 넣는 자리다.
   - `node:http2`의 `connect(origin)`. 연결은 하나를 재사용하고, 닫혔거나 오류가 났으면 다음 `send` 때 다시 연다. 60초 동안 쓰지 않으면 닫는다(`unref()`).
   - 요청: `:method POST`, `:path /3/device/<token>`, `authorization: bearer <providerToken>`, `apns-topic`, `apns-push-type`, `apns-priority`, `apns-expiration`, `content-type: application/json`. 본문은 JSON.
   - 응답 본문이 있으면 `{ "reason": "…" }`에서 `reason`을 읽는다. 요청 하나의 제한 시간은 10초다(넘으면 `status: 0`, `reason: "timeout"`).
   - **`config().apns.enabled`가 거짓이면 `createApnsClient`를 부르는 코드가 실행되지 않아야 한다**(연결 시도 자체가 없다).
4. `apns/notify.ts`
   ```ts
   export async function notifyStage(recordingId: string, stage: string, progress: number | null): Promise<void>
   export async function notifyFinished(recordingId: string, outcome: "ready" | "partial" | "failed"): Promise<void>
   export function setApnsClientForTests(client: ApnsClient | null): void
   ```
   공통: `apnsAuth()`가 `null`이면 바로 돌아간다. 두 함수는 **절대 던지지 않는다**(전체 `try/catch`, `logger.warn`에 녹음 id와 상태 코드만). 호출하는 쪽은 `void notifyStage(…)`로 기다리지 않는다(푸시 때문에 처리가 느려지거나 실패하면 안 된다).
   - `notifyStage`
     - 같은 녹음에 **직전에 보낸 단계와 같으면 보내지 않는다**(모듈 안의 `Map<recordingId, stage>`. 완료 때 지운다). 진행률만 바뀐 것은 보내지 않는다.
     - 받는 곳 ①: 그 녹음의 `live_activity` 중 `state = 'active'`인 행의 `push_token` → `liveActivityUpdate`. 토픽 `<APNS_TOPIC_IOS>.push-type.liveactivity`, `pushType: "liveactivity"`, `priority: 5`, `expiration: now + 3600`.
     - 받는 곳 ②(push-to-start): 녹음을 만든 사용자의 `push_device`(`platform = 'ios'`) 중 `push_to_start_token`이 있고 그 기기에 이 녹음의 `live_activity` 행이 **없는** 것 → 이 녹음에서 처음 한 번만 `liveActivityStart`. 같은 토픽·푸시 유형, `priority: 10`.
   - `notifyFinished`
     - 그 녹음의 활성 `live_activity` → `liveActivityEnd`(`stage_label`은 `문서 준비됨`/`처리 실패`, `document_ready`는 `ready`·`partial`일 때 참) 뒤 행을 `ended`로.
     - 녹음을 만든 사용자의 모든 iOS `push_device` → 알림(`documentReadyAlert` 또는 `processingFailedAlert`). 토픽 `<APNS_TOPIC_IOS>`, `pushType: "alert"`, `priority: 10`, `expiration: now + 86400`. `url`은 `${config().baseUrl}/app/recordings/<id>`.
   - 응답 처리(모든 발송에 공통)
     - `200`: 끝.
     - `410`, 또는 `400`이면서 `reason`이 `BadDeviceToken`·`DeviceTokenNotForTopic`: 기기 토큰이면 `deletePushDeviceByToken`, Live Activity 토큰이면 그 `live_activity` 행을 `ended`로. 재시도하지 않는다.
     - `403`이면서 `reason`이 `ExpiredProviderToken`: 토큰 캐시를 버리고 한 번 다시 보낸다.
     - `429`, `5xx`, `status: 0`: 1초, 4초 뒤 두 번까지 다시 보낸다(기다림은 주입 가능한 `sleep`). 그래도 실패면 버린다.
     - 그 밖의 `4xx`: 버리고 `logger.warn`.
   - 토픽이 없으면(`APNS_TOPIC_IOS` 없음) 아무것도 보내지 않는다. `platform = 'macos'` 기기에는 보내지 않는다.
5. 호출 지점
   - `process-job.ts`의 `emitStage(stage)` 안에서 `void notifyStage(recordingId, stage, progress)`.
   - 녹음 상태가 `ready`·`partial`·`failed`로 정해지는 곳에서 `void notifyFinished(recordingId, outcome)`. 취소된 작업은 `failed`로 보내지 않고 Live Activity만 끝낸다(알림 없음): `notifyFinished`에 넷째 값 `"canceled"`를 받게 하지 말고, 취소 경로에서는 `endAllLiveActivities(recordingId)`(이 파일에 둔다. `liveActivityEnd`를 `stage_label: "취소됨"`으로 보낸다)를 부른다.
   - `regenerate-job.ts`: 끝났을 때만 `notifyFinished`.
6. `test/fakes/apns.ts`
   ```ts
   export interface FakeApns { origin: string; requests: { path: string; headers: Record<string, string>; body: any }[];
     respondWith(match: string | RegExp, response: { status: number; reason?: string }, times?: number): void;   // matched against the device token in the path
     close(): Promise<void> }
   export async function startFakeApns(): Promise<FakeApns>   // node:http2 createServer() on 127.0.0.1, cleartext
   ```
   테스트용 `.p8`은 테스트가 P-256 키를 만들어 임시 디렉터리에 쓴다(P5-05와 같은 방법). 저장소에 키 파일을 넣지 않는다.

## 10. 명세 작성자 메모

- Bun의 `node:http2` 클라이언트가 Apple의 실제 서버(TLS + ALPN h2)와 붙는지는 이 작업으로 확인되지 않는다. 가짜는 평문 h2다. Pi에서의 실제 확인이 STATUS "실측 필요"에 있다.
- 외부 워커(`LECTERN_WORKER_MODE`)가 작업을 돌리면 발송도 워커 프로세스에서 일어난다. "직전에 보낸 단계" 기억은 프로세스 메모리라서, 작업이 다른 프로세스에서 재개되면 같은 단계가 한 번 더 갈 수 있다. 받아들인다.
- push-to-start의 `attributes-type` 이름(`ProcessingActivityAttributes`)은 앱(P6-A11)의 타입 이름과 같아야 한다. CONTRACTS 보충 절에 적었다.
