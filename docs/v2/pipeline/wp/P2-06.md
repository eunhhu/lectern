## 5. 단계

1. `ApiClient`:
   ```ts
   deleteRecordingAudio(recordingId: string): Promise<void>;
   reprocessRecording(recordingId: string, body: ReprocessRequest): Promise<ReprocessResponse>;
   exportDocument(documentId: string): Promise<{ filename: string; blob: Blob }>;
   listAskSuggestions(query: ListAskSuggestionsParams): Promise<AskSuggestions>; // { workspace_id, scope_type, scope_id? }
   ```
   `ListAskSuggestionsParams`는 `types.ts`에서 `z.infer<typeof ListAskSuggestionsQuery>`로 정의한다.
2. `http/client.ts`:
   - `deleteRecordingAudio: (id) => call("deleteRecordingAudio", { params: { recording_id: id } })`
   - `reprocessRecording: (id, body) => call("reprocessRecording", { params: { recording_id: id }, body })` — 이 라우트는 200과 202 둘 다 `ReprocessResponse`로 파싱한다(`call`은 `route.responses[res.status].schema`를 쓴다. 이미 둘 다 정의돼 있다).
   - `listAskSuggestions: (q) => call("listAskSuggestions", { query: q })`
   - `exportDocument`: `call`을 쓰지 않는다(JSON이 아니다). `send(routeUrl(ROUTES_BY_OPERATION.exportDocument!, { document_id }, { format: "md" }), { method: "GET" })`. `!res.ok`면 `throw await errorFrom(res)`(401이면 `signalUnauthorized()`). 파일 이름은 `Content-Disposition`의 `filename*=UTF-8''…`를 `decodeURIComponent`로 읽고, 없으면 `note.md`. 반환 `{ filename, blob: await res.blob() }`.
3. `fixture/client.ts`:
   - `deleteRecordingAudio`: 해당 녹음의 `data.assets` 중 `kind`가 `audio`로 시작하는 것을 지운다(없어도 성공). 없는 녹음은 `notFound("녹음")`.
   - `reprocessRecording`: 녹음이 없으면 404. `mode:"document"`이고 전사가 없으면 `ApiClientError(409,"conflict","전사가 없는 녹음이라 문서만 다시 만들 수 없습니다. 전체 재처리를 선택하세요.")`. 추정치 `{ estimated_microusd: mode==="full" ? Math.ceil(duration_ms/3_600_000*120_000) : 2_000, audio_ms: mode==="full" ? duration_ms ?? 0 : 0, within_quota: true }`. `dry_run`이면 `{ estimate, job: null }`. 아니면 녹음 `status`를 `"queued"`로 바꾸고 `{ estimate, job: <가짜 Job> }`(`Job` 스키마를 만족하는 객체를 만든다. 같은 파일에서 업로드 완료가 만드는 job 객체를 본보기로 쓴다).
   - `exportDocument`: 문서를 찾고(없으면 404) `{ filename: `${title}.md`, blob: new Blob([rendered_md + "\n"], { type: "text/markdown" }) }`.
   - `listAskSuggestions`: 항상 `throw new ApiClientError(501, "not_implemented", "아직 준비 중인 기능입니다.")`. (fixture 화면은 지금의 규칙 그대로 보인다. 기존 e2e를 바꾸지 않는다.)
4. `lib/download.ts`: `saveBlob(blob, filename)` — `URL.createObjectURL`, 숨은 `<a download>`를 만들어 `click()`, 바로 `revokeObjectURL`(`setTimeout 0`). 새 스타일을 쓰지 않는다(`a.hidden = true`).
5. `lib/ask-suggestions.ts`: `export function pickSuggestions(remote: string[] | undefined, fallback: string[]): string[]` — `remote`가 비어 있지 않으면 `remote.slice(0, 6)`, 아니면 `fallback`.
6. `queries.ts`: `useAskSuggestions(ws, scope)`를 고친다. 기존 계산(`fallback`)은 그대로 두고 추가로
   ```ts
   const remote = useQuery({
     queryKey: ["ask-suggestions", ws, scope.kind, scope.kind === "recording" ? scope.recording_id : scope.kind === "folder" ? scope.folder_id : ""] as const,
     queryFn: () => api.listAskSuggestions({ workspace_id: ws, scope_type: scope.kind, ...(scope.kind === "workspace" ? {} : { scope_id: scope.kind === "recording" ? scope.recording_id : scope.folder_id }) }).then((r) => r.suggestions),
     retry: false, staleTime: 5 * 60_000,
   });
   return pickSuggestions(remote.data, fallback);
   ```
   (`AskScope`의 폴더 필드 이름은 `packages/domain/src/api/ask.ts`의 `AskFolderScope`에서 확인해 맞춘다.) 오류(501 포함)는 조용히 `fallback`이다. 화면에 오류를 띄우지 않는다.
   - `useReprocessEstimate(recordingId, mode, enabled)`: `useQuery`, 키 `["reprocess-estimate", recordingId, mode]`, `queryFn: () => api.reprocessRecording(recordingId, { mode, dry_run: true })`, `retry: false`, `gcTime: 0`, `staleTime: 0`.
   - `useReprocess(recordingId)`: `useMutation`(`mode`을 받아 `api.reprocessRecording(recordingId, { mode })`), `onSettled`에서 `queryKeys.recording(recordingId)`와 `["recordings", ws]`는 `queryKeys.recordings(ws)` 무효화(`ws`는 인자).
   - `useDeleteAudio(recordingId, ws)`: 같은 무효화.
7. `ReprocessDialog.tsx` — 속성 `{ recording: Recording; mode: "full" | "document"; isOpen: boolean; onOpenChange(open: boolean): void }`. `ModalDialog`:
   - 제목 `다시 처리`(full) / `문서만 다시 만들기`(document). 본문 설명: full `원본 오디오로 전사부터 모든 단계를 다시 실행합니다. 지금 문서는 버전 이력에 남습니다.` / document `저장된 전사로 문서만 다시 만듭니다. 전사는 바뀌지 않고, 지금 문서는 버전 이력에 남습니다.`
   - 열려 있는 동안 `useReprocessEstimate`. 로딩 `예상 비용을 계산하는 중…`(`aria-busy`). 성공: `예상 비용 {비용}` 과 (full이면) `처리할 오디오 {formatDuration(audio_ms)}`. 비용 표기: `estimated_microusd`를 `/1_000_000`해 `$0.00` 형식(소수 둘째 자리), 0.01 미만이면 `$0.01 미만`, 0이면 `무료`. `within_quota === false`면 `role="alert"` `AI 사용 한도를 넘어 지금은 실행할 수 없습니다.`이고 확인 버튼 비활성. 실패: `role="alert"`에 `errorMessage(err)`(서버가 준 409 문구가 그대로 나온다), 확인 버튼 비활성.
   - 푸터: `취소`, `다시 처리`(document는 `문서 다시 만들기`) primary — **추정이 성공했고 `within_quota`일 때만 활성**. 누르면 `useReprocess` 실행(진행 중 `요청하는 중…`), 성공이면 닫고 toast `다시 처리를 시작했습니다.` 설명 `끝나면 이 화면에 바로 표시됩니다.`; 실패는 `toastError("다시 처리를 시작하지 못했습니다.", err)`.
   - 비용 확인 없이는 실제 요청이 나갈 수 없어야 한다: 확인 버튼 핸들러 첫 줄에서 `if (!estimate.data?.estimate.within_quota) return;`.
8. `DeleteAudioDialog.tsx` — `ModalDialog role="alertdialog"` 제목 `오디오만 삭제할까요?`, 본문 `녹음 파일만 서버에서 지웁니다. 전사와 문서는 남지만 오디오를 다시 들을 수 없고, 전체 다시 처리도 할 수 없습니다. 되돌릴 수 없습니다.` 버튼 `취소`, `오디오 삭제`(danger). 성공 toast `오디오를 삭제했습니다.`, 실패 `toastError("오디오를 삭제하지 못했습니다.", err)`.
9. `RecordingPage.tsx` — 메뉴를 이렇게 만든다(기존 항목은 그대로, 새 항목을 `태그…`와 `삭제…` 사이에, 위쪽 구분은 `<Separator>`가 있으면 쓴다):
   `다시 처리…`(id `reprocess`, 아이콘 `forward`), `문서만 다시 만들기`(id `regenerate`, 아이콘 `spark`), `오디오만 삭제…`(id `delete-audio`, 아이콘 `trash`), `Markdown 내려받기`(id `export`, 아이콘 `copy`는 어색하므로 `forward` 대신 `back`을 쓰지 말고 아이콘 없이 텍스트만).
   - `Menu`의 `disabledKeys`: `detail.assets`에 `kind`가 `audio`로 시작하는 것이 없으면 `delete-audio`와 `reprocess`; `detail.documents`가 비었으면 `export`와 `regenerate`; `rec.status`가 `processing`/`queued`면 `reprocess`, `regenerate`.
   - `onAction`: 기존 `move|tag|delete`는 지금처럼 `setAction`. `reprocess`/`regenerate`는 `setReprocess("full" | "document")`, `delete-audio`는 `setDeleteAudio(true)`, `export`는 `api.exportDocument(detail.documents[0].id)`를 불러 `saveBlob(blob, filename)`(실패 `toastError("내려받지 못했습니다.", err)`).
   - 대화상자 두 개를 `dialogs` 변수에 넣는다.
   - 같은 메뉴를 P2-05(공유…)도 고친다. 충돌 시 두 쪽 항목과 `onAction` 분기를 모두 남긴다.
