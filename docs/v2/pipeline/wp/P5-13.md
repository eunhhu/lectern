## 1. 목표

새 관리자 콘솔에 나머지 화면을 넣는다: 저장소(압축·정리·보존 정책 적용), 운영(유지보수, 백업, 배포, 서버, 데이터베이스, v1 작업), 설정, 감사 로그, 개요의 "확인 필요"와 "최근 활동", 콘솔 껍데기(탭의 개수·점, 명령 팔레트, 단축키, 자동 갱신), v1 사용량(P6-C 뒤). 그리고 P5-16이 만든 대조표 `PARITY-ADMIN.md`의 남은 행(`P5-13` 몫)을 모두 채운다. 이 대조표가 다 채워져야 옛 콘솔을 지울 수 있다(P5-14).

이 작업은 처음 명세에서 둘로 나뉜 뒤쪽이다(CONTRACTS S-33). 멤버·녹음 화면과 대조표의 왼쪽은 P5-16이 했다.

## 5. 단계

1. `api/admin.ts`에 메서드를 더한다. 메서드·본문·응답 모양은 서버 코드에서 읽은 그대로다.
   ```ts
   storage(): Promise<AdminStorage>;                                   // GET /api/admin/storage
   compactAll(dryRun: boolean): Promise<CompactResponse>;              // POST /api/admin/storage/compact { all: true, dryRun }
   gcStorage(dryRun: boolean): Promise<GcResponse>;                    // POST /api/admin/storage/gc { dryRun }
   applyRetention(dryRun: boolean): Promise<RetentionResponse>;        // POST /api/admin/storage/retention { dryRun }
   ops(): Promise<AdminOps>;                                           // GET /api/admin/ops
   runMaintenance(): Promise<MaintenanceResult>;                       // POST /api/admin/maintenance/run (409 = 이미 실행 중)
   settings(): Promise<AdminSettings>;                                 // 개요 응답의 settings (GET 경로가 없다)
   saveSettings(patch: Partial<AdminSettings>): Promise<AdminSettings>; // PATCH /api/admin/settings
   audit(q: { action?: string; q?: string; cursor?: string; limit?: number }): Promise<AdminAuditPage>;  // GET /api/admin/audit
   v1Usage(q: { from?: string; to?: string }): Promise<V1UsagePage>;   // GET /api/v2/admin/v1-usage (P6-C 뒤)
   ```
2. 화면(탭 이름과 경로)
   - `저장소` `/admin/storage`: 수치(오디오, 업로드 폴더, 디스크 여유와 막대, 압축으로 절약), 압축 카드(자동 압축 켜짐·꺼짐, ffmpeg 없음, 비트레이트, 대상, 예상 절약, 완료, 진행), 회수 가능 공간(실패한 강의의 오디오, 보존 기간이 지난 오디오, 고아 파일, 휴지통), 형식별·상태별·사용자별 막대(글자로도 수치), 가장 큰 녹음(압축·오디오 삭제는 P5-16의 메서드). 버튼 `전체 압축`, `정리`(보존 정책 적용), `휴지통으로 이동`(고아 파일). **세 버튼은 옛 콘솔처럼 미리보기(`dryRun: true`)를 먼저 보내** 대상 수·용량을 확인 대화상자에 보이고, 확인하면 실제 요청을 한 번 보낸다. 대상이 없으면 대화상자 없이 토스트(`압축할 녹음이 없습니다.` 등). 결과는 토스트.
   - `운영` `/admin/ops`: 유지보수(주기, 마지막 실행 시각과 요약, 실행 중 표시)와 버튼 `유지보수 지금 실행`(확인 대화상자의 항목 목록 → 실행 → 결과 대화상자: 만료 세션, 인증 코드, 감사 로그 정리, 고아 파일, 임시 파일, 보존 정책, 실패한 강의, 백업, WAL, 걸린 시간, 오류). 백업(최신 파일·크기·시각, 보관 수·최대·합계). 배포(진행 중, 성공·실패, 커밋, 시각, 오류). 서버(커밋, 가동 시간, 메모리, Bun, 플랫폼, PID, ffmpeg, 요청·5xx). 데이터베이스(크기, WAL, 멤버·강의·세션·감사 로그 수). v1 작업(`ops.jobs`: 실행 중·대기·24시간 완료·실패·평균 처리 시간, 동시 실행 수, 실행 중·대기·최근 완료 목록). 응답에 없는 항목은 그리지 않는다.
   - `설정` `/admin/settings`: 옛 콘솔의 설정 폼과 같은 항목 — 가입 정책(공개 회원가입, 가입 승인 필요, 기본 역할, 서버 AI 키 기본 허용, 기본 오디오 한도 MB), 스토리지(자동 압축, 압축 비트레이트와 "녹음 1시간당 약 N MB"), 보존 정책(완료된 강의의 오디오·실패한 강의·감사 로그: 각각 켜기 스위치와 일수, 영구 삭제 경고). 바뀐 것이 있을 때만 `저장`이 켜지고 `되돌리기`가 보인다. 저장하지 않고 다른 탭으로 가면 묻는다. 저장 토스트 `설정을 저장했습니다.` 설정에는 비밀 값이 없다.
   - `감사 로그` `/admin/audit`: 표(시각, 행위자, 동작, 대상, 상세). 동작 접두어 필터(옛 콘솔의 `AUDIT_PREFIXES`, 개수)와 검색(250ms 뒤). 둘 다 주소에 남는다. 더 보기(`cursor`). 줄을 누르면 상세(시각, 동작, 수행자, 대상 — 사용자·녹음이면 그 상세 링크, ID, 상세 전문).
   - **개요** 보탬: `확인 필요`(가입 승인 대기와 `승인`, 분석 실패 녹음과 `재시도`, 디스크 부족, 백업 없음·오래됨과 `유지보수 실행`, ffmpeg 없음, 압축 가능한 녹음, 유지보수 오류, 최근 배포 실패)와 `최근 활동`(감사 로그 10건, `감사 로그 전체 보기`). 오디오 용량 카드에 디스크 여유.
   - **녹음 상세** 보탬: 진행 중 작업 상자(`ops.jobs`에서 그 강의의 실행 중·대기 작업).
   - **껍데기**: 관리 탭의 개수·점(사용자 수와 승인 대기 점, 녹음 수와 오류 점, 실행·대기 작업 수, 디스크 부족 점). 명령 팔레트(⌘K)에 관리 화면 이동과 명령(유지보수, 전체 압축, 고아 파일 정리, 보존 정책 적용, 새 사용자) — 앱의 팔레트를 쓰고 운영자에게만 보인다. 개요·운영은 5초마다 다시 읽는다(창이 보일 때만).
   - `v1 사용량` `/admin/v1-usage`(P6-C가 병합됐을 때만): 날짜 범위(기본 최근 30일), 표(날짜, 경로, 클라이언트, 건수), 클라이언트별 합계. 안내 `v1 API를 아직 쓰는 클라이언트가 있는지 확인하는 화면입니다. 건수가 0이 된 뒤에 v1 차단을 켭니다.`
3. 되돌릴 수 없거나 무거운 동작(GC, 압축, 보존 정책, 유지보수)은 모두 확인 대화상자를 거치고, 실행 중에는 버튼이 꺼지고 `실행 중…`으로 바뀐다. 실제 요청은 한 번만 보낸다.
4. 대조표를 완성한다. `P5-13` 몫의 모든 행에 새 화면 경로와 e2e 이름을 채운다. `없음`이 한 행이라도 남으면 이 작업은 끝난 것이 아니다. `일부러 뺌`은 사유를 쓰고 보고의 `DEVIATIONS`에도 적는다(사용자가 P5-14를 승인할 때 읽는다). 옛 콘솔의 단축키(`G`+글자 이동, `C`, `J`/`K` 줄 이동, `?`)는 앱의 단축키 체계(P2)와 겹치지 않는 것만 옮기고, 나머지는 사유와 함께 `일부러 뺌`.
5. fixture에 위 화면의 데이터를 넣는다(백업 3개, 감사 로그 30행 이상, 설정 값, 저장소 수치, v1 작업).

## 10. 명세 작성자 메모

- 처음 명세의 `setRetention(body)`와 "settings: blank secret means unchanged"는 옛 콘솔과 맞지 않아 고쳤다. `/api/admin/storage/retention`은 설정 폼이 아니라 `{ dryRun }`을 받는 실행이고, 보존 일수는 설정(`PATCH /api/admin/settings`)의 키다. 설정에는 비밀 값이 없다("비우면 그대로"는 P5-16의 사용자 비밀번호가 맡는다). 설정을 읽는 GET도 없다.
- 압축·정리·보존은 옛 콘솔이 미리보기 요청을 먼저 보낸다. "요청 1회"는 실제 실행 요청의 수다.
- 옛 콘솔의 `작업` 보기는 `/api/admin/ops`의 v1 큐(distill, compact)다. P5-12의 `작업` 탭은 v2 작업 목록이므로, v1 큐는 `운영`에 둔다.
- v1 사용량 화면은 P6-03이 데이터를 만들어야 뜻이 있다. P6-C 전에 이 작업이 돌면 그 화면은 빠지고, P6-03 뒤에 누군가 더해야 한다(STATUS "넘겨받은 요청"에 적는다).
