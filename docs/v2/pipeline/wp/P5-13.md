새 관리자 콘솔에 나머지 화면을 넣는다: 저장소(압축·정리·보존), 운영(유지보수 실행, 백업, 배포 기록), 설정, 감사 로그, v1 사용량. 그리고 옛 콘솔의 모든 기능이 새 콘솔 어디에 있는지 적은 대조표를 만든다. 이 대조표가 다 채워져야 옛 콘솔을 지울 수 있다(P5-14).

## 5. 단계

1. **먼저 대조표의 왼쪽을 만든다.** `ui.ts`의 관리자 콘솔 코드를 처음부터 끝까지 읽고, 화면에 보이는 것과 누를 수 있는 것을 하나도 빼지 않고 `PARITY-ADMIN.md`에 적는다. 형식:
   ```markdown
   | # | 옛 콘솔 기능 | 옛 요청 (메서드 경로) | 새 화면 | e2e 이름 | 상태 |
   |---|---|---|---|---|---|
   | 1 | 개요: 사용자 수 | GET /api/admin/overview | /app/admin | admin "overview cards" | 있음 |
   ```
   상태는 `있음`, `없음`, `일부러 뺌(사유)` 셋 중 하나다. P5-12가 만든 화면의 행도 넣는다.
2. `api/admin.ts`에 메서드를 더한다. 이름은 다음을 쓰고, 메서드·본문·응답 모양은 서버 코드에서 읽은 그대로다.
   ```ts
   storage(): Promise<AdminStorage>;                    // GET /api/admin/storage
   compactStorage(body?: Record<string, unknown>): Promise<unknown>;   // POST /api/admin/storage/compact
   gcStorage(body?: Record<string, unknown>): Promise<unknown>;        // POST /api/admin/storage/gc
   setRetention(body: Record<string, unknown>): Promise<unknown>;      // /api/admin/storage/retention
   ops(): Promise<AdminOps>;                            // GET /api/admin/ops
   runMaintenance(): Promise<unknown>;                  // POST /api/admin/maintenance/run
   settings(): Promise<AdminSettings>;                  // GET /api/admin/settings
   saveSettings(patch: Record<string, unknown>): Promise<AdminSettings>;
   audit(q: Record<string, string>): Promise<AdminAuditPage>;          // GET /api/admin/audit
   recordings(q: Record<string, string>): Promise<AdminLecturePage>;   // GET /api/admin/lectures
   v1Usage(q: { from?: string; to?: string }): Promise<V1UsagePage>;   // GET /api/v2/admin/v1-usage (after P6-C)
   ```
3. 화면(탭 이름과 경로)
   - `저장소` `/admin/storage`: 용량 요약(디스크 여유, 오디오·아카이브·DB 크기 등 응답에 있는 것). 버튼 `오디오 압축 실행`, `정리(GC) 실행`. 보존 설정 폼(응답에 있는 항목 그대로). 실행 버튼은 확인 대화상자를 거친다: `지금 실행할까요? 끝날 때까지 서버가 느려질 수 있습니다.` 결과는 토스트와 화면의 "마지막 실행" 줄.
   - `운영` `/admin/ops`: 유지보수 마지막 실행 시각·결과와 버튼 `유지보수 지금 실행`. 백업 목록(시각, 크기, 검증 결과). 배포 기록(버전, 시각, 결과). 응답에 없는 항목은 그리지 않는다.
   - `설정` `/admin/settings`: 옛 콘솔의 설정 폼과 같은 항목. 저장 토스트 `설정을 저장했습니다.` 비밀 값(API 키 등)을 응답이 가려서 주면 가린 채로 보이고, 빈 입력은 "바꾸지 않음"이다.
   - `감사 로그` `/admin/audit`: 표(시각, 행위자, 동작, 대상, 상세). 필터는 옛 콘솔과 같은 것. 더 보기.
   - `녹음` `/admin/recordings`: 전체 녹음 표(소유자, 제목, 상태, 길이, 만든 시각)와 옛 콘솔에 있는 동작.
   - `v1 사용량` `/admin/v1-usage`(P6-C가 병합됐을 때만): 날짜 범위(기본 최근 30일), 표(날짜, 경로, 클라이언트, 건수), 클라이언트별 합계. 안내 `v1 API를 아직 쓰는 클라이언트가 있는지 확인하는 화면입니다. 건수가 0이 된 뒤에 v1 차단을 켭니다.`
4. 되돌릴 수 없거나 무거운 동작(GC, 압축, 유지보수, 삭제)은 모두 확인 대화상자를 거치고, 실행 중에는 버튼이 꺼지고 `실행 중…`으로 바뀐다. 같은 요청을 두 번 보내지 않는다.
5. 대조표를 완성한다. 모든 행에 새 화면 경로와 e2e 이름을 채운다. `없음`이 한 행이라도 남으면 이 작업은 끝난 것이 아니다. `일부러 뺌`은 사유를 쓰고 보고의 `DEVIATIONS`에도 적는다(사용자가 P5-14를 승인할 때 읽는다).
6. fixture에 위 화면의 데이터를 넣는다(백업 3개, 감사 로그 30행, 설정 값).

## 6. 테스트

| 종류 | 테스트 이름 | 준비 | 기대 |
|---|---|---|---|
| e2e | "storage: compaction asks first" | `오디오 압축 실행` | 확인 대화상자 → 요청 1회 → 토스트. 실행 중 버튼 `disabled` |
| e2e | "storage: retention form saves" | 값을 바꾸고 저장 | `setRetention`이 바뀐 값으로 불린다 |
| e2e | "ops: run maintenance" | 버튼 | 요청 1회, "마지막 실행" 줄이 바뀐다 |
| e2e | "ops: backups table" | fixture 백업 3개 | 3줄, 크기와 검증 결과 |
| e2e | "settings: blank secret means unchanged" | 비밀 입력을 비운 채 저장 | 요청 본문에 그 키가 없다 |
| e2e | "audit: filter and more" | 필터 → 더 보기 | 줄 수 증가, 필터가 주소에 남는다 |
| e2e | "recordings table sorts" | `길이` 머리글 Enter | `aria-sort="ascending"` |
| e2e | "v1 usage totals" (P6-C 뒤) | fixture | 클라이언트별 합계가 줄들의 합과 같다 |
| server e2e | "admin storage and audit render against the real server" | 운영자 계정 | 두 화면이 오류 없이 그려진다 |
| e2e | a11y "admin storage/ops/settings/audit/recordings" | 각 화면 | axe 위반 0건 |
| 문서 | `PARITY-ADMIN.md` | `git grep -c "| 없음 |" -- docs/v2/pipeline/PARITY-ADMIN.md` | 아무것도 출력하지 않는다(0건. 이때 종료 코드는 1이다) |

대조표의 e2e 이름은 실제 테스트 이름과 글자 그대로 같아야 한다(`git grep`으로 찾아진다).
