> 등급: `careful` · 게이트: `full` · 의존: `P4-C` · 소유: `apps/server/`

## 1. 목표

설정에서 "Google 캘린더 연결"을 누르면 Google 동의 화면을 거쳐 돌아오고, 전용 캘린더 "Lectern"이 만들어진다. 연결을 해제할 수 있다. 토큰이 무효가 되면 연동이 `needs_reauth`가 된다. 일정 동기화는 이 작업이 아니다(P4-03). 테스트는 가짜 Google만 쓴다.

## 5. 단계

1. `google/oauth.ts` (모든 HTTP는 `fetch`. 새 의존성 없음)
   ```ts
   export const GOOGLE_AUTH_URL = "https://accounts.google.com/o/oauth2/v2/auth";
   export const GOOGLE_TOKEN_URL = "https://oauth2.googleapis.com/token";
   export const GOOGLE_REVOKE_URL = "https://oauth2.googleapis.com/revoke";
   export const CALENDAR_SCOPE = "https://www.googleapis.com/auth/calendar.app.created";
   export class GoogleAuthError extends Error { constructor(readonly code: "invalid_grant" | "unauthorized" | "transient" | "config", message: string) }
   export function googleClient(): { clientId: string; clientSecret: string } | null   // readSecret; null when either is missing
   export function newPkce(): { verifier: string; challenge: string }                   // verifier: 32 random bytes base64url; challenge: base64url(sha256(verifier))
   export function authorizationUrl(p: { clientId: string; redirectUri: string; scope: string; state: string; challenge: string }): string
   export async function exchangeCode(p: { code: string; verifier: string; redirectUri: string }): Promise<{ access_token: string; refresh_token?: string; expires_in: number; scope: string; id_token?: string }>
   export async function refreshAccessToken(refreshToken: string): Promise<{ access_token: string; expires_in: number }>
   export async function revokeToken(token: string): Promise<void>   // best effort: never throws
   ```
   - 인가 URL 파라미터: `client_id`, `redirect_uri`, `response_type=code`, `scope`, `access_type=offline`, `prompt=consent`, `state`, `code_challenge`, `code_challenge_method=S256`.
   - 토큰 요청은 `POST`, `Content-Type: application/x-www-form-urlencoded`. 교환: `code`, `client_id`, `client_secret`, `redirect_uri`, `grant_type=authorization_code`, `code_verifier`. 갱신: `refresh_token`, `client_id`, `client_secret`, `grant_type=refresh_token`.
   - 오류 분류: 응답 본문의 `error`가 `invalid_grant` → `GoogleAuthError("invalid_grant")`. 401 → `"unauthorized"`. 429·5xx·네트워크 → `"transient"`. 시크릿 없음 → `"config"`.
   - 리디렉션 URI는 `` `${config().baseUrl}/api/v2/integrations/google/callback` ``다.
2. state 저장(`oauth.ts`에 둔다)
   ```ts
   export function createOAuthState(p: { userId: string | null; workspaceId: string | null; purpose: "google_calendar" | "google_login" | "apple_login"; verifier: string | null; redirectAfter: string | null }): string  // returns the raw state (32 random bytes base64url); stores sha256Hex(state); expires in 10 minutes
   export function consumeOAuthState(state: string, purpose: string): { userId: string | null; workspaceId: string | null; verifier: string | null; redirectAfter: string | null } | null  // deletes the row; null when missing, expired or purpose differs
   ```
   만료된 행은 `consumeOAuthState`를 부를 때 함께 지운다.
3. `google/tokens.ts`
   ```ts
   export function sealGoogleTokens(t: { refresh_token: string }): string            // sealSecret(JSON.stringify(t))
   export async function accessTokenFor(integrationId: string): Promise<string>       // opens token_enc, refreshes, caches in memory until 60s before expiry
   export function markNeedsReauth(integrationId: string): void                      // status = 'needs_reauth'
   ```
   `accessTokenFor`는 갱신이 `invalid_grant`면 `markNeedsReauth`를 부르고 그 오류를 다시 던진다.
4. `google/calendar.ts`: `export async function createCalendar(accessToken: string, timeZone: string): Promise<string>` — `POST https://www.googleapis.com/calendar/v3/calendars`, 본문 `{ "summary": "Lectern", "timeZone": timeZone }`, 응답의 `id`.
5. `integrations.ts` `startGoogleIntegration`
   - `config().calendar`가 거짓이거나 `googleClient()`가 `null`이면 501.
   - `requireWorkspace`. PKCE와 state를 만들고(`purpose: "google_calendar"`, `redirectAfter: body.return_to ?? "/app/settings#integrations"`) `{ authorization_url }`을 돌려준다.
6. `google-callback.ts` `GET /integrations/google/callback` (쿠키로 인증된 브라우저 요청이다)
   - 로그인하지 않았으면 `302 /app/login`.
   - 쿼리에 `error`가 있거나 `code`·`state`가 없거나 `consumeOAuthState`가 `null`이거나 state의 `userId`가 지금 사용자와 다르면 `302 /app/settings?google=error#integrations`. 토큰 교환을 하지 않는다.
   - `exchangeCode` → `refresh_token`이 없으면 오류로 처리 → `createCalendar`(시간대는 사용자의 `timezone`, 없으면 `Asia/Seoul`) → `integration` 행을 넣는다(같은 워크스페이스·사용자·`provider = 'google'` 행이 있으면 갱신): `scopes_json = [CALENDAR_SCOPE]`, `token_enc`, `calendar_id`, `status = 'active'`.
   - 성공: `302 <redirectAfter>`의 경로에 `?google=connected`를 붙여 보낸다. `redirectAfter`는 `/`로 시작하고 `//`로 시작하지 않을 때만 쓴다. 아니면 `/app/settings#integrations`.
   - `code`, 토큰, state를 로그에 남기지 않는다.
7. `integrations.ts` `disconnectIntegration` (D-P4-6): 자기 연동만(남의 것은 404). `revokeToken`(실패해도 계속) → 그 연동의 `calendar_event_link` 행 삭제 → 그 행들이 가리키던 `event_candidate` 중 `status = 'synced'`를 `accepted`로 → `integration` 행 삭제. 한 트랜잭션(폐기 요청은 트랜잭션 밖, 먼저). 204.
8. `index.ts`: `v2.all("*")` 앞에 `v2.get("/integrations/google/callback", googleCalendarCallback)`.
9. `test/fakes/google.ts` (D-P4-9. `fetch` 경계의 가짜. P4-03, P4-04, P5-04가 같은 것을 쓴다)
   ```ts
   export interface FakeGoogle {
     install(): void;   // replaces globalThis.fetch; a request to any host other than accounts.google.com, oauth2.googleapis.com, www.googleapis.com throws
     restore(): void;
     requests: { method: string; url: string; headers: Record<string, string>; form?: Record<string, string>; json?: unknown }[];
     issueCode(code: string, opts?: { refreshToken?: string | null }): void;      // a code the token endpoint accepts once
     failNext(match: string | RegExp, response: { status: number; json: unknown }, times?: number): void;  // e.g. failNext("oauth2.googleapis.com/token", { status: 400, json: { error: "invalid_grant" } })
     calendars: Map<string, { summary: string; timeZone: string }>;
     events: Map<string, Map<string, Record<string, unknown>>>;   // calendarId → eventId → event resource (P4-03 uses it)
     revoked: string[];
   }
   export function createFakeGoogle(): FakeGoogle
   ```
   접근 토큰은 `at-<n>`, 갱신 토큰은 `rt-<n>` 형식의 가짜 값이다. 실제 호스트로 나가는 요청은 없다.

## 6. 테스트

`google-oauth.test.ts` (`LECTERN_CALENDAR=1`, 가짜 시크릿 `GOOGLE_OAUTH_CLIENT_ID=test-id`, `GOOGLE_OAUTH_CLIENT_SECRET=test-secret`)

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| "start returns a Google URL with PKCE" | `startGoogleIntegration` | URL이 `GOOGLE_AUTH_URL`로 시작, `scope`가 `CALENDAR_SCOPE` 하나, `code_challenge_method=S256`, `access_type=offline`, `oauth_state` 행 1개 |
| "callback connects" | `issueCode("c1")` 뒤 콜백 | 302 `/app/settings?google=connected#integrations`, `integration` 행 1개 `status=active`, `calendar_id` 있음, 가짜의 `calendars`에 `Lectern` |
| "tokens are sealed" | 위 뒤 | `integration.token_enc`와 로그 출력에 `rt-`가 없다. `openSecret`으로 열면 갱신 토큰이 나온다 |
| "state is single use" | 같은 `state`로 콜백 두 번 | 두 번째는 `?google=error`, 토큰 요청이 늘지 않는다 |
| "state of another user" | 사용자 A가 시작, B가 콜백 | `?google=error`, 연동 없음 |
| "expired state" | `expires_at`을 과거로 고침 | `?google=error` |
| "denied consent" | 콜백에 `error=access_denied` | `?google=error`, 토큰 요청 0회 |
| "return_to must be a local path" | `return_to: "//evil.example"`은 스키마가 400. state의 `redirect_after`를 직접 `https://evil.example`로 고친 뒤 콜백 | `Location`이 `/app/settings`로 시작 |
| "invalid_grant marks needs_reauth" | 연결 뒤 `failNext(token, invalid_grant)`, `accessTokenFor` | 던지고, `integration.status === "needs_reauth"` |
| "disconnect" | 링크 2개와 `synced` 일정 2개를 넣고 해제 | 204, 링크 0개, 두 일정 `accepted`, 연동 행 없음, `revoked`에 갱신 토큰, Google 일정은 그대로 |
| "disconnect someone else's" | 사용자 B가 A의 id로 | 404 |
| "no client configured" | 시크릿을 지움 | `startGoogleIntegration` 501 |
| "flag off" | `LECTERN_CALENDAR=0` | 501 |

## 10. 명세 작성자 메모

- 콜백은 다른 사이트(Google)에서 오는 최상위 이동이다. 세션 쿠키가 `SameSite=Lax`라서 `GET` 이동에는 실린다. 확인 필요: 테스트에서 쿠키를 실어 콜백을 부르는 방법은 `api-v2.test.ts`의 인증 방식을 따른다.
- `sealSecret`의 입력·출력 타입은 확인하지 않았다. 파일을 읽고 맞춘다.
- 실제 Google로 하는 확인(동의 화면, 전용 캘린더 생성)은 사용자 몫이다(`STATUS.md` "실측 필요").
