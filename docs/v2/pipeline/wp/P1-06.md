# P1-06 extract 단계

> 등급: `basic` · 게이트: `unit` · 의존: `P1-04` · 소유: `packages/harness/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

전사에서 일정(`events`), 할 일(`action_items`), 결정(`decisions`), 용어(`glossary`)를 한 번의 모델 호출로 뽑는 `extract` 단계를 만든다. 템플릿이 켠 항목만 묻고, 켠 항목이 없으면(`interview`) 모델을 부르지 않는다. `structure`와 같은 시스템·전사 접두부를 쓴다. 사용자가 보는 변화는 없다.

## 5. 단계

1. 도우미.
   ```ts
   /** Strict: a field the template switched off is an error, not silently stripped. */
   export function extractSchemaFor(def: TemplateDefinition): ZodType<Partial<ExtractResult>> {
     const base = extractResultSchema(def) as unknown as z.ZodObject;
     return z.strictObject(base.shape) as unknown as ZodType<Partial<ExtractResult>>;
   }
   export function enabledExtractFields(def: TemplateDefinition): ExtractField[]; // ExtractField.options order, extract[f] === true
   export function formatRecordedAt(ms: number, tz: string): string;               // "2026-10-19 (월) 14:00 Asia/Seoul"
   ```
   - 왜 strict인가: `z.object`는 모르는 키를 조용히 지우므로 "꺼진 항목이 응답에 있으면 거절"이 안 된다.
   - `formatRecordedAt`: `Intl.DateTimeFormat("ko-KR", { timeZone: tz, year: "numeric", month: "2-digit", day: "2-digit", hour: "2-digit", minute: "2-digit", weekday: "short", hourCycle: "h23" }).formatToParts`에서 연·월·일·요일·시·분을 뽑아 `${y}-${mo}-${d} (${weekday}) ${hh}:${mm} ${tz}`로 조립한다.
2. 단계.
   ```ts
   export interface ExtractInput {
     template: LoadedTemplate;
     segments: CompactSegment[];
     language: string;
     recordedAtMs: number;
     tz: string;
   }
   export const EXTRACT_STAGE_VERSION = 1;
   export function extractStage(llm: LlmProvider, routing: Routing): StageDefinition<ExtractInput, Partial<ExtractResult>>;
   ```
   - `defineStage({ name: "extract", version: EXTRACT_STAGE_VERSION, output: ExtractResult.partial(), memo: "shared", retry: { maxAttempts: 3, repairs: 1 }, key, run })`.
   - `key`: `inputs: [sha256Hex(formatCompactTranscript({ segments }).text)]`, `prompt: sha256Hex(NOTES_SYSTEM + "\u0000" + EXTRACT_INSTRUCTION + "\u0000" + canonicalJson(FIELD_HELP))`, `template: \`${def.id}@${def.version}:${template.hash}\``, `provider: llm.id`, `model: routing.extract.model`, `params: { schema: llmSchemaHash(extractSchemaFor(def)), maxOutputTokens: routing.extract.maxOutputTokens, language, recordedAt: formatRecordedAt(recordedAtMs, tz) }`. 켠 항목이 없으면 `schema`는 `null`로 둔다(스키마를 만들지 않는다).
   - `run`: 켠 항목이 없으면 **모델을 부르지 않고** `{}`를 돌려준다. 있으면 한 번 호출:
     `await ctx.meter({ provider: llm.id, model: routing.extract.model }, () => llm.generate({ schema: extractSchemaFor(def), system: NOTES_SYSTEM, context: notesContext(segments), instruction, model: routing.extract.model, maxOutputTokens: routing.extract.maxOutputTokens, signal: ctx.signal }))`.
     `system`과 `context`는 `structure`와 **같은 함수·같은 값**을 쓴다(접두부 공유). 다르게 만들지 않는다.
   - `instruction` = `EXTRACT_INSTRUCTION`("위 전사에서 아래 항목만 JSON으로 추출한다. 전사에 실제로 나온 것만 쓴다.") + `\n\n` + `template.extractPrompt` + `\n\n녹음 시각: ${formatRecordedAt(...)}\n출력 언어: ${language}\n추출 항목:` + 켠 항목마다 `\n- <field>: <FIELD_HELP[field]>` + (repair 있으면 `\n\n이전 응답이 검증을 통과하지 못했다: <issues>\n규칙을 지켜 다시 답한다.`).
   - `FIELD_HELP`(한국어 고정 객체; 켠 항목만 instruction에 들어간다):
     - `events`: "마감·시험·회의·발표 등 날짜가 있는 일정. kind는 deadline, exam, meeting, task, other 중 하나. raw_expression은 말한 날짜 표현 그대로, model_resolution은 녹음 시각 기준 네 해석(date, time, end_time, all_day)."
     - `action_items`: "누군가 해야 할 일. owner_name은 이름이 나올 때만, due_raw는 기한 표현 그대로(없으면 null)."
     - `decisions`: "회의에서 확정된 결정. text와 evidence."
     - `glossary`: "설명된 용어. term, definition, evidence."
     - `questions` 항목은 만들지 않는다(D-P1-7).
   - 반환값: 호출한 경우 `value`(켠 필드만 가진 객체).
3. `src/index.ts`에 export를 더한다.

## 6. 테스트

파일: `packages/harness/test/extract.test.ts`. 준비: `testEnv()`, `env.job("job-1")`, `harness().job({ jobId: "job-1", scope: "ws" })`, `loadRouting()`, 세그먼트 10개(`idx 0..9`, `start_ms = idx*60000`, `S1`, "내용 <idx>"). `base = { recordedAtMs: Date.parse("2026-10-19T14:00:00+09:00"), tz: "Asia/Seoul", language: "ko" }`. 정상 lecture 답:
`lectureOut = { events: [{ title:"과제 제출", kind:"deadline", raw_expression:"다음 주 화요일까지", model_resolution:{ date:"2026-10-27", time:null, end_time:null, all_day:true }, evidence:["#3"], quote:"다음 주 화요일까지 제출", confidence:0.9 }], glossary: [{ term:"ECB", definition:"블록 암호 운영 모드", evidence:["#2"] }] }`

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| lecture normal path | `lecture` 템플릿, `fromList([lectureOut])` | `value`가 `lectureOut`과 같음; `calls.length === 1`; `req.model === "gemini-3.8-flash"`; `req.maxOutputTokens === 8192`; `ai_call` 1행 |
| only enabled fields are asked | 위 호출의 `req.instruction` | `- events:`·`- glossary:` 포함, `- action_items:`·`- decisions:`·`- questions:` 미포함; `녹음 시각: 2026-10-19 (월) 14:00 Asia/Seoul`와 `출력 언어: ko` 포함 |
| meeting asks events, action_items, decisions | `meeting`, 답 `{events:[],action_items:[],decisions:[]}` | 성공; instruction에 세 줄 모두 있고 `glossary` 줄 없음 |
| a switched-off field is rejected | lecture, 첫 답 `{ ...lectureOut, action_items: [] }`, 둘째 `lectureOut` | `calls.length === 2`(첫 답이 스키마 위반 → 수리 1회), 둘째 `instruction`에 `이전 응답이 검증을 통과하지 못했다` |
| `extractSchemaFor` is strict | lecture 스키마에 `{events:[],glossary:[],action_items:[]}` | `success === false`; `{events:[],glossary:[]}`는 `true`; `{events:[]}`는 `false`(필드 누락) |
| interview makes no call | `interview` 템플릿, `ScriptedLlmProvider.fromList([])` | `value` `{}`, `calls.length === 0`, `ai_call` 0행, 던지지 않음 |
| same prefix as structure | lecture. `structureStage`(P1-04)와 `extractStage`를 각각 다른 `ScriptedLlmProvider`로 같은 세그먼트에 실행(structure 답은 P1-04 테스트의 `okOut`) → 각 `calls[0].req`를 `new GeminiLlmProvider({ apiKey: () => "k" }).requestBody(req)`로 변환 | 두 본문의 `systemInstruction`이 같고, `contents[0].parts`에서 마지막(지시문)을 뺀 나머지가 `JSON.stringify` 기준으로 같고, 마지막 파트(지시문)는 서로 다름 |
| memo hit on resume | 같은 `run`으로 같은 입력 두 번 | 두 번째 `resumed === true`, `calls.length === 1` |
| changed recorded time misses memo | `recordedAtMs`를 하루 뒤로 | `calls.length === 2` |
| editing a template prompt misses memo | `templates/`를 임시 폴더로 복사 후 `lecture/prompt.extract.md`에 문장 추가 → `loadTemplate("lecture", tmp)` | `calls.length === 2` |
| transient error is retried | 첫 호출 `new HarnessError("transient","503")`, 둘째 `lectureOut` | 성공, `calls.length === 2` |
| budget stop | `env.job("job-b",{budgetMicrousd:5})`, `UPDATE job SET spent_microusd = 10 WHERE id='job-b'` | `HarnessError` kind `budget`, `calls.length === 0` |
| formatRecordedAt | `Date.parse("2026-10-19T14:00:00+09:00")`, `Asia/Seoul`; 같은 시각 `America/New_York` | `2026-10-19 (월) 14:00 Asia/Seoul`; `2026-10-19 (월) 01:00 America/New_York` |

## 8. 하지 않는 것

- 날짜 해석(`raw_expression` → 실제 날짜): `verify`가 `resolveKoreanDate`(P1-05)로 한다. 이 단계는 모델 값을 그대로 돌려준다.
- 인용 일치·출처 검사·중복 제거: `verify`(P1-07).
- `questions` 추출 금지(D-P1-7).
- 긴 전사의 map-reduce: 하지 않는다(전체 전사를 한 번에 보낸다).
- 실제 Gemini 호출 금지.

## 10. 명세 작성자 메모

- `extractResultSchema(def)`는 `z.object`라 꺼진 항목을 거절하지 않고 지운다. 카탈로그의 "꺼진 항목이 응답에 있으면 스키마가 거절"을 맞추려고 하네스 쪽에서 `z.strictObject(shape)`로 감싼다(domain은 동결이라 고치지 않는다). 이 때문에 모델이 불필요한 키를 하나라도 보내면 수리 1회를 쓴다.
- 입력에 `recordedAtMs`·`tz`를 더했다(모델이 `model_resolution`을 계산하려면 기준 시각이 필요하다. 계약에 명시는 없다).
- 전사가 매우 길어도 `extract`는 전체를 한 번에 보낸다. 3시간 강의(약 15만 자)는 Gemini 문맥 안이라고 보지만 확인하지 못했다.
- `formatRecordedAt`의 `ko-KR` 요일 약어(`월`)는 ICU 데이터에 기대며 실행해 확인하지는 못했다. 테스트가 잡는다.
