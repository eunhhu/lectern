# P1-02 템플릿 5종과 로더

> 등급: `basic` · 게이트: `unit` · 의존: `P1-01` · 소유: `packages/harness/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

노트 템플릿 5종(`lecture`, `meeting`, `seminar`, `interview`, `general`)을 `packages/harness/templates/<id>/`에 파일로 만들고, 읽어 오는 `loadTemplate`과 도메인→템플릿 규칙 `templateForDomain`을 만든다. 사용자가 보는 변화는 없다(P1-04부터 쓰인다).

## 2. 먼저 읽을 것

- 계약: `CONTRACTS.md` §1.3(`templates.ts` 시그니처), §1.5(표), D-P1-7.
- 레시피: `RECIPES.md` R6(하네스 파일 관례).
- 코드: `packages/domain/src/harness.ts` — `TemplateDefinition`(검증 규칙: 섹션 키 중복 금지, 비-structure `fill`은 `extract`에서 켜져 있어야 함, `extract`는 **다섯 키 전부** 필요), `templateOutputSchema`, `extractResultSchema`, `ExtractField`.
- 코드: `packages/domain/src/templates.ts` — `LECTURE_TEMPLATE`(placeholder, 동결. 고치지 않는다. 모양 본보기).
- 코드: `packages/domain/src/enums.ts` — `RecordingDomain`. `packages/domain/src/primitives.ts` — `TemplateId`.

## 5. 단계

1. 모든 `template.json`의 공통 모양: `{ "id", "version": 1, "name", "domains": [...], "sections": [ {key,title,fill,instructions,block_types,required} ], "extract": {"events":b,"action_items":b,"questions":false,"decisions":b,"glossary":b}, "question_kinds": [] }`. `extract`는 항상 다섯 키를 모두 쓴다(표에 없는 것은 `false`). `questions`는 전부 `false`(D-P1-7). 들여쓰기 2칸, 끝 개행 1개.
2. 템플릿 값(섹션 순서가 곧 배열 순서). `fill`이 `structure`가 아닌 섹션은 `instructions`가 `""`이다. 블록 타입은 `·`로 구분한 것을 배열로 쓴다.

   **lecture** — name `강의 노트`, domains `["lecture"]`, extract: events, glossary = true
   | key | title | fill | block_types | required | instructions |
   |---|---|---|---|---|---|
   | summary | 핵심 요약 | structure | paragraph, list | true | 강의 전체의 핵심을 짧은 문단이나 목록으로 요약한다. |
   | exam_points | 시험·과제 포인트 | structure | callout, list | false | 시험, 과제, 강조된 내용만 모은다. 말하지 않았으면 이 섹션을 비운다. |
   | topics | 주제별 상세 | structure | paragraph, list, term, formula, callout | true | 주제마다 heading을 두고 용어, 공식, 예시를 들은 순서대로 정리한다. |
   | quotes | 주요 발언 | structure | quote | false | 그대로 옮길 가치가 있는 발언만 고른다. |
   | glossary | 용어 | glossary | list | false | (빈 문자열) |
   | events | 일정 | events | list | false | (빈 문자열) |

   **meeting** — name `회의록`, domains `["meeting","one_on_one","call"]`, extract: events, action_items, decisions = true
   | key | title | fill | block_types | required | instructions |
   |---|---|---|---|---|---|
   | summary | 요약 | structure | paragraph, list | true | 회의의 목적과 결론을 짧게 요약한다. |
   | decisions | 결정 사항 | decisions | list | false | (빈) |
   | action_items | 할 일 | action_items | list | false | (빈) |
   | topics | 논의 주제별 요점 | structure | paragraph, list, quote | true | 논의 주제마다 heading을 두고 나온 의견과 근거를 정리한다. |
   | open_issues | 미결 쟁점 | structure | list, paragraph | false | 결론이 나지 않은 쟁점만 적는다. |
   | next_events | 다음 일정 | events | list | false | (빈) |

   **seminar** — name `세미나 노트`, domains `["seminar"]`, extract: glossary = true
   | key | title | fill | block_types | required | instructions |
   |---|---|---|---|---|---|
   | summary | 발표 요지 | structure | paragraph, list | true | 발표의 주제와 결론을 요약한다. |
   | claims | 핵심 주장·근거 | structure | paragraph, list, quote | true | 주장마다 근거를 붙여 정리한다. |
   | qa | 질의응답 | structure | list, paragraph | false | 질문과 답변을 짝지어 적는다. |
   | references | 참고 자료 | structure | list | false | 발표 중 언급된 자료, 논문, 도구 이름만 적는다. |
   | glossary | 용어 | glossary | list | false | (빈) |

   **interview** — name `인터뷰 노트`, domains `["interview"]`, extract: 전부 false (extract 단계를 건너뛴다)
   | key | title | fill | block_types | required | instructions |
   |---|---|---|---|---|---|
   | context | 인물·맥락 | structure | paragraph | true | 말한 사람과 인터뷰의 배경을 들은 범위에서만 적는다. |
   | answers | 질문별 답변 요지 | structure | paragraph, list | true | 질문마다 heading을 두고 답변의 요지를 정리한다. |
   | quotes | 인용 | structure | quote | false | 그대로 인용할 가치가 있는 발언만 고른다. |
   | follow_ups | 후속 질문 | structure | list | false | 대화에서 나온 후속 질문만 적는다. |

   **general** — name `일반 노트`, domains `["other"]`, extract: events, action_items = true
   | key | title | fill | block_types | required | instructions |
   |---|---|---|---|---|---|
   | summary | 요약 | structure | paragraph, list | true | 전체 내용을 짧게 요약한다. |
   | topics | 주제별 요점 | structure | paragraph, list | true | 주제마다 heading을 두고 요점을 정리한다. |
   | action_items | 할 일 | action_items | list | false | (빈) |
   | events | 일정 | events | list | false | (빈) |

3. 프롬프트 파일. 다섯 템플릿의 `prompt.structure.md`는 아래 **공통 본문**으로 시작하고, 끝에 템플릿별 한 줄(`이 노트는 <name> 형식이다. <섹션 키 나열>을 채운다.`)을 붙인다. `prompt.extract.md`는 **추출 본문**으로 시작해 템플릿별 한 줄(`추출 항목: <extract가 true인 키 나열>.`)을 붙인다. `interview`의 extract 파일은 본문 대신 `이 템플릿은 추출 단계를 쓰지 않는다.` 한 줄만 둔다.

   공통 본문(structure):
   ```
   전사를 읽고 노트를 만든다.
   - 전사에서 들은 내용만 쓴다. 지어내거나 추측하지 않는다. 확실하지 않으면 쓰지 않는다.
   - 모든 블록과 목록 항목에는 근거가 되는 세그먼트 출처(sources)가 있어야 한다. 출처가 없는 내용은 쓰지 않는다.
   - 출처는 전사 줄 앞의 번호로만 쓴다: "#12" 또는 범위 "#40-#44". 시간(분:초)은 쓰지 않는다.
   - 출력 언어는 녹음의 언어다(전사가 한국어면 한국어).
   - 섹션 key와 허용된 블록 type만 쓴다. 비어 있는 섹션은 blocks를 빈 배열로 둔다.
   ```
   추출 본문(extract):
   ```
   전사에서 항목을 추출한다. 전사에 실제로 나온 것만 추출한다.
   - 날짜 표현(raw_expression)은 말한 그대로 옮긴다("다음 주 화요일 수업 전까지"). 날짜를 계산해 바꿔 쓰지 않는다. model_resolution에는 네 해석을 따로 적는다.
   - 모든 항목에 근거 출처(evidence)를 "#12" 또는 "#40-#44" 형식으로 단다. 시간은 쓰지 않는다.
   - quote에는 근거 구간의 말을 그대로 짧게 옮긴다.
   - 출력 언어는 녹음의 언어다.
   ```
4. `src/templates.ts`:
   ```ts
   export const TEMPLATE_IDS = ["lecture", "meeting", "seminar", "interview", "general"] as const;
   export type TemplateKey = (typeof TEMPLATE_IDS)[number];
   export interface LoadedTemplate { def: TemplateDefinition; structurePrompt: string; extractPrompt: string; hash: string }
   export const TEMPLATES_DIR = new URL("../templates/", import.meta.url);
   export function loadTemplate(id: string, dir: URL | string = TEMPLATES_DIR): LoadedTemplate;
   export function templateForDomain(domain: RecordingDomain, confidence?: number): TemplateKey;
   ```
   - `loadTemplate`: `id`가 `TEMPLATE_IDS`에 없으면 `Error("unknown template: <id>")`. 세 파일을 `readFileSync`(UTF-8)로 읽는다. `def = TemplateDefinition.parse(JSON.parse(...))`. `def.id !== id`이면 던진다. `hash = sha256Hex(templateJson + "\u0000" + structurePrompt + "\u0000" + extractPrompt)`(파일 **원문**으로 계산, 정규화 없음). 캐시하지 않는다.
   - `templateForDomain`: `confidence !== undefined && confidence < 0.5`이면 `"general"`. 아니면 lecture→`lecture`, meeting·one_on_one·call→`meeting`, seminar→`seminar`, interview→`interview`, other→`general`. `switch`에 `default` 없이 `never` 검사를 둔다(새 도메인 값이 생기면 타입 오류).
5. `src/index.ts`에 `export * from "./templates.ts";`를 더한다.

## 6. 테스트

파일: `packages/harness/test/templates.test.ts`

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| every shipped template parses | `TEMPLATE_IDS`마다 `loadTemplate` | 던지지 않음, `def.id`가 id와 같음, `def.version === 1` |
| section keys and order match the contract | 5개 | lecture `["summary","exam_points","topics","quotes","glossary","events"]`; meeting `["summary","decisions","action_items","topics","open_issues","next_events"]`; seminar `["summary","claims","qa","references","glossary"]`; interview `["context","answers","quotes","follow_ups"]`; general `["summary","topics","action_items","events"]` |
| required sections | 5개 | lecture `summary,topics`; meeting `summary,topics`; seminar `summary,claims`; interview `context,answers`; general `summary,topics` (나머지는 required false) |
| questions are off everywhere | 5개 | `def.extract.questions === false`, `def.question_kinds` 비어 있음 |
| extract flags | 5개 | lecture `{events,glossary}`만 true; meeting `{events,action_items,decisions}`; seminar `{glossary}`; interview 전부 false; general `{events,action_items}` |
| output and extract schemas build | 5개 | `templateOutputSchema(def)`와 `extractResultSchema(def)`가 던지지 않음; interview의 `extractResultSchema(def).parse({})`가 `{}` |
| template output schema accepts a minimal lecture | lecture, `{sections:[{key:"summary",blocks:[{type:"paragraph",heading:null,text:"요약",sources:["#1"],pdf_pages:[]}]},{key:"topics",blocks:[]}]}` | `safeParse(...).success === true` |
| template output schema rejects a missing required section | lecture, `{sections:[]}` | `success === false` |
| prompts carry the rules | 10개 파일 중 structure 5개 | 본문에 `지어내`, `#12`, `출력 언어`가 들어 있음; extract 4개(interview 제외)에 `raw_expression`이 들어 있음 |
| templateForDomain table | 7개 도메인 | lecture→lecture, meeting→meeting, one_on_one→meeting, call→meeting, seminar→seminar, interview→interview, other→general |
| low confidence falls back to general | `templateForDomain("lecture", 0.49)`, `("lecture", 0.5)` | `general`, `lecture` |
| hash changes with any of the three files | `lecture` 디렉터리를 `mkdtemp`로 복사(5개 전부 복사해도 됨); 원본 hash 기록 → `prompt.extract.md`에 문자 하나 추가 → 다시 로드 | 해시가 다름; 되돌리면 같음; `template.json`, `prompt.structure.md`도 각각 같은 방식으로 바뀜 |
| same files give the same hash | `loadTemplate("lecture")` 두 번 | 해시 같고 64자 hex |
| unknown id | `loadTemplate("nope")` | 던짐 |

## 10. 명세 작성자 메모

- 계약 표는 템플릿 `name`, 섹션 `instructions` 문구를 정하지 않았다. 위 값은 명세 작성자가 `LECTURE_TEMPLATE` placeholder 문체를 따라 정했다(`meeting` 이하 `name`은 새로 지었다). 바꾸고 싶으면 오케스트레이터가 정한다.
- 계약 `templateForDomain(domain)` 시그니처에 "신뢰도 0.5 미만이면 general"이 함께 적혀 있어 선택 인자 `confidence?`를 더했다(호출은 기존 시그니처와 호환).
- `TemplateDefinition.extract`는 zod의 enum-키 record라 다섯 키가 모두 있어야 한다(표의 "표에 없는 항목은 false"를 이렇게 구현). 실제 parse로 확인하지는 않았다. 테스트가 잡는다.
- 템플릿별 한 줄 접미사와 공통 본문은 카탈로그의 프롬프트 규칙(지어내지 않기, 출처 토큰 필수, `#id`만, 출력 언어, `raw_expression` 원문)을 문장으로 옮긴 것이다.
