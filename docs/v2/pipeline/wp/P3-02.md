# P3-02 packages/pdf: 쪽 글자 추출

> 등급: `careful` · 게이트: `unit` · 의존: `P3-C` · 소유: `packages/pdf/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

`@lectern/pdf`가 PDF 파일 하나에서 쪽별 글자를 뽑는다. `pdfjs-dist` legacy 빌드를 워커 없이(메인 스레드) 쓴다. 글자 층이 없는 쪽을 알아내고, 절반 이상이 그런 쪽이면 `scanned`다. 암호 걸린 PDF·손상 파일·500쪽 초과는 분류된 오류다. 이 패키지는 DB·서버·모델을 모른다.

## 2. 먼저 읽을 것

- 계약: `CONTRACTS.md` D-P3-1, D-P3-2(500쪽), D-P3-3(20자 기준, 절반 이상이면 scanned)
- 코드: `packages/media/package.json`, `packages/media/src/index.ts` — 패키지 모양과 내보내기 방식
- `packages/pdf/package.json`, `src/index.ts` — `P3-C`가 만든다(`pdfjs-dist` 정확한 버전, `pdf-lib` devDependency)
- `packages/ask/src/text.ts` — `normalizeText` (글자 정규화 관례; 이 패키지는 `@lectern/ask`를 import하지 않는다)

## 5. 단계

1. `extract.ts`의 공개 형태(이름·시그니처는 그대로):
```ts
export const MAX_PDF_PAGES = 500;
export const MIN_TEXT_CHARS = 20; // a page with fewer characters has no usable text layer
export type PdfErrorCode = "encrypted" | "corrupt" | "too_many_pages" | "unreadable";
export class PdfError extends Error {
  constructor(readonly code: PdfErrorCode, message: string) { super(message); this.name = "PdfError"; }
}
export interface ExtractedPage { pageNo: number; text: string; charCount: number; hasTextLayer: boolean }
export interface ExtractedPdf { pageCount: number; pages: ExtractedPage[]; scanned: boolean }
export interface TextItemLike { str: string; transform: number[]; hasEOL?: boolean }
export function classifyPdfError(err: unknown): PdfErrorCode; // by err.name, see step 3
export function cleanPageText(items: readonly TextItemLike[]): string;
export function extractPdfPages(path: string, options?: { maxPages?: number }): Promise<ExtractedPdf>;
```
2. `cleanPageText(items)` 규칙(순수 함수, pdf.js를 부르지 않는다):
   - `str`이 빈 항목은 버린다. `transform[5]`가 y, `transform[4]`가 x다.
   - 줄 묶기: y가 큰 것(위쪽)부터. 앞 항목과 y 차이가 2 이하이면 같은 줄이다. 한 줄 안에서는 x 오름차순.
   - 같은 줄의 항목은 공백 없이 이어 붙이고(PDF가 이미 공백 항목을 낸다), 줄은 `\n`으로 잇는다.
   - 정리: `normalize("NFC")`, 줄 안의 연속 공백·탭을 공백 하나로, 줄 앞뒤 공백 제거, 빈 줄 제거. 결과 앞뒤 `trim()`.
3. `extractPdfPages`:
   - `const data = new Uint8Array(await Bun.file(path).arrayBuffer());` 파일이 없으면 `PdfError("unreadable", ...)`.
   - `import * as pdfjs from "pdfjs-dist/legacy/build/pdf.mjs";` (legacy 빌드만. 일반 빌드를 쓰지 않는다.)
   - `pdfjs.getDocument({ data, isEvalSupported: false, useSystemFonts: false, disableFontFace: true, useWorkerFetch: false, verbosity: 0 }).promise`.
   - 워커: **띄우지 않는다.** pdf.js는 Node/Bun에서 `GlobalWorkerOptions.workerSrc`가 비어 있으면 같은 스레드 "가짜 워커"로 `pdfjs-dist/legacy/build/pdf.worker.mjs`를 불러 쓴다. 첫 호출이 워커 오류를 내면 `pdfjs.GlobalWorkerOptions.workerSrc`에 `new URL(import.meta.resolve("pdfjs-dist/legacy/build/pdf.worker.mjs")).href`를 한 번 지정한다. 어느 쪽이 맞았는지 보고의 DEVIATIONS에 한 줄로 적는다.
   - 오류 분류: `err.name === "PasswordException"` → `encrypted`; `"InvalidPDFException"` 또는 `"FormatError"` 또는 `"MissingPDFException"` → `corrupt`; 그 밖 → `unreadable`.
   - `doc.numPages > (options.maxPages ?? MAX_PDF_PAGES)`이면 쪽을 읽기 전에 `PdfError("too_many_pages", "PDF는 500쪽까지 지원합니다.")`.
   - 쪽마다 `const page = await doc.getPage(n); const content = await page.getTextContent();` 항목 중 `"str" in item`인 것만 `cleanPageText`에 넣고 `page.cleanup()`. `charCount = [...text.replace(/\s/g, "")].length`, `hasTextLayer = charCount >= MIN_TEXT_CHARS`.
   - 끝에 `finally { await doc.destroy(); }`.
   - `scanned = pages.filter((p) => !p.hasTextLayer).length * 2 >= pageCount` (쪽이 1개 이상일 때).
4. `test/make-pdf.ts` 도우미 세 개:
   - `async function makePdf(pages: string[]): Promise<Uint8Array>`: `pdf-lib`의 `PDFDocument.create()`, `StandardFonts.Helvetica`, 쪽마다 `page.drawText(text, { x: 50, y: 700, size: 12, font })`(글이 길면 줄마다 `y`를 14씩 내려 여러 번 호출). 빈 문자열이면 아무것도 그리지 않는다. **영어(ASCII)만 쓴다**: 표준 글꼴은 한글을 못 그린다.
   - `function makeKoreanPdf(text: string): Uint8Array`: 글꼴 없이 한글을 낼 수 있게 손으로 쓴 최소 PDF. 개체 6개(Catalog, Pages, Page, 내용 스트림, Type0 글꼴 `/Encoding /Identity-H` + `/DescendantFonts`(CIDFontType2, `/CIDSystemInfo (Adobe)(Identity)0`, FontDescriptor 포함, 글꼴 파일 없음) + `/ToUnicode` CMap 스트림). 글자마다 CID를 1부터 순서대로 붙이고(`<0001><0002>…` 를 `Tj`에 16진 문자열로), ToUnicode의 `beginbfchar`에 `<CID> <UTF-16BE 코드>`를 넣는다. xref 표는 틀려도 된다(pdf.js가 파일을 훑어 다시 만든다). 만든 문자열은 `new TextEncoder().encode`로 바이트로 바꾼다.
   - `async function writeTemp(bytes: Uint8Array, name: string): Promise<string>`: `os.tmpdir()` 아래 `mkdtemp`한 디렉터리에 쓰고 경로를 돌려준다. 테스트는 `afterAll`에서 지운다.
5. 한글 PDF(`makeKoreanPdf`)가 3번의 시도 안에 `"안녕하세요 이것은 한국어 문장입니다"`를 돌려주지 못하면 WORKER.md 4절대로 `BLOCKED`로 멈춘다(6절 테스트를 약하게 고치지 않는다).

## 6. 테스트

파일: `packages/pdf/test/extract.test.ts`. 모든 PDF는 테스트 안에서 만든다(다운로드 금지).

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| english pages in order | `makePdf(["Page one has plenty of readable words here", "Second page talks about block ciphers and keys", "Third page ends the sample document today"])` | `pageCount 3`, `pages.map(p=>p.pageNo)` = `[1,2,3]`, 각 `text`가 해당 문장과 같음, 모두 `hasTextLayer true`, `scanned false` |
| korean page text | `makeKoreanPdf("안녕하세요 이것은 한국어 문장입니다")` | 1쪽 `text`가 위 문장과 같음, `hasTextLayer true` |
| mixed korean and english | 한국어 1쪽 PDF 파일과 영어 PDF를 따로 | 각각 위 기대 |
| line order and spacing | `makePdf`로 한 쪽에 세 줄 `"Alpha line one"`, `"Beta line two"`, `"Gamma line three"`을 y 700, 686, 672에 그림 | `text === "Alpha line one\nBeta line two\nGamma line three"` |
| empty page has no text layer | `makePdf(["This first page has enough words in it", "", "Last page also has enough words in it"])` | 2쪽 `charCount 0`, `hasTextLayer false`; 1·3쪽 true; `scanned false` |
| short page below 20 chars | `makePdf(["Too short"])` | `charCount 8`, `hasTextLayer false`, `scanned true` |
| scanned when half or more lack text | `makePdf(["", "Enough words here to count as text ok"])` | `scanned true` (2쪽 중 1쪽 = 절반) |
| not scanned below half | `makePdf(["", "Enough words here to count as text ok", "More than twenty chars of text on page"])` | `scanned false` |
| cleanPageText sorts by y then x | 항목 `{str:"world",transform:[1,0,0,1,60,700]}`, `{str:"hello ",transform:[1,0,0,1,10,700]}`, `{str:"top",transform:[1,0,0,1,10,720]}` | `"top\nhello world"` |
| cleanPageText collapses spaces | 항목 `"a   b\t c"` 한 개 | `"a b c"` |
| cleanPageText NFC | 항목 `"한"`(분해된 한) | `"한"`(조합형 한) |
| corrupt file | 바이트 `"not a pdf at all"`을 `.pdf`로 저장 | `extractPdfPages`가 `PdfError`로 reject, `code === "corrupt"` |
| truncated pdf | 정상 PDF 바이트의 앞 40%만 저장 | reject, `PdfError`, `code`가 `"corrupt"` 또는 `"unreadable"` |
| missing file | 없는 경로 | `PdfError`, `code === "unreadable"` |
| encrypted pdf | `pdf-lib`의 `PDFDocument`에는 암호화 기능이 없으므로 **손으로 쓴 최소 암호화 PDF**를 쓰지 않는다. 대신 `PasswordException` 분류를 순수 함수 `classifyPdfError({name:"PasswordException"})` → `"encrypted"`로 검증 | `classifyPdfError`를 `extract.ts`에서 내보내고(`(err: unknown) => PdfErrorCode`) 이름 4개(`PasswordException`→encrypted, `InvalidPDFException`→corrupt, `FormatError`→corrupt, `Error`→unreadable)를 표로 확인 |
| page limit | `makePdf` 3쪽, `extractPdfPages(path, { maxPages: 2 })` | `PdfError`, `code === "too_many_pages"` |
| default limit constant | — | `MAX_PDF_PAGES === 500` |

## 10. 명세 작성자 메모

- **충돌**: CATALOG의 "한국어·영어 3쪽 PDF를 `pdf-lib`로 만든다"는 불가능하다. `pdf-lib`의 표준 글꼴은 한글을 인코딩하지 못하고, 한글 글꼴 임베드에는 `@pdf-lib/fontkit`과 글꼴 파일이 필요한데 의존성은 P3-C만 더할 수 있다. 영어는 `pdf-lib`로, 한글은 손으로 쓴 최소 PDF(ToUnicode CMap)로 만든다. 이 한글 PDF에서 pdf.js가 글자를 돌려주는지는 **작성 시점에 실행해 보지 못했다**(미검증).
- 암호화 PDF 실물 테스트는 만들 수 없어 오류 분류 함수의 표 테스트로 대신한다.
- pdf.js가 Bun에서 가짜 워커를 자동으로 쓰는지는 미검증이다. 5단계 3번에 대체 경로를 적었다.
- 줄 묶기 임계값(y 차이 2)은 임의의 시작값이다. 6절의 "line order" 테스트가 통과하는 한 바꾸지 않는다.
