# P2-08 v1 화면 기능 대조표와 e2e

> 등급: `careful` · 게이트: `full` · 의존: `P2-03`, `P2-04`, `P2-05`, `P2-06` · 소유: `apps/web/`, `docs/v2/pipeline/PARITY.md`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

`apps/server/src/ui.ts`의 사용자 앱 화면이 하는 일을 **전부** 나열한 대조표 `docs/v2/pipeline/PARITY.md`를 만든다. 행마다 새 앱의 위치와, 그것을 덮는 e2e 테스트 이름(실제 `test("…")` 제목)을 적는다. 덮는 테스트가 없는 행은 테스트를 추가한다(`apps/web/e2e/`). 새 앱에 기능 자체가 없으면 상태를 `없음`으로 적고 사유를 쓴다. 그런 행은 **만들지 않는다.** 구현하지 않고 보고의 `NEEDS`에 올린다(`BLOCKED`로 멈추지 않는다). P2-09가 이 표를 읽는다.

## 5. 단계

1. `PARITY.md` 머리말: 한 문단(목적), 상태 값 설명(`있음` = 새 앱에 같은 일을 하는 기능이 있다 / `없음` = 새 앱에 없다), 마지막에 `없음` 행 개수를 적는 줄 `없음 행: N개`.
2. 표 형식(마크다운, 열 순서 고정):
   `| # | v1 기능 | v1 위치(ui.ts) | 새 앱의 위치 | 덮는 e2e 테스트 | 상태 |`
   "덮는 e2e 테스트"는 `파일명 › 테스트 제목` 형식이다. 한 행에 여러 개면 `;`로 잇는다. `없음` 행은 이 칸에 `-`, "새 앱의 위치" 칸에 사유를 쓴다.
3. 아래 **초안 행**을 출발점으로 삼는다. 각 행을 `git grep`과 화면 코드로 확인해 상태·위치·테스트를 채운다. 초안의 "예상"이 틀리면 고친다. 초안에 없는데 `ui.ts`에 있는 기능을 찾으면 행을 더한다(3절의 `data-action` 목록과 `fetch('/api` 목록이 빠짐없는지 마지막에 대조한다).

4. 덮는 테스트가 없는 `있음` 행마다 e2e를 **추가**한다. 새 server e2e는 `apps/web/e2e/server/parity.e2e.ts`(`import { expect, test } from "../fixtures.ts"`, 로그인은 `flow.e2e.ts`의 `signIn` 방식). 서버 없이도 확인되는 순수 UI 행(테마, 좁은 화면 탭)은 `apps/web/e2e/parity.e2e.ts`(fixture 프로젝트). 이 파일은 **노트 본문·오디오를 바꾸지 않는다**(바꾸는 server e2e는 `zz-`로 시작해 마지막에 돈다). 최소로 추가할 것(이미 덮여 있으면 추가하지 않는다):
   - 테마 전환: 사용자 메뉴 `테마 전환`을 누르면 `html`의 `data-theme`(또는 `color-scheme` 결과)이 바뀌고 새로 고쳐도 유지된다.
   - 검색: 라이브러리 검색창에 노트 제목 일부(`블록 암호`)를 쓰면 그 노트만 목록에 남는다(server). `/` 키로 검색창 포커스.
   - 좁은 화면: `page.setViewportSize({ width: 390, height: 844 })`에서 녹음 상세에 `녹음 보기` 탭 목록(탭 `문서`·`전사`·`자료`·`물어보기`)이 있고 키보드로 전환된다.
   - 마이크 녹음: `test.use({ permissions: ["microphone"], launchOptions: { args: ["--use-fake-ui-for-media-stream", "--use-fake-device-for-media-stream"] } })`로 업로드 대화상자의 녹음을 시작·일시정지·종료할 수 있는지(fixture). 세 번 시도해도 안 되면 그 행의 e2e 칸에 이를 덮는 단위 테스트 이름(`apps/web/test/…`)과 이유를 쓴다. 이 경우에만 단위 테스트를 허용한다.
   - 노트 삭제(server): 업로드한 뒤가 아니라 **임시로 만든 녹음**을 지워야 한다. 기존 노트 두 개를 지우지 않는다. 임시 녹음이 필요하면 server e2e 안에서 `page.request`로 만든다. 그게 어려우면 fixture e2e의 삭제 테스트(`a11y.e2e.ts`의 `library bulk delete confirmation…` 등)를 덮는 테스트로 적고 server 칸은 비운다는 사유를 쓴다.
5. `없음` 행: 구현하지 않는다. 행의 "새 앱의 위치"에 `없음: <이유 한 문장>`을 쓰고 상태 `없음`. 맨 아래 `없음 행: N개`를 맞춘다. 보고서 `NEEDS`에 `없음 행 N개: #4, #6, … (P2-09 전에 구현할지 사용자가 정해야 한다)`를 쓴다.
6. 표의 모든 행에 대해 "덮는 e2e 테스트" 칸의 제목이 실제 파일에 존재하는지 확인하는 스크립트성 테스트를 만든다(6절).

## 6. 테스트

파일: `apps/web/test/parity-doc.test.ts` (`bun test`가 도는 단위 테스트. 모델: `test/styles.test.ts`가 파일을 읽는 방식)

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| 대조표 형식 | `docs/v2/pipeline/PARITY.md` 읽기 | 표의 모든 데이터 행이 6열이다. 상태 칸은 `있음` 또는 `없음`으로 시작한다 |
| 행마다 e2e 또는 사유 | 각 행 | `있음` 행은 "덮는 e2e 테스트"가 `-`가 아니다. `없음` 행은 "새 앱의 위치"가 `없음:`으로 시작한다 |
| e2e 이름이 실제로 있다 | 각 `파일명 › 제목` | 그 파일(`apps/web/e2e/<파일명>` 또는 `apps/web/e2e/server/<…>`)에 `test("제목"` 또는 ``test(`제목` ``이 문자열로 들어 있다. 단위 테스트 예외 행은 `apps/web/test/<…>.test.ts` 존재만 확인 |
| 없음 개수 줄 | 마지막 줄 `없음 행: N개` | N이 `없음` 행 수와 같다 |
| ui.ts 기능 누락 없음 | `apps/server/src/ui.ts`에서 `data-action="…"` 이름 추출 | 모든 이름이 `PARITY.md` 본문 어딘가에 나온다(예: 행의 "v1 기능" 칸의 백틱 안). 단 `close-modal`, `auth-mode`는 행 #2에 묶어 적어도 된다 |

새 e2e 테스트(4단계)는 각각 한 개씩이고 이름은 한국어/영어 자유다. 모두 `axe`를 최소 한 번 호출한다(해당 화면에서).

## 8. 하지 않는 것

- 새 앱에 없는 기능을 이 WP에서 만드는 일(`없음` 행). 사용자 결정이 필요하다.
- `apps/server/src/ui.ts`, `CONTRACTS.md`, `CATALOG.md` 수정.
- 기존 e2e 단언을 지우거나 느슨하게 만들기, 기존 시드 노트를 바꾸거나 지우기.
- `LECTERN_WEB_SHELL` 기본값 변경: P2-09.

## 9. 끝났다는 기준

- [ ] 6절의 테스트가 모두 있고 통과한다
- [ ] 7절의 게이트가 통과한다
- [ ] 바뀐 파일이 전부 소유 경로 안이다
- [ ] 실제 외부 호출이 없다
- [ ] `PARITY.md`의 모든 행에 e2e 이름이 있거나 `없음` 사유가 있다, `ui.ts`의 모든 `data-action`이 표에 있다, 보고서 `NEEDS`에 `없음` 행 목록이 있다

## 10. 명세 작성자 메모

- 초안의 "없음 예상"은 이 명세 작성 때 `apps/web/src`를 `git grep`한 결과다(비밀번호 변경, API 토큰, 과목 정리, 오디오 내려받기 등은 흔적을 찾지 못했다). 워커가 다시 확인해 확정한다. 이 행들이 남으면 P2-09는 계약대로 BLOCKED다.
- **중요(계약 밖)**: v1 `/`는 로그아웃 상태에서 서비스 소개와 개인정보·이용약관 링크를 보여 주는 공개 홈페이지다(Google OAuth 검증용, 커밋 `e595ea9`). `/`가 `/app/login`으로 가면 이 소개가 사라질 수 있다. 행 #29가 `없음`이면 반드시 보고한다.
- 노트 삭제 같은 파괴적 server e2e는 시드 노트 두 개를 다른 spec이 쓰기 때문에 조심해야 한다(4단계). 임시 녹음을 만드는 쉬운 방법은 확인하지 못했다.
- `ui.ts` 4천 줄 구간을 읽지 않고 `data-action`·`fetch` 목록으로 행을 뽑았다. 행이 모자라면 5단계 3번의 대조가 잡는다.
