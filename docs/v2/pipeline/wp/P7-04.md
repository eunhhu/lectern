## 1. 목표

마우스 없이 서비스를 처음부터 끝까지 쓸 수 있다는 것을 e2e 하나로 고정한다: 가입 → 업로드 → 문서 → 공유 → 설정 → 관리자. 그리고 자동으로 확인할 수 없는 것(VoiceOver가 실제로 무엇을 읽는가)을 화면별 수동 점검표로 만든다. 점검표의 수동 항목은 사람이 채운다.

## 5. 단계

1. `apps/web/e2e/keyboard-only.ts`
   ```ts
   import { expect, type Page } from "@playwright/test";
   import { tabTo } from "./fixtures.ts";
   export { tabTo };
   /** Types into the focused field (the caller reached it with Tab). Never uses locator.fill(). */
   export async function typeInto(page: Page, text: string): Promise<void>
   /** Presses `key` until the focused element's accessible name matches; fails after `max` presses. */
   export async function pressUntil(page: Page, key: string, name: string | RegExp, max?: number): Promise<void>
   /** The focused element is visible and matches :focus-visible. */
   export async function expectFocusVisible(page: Page): Promise<void>
   /** Activates the focused control with Enter (or Space when `space` is true). */
   export async function activate(page: Page, space?: boolean): Promise<void>
   ```
   - 포커스된 요소의 이름을 읽는 방법은 `tabTo`와 같다(`aria-label` → `aria-labelledby` → 텍스트).
   - `typeInto`는 `page.keyboard.type(text)`. 칸에 값이 있으면 먼저 전체 선택(`ControlOrMeta+A`) 후 입력한다.
2. `zzz-keyboard-journey.e2e.ts` — `import { expect, test } from "../fixtures.ts"`. `test.describe.configure({ mode: "serial" })`. **이 파일에서 쓸 수 있는 조작은 `page.goto`, `page.keyboard.*`, `page.waitForEvent("filechooser")`와 `fileChooser.setFiles`(OS의 파일 대화상자는 Playwright가 키보드로 다룰 수 없다)뿐이다.** 읽기(`expect`, `getByRole(...)`의 단언, `page.evaluate`로 포커스 읽기)는 자유다.
   각 화면에서 `expectFocusVisible`을 한 번 이상, 화면이 바뀔 때마다 `axe(page, "<이름>")`을 부른다.

   **여정 A — 새 사용자**(계정 이메일은 `journey-<Date.now()>@example.com`, 비밀번호는 이 테스트 전용 값을 파일 상수로)
   1. `page.goto("/app/login")` → `tabTo(page, "회원가입")` → Enter → `/app/signup`.
   2. 이름·이메일·비밀번호·비밀번호 확인 칸을 Tab으로 옮겨 다니며 `typeInto`. 이 서버에는 메일 키가 없어 인증번호 없이 가입된다(P2-03). `tabTo(page, "가입하기")` → Enter → 홈(`/app` 또는 `/app/`)으로 간다. 제목(`<h1>`)이 보인다.
   3. 업로드: 단축키 `u`(또는 `tabTo`로 `올리기` 버튼) → 대화상자. 파일 선택 버튼에 포커스를 두고 `page.waitForEvent("filechooser")`와 Enter를 같이 기다려 `wav(8)` 파일 `키보드 여정.wav`를 넣는다(`keyboard.e2e.ts`가 하는 방식 그대로). `tabTo(page, "올리기")` → Enter → `녹음 1개를 올렸습니다.`.
   4. 홈이나 라이브러리에서 방금 올린 녹음 줄로 Tab·화살표로 이동 → Enter → 녹음 화면. 작업 러너가 없으므로 상태는 대기·처리 중이다. 그 상태 안내가 보이고 `role="status"` 또는 제목으로 읽힌다는 것을 단언한다(문구는 화면의 실제 문구를 쓴다).
   5. 설정: 사용자 메뉴(`tabTo`로 메뉴 버튼 → Enter → 화살표로 `설정` → Enter) → `/app/settings`. 표시 이름 칸에 `typeInto(page, "여정 사용자")` → `tabTo(page, "저장")` → Enter → 저장 알림.
   6. 로그아웃: 사용자 메뉴 → `로그아웃` → Enter → `/app/login`.

   **여정 B — 운영자**(`E2E_OWNER_EMAIL`, `E2E_OWNER_PASSWORD`)
   1. 로그인 화면에서 이메일·비밀번호를 `typeInto` → Enter → 홈.
   2. 라이브러리로 이동(내비게이션 링크를 `tabTo` → Enter). 목록에서 `E2E_LECTURES[0].title` 줄로 이동 → Enter → 녹음 화면.
   3. 문서: 본문 제목이 보인다. 문서 안의 시각 표시나 출처 버튼까지 `tabTo` → Enter → 플레이어의 재생 위치(`slider` `재생 위치`의 `aria-valuetext`)가 바뀐다.
   4. 공유: `tabTo(page, "녹음 작업")` → Enter → 화살표로 `공유…` → Enter → 대화상자 `공유`. `tabTo(page, "링크 만들기")` → Enter → `공유 링크` 칸에 값이 생긴다. Esc → 포커스가 `녹음 작업` 버튼으로 돌아온다.
   5. 설정 화면을 연다(여정 A의 5와 같은 방법). 구역 제목들을 차례로 지나갈 수 있다(각 구역의 첫 조작 요소에 Tab으로 닿는다).
   6. 관리자: 사용자 메뉴나 내비게이션의 `관리자`(실제 이름은 `AdminLayout`·내비게이션에서 읽는다) → Enter → `/app/admin`. 관리자 내비게이션의 **모든 링크**를 차례로 `tabTo` → Enter 하고, 페이지마다 `<h1>`이 보이는지와 `axe`를 확인한다. 표가 있는 페이지에서는 표 안으로 포커스가 들어가고 나올 수 있다(Tab으로 표 다음 요소에 닿는다 — 키보드 함정이 없다).
   7. 로그아웃.
   - 관리자 화면에서 **아무것도 바꾸지 않는다**(재시도, 쿼터 저장, 유지보수 실행 버튼을 누르지 않는다).
   - 대기는 `expect(...).toBeVisible()`류로 한다. `waitForTimeout`은 쓰지 않는다.
3. `apps/web/test/keyboard-only.test.ts`: `e2e/server/zzz-keyboard-journey.e2e.ts`의 소스를 읽어 다음 문자열이 **없는지** 검사한다: `.click(`, `.dblclick(`, `.tap(`, `.hover(`, `.dragTo(`, `.mouse.`, `.fill(`, `.check(`, `.uncheck(`, `.selectOption(`, `.focus(`, `.setInputFiles(`, `.dispatchEvent(`, `waitForTimeout(`. 그리고 `keyboard.press(`가 20번 이상, `axe(page`가 8번 이상 있는지.
4. 여정을 돌린다: `cd apps/web && bunx playwright test e2e/server/zzz-keyboard-journey.e2e.ts --project server`(빌드가 필요하면 `bun run web:build` 먼저).
5. 막히는 곳이 나오면 원인을 가른다.
   - **테스트가 틀렸다**(이름을 잘못 적었다, 순서가 다르다) → 테스트를 고친다.
   - **화면의 접근성 결함이다**(Tab으로 닿지 않는 버튼, 이름 없는 버튼, 대화상자를 닫은 뒤 포커스가 사라진다, 포커스 표시가 없다, 키보드 함정) → 6단계.
6. 결함 수정의 범위: 한 결함당 **한 파일, 20줄 이내**로 고칠 수 있는 것만 고친다 — `aria-label` 추가, `<div onClick>`을 `<button>`으로, 포커스 복귀, `tabIndex` 정리. 고친 것은 `A11Y-AUDIT.md`의 "이 작업에서 고친 것" 표에 적는다(화면, 증상, 고친 파일). 그보다 큰 결함(컴포넌트 구조를 바꿔야 한다, 디자인 결정이 필요하다)은 고치지 않는다: 여정에서 그 단계를 `test.fixme`로 두지 말고, **여정을 실패한 채로 두고 `RESULT: BLOCKED`**로 보고한다(`NEEDS`에 화면·증상·재현 키 순서).
7. `docs/v2/pipeline/A11Y-AUDIT.md`를 쓴다. 구조:
   - `## 1. 기준` — WCAG 2.2 AA, DESIGN §5. 자동(axe, 키보드 e2e)과 수동(VoiceOver, 확대, 대비)의 구분.
   - `## 2. 자동 확인 범위` — 표: 화면(경로) / axe를 도는 e2e 파일 / 키보드 e2e 파일. `router.tsx`의 모든 경로가 한 줄씩 있어야 한다. e2e가 없는 화면은 칸에 `없음`이라고 적는다(숨기지 않는다). `git grep -n "axe(page, " -- apps/web/e2e`의 라벨로 채운다.
   - `## 3. 이 작업에서 고친 것` — 6단계의 표(없으면 "없음").
   - `## 4. VoiceOver 수동 점검표` — 화면별 소절. 각 소절은 표: 확인 항목 / 기대 / 결과(빈칸) / 확인한 날. 화면: 로그인, 회원가입, 비밀번호 재설정, 홈, 라이브러리(폴더 트리·목록), 업로드 대화상자, 녹음 상세(문서·전사·플레이어·출처), 문서 편집, 공유 대화상자, 공개 공유 페이지(`/s/…`), 물어보기, 일정, 설정(각 구역), 초대 수락, 관리자(각 페이지), 명령 팔레트(⌘K), 단축키 표. 화면마다 공통 항목 7개와 그 화면만의 항목 2~4개:
     1. 페이지에 들어가면 제목(문서 제목과 `<h1>`)을 읽는다
     2. 로터의 랜드마크 목록에 내비게이션·본문이 있다
     3. 로터의 제목 목록이 화면 구조와 맞다
     4. 모든 버튼·링크·입력 칸의 이름을 읽는다(아이콘 버튼 포함)
     5. 상태가 바뀌면 알려 준다(저장됨, 오류, 업로드 진행, 처리 완료)
     6. 대화상자·메뉴를 열면 그 안으로 가고, 닫으면 연 곳으로 돌아온다
     7. 오류 문구가 해당 입력 칸과 함께 읽힌다
     - 화면별 예: 녹음 상세 — "재생 중 현재 전사 줄이 바뀔 때 계속 읽어 대지 않는다", "출처 버튼이 `출처 1, 12분 30초` 식으로 읽힌다", "재생 위치 슬라이더의 값이 시간으로 읽힌다". 라이브러리 — "폴더 트리의 펼침 상태와 단계가 읽힌다", "선택한 녹음 수가 읽힌다". 관리자 — "표의 열 제목이 칸과 함께 읽힌다".
   - `## 5. 그 밖의 수동 항목` — 200% 확대에서 가로 스크롤 없음, 320 px 폭, 다크 모드 대비(계산값이 아니라 눈으로), 동작 줄이기(`prefers-reduced-motion`), 키보드만으로 Safari·Firefox에서 여정 한 번.
   - `## 6. 확인 방법` — macOS VoiceOver 켜는 법(⌘F5), 로터(VO+U), 이 점검표를 채우는 순서, 결함을 찾았을 때 적는 곳(STATUS "넘겨받은 요청").
   - **결과 칸은 비워 둔다.** 워커가 "확인함"이라고 적지 않는다(VoiceOver를 실제로 듣지 않았다).
8. `apps/web/README.md`의 테스트 절에 한 줄: 키보드 전용 여정(`e2e/server/zzz-keyboard-journey.e2e.ts`: 가입 → 업로드 → 설정, 로그인 → 문서 → 공유 → 설정 → 관리자)과 `docs/v2/pipeline/A11Y-AUDIT.md` 링크.

## 8. 하지 않는 것

- 점검표의 수동 결과를 채우는 것(사람이 한다. STATUS "실측 필요").
- 큰 접근성 개편, 디자인 변경, 새 컴포넌트.
- 서버·`packages/` 수정.
- 처리 완료까지 기다리는 여정(작업 러너가 필요하다. `process.e2e.ts`가 따로 본다).
- 네이티브 앱의 접근성(각 앱의 `MANUAL_CHECKS.md`에 있다).

## 9. 끝났다는 기준

- [ ] 여정 e2e 두 개가 통과한다
- [ ] 여정 파일에 마우스·`fill` 류 호출이 없다(테스트가 지킨다)
- [ ] 게이트 `full`이 통과한다
- [ ] `A11Y-AUDIT.md`에 모든 경로의 자동 확인 범위와 화면별 수동 점검표가 있고, 결과 칸이 비어 있다
- [ ] 고친 결함이 있으면 §3 표에 있다

## 10. 명세 작성자 메모

- CATALOG의 한 줄 여정(가입 → … → 관리자)을 두 계정으로 나눴다. 새 계정은 운영자가 아니고, 이 e2e 서버에서는 작업이 돌지 않아 새로 올린 녹음에 문서가 생기지 않기 때문이다. 문서·공유·관리자는 시드된 운영자 계정의 노트로 본다.
- 화면의 실제 이름(버튼 라벨, 메뉴 항목)은 앞선 작업들이 정했다. 이 명세의 이름(`올리기`, `녹음 작업`, `공유…`, `링크 만들기`, `저장`, `로그아웃`)은 그 명세들에서 가져왔지만, 다르면 화면이 기준이다.
- `fileChooser.setFiles`는 키보드 조작이 아니다. 파일 선택 대화상자는 OS의 것이라 자동화할 수 없어 예외로 뒀다. 대화상자를 여는 것까지는 키보드(Enter)로 한다.
- 가입 화면의 칸 이름과 인증번호 없이 가입되는 조건은 P2-03의 명세에 기댔다.
