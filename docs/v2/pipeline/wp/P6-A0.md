# P6-A0 macOS: 토큰을 Keychain으로

> 등급: `basic` · 게이트: `apple` · 의존: 없음 · 소유: `apps/macos/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

지금의 macOS 메뉴바 앱은 API 토큰을 `UserDefaults`에 평문으로 둔다. 이것을 Keychain으로 옮긴다. 이미 로그인한 사용자는 업데이트 뒤 첫 실행 때 토큰이 자동으로 Keychain으로 옮겨지고 `UserDefaults`의 값은 지워진다. 다시 로그인할 필요가 없다.

## 2. 먼저 읽을 것

- 계약: `CONTRACTS.md` D-P6-11(기존 `apps/macos`에는 이 작업만 한다)
- 문서: `docs/v2/NATIVE.md` §2 "바로 고칠 것", §7 N0
- 코드: `apps/macos/Package.swift`(실행 타깃 하나, `swift-tools-version: 5.9`, macOS 13)
- 코드: `apps/macos/Sources/LecternMenuBar/main.swift` — `lectern_auth_token`을 읽는 곳 1개(`@Published var authToken`), 쓰는 곳 1개(로그인 성공), 지우는 곳 1개(로그아웃)
- 코드: `apps/macos/build-app.sh`(번들 id와 서명. 고치지 않는다)

## 3. 사전 점검

```bash
git grep -n "lectern_auth_token" -- apps/macos
git grep -n "kSecClass" -- apps/macos
cd apps/macos && swift build 2>&1 | tail -3
```
첫 명령은 3줄(읽기·쓰기·지우기), 둘째는 0줄이어야 한다. 셋째가 실패하면(이 작업 전부터 빌드가 안 됨) 멈추고 출력을 보고한다.

## 5. 단계

1. `Package.swift`: 타깃을 더한다(기존 실행 타깃의 설정은 그대로 두고 의존만 더한다).
   ```swift
   .target(name: "LecternMenuBarCore", path: "Sources/LecternMenuBarCore", linkerSettings: [.linkedFramework("Security")]),
   .testTarget(name: "LecternMenuBarCoreTests", dependencies: ["LecternMenuBarCore"], path: "Tests/LecternMenuBarCoreTests"),
   ```
   실행 타깃에 `dependencies: ["LecternMenuBarCore"]`.
2. `TokenStore.swift`
   ```swift
   import Foundation
   import Security

   public protocol TokenStore {
       func read() -> String?
       @discardableResult func write(_ token: String) -> Bool
       func delete()
   }

   /// The parts of UserDefaults the migration needs. UserDefaults conforms as is.
   public protocol LegacyDefaults {
       func string(forKey defaultName: String) -> String?
       func removeObject(forKey defaultName: String)
   }
   extension UserDefaults: LegacyDefaults {}

   public final class KeychainTokenStore: TokenStore {
       public init(service: String = "com.qucord.lectern.macos", account: String = "auth_token")
       // kSecClassGenericPassword, kSecAttrService, kSecAttrAccount,
       // kSecAttrAccessible = kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly
       // write: SecItemUpdate first, SecItemAdd when the item is missing. Returns false on any other status.
       // read: SecItemCopyMatching with kSecReturnData, kSecMatchLimitOne. nil when missing or not UTF-8.
       // delete: SecItemDelete, ignoring errSecItemNotFound.
   }

   public final class InMemoryTokenStore: TokenStore { public init(_ initial: String? = nil) }   // tests and fallback

   public let legacyTokenKey = "lectern_auth_token"

   /// Moves a token left in UserDefaults into the store. Returns true when something was moved.
   /// The UserDefaults value is removed only after the store confirmed the write.
   @discardableResult
   public func migrateLegacyToken(defaults: LegacyDefaults, store: TokenStore) -> Bool
   ```
   `migrateLegacyToken` 규칙
   - `UserDefaults`에 값이 없거나 빈 문자열이면: 빈 문자열은 지우고 `false`.
   - 저장소에 이미 토큰이 있으면: 저장소 것을 그대로 두고 `UserDefaults` 값만 지운다(`false`).
   - 저장소가 비어 있으면: `store.write(값)`이 `true`이고 `store.read() == 값`일 때만 `UserDefaults` 값을 지우고 `true`. 쓰기가 실패하면 **아무것도 지우지 않는다**(다음 실행 때 다시 시도한다. 로그인이 풀리면 안 된다).
3. `main.swift`
   - 파일 위에 `import LecternMenuBarCore`. 앱 상태 객체에 `private let tokenStore: TokenStore = KeychainTokenStore()`.
   - `@Published var authToken`의 초기값: 초기화 전에 `migrateLegacyToken(defaults: UserDefaults.standard, store: tokenStore)`를 한 번 부르고 `tokenStore.read() ?? ""`를 쓴다. 프로퍼티 초기화 순서 때문에 한 줄로 안 되면 정적 도우미 `static func loadToken() -> String`을 만들어 초기값으로 쓴다.
   - 로그인 성공: `UserDefaults.standard.set(user.apiToken, forKey: "lectern_auth_token")` → `tokenStore.write(user.apiToken)`.
   - 로그아웃: `UserDefaults.standard.removeObject(forKey: "lectern_auth_token")` → `tokenStore.delete()`.
   - `lectern_user_label`, `lectern_login_email`, `lectern_course`는 비밀이 아니다. 그대로 둔다.
4. `git grep -n "lectern_auth_token" -- apps/macos/Sources/LecternMenuBar`가 0줄인지 본다(키 이름은 `LecternMenuBarCore`의 상수에만 남는다).

## 6. 테스트

`TokenStoreTests.swift` (XCTest. `InMemoryTokenStore`와 가짜 `LegacyDefaults`를 쓴다. 실제 Keychain과 `UserDefaults.standard`는 건드리지 않는다)

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| `testMovesLegacyToken` | defaults에 `abc`, 저장소 비어 있음 | `true`, 저장소 `abc`, defaults에서 지워짐 |
| `testNothingToMove` | defaults 비어 있음 | `false`, 저장소 그대로 |
| `testEmptyLegacyValueIsRemoved` | defaults에 `""` | `false`, defaults에서 지워짐, 저장소 `nil` |
| `testKeepsExistingKeychainToken` | defaults `old`, 저장소 `new` | `false`, 저장소 `new`, defaults에서 지워짐 |
| `testFailedWriteKeepsLegacyValue` | `write`가 항상 `false`인 가짜 저장소 | `false`, defaults에 `abc`가 남아 있다 |
| `testRunningTwiceIsHarmless` | 한 번 옮긴 뒤 다시 | 두 번째 `false`, 저장소 그대로 |
| `testInMemoryStoreRoundTrip` | `write` → `read` → `delete` → `read` | 값, `nil` |

`KeychainTokenStore`의 실제 동작(Keychain 접근)은 단위 테스트하지 않는다. 서명되지 않은 테스트 실행에서 Keychain 접근이 대화상자를 띄울 수 있어서다. 확인 방법은 10절에 있다.

## 8. 하지 않는 것

- 메뉴바 앱의 다른 부분(녹음, 업로드, UI)을 고치지 않는다. `main.swift`를 파일로 나누지 않는다.
- 번들 id, 서명, `build-app.sh`, 최소 OS 버전을 바꾸지 않는다.
- 새 앱(`apps/apple`)은 이 작업과 무관하다.

## 9. 끝났다는 기준

- [ ] `swift build`와 `swift test`가 통과한다
- [ ] 실행 타깃에 `lectern_auth_token`을 `UserDefaults`로 읽고 쓰는 코드가 없다
- [ ] 쓰기가 실패하면 옛 값이 남는다(테스트)

## 10. 명세 작성자 메모

- 사람이 확인할 것(STATUS "실측 필요"): 옛 버전으로 로그인한 Mac에서 새 빌드를 실행 → 로그인이 유지되는지, `defaults read com.qucord.lectern.macos lectern_auth_token`이 "does not exist"인지, 키체인 접근 앱에 `com.qucord.lectern.macos` 항목이 있는지.
- 서명이 바뀌면(ad-hoc 서명 빌드 사이) Keychain 항목을 읽을 때 macOS가 허용 여부를 물을 수 있다. 공증된 빌드(P6-A12)에서는 묻지 않는다.
- `pipeline.json`의 게이트 이름은 `apple`이지만 이 작업의 검증은 7절의 두 명령이다(`apps/apple`이 아직 없을 수 있다). ORCHESTRATOR의 게이트 표에 그렇게 적혀 있다.
