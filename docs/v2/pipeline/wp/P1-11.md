# P1-11 노트 발행과 브리지 (서버)

> 등급: `careful` · 게이트: `full` · 의존: `P1-09, P1-10` · 소유: `apps/server/`, `packages/db/src/legacy.ts`, `packages/db/test/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

`runNotesPipeline`의 결과(`NotesResult`)를 DB에 발행하는 `publishNotes`를 만든다. 한 트랜잭션으로 구조화 문서 버전, 일정 후보, 할 일, 녹음의 제목·도메인·`template_id`, 그리고 `lectures.markdown` 브리지를 쓴다. 그와 함께 `packages/db/src/legacy.ts`의 `projectLecture`가 브리지 규칙(D-P1-3)을 따르게 한다. 강의 Markdown이 구조화 문서의 현재 `rendered_md`와 같으면 legacy 문서를 만들지 않고, 다르면(v1 클라이언트가 고침) 지금처럼 legacy 버전을 만들고 구조화 문서에 `user_edited = 1`을 표시한다. 이 패키지는 동작 변화가 없다(호출하는 코드는 `P1-12`).

## 5. 단계

1. `legacy.ts`에 비공개 도우미를 더한다.
   ```ts
   /** The recording's newest structured (non-legacy) document and its current Markdown, or null. */
   function structuredDocument(sqlite: Database, recordingId: string): { id: string; rendered_md: string; md_source_path: string | null } | null {
     return sqlite.query(
       `SELECT d.id, d.md_source_path, v.rendered_md FROM document d
        JOIN document_version v ON v.document_id = d.id AND v.version = d.current_version
        WHERE d.recording_id = ? AND d.template_id != '${LEGACY_TEMPLATE_ID}'
        ORDER BY d.created_at DESC, d.id DESC LIMIT 1`
     ).get(recordingId) as any ?? null;
   }
   ```
2. `projectDocument`(같은 파일)에 **비교 하나**를 더한다. 함수 맨 앞에서 `const structured = structuredDocument(sqlite, recordingId);`를 구한다.
   - legacy 문서가 **없는** 분기(`!doc`): `l.markdown === ""`이면 지금처럼 `false`. 아니면 `structured && structured.rendered_md === l.markdown`일 때 legacy 문서를 만들지 않고 `bridgeSourcePath(structured)`만 하고 반환한다. 다르면(또는 구조화 문서 없음) 지금 코드 그대로 legacy 문서와 버전 1을 만든다. 구조화 문서가 있는데 달랐다면 같은 분기에서 `UPDATE document SET user_edited = 1, updated_at = ? WHERE id = ?`(구조화 문서)를 한다.
   - legacy 문서가 **있는** 분기: `current.rendered_md === l.markdown`이면 지금처럼 반환(변경 없음). 다르면 먼저 `structured && structured.rendered_md === l.markdown`인지 본다. 같으면 새 legacy 버전을 만들지 않고 반환한다(`bridgeSourcePath` 호출). 다르면 지금 코드대로 새 legacy 버전을 만들고, 구조화 문서가 있으면 `user_edited = 1`을 건다.
   - `bridgeSourcePath(structured)`: `structured.md_source_path !== l.md_source_path`이면 `UPDATE document SET md_source_path = ? WHERE id = ?`를 하고 `true`를 돌려준다.
   - 다른 곳(폴더, 오디오, 공유 링크)은 건드리지 않는다.
3. `projectLectureTx`(같은 파일)의 `status` 계산에 **비교 하나**를 더한다: `rec?.status === "partial" && l.status === "done"`이면 `status = "partial"`(그 외는 `recordingStatusOf(l.status)` 그대로). 이때 `failureCode`·`failureMessage`도 계산값(`null`) 대신 `rec.failure_code`·`rec.failure_message`를 그대로 유지한다. `process` 작업이 `partial`로 끝낸 녹음(이유 코드·한국어 메시지 포함)이 다음 투영에서 `ready`/`null`로 되돌아가지 않게 하기 위해서다. `verifyLegacy`는 이 두 필드를 비교하지 않는다.
3b. `projectAudio`(같은 파일)에 **비교 하나**를 더한다: 녹음에 오디오 asset이 둘 이상(`SELECT COUNT(*) FROM asset WHERE recording_id = ? AND kind = 'audio'` > 1)이면 첫 오디오 asset의 `duration_ms`를 강의 길이로 덮어쓰지 않는다(`existing.duration_ms === durationMs` 비교와 `UPDATE`의 `duration_ms`에서 기존 값을 유지). 여러 파트 업로드(`P1-14`)에서 파트 길이가 파트별로 남게 하기 위해서다. 오디오 asset이 하나뿐이면 이전과 같다.
4. `verifyLegacy`(같은 파일)에 비교 두 곳을 더한다. 기존 필드 이름(`FIELDS`)·체크섬 형식은 바꾸지 않는다.
   - `v2.markdown`: legacy 문서의 `rendered_md`가 `l.markdown`과 다르고 `structuredDocument(sqlite, r.id)?.rendered_md === l.markdown`이면 그 구조화 문서의 Markdown으로 계산한다(`archive`도 그 문서의 `md_source_path`). 구조화 문서가 없거나 다르면 지금과 같다.
   - `v2.status`: `r.status === "partial"`이고 `l.status === "done"`이면 `"ready"`로 정규화해 비교한다.
   - `counts.documents.v2`: 지금 식에 더해 "legacy 문서가 비었거나 없지만 구조화 문서의 현재 Markdown이 강의 Markdown과 같은 강의 수"를 더한다. SQL: `lectures l JOIN recording r ON r.lecture_id = l.id JOIN document d ON d.recording_id = r.id AND d.template_id != 'legacy-markdown' JOIN document_version v ON ... WHERE l.markdown != '' AND v.rendered_md = l.markdown AND NOT EXISTS (legacy 문서의 현재 버전이 비어 있지 않고 l.markdown과 같음)`. 한 강의를 두 번 세지 않게 `COUNT(DISTINCT l.id)`.
5. `apps/server/src/notes-publish.ts`를 만든다(`index.ts` import 금지).
   ```ts
   import type { NotesResult } from "@lectern/harness";
   export interface PublishNotesInput { recordingId: string; workspaceId: string; result: NotesResult; keepTitle?: boolean }
   export interface PublishNotesResult { documentId: string; version: number; events: number; actionItems: number; lectureId: string | null }
   export function publishNotes(input: PublishNotesInput): PublishNotesResult
   ```
   `keepTitle`은 계약 시그니처에 더하는 선택 필드다: 사용자가 정한 제목(업로드 힌트, 편집)을 덮어쓰지 않기 위해 `P1-12`·`P1-13`이 준다.
6. `publishNotes` 본문은 `transact(() => {...})` 한 번(`api/v2/store.ts`). 안에서 순서대로:
   1. 녹음 행을 읽는다. 없으면 `Error("recording not found")`.
   2. **문서**: `structuredDocument` 식과 같은 조건으로 기존 구조화 문서를 찾는다. 없으면 `INSERT INTO document (id, workspace_id, recording_id, template_id, template_version, current_version, user_edited, md_source_path, created_at, updated_at) VALUES (uuidv7(), ?, ?, ?, ?, 1, 0, NULL, ?, ?)`와 버전 1. 있으면 `version = current_version + 1`로 `UPDATE document SET template_id = ?, template_version = ?, current_version = ?, updated_at = ?`. 버전 행: `INSERT INTO document_version (id, workspace_id, document_id, recording_id, version, base_version, template_id, template_version, body_json, rendered_md, created_by, author_id, created_at) VALUES (documentVersionId(docId, v), ..., NULL, ..., JSON.stringify(result.body), result.markdown, 'ai', NULL, now)`. `user_edited`는 건드리지 않는다.
   3. **일정(D-P1-5)**: `DELETE FROM event_candidate WHERE recording_id = ? AND status = 'suggested'`. 남은 행(`accepted`·`dismissed`·`synced`)의 키 집합 `norm(title) + "|" + 시작일(tz 기준 YYYY-MM-DD)`을 만든다. `result.events`를 돌며 키가 집합에 있으면 버리고, 아니면 `INSERT INTO event_candidate (id, workspace_id, recording_id, kind, title, start_at, end_at, all_day, tz, raw_expression, resolution_json, confidence, evidence_json, flags_json, status, created_at, updated_at) VALUES (uuidv7(), ..., 'suggested', now, now)`. `resolution_json`·`evidence_json`·`flags_json`은 `JSON.stringify`. `all_day`는 0/1.
   4. **할 일(D-P1-5)**: `DELETE FROM action_item WHERE recording_id = ? AND status = 'open' AND updated_at = created_at`(사용자가 고치지 않은 열린 것만). 남은 행의 키 `norm(text) + "|" + (due_at의 날짜 | "none")`과 같은 새 항목은 버린다. 나머지는 `INSERT INTO action_item (id, workspace_id, recording_id, text, owner_name, due_at, due_raw, status, evidence_json, flags_json, created_at, updated_at) VALUES (uuidv7(), ..., 'open', ?, ?, now, now)`.
   5. **녹음**: `UPDATE recording SET domain = ?, template_id = ?, language = ?, title = ?, updated_at = ? WHERE id = ?`. `domain = result.classification.domain`, `template_id = result.template.id`, `language = result.classification.language`, `title = keepTitle ? 기존 : result.classification.title`. 상태는 바꾸지 않는다(`P1-12`가 한다).
   6. **브리지(D-P1-3)**: 녹음의 `lecture_id`가 있으면 `UPDATE lectures SET markdown = ?, excerpt = ?, title = ?, status = 'done', stage = 'done', stage_message = '완료', progress = 100, error_message = NULL, updated_at = ? WHERE id = ?`. `markdown = result.markdown`, `excerpt = extractExcerpt(result.markdown)`(`packages/core/src/index.ts`, `db.ts`와 같은 함수), `title`은 5번과 같은 값, `updated_at`은 ISO 문자열(`new Date().toISOString()`).
   - `norm(s)`: `s.normalize("NFKC").toLowerCase().replace(/[\s\p{P}]+/gu, " ").trim()`. 파일 안 비공개 함수.
7. 트랜잭션이 끝난 뒤 `syncPendingLectures()`(`db.ts`)를 부른다. 이것이 `projectLecture`를 돌려 브리지 규칙(2단계)을 적용한다: 방금 쓴 강의 Markdown이 구조화 문서와 같으므로 legacy 문서는 생기지 않는다. 호출은 `try/catch`로 감싸 로그(`logger.error("could not sync lecture after notes publish", { err })`)만 남긴다.
8. 반환값에 `lectureId`(녹음의 `lecture_id`)를 담는다. 이벤트(`announceLectures`)·색인·상태 변경은 하지 않는다(`P1-12`).

## 10. 명세 작성자 메모

- 계약 D-P1-3은 비교 하나(`projectLecture`)만 말하지만, `recording.status = partial`(D-P1-2)이 다음 투영에서 `ready`로 덮이는 것과 `verifyLegacy`가 legacy 문서만 보는 것이 실제 코드와 부딪힌다. 그래서 3·4단계(상태 보존, `verifyLegacy` 정규화)를 더했다. 모두 구조화 문서가 있을 때만 작동하고 없으면 이전 동작이다.
- 3b단계(여러 오디오 asset이면 첫 asset 길이를 덮지 않음)는 `P1-14`가 필요로 해서 여기에 넣었다.
