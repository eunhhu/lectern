> 등급: `careful` · 게이트: `full` · 의존: `P5-02`, `P5-03`, `P5-04`, `P5-06`, `P2-02` · 소유: `apps/server/test/`, `docs/v2/pipeline/SECURITY-REVIEW.md`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

계정·권한·토큰·업로드에 대한 보안 테스트를 한 묶음으로 만든다. 통과하는 것은 회귀 방지 테스트로 남고, 실패하는 것은 **고치지 않고** 보고서에 심각도와 함께 적는다. 이 작업은 코드를 고치지 않는다(소유가 테스트와 보고서뿐이다).

## 5. 단계

1. 6절의 테스트를 파일별로 쓴다. 각 테스트는 실제 서버 앱(`api-v2.test.ts`가 쓰는 방식)에 요청을 보내 **관찰된 동작**을 검사한다. 내부 함수를 직접 부르지 않는다(토큰 저장 검사는 DB를 읽는다).
2. 테스트를 돌린다. 실패하는 테스트마다:
   - 테스트가 틀렸는지(기대가 계약과 다른지) 먼저 확인한다. 틀렸으면 테스트를 고친다.
   - 서버가 틀렸으면 **서버를 고치지 않는다.** 그 테스트를 `test.todo("<이름>")`로 바꾸지도, `test.failing`·`test.skip`으로 가리지도 않는다. 테스트는 실패하는 채로 두고 보고서에 적은 뒤 `RESULT: BLOCKED`로 보고한다(`BLOCKED_REASON`에 보고서 경로와 발견 수). 오케스트레이터가 고칠 작업을 따로 만든다.
3. `SECURITY-REVIEW.md`를 쓴다.
   ```markdown
   # 보안 테스트 결과 (P5-15)
   - 실행한 커밋: <sha> · 날짜: <YYYY-MM-DD> · 테스트 수: <n> · 통과: <n> · 실패: <n>
   ## 발견
   | # | 심각도 | 분류 | 무엇 | 재현 (테스트 이름) | 영향 | 고칠 곳 (파일:줄) |
   ## 확인한 것 (통과)
   | 분류 | 테스트 | 확인한 성질 |
   ## 테스트하지 못한 것
   - (이유와 함께. 예: 실제 Google·Apple과의 흐름, TLS 설정, 프록시 뒤의 `X-Forwarded-For` 신뢰 범위)
   ## 사람이 봐야 하는 것
   - 이 테스트는 알려진 유형만 본다. 인증·권한 코드의 리뷰는 사용자(또는 상위 모델)의 몫이다.
   ```
   심각도: `높음`(인증 없이 또는 남의 데이터에 접근·변경, 토큰 평문 저장, 계정 탈취 경로), `중간`(횟수 제한 없음, CSRF로 상태 변경, 열린 리다이렉트), `낮음`(헤더 누락, 정보 노출이 적은 오류 문구).

## 6. 테스트

**`session.test.ts`**

| 테스트 이름 | 기대 |
|---|---|
| "login issues a new session id" | 로그인 전 임의의 `lectern_session` 쿠키를 실어 로그인 → 응답 쿠키 값이 보낸 값과 다르고, 보낸 값으로는 인증되지 않는다(세션 고정 방지) |
| "session cookie attributes" | `Set-Cookie`에 `HttpOnly`, `SameSite=Lax`(또는 `Strict`), `Path=/`. 요청이 https(또는 `X-Forwarded-Proto: https`)면 `Secure` |
| "logout invalidates the session" | 로그아웃 뒤 같은 쿠키로 `GET /api/v2/me` → 401 |
| "password reset signs other sessions out" | 재설정 뒤 옛 세션 401 |
| "expired session" | `sessions.expires_at`을 과거로 → 401 |

**`csrf.test.ts`** (쿠키로 인증한 변경 요청. 메서드가 `POST`·`PUT`·`PATCH`·`DELETE`인 v2 라우트 전부를 `ROUTES`에서 돈다)

| 테스트 이름 | 기대 |
|---|---|
| "cross-site cookie requests are refused" | `Origin: https://evil.example`(또는 `Sec-Fetch-Site: cross-site`)과 쿠키 → 403. 상태가 바뀌지 않는다 |
| "same-origin cookie requests pass" | `Origin`이 서버 자신 → 평소 응답 |
| "token requests need no origin check" | `Authorization: Bearer <PAT>`에는 `Origin`이 달라도 평소 응답 |
| "form content types cannot reach JSON routes" | `Content-Type: application/x-www-form-urlencoded`·`text/plain` 본문 → 400 또는 415(본문이 JSON으로 해석되지 않는다) |
| "apple callback is the only cross-site POST" | `/api/v2/auth/apple/callback`만 출처 검사에서 빠져 있다 |

**`rate-limit.test.ts`** (각각 한도까지 실패시킨 뒤 다음 요청)

| 테스트 이름 | 기대 |
|---|---|
| "login" | 429와 `Retry-After` |
| "native token password grant" | 429 |
| "share link password" | 429(또는 P2-02가 정한 잠금 응답) |
| "invite accept" | 429 |
| "signup code and reset code" | 429 |
| "limits are per e-mail and per IP" | 다른 이메일·같은 IP는 IP 한도까지 가능, 같은 이메일·다른 IP는 이메일 한도에 걸린다 |
| "X-Forwarded-For cannot dodge the limit" | 헤더 값을 요청마다 바꿔도(신뢰하지 않는 프록시 구성에서) 한도에 걸린다 |

**`upload.test.ts`**

| 테스트 이름 | 기대 |
|---|---|
| "rejects a non-audio file" | `mime: "text/html"`, 이름 `x.html` → 415 또는 400 |
| "rejects a mismatched extension" | `mime: "audio/mpeg"`, 이름 `x.exe` → 거절하거나 저장 이름에 `.exe`가 없다 |
| "path traversal in the file name" | 이름 `../../etc/passwd`, `..\\x`, `/abs/x`, NUL 포함 → 저장 경로가 데이터 디렉터리 안이고 이름에 구분자가 없다 |
| "part numbers out of range" | `part` 0, 음수, 10만 → 400 |
| "oversized part" | 한도보다 큰 파트 → 413 |
| "someone else's upload session" | B가 A의 `upload_id`에 파트 PUT·complete → 404 |
| "asset content needs access" | B가 A의 비공개 녹음의 `asset_id`로 `getAssetContent` → 404 |
| "served files are not executable in the browser" | 오디오·PDF 응답에 `X-Content-Type-Options: nosniff`, HTML로 해석될 `Content-Type`이 아니다 |

**`redirect.test.ts`**

| 테스트 이름 | 기대 |
|---|---|
| "oauth next" | `next`가 `https://evil.example`, `//evil.example`, `/\\evil.example`, `/%2F%2Fevil.example`, `javascript:alert(1)` → 최종 `Location`이 `/app`으로 시작 |
| "google calendar return_to" | 같은 값들 → 스키마 400 또는 `Location`이 `/app/settings`로 시작 |
| "/ and /admin redirects are fixed" | `Location`이 요청 값에 좌우되지 않는다(`Host` 헤더를 바꿔도 상대 경로) |

**`token-storage.test.ts`** — 각 토큰을 만든 뒤 **DB 파일의 모든 테이블 모든 TEXT 열**에서 원문을 찾는다.

| 테스트 이름 | 기대 |
|---|---|
| "PAT", "native access", "native refresh", "invite", "ICS feed", "share link (v2)", "oauth state" | 원문이 어디에도 없다. 해당 `*_hash` 열에 `sha256Hex(원문)`이 있다 |
| "google refresh token is sealed" | `integration.token_enc`에 원문이 없고 `openSecret`으로 열린다 |
| "known exceptions are exactly the v1 ones" | 평문으로 남는 토큰은 `users.api_token`, `sessions.token`, `lectures.share_token` 셋뿐이다(v1 계약. 보고서 "확인한 것"에 예외로 적는다) |
| "tokens do not appear in logs" | 위 흐름 동안의 로그 출력에 원문이 없다 |

**`idor.test.ts`**

| 테스트 이름 | 기대 |
|---|---|
| "every v2 route refuses a foreign workspace" | 사용자 A의 리소스 id(워크스페이스, 녹음, 문서, 폴더, 태그, 작업, 물어보기 대화, 공유 링크, 초대, 내보내기, 토큰, identity …)를 `PATH_PARAMS`와 쿼리·본문의 `workspace_id`에 넣어 사용자 B로 `ROUTES` 전부를 부른다 → 모두 403 또는 404. 2xx가 하나도 없다. 응답 본문에 A의 데이터(제목, 이메일)가 없다 |
| "unauthenticated" | 쿠키·토큰 없이 `public`이 아닌 라우트 전부 → 401 |
| "viewer cannot write" | 팀의 viewer로 변경 라우트 → 403 |
| "private recording inside a shared workspace" | 같은 팀의 다른 멤버 → 404 |
| "ids are not guessable sequences" | 새 녹음 두 개의 id가 연속된 정수가 아니다 |
| "SSE stream only carries my workspaces" | B가 `streamEvents`로 A의 워크스페이스를 구독 → 403, A의 이벤트가 오지 않는다 |

**`headers.test.ts`**

| 테스트 이름 | 기대 |
|---|---|
| "html responses carry a CSP without unsafe-inline scripts" | `/app`, `/privacy`, 공유 페이지의 `Content-Security-Policy`에 `script-src`가 있고 `'unsafe-inline'`·`'unsafe-eval'`이 없다 |
| "frame and sniff protections" | `X-Content-Type-Options: nosniff`, `frame-ancestors 'none'`(또는 `X-Frame-Options: DENY`), `Referrer-Policy` |
| "api responses are not cached" | 인증된 v2 JSON 응답에 `Cache-Control`이 `no-store` 또는 `private` |
| "errors do not leak internals" | 500을 유발한 응답 본문에 스택 추적·파일 경로·SQL이 없다 |

## 8. 하지 않는 것

- **서버 코드를 고치지 않는다.** 발견은 보고서로만 남긴다.
- 실패를 `test.failing`·`test.skip`·`test.todo`로 가리지 않는다.
- 실제 외부 서비스, 운영 서버, 운영 데이터를 대상으로 하지 않는다.
- 침투 도구·퍼저를 들여오지 않는다(새 의존성 없음).

## 9. 끝났다는 기준

- [ ] 6절의 테스트가 모두 있다
- [ ] 전부 통과하면 `RESULT: DONE`, 하나라도 서버 문제로 실패하면 보고서에 적고 `RESULT: BLOCKED`
- [ ] 보고서의 "테스트하지 못한 것"이 채워져 있다
- [ ] 바뀐 파일이 소유 경로 안이다

## 10. 명세 작성자 메모

- 이 명세는 서버에 CSRF 출처 검사가 **있는지 확인하지 않았다.** 없으면 `csrf.test.ts`가 실패하고 그것이 첫 발견이 된다(`SameSite=Lax` 쿠키가 교차 사이트 `POST`를 막아 주지만, 같은 사이트의 다른 하위 도메인은 막지 못한다).
- "X-Forwarded-For cannot dodge the limit"은 `getClientIp`가 프록시 헤더를 어떻게 믿는지에 달렸다. 기대가 운영 구성(Cloudflare 터널 뒤)과 맞는지 테스트 준비에서 설정을 명시한다.
- 통과했다는 것이 안전하다는 뜻은 아니다. 사람의 리뷰는 STATUS "사용자 필요"에 올라 있다.
