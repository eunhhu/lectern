# P6-A9 macOS 앱

> 등급: `careful` · 게이트: `apple` · 의존: `P6-A4`, `P6-A5` · 소유: `apps/apple/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

새 macOS 앱을 만든다. 메뉴바 아이콘에서 녹음을 시작·정지하고 경과 시간과 레벨을 보고, 메인 창에서 폴더 → 목록 → 문서·전사를 읽는다. 전역 단축키로 녹음을 켜고 끄고, 로그인할 때 자동으로 실행되게 할 수 있고, 문서가 준비되면 알림이 온다. 기존 `apps/macos`와 같은 번들 id를 써서 마이크 권한이 이어진다. 기존 앱은 지우지 않는다.

## 5. 단계

1. `LecternMacApp`
   ```swift
   @main struct LecternMacApp: App {
       var body: some Scene {
           MenuBarExtra { MenuBarHUD(model: recording) } label: { MenuBarLabel(model: recording) }.menuBarExtraStyle(.window)
           WindowGroup("Lectern", id: "main") { MainWindow() }
           Settings { SettingsView() }
       }
   }
   ```
   `Info.plist`의 `LSUIElement`는 `false`로 둔다(Dock 아이콘과 메인 창이 있다). 메인 창을 닫아도 앱은 메뉴바에 남는다.
2. 메뉴바
   - 라벨: 평소에는 아이콘, 녹음 중에는 아이콘 + 경과 시간(`12:05`). 접근성 레이블 `Lectern, 녹음 중 12분 5초` / `Lectern`.
   - HUD(창 형식 팝오버): 큰 버튼 `녹음 시작` / `정지`, `일시정지`·`재개`, `중요`, 레벨 막대, 경과 시간, 무음 경고 `소리가 들리지 않습니다. 마이크를 확인해 주세요.`, 저장할 폴더 선택, 업로드 대기열 요약(`업로드 중 1개`, `실패 1개 — 다시 시도`), `Lectern 열기`, `설정…`, `종료`.
   - 로그인하지 않았으면 HUD에 `로그인이 필요합니다`와 버튼 `로그인`(메인 창을 연다).
3. `MacRecordingViewModel`(`@MainActor`, `ObservableObject`. `RecorderKit`과 `UploadQueue`를 프로토콜로 받는다)
   - 상태: `idle`, `recording(elapsedMs)`, `paused(elapsedMs)`, `saving`, `failed(message)`.
   - `toggle()`(녹음 중이 아니면 시작, 녹음 중이면 정지), `pauseResume()`, `addMarker()`.
   - 정지하면 결과를 `UploadQueue.enqueue`(파일을 App Group 컨테이너로 옮긴다. `recordedAt`과 마커 포함)하고 `run()`.
   - 2초보다 짧으면 버린다(P6-A7과 같은 규칙).
   - 마이크 권한이 거부됐으면 `failed("마이크 권한이 필요합니다. 시스템 설정 > 개인정보 보호 및 보안 > 마이크에서 Lectern을 켜 주세요.")`.
   - 경과 시간 표시 문자열(`0:07`, `12:05`, `1:02:05`)은 순수 함수로.
4. 메인 창: `NavigationSplitView`(사이드바: 워크스페이스·폴더 / 목록 / 상세). 상세는 문서와 전사를 나란히(창이 좁으면 탭). 아래에 `PlayerBar`. 뷰모델과 문구는 P6-A6과 같은 것을 쓴다. 키보드: `⌘R` 새로 고침, `Space` 재생·일시정지(글 입력 중이 아닐 때), `⌘1`·`⌘2` 문서·전사. 메뉴 막대에 같은 명령을 넣는다(`.commands`).
5. `HotKey.swift`: 기존 앱과 **같은 키 조합**을 기본값으로 `RegisterEventHotKey`(Carbon)로 등록한다. 설정에서 조합을 바꿀 수 있다(키 입력을 받아 `UserDefaults`의 `hotkey_keycode`, `hotkey_modifiers`에 저장하고 다시 등록). 등록에 실패하면(다른 앱이 쓰는 조합) 설정에 `이 단축키는 사용할 수 없습니다. 다른 조합을 골라 주세요.` 조합을 글자로 보이는 함수(`⌥⌘R` 같은 표기)는 순수 함수로 뺀다.
6. `LoginItem.swift`: `SMAppService.mainApp`의 `register()`/`unregister()`. 설정의 토글 `로그인할 때 Lectern 실행`. 상태는 `SMAppService.mainApp.status`에서 읽는다. 실패하면 토글을 되돌리고 `로그인 항목을 바꾸지 못했습니다.`
7. `Notifications.swift`: `UNUserNotificationCenter`. 권한은 첫 녹음이 끝났을 때 묻는다(앱을 켜자마자 묻지 않는다). 업로드한 녹음의 상태를 메인 창이 열려 있거나 대기열이 돌 때 확인해(이 단계에는 푸시가 없다) `ready`가 되면 알림 `문서가 준비되었습니다` / 본문 녹음 제목. 알림을 누르면 메인 창에서 그 녹음을 연다.
8. 옛 앱에서 넘어오기(`LegacyMacToken`)
   - 옛 앱(P6-A0 뒤)은 토큰을 Keychain service `com.qucord.lectern.macos`, account `auth_token`에 둔다. 그것은 **v1 API 토큰**이다.
   - 새 앱의 첫 실행 때: 새 저장소에 인증 정보가 없고 옛 항목이 있으면, 그 토큰으로 `ApiTokenProvider` 로그인 상태를 만든다(다시 로그인하지 않아도 된다). 옛 항목은 지우지 않는다(옛 앱으로 돌아갈 수 있게).
   - 순수 로직: `func legacyMigrationPlan(newStoreHasCredential: Bool, legacyToken: String?) -> LegacyPlan`(`.none`, `.adopt(token)`).
   - 옛 `UserDefaults`의 `lectern_course`(기본 과목 이름)는 가져오지 않는다.
9. `MANUAL_CHECKS.md`에 행(실제 Mac)
   - 옛 앱(`apps/macos`)을 쓰던 Mac에 새 앱을 설치하면 마이크 권한을 다시 묻지 않는다(같은 번들 id와 같은 서명일 때)
   - 옛 앱의 로그인이 새 앱에서 이어진다
   - 메뉴바에서 녹음 → 정지 → 업로드 → 알림 → 알림을 눌러 문서가 열린다
   - 전역 단축키가 다른 앱이 앞에 있을 때도 동작한다
   - 로그인 시 실행을 켜고 재로그인하면 앱이 뜬다
   - 메인 창을 닫아도 녹음이 이어진다

## 8. 하지 않는 것

- 시스템 오디오와 회의 감지(`P6-A10`), 푸시·위젯·Spotlight(`P6-A11`), Sparkle·공증(`P6-A12`).
- 기존 `apps/macos`를 지우거나 고치지 않는다(D-P6-11).
- 앱 샌드박스를 끄지 않는다(권한이 더 필요하면 entitlements에 그 권한만 더하고 `DEVIATIONS`에 적는다).

## 10. 명세 작성자 메모

- 샌드박스 앱에서 `RegisterEventHotKey`는 동작한다(입력 모니터링 권한이 필요 없는 API다). 동작하지 않으면 기기 확인에서 드러난다.
- 샌드박스 앱이 **다른(샌드박스가 아닌) 옛 앱의 Keychain 항목**을 읽을 수 있는지는 서명 팀과 접근 그룹에 달렸다. 못 읽으면 사용자는 한 번 다시 로그인한다. 그 경우를 점검표에 "옛 로그인이 이어지지 않으면 다시 로그인"으로 적는다.
- 기존 앱의 단축키 조합은 사전 점검 넷째 명령으로 읽는다(이 명세는 값을 확인하지 않았다).
