## 1. 목표

노트 파이프라인 단계들이 주고받는 값의 zod 스키마(`ClassifyOutput`, `VerifiedEvent`, `VerifiedActionItem`, `VerifyReport`, `NotesResult`)를 `src/notes/schemas.ts`에 정하고, 첫 단계 `classify`(도메인·언어·제목·폴더·태그 제안)를 만든다. 사용자가 보는 변화는 없다.

## 5. 단계

1. `src/notes/schemas.ts` (모양은 계약 §1.6 그대로; 타입은 `z.infer`로 같은 이름 export).
   ```ts
   export const ClassifyOutput = z.object({
     domain: RecordingDomain, language: LanguageTag,
     title: z.string().trim().min(1).max(60),
     participants: z.array(z.string().min(1)),
     folder_suggestion: z.object({ folder_id: z.string().nullable(), new_name: z.string().min(1).nullable() }),
     tags: z.array(z.string().min(1)).max(5),
     confidence: Confidence,
   });
   export const VerifiedEvent = z.object({
     title: z.string().min(1), kind: EventKind, start_at: z.int(), end_at: z.int().nullable(),
     all_day: z.boolean(), tz: TimeZone, raw_expression: z.string().min(1), resolution: DateResolution,
     confidence: Confidence, evidence: Evidence, flags: z.array(z.string()),
   });
   export const VerifiedActionItem = z.object({
     text: z.string().min(1), owner_name: z.string().min(1).nullable(), due_at: z.int().nullable(),
     due_raw: z.string().min(1).nullable(), evidence: Evidence, flags: z.array(z.string()),
   });
   export const VerifyReport = z.object({
     repaired: z.boolean(), dropped_blocks: z.int().nonnegative(),
     items: z.array(z.object({
       kind: z.enum(["block", "event", "action_item", "decision", "glossary"]),
       ref: z.string(), outcome: z.enum(["ok", "fixed", "dropped"]), reasons: z.array(z.string()),
     })),
   });
   export const NotesResult = z.object({
     classification: ClassifyOutput, template: z.object({ id: z.string(), version: z.int().min(1) }),
     body: DocumentBody, markdown: z.string(), events: z.array(VerifiedEvent),
     action_items: z.array(VerifiedActionItem), report: VerifyReport, partial: z.boolean(),
   });
   ```
   `flags`는 문자열 배열이다(값 목록은 계약 §1.6: `needs_review`, `date_mismatch`, `recorded_at_estimated`, `low_confidence`, `weekday_mismatch`). 상수 `NOTE_FLAGS`로 export한다(`as const` 배열, 스키마에는 넣지 않는다).
2. `src/notes/classify.ts`
   ```ts
   export interface ClassifyInput {
     segments: CompactSegment[];                 // whole transcript
     filename: string | null;
     hint: { domain: RecordingDomain | null; folder_id: string | null };
     folders: { id: string; name: string }[];
     tags: string[];                             // existing tag names
   }
   export function sampleForClassify(segments: readonly CompactSegment[]): string;
   export function classifyStage(llm: LlmProvider, routing: Routing): StageDefinition<ClassifyInput, ClassifyOutput>;
   ```
   - `sampleForClassify` (결정적, 길이 ≤ 6000자): `head` = `start_ms < 180000`인 세그먼트를 앞에서부터 압축 줄(`formatCompactTranscript` 형식)로, 합계 2900자를 넘기 직전까지. `rest` = 나머지 세그먼트를 인덱스로 4등분하고, 각 구간 `[k]`의 시작점을 `floor(rest.length * (k + 0.5) / 4)`로 잡아 거기서부터 줄 단위로 750자를 넘기기 직전까지. 줄 하나가 예산보다 길면 그 줄 본문을 예산에 맞게 잘라서 넣는다. 조각은 `"\n...\n"`으로 잇는다. `rest`가 비어 있으면 head만.
   - `classifyStage`: `defineStage({ name: "classify", version: 1, output: ClassifyOutput, memo: "shared", retry: { maxAttempts: 3, repairs: 1 }, key, run })`.
     - `key(input)`: `inputs: [sha256Hex(formatCompactTranscript({segments}).text), sha256Hex(canonicalJson({ filename, hint, folders, tags }))]`, `prompt: sha256Hex(CLASSIFY_SYSTEM + "\u0000" + CLASSIFY_INSTRUCTION)`, `provider: llm.id`, `model: routing.classify.model`, `params: { schema: llmSchemaHash(ClassifyOutput), maxOutputTokens: routing.classify.maxOutputTokens }`.
     - `run`: 요청 = `{ schema: ClassifyOutput, system: CLASSIFY_SYSTEM, context: [{ type: "text", text: sampleForClassify(segments) }], instruction, model: routing.classify.model, maxOutputTokens: routing.classify.maxOutputTokens, signal: ctx.signal }`. 호출은 `await ctx.meter({ provider: llm.id, model: routing.classify.model }, () => llm.generate(req))`. `instruction` = `CLASSIFY_INSTRUCTION` + 파일명 줄 + 힌트 줄 + `기존 폴더:` 목록(`- <id>: <name>`, 없으면 `(없음)`) + `기존 태그:` 목록; `ctx.repair`가 있으면 끝에 `\n\n이전 응답이 검증을 통과하지 못했다: <issues>\n규칙을 지켜 다시 답한다.`.
     - 후처리(값을 돌려주기 전, 이 순서):
       1. `hint.domain`이 있으면 `domain = hint.domain`(사용자 우선).
       2. `folder_suggestion.folder_id`가 `folders`의 id에 없으면: `new_name`이 있으면 `{ folder_id: null, new_name }`, 없으면 `{ folder_id: null, new_name: null }`.
       3. `folder_id`와 `new_name`이 둘 다 있으면 `new_name = null`(기존 폴더 id 하나 **또는** 새 이름 하나).
       4. `tags`: 앞뒤 공백 제거, 빈 값 제거, 대소문자 구분 없는 중복 제거(먼저 나온 것 유지), 최대 5개.
       5. `participants`: 공백 제거, 빈 값·중복 제거.
   - 상수 문구(한국어, `classify.ts` 안): `CLASSIFY_SYSTEM`은 "녹음 전사의 일부를 보고 분류한다. 전사에 나온 내용만 근거로 한다. 확실하지 않으면 confidence를 낮게 적는다."를 포함한다. `CLASSIFY_INSTRUCTION`은 출력 필드(`domain`: lecture/meeting/seminar/interview/one_on_one/call/other 중 하나, `language`: BCP 47, `title`: 60자 이내 한 줄, `participants`: 이름이 언급된 사람만, `folder_suggestion`: 기존 폴더 id 또는 새 이름 중 하나, `tags`: 최대 5개, `confidence`: 0~1)를 설명한다.
3. `src/index.ts`에 `export * from "./notes/schemas.ts"; export * from "./notes/classify.ts";`를 더한다.

## 10. 명세 작성자 메모

- 계약 §1.6의 `flags`는 `date_mismatch`, `weekday_mismatch`를 쓰지만 domain `VerifyFlag`(`EventCandidate.flags`, `ActionItem.flags`)는 `low_confidence`, `date_corrected`, `needs_review`, `recorded_at_estimated` 네 값뿐이고 `z.enum`이다. P1-11(`notes-publish`)이 행을 쓸 때 `date_mismatch`→`date_corrected`로 바꾸고 `weekday_mismatch`는 domain에 없어 버려야 한다. domain 소유 WP가 값을 추가하지 않으면 `checkV2Rows`(preflight)가 실패한다. 오케스트레이터가 정해야 한다.
- 샘플링 예산(앞 2900자 + 4×750자 + 구분자 ≤ 6000자)은 카탈로그의 "합쳐 6,000자 이내"를 맞추려고 명세 작성자가 정한 값이다.
- 사용자가 업로드 때 폴더를 골랐을 때(`hint.folder_id`)의 처리는 계약에 없다. 이 단계는 힌트를 프롬프트에만 알리고 결과를 덮어쓰지 않는다. 서버 쪽 규칙은 P1-11/P1-12가 정한다.
