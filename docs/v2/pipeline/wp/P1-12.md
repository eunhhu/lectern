# P1-12 process 작업 (서버)

> 등급: `careful` · 게이트: `full` · 의존: `P1-11` · 소유: `apps/server/`, `apps/worker/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

`LECTERN_PIPELINE=v2`일 때 업로드가 끝나면 `distill` 대신 `process` 작업을 큐에 넣는다. `process`는 전사 파이프라인 → 전사 발행 → 색인 → 노트 파이프라인 → 노트 발행 → 색인 → 녹음 상태(`ready`/`partial`/`failed`) 순으로 돈다. 진행 이벤트(`job.progress`)에는 실제 단계 이름이 실린다. `LECTERN_PIPELINE=v1`(기본)이면 지금 동작이 그대로다. 사용자가 보는 변화: 플래그를 켜면 전사 화면과 구조화 문서가 생긴다.

## 5. 단계

1. `process-job.ts` 뼈대. `index.ts`를 import하지 않는다.
   ```ts
   export const PROCESS_JOB_KIND = "process";
   export const PROCESS_STAGE_PROGRESS: Record<string, [number, string]> = {
     ingest: [8, "오디오 확인 중..."], normalize: [14, "오디오 정리 중..."], speech_map: [20, "말소리 구간 찾는 중..."],
     chunk: [24, "오디오 나누는 중..."], transcribe: [40, "받아쓰는 중..."], merge: [60, "전사 합치는 중..."],
     speakers: [64, "화자 구분 중..."], classify: [70, "녹음 종류 파악 중..."], structure: [80, "노트 구성 중..."],
     extract: [88, "일정·할 일 찾는 중..."], verify: [93, "내용 검증 중..."], publish: [97, "저장 중..."], index: [99, "검색 색인 중..."],
   };
   export function processBudgetMicrousd(durationSec: number): number; // max(500_000, ceil(hours * 900_000))
   export function enqueueRecordingProcessing(lectureId: string, ownerId: string, input: DistillInput): { jobId: string; deduplicated: boolean; position: number }
   export interface ProcessJobDeps { harness?: Harness; transcription?: TranscriptionProvider; llm?: LlmProvider; pipeline?: Omit<TranscriptPipelineOptions, "provider" | "workDir">; notes?: Record<string, unknown> /* options of runNotesPipeline */ }
   export async function runProcessJob(job: LeasedJob, deps?: ProcessJobDeps): Promise<JobOutcome>
   ```
   `DistillInput`은 `job-handlers.ts`의 타입이다(타입만 `import type`; 순환을 피하려고 값은 import하지 않는다).
2. `enqueueRecordingProcessing`: `config().pipeline === "v2"`이고 `isFfmpegAvailable()`이고 `readSecret("GEMINI_API_KEY")`(서버 키)이 있을 때만 `enqueueJob({ kind: PROCESS_JOB_KIND, ownerId, subjectId: lectureId, payload: { title, course }, budgetMicrousd: processBudgetMicrousd(lecture.duration_sec) })`. 아니면 `logger.warn`(v2인데 키·ffmpeg 없음일 때만)과 함께 `enqueueDistillation`(`job-handlers.ts`)을 그대로 부른다. 새로 큐에 넣고 `position > 0`이면 `updateLectureProgress(id, "queued", "분석 대기열 N번째 — 앞선 작업이 끝나면 자동으로 시작됩니다.", 5)`와 `progress` 이벤트(`enqueueDistillation`의 `emitProgress`와 같은 모양)를 낸다. 사용자 키는 쓰지 않는다(v2 업로드 경로는 서버 키만 쓴다. `uploads.ts`가 `apiKey`를 안 넘긴다).
3. `runProcessJob` 흐름(각 단계는 `run.run`이므로 같은 jobId로 다시 돌면 건너뛴다):
   1. `config().pipeline === "v1"`이면 `{ ok: true, result: { skipped: "pipeline_v1" } }`. 강의 또는 오디오가 없으면 `dropArtifacts` 후 `{ ok: false, error: PROCESS_SOURCE_GONE_MESSAGE }`(`"녹음이나 그 오디오가 삭제되어 처리를 중단했습니다."`).
   2. `runTranscriptJob`과 같은 방식으로 `AbortController`, `checkSource()`, `harness.job({ jobId, scope: workspaceId, workspaceId, signal, onEvent })`를 만든다. `onEvent`의 `started`/`retry`에서 `checkSource()`.
   3. `runTranscriptPipeline(run, { audioPath, language: recording.language ?? undefined }, { ...deps.pipeline, provider, workDir: join(DATA_DIR, "work"), onStage })`. `onStage`마다 `emitStage(stage)`(5단계)와 `checkSource()`.
   4. 전사 전부 실패(예외 `HarnessError`, 한국어 메시지): `failLectureRecord(id, message)` + `type: "error"` 이벤트 → 녹음 `failed`(투영이 처리). 결과 `{ ok: false, error: message }`. 이미 발행한 전사는 없다.
   5. 성공하면 `publishTranscript({ recordingId, workspaceId, transcript })`, `UPDATE lectures SET duration_sec = ?`(`round(duration_ms/1000)`), `scheduleLectureIndex(lectureId, ownerId)`, `announceLectures([lectureId])`.
   6. `runNotesPhase(...)`(7단계)를 부른다.
   7. 끝에 `dropArtifacts`(성공·partial일 때만. 실패하면 남긴다: 재시도가 앞 단계를 메모로 건너뛴다).
4. `runNotesPhase(ctx: { job, run, lectureId, recordingId, workspaceId, transcript, signal, deps, keepTitle }): Promise<"ready" | "partial">`를 **내보낸다**(`P1-13`의 `regenerate`가 재사용한다):
   - `runNotesPipeline(run, input, { signal, onStage: emitStage, llm, routing: loadRouting(), ...deps.notes })`. `input`의 모양은 `P1-09`가 내보내는 입력 타입을 따른다(전사, 녹음 시각 `recorded_at`/`recorded_at_source`, 시간대 `Asia/Seoul`, 사용자 힌트(도메인·템플릿), 파일명, 기존 폴더·태그 이름).
   - 성공: `publishNotes({ recordingId, workspaceId, result, keepTitle })`, 이벤트 `{ type: "completed", id, lecture }` + `announceLectures`, `scheduleLectureIndex`. `result.partial`이면 `markPartial(recordingId, "notes_partial", "일부 내용을 만들지 못했습니다. 전사와 검색은 쓸 수 있습니다.")`, 아니면 `"ready"`.
   - 예외(예산 `budget` 포함, 취소 `canceled`는 제외): D-P1-2대로 전사는 이미 발행됐다. 강의를 `UPDATE lectures SET status='done', stage='done', stage_message='완료', progress=100, excerpt='노트를 만들지 못했습니다. 전사는 사용할 수 있습니다.', updated_at=? WHERE id=?`로 끝내고(`markdown`은 그대로), `markPartial(recordingId, "notes_failed" 또는 "budget_exceeded", 한국어 메시지)`. 작업 결과는 `ok: true`.
   - `markPartial`: 투영이 끝난 뒤(`syncPendingLectures()`) `UPDATE recording SET status = 'partial', failure_code = ?, failure_message = ?, updated_at = ? WHERE id = ?`와 `announceLectures`. (`P1-11`의 투영 규칙이 `partial`을 지켜 준다.)
   - 취소(`canceled`)와 원본 삭제는 `ok: false`로 끝낸다.
5. `emitStage(stage)`: `PROCESS_STAGE_PROGRESS[stage]`가 있으면 `updateLectureProgress(lectureId, stage, message, progress)`와 `emitLectureEvent(ownerId, { type: "progress", id, stage, stage_message, progress, lecture })`. `stage`는 `StageName`에 있는 이름뿐이다(새 이름 금지; 발행 직전에는 `publish`).
6. `events.ts` `translate`: 진행 이벤트의 `stage`를 `StageName.safeParse(payload.stage)`가 성공하면 그 값으로, 아니면 `"legacy_distill"`로 둔다. `store.ts` `progressOf`도 `lecture?.stage`에 같은 규칙을 쓴다. `stage_state`는 지금처럼.
7. `job-handlers.ts`: `registerJobHandler(PROCESS_JOB_KIND, async (job) => ({ ...(await runProcessJob(job)), followUp: () => compactAfterTranscript(job.subjectId!, job.ownerId) }), { concurrency: 1, onLost })`. `onLost`: 아티팩트 삭제 + `failLectureRecord(subjectId, "처리 중 서버 프로세스가 여러 번 중단되었습니다. 다시 시도해주세요.")` + `error` 이벤트. `runCompaction`의 바쁨 검사에 `PROCESS_JOB_KIND`와 `"regenerate"`를 더한다. 테스트가 공급자를 바꿀 수 있게 `registerProcessJobHandler(deps = {})`로 감싸 내보낸다(`registerTranscriptJobHandler`와 같은 방식).
8. `ask/legacy.ts` `lectureSources`: 구조화 문서(`template_id != 'legacy-markdown'`)가 있으면 `document: { kind: "blocks", documentId, version, body: DocumentBody.parse(JSON.parse(body_json)) }`로 돌려준다. 없으면 지금 그대로. `isIndexable`은 그대로(`P1-10`이 넓힌 조건 포함).
9. `uploads.ts`·`recordings.ts`: `enqueueDistillation(...)` 호출 세 곳을 같은 인자로 `enqueueRecordingProcessing(...)`으로 바꾼다. 시그니처가 같으므로 다른 줄은 건드리지 않는다.

## 10. 명세 작성자 메모

- `runNotesPipeline`의 `input`·`options` 필드와 `GeminiLlmProvider` 생성자 옵션은 계약에 없다(`runNotesPipeline(run, input, options)`만 있다). `P1-09`·`P1-01`이 내보낸 실제 타입을 따른다. 다르면 멈추고 보고한다.
- 실패 코드: `projectLecture`가 `failure_code`를 `legacy_error`로 덮으므로 완전 실패(`failed`)의 코드는 `legacy_error`다. `partial`의 코드는 `P1-11`의 투영 규칙이 지킨다.
- 계약은 사용자 키/서버 키 규칙을 "v1 distill과 같게" 한다. v2 업로드 경로는 원래 서버 키만 쓰므로 `process`도 서버 키만 쓴다. 서버 키·ffmpeg가 없으면 distill로 되돌아간다(계약에 없는 안전장치).
- `apps/worker/`는 수정 없음(공유 모듈 import로 핸들러가 등록된다).
- `process` 작업은 v1 distill이 하던 관리자 아카이브(`.md` 파일) 쓰기를 하지 않는다.
