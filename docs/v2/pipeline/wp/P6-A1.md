# P6-A1 apps/apple 뼈대와 게이트

> 등급: `careful` · 게이트: `apple` · 의존: 없음 · 소유: `apps/apple/`, `.gitignore`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

새 Apple 앱의 뼈대를 만든다. XcodeGen 정의 하나에서 iOS 앱, macOS 앱, 위젯 확장, 공유 확장이 생성되고, Swift 패키지 네 개가 빈 채로 빌드·테스트된다. 화면은 "Lectern" 글자 하나뿐이다. 이 작업이 만드는 `apps/apple/scripts/gate.sh`가 이후 모든 Apple 작업의 게이트다.

## 2. 먼저 읽을 것

- 계약: `CONTRACTS.md` §6.2(구조, D-P6-7~D-P6-11)
- 문서: `docs/v2/NATIVE.md` §1(최소 OS), §3(공통 구조)
- 코드: `apps/macos/build-app.sh`(기존 macOS 앱의 번들 id `com.qucord.lectern.macos`와 권한 문구), `.gitignore`

## 3. 사전 점검

```bash
xcodebuild -version
xcodegen --version
swift --version
ls apps/apple 2>/dev/null
```
- `xcodebuild`가 Xcode 26보다 낮거나 없으면 멈춘다(`BLOCKED_REASON`: iOS 26 SDK가 필요하다).
- `xcodegen`이 없으면 멈추고 `NEEDS`에 `brew install xcodegen`을 적는다(직접 설치하지 않는다).
- `apps/apple`이 이미 있으면 멈춘다.

## 5. 단계

1. 루트 `.gitignore` 끝에 더한다.
   ```
   # Apple app (apps/apple): the project is generated by XcodeGen; signing values stay local.
   apps/apple/*.xcodeproj
   apps/apple/Local.xcconfig
   apps/apple/**/.build/
   ```
   `apps/apple/.gitignore`: `DerivedData/`, `*.xcuserstate`, `xcuserdata/`.
2. `Config/Base.xcconfig`
   ```
   // Shared build settings. Signing values come from Local.xcconfig (not committed).
   LECTERN_SERVER_URL = http:/$()/localhost:18775
   DEVELOPMENT_TEAM =
   CODE_SIGN_STYLE = Automatic
   SWIFT_VERSION = 5.0
   IPHONEOS_DEPLOYMENT_TARGET = 26.0
   MACOSX_DEPLOYMENT_TARGET = 26.0
   MARKETING_VERSION = 0.1.0
   CURRENT_PROJECT_VERSION = 1
   #include? "../Local.xcconfig"
   ```
   (`http:/$()/`는 xcconfig에서 `//`가 주석이 되는 것을 피하는 표기다.) `Local.xcconfig.example`:
   ```
   // Copy to Local.xcconfig and fill in. Never commit Local.xcconfig.
   DEVELOPMENT_TEAM =
   LECTERN_SERVER_URL = https:/$()/your-server.example
   ```
   팀 id, 실제 서버 주소, 개인 이름을 저장소에 넣지 않는다.
3. 패키지 네 개. `Package.swift`(이름만 바꾼다):
   ```swift
   // swift-tools-version: 6.0
   import PackageDescription

   let package = Package(
       name: "LecternKit",
       platforms: [.iOS("26.0"), .macOS("26.0")],
       products: [.library(name: "LecternKit", targets: ["LecternKit"])],
       targets: [
           .target(name: "LecternKit", swiftSettings: [.swiftLanguageMode(.v5)]),
           .testTarget(name: "LecternKitTests", dependencies: ["LecternKit"], swiftSettings: [.swiftLanguageMode(.v5)]),
       ]
   )
   ```
   - 의존: `LecternUI` → `LecternKit`, `LecternIntents` → `LecternKit`(`.package(path: "../LecternKit")`). `RecorderKit`와 `LecternKit`은 의존이 없다.
   - 소스 파일 하나: `public enum LecternKitInfo { public static let name = "LecternKit" }`(이름만 바꾼다).
   - 테스트 하나(XCTest): `XCTAssertEqual(LecternKitInfo.name, "LecternKit")`.
   - 언어 모드를 Swift 5로 둔 이유를 `Package.swift` 주석에 적는다: `// Swift 5 language mode: strict concurrency comes later, package by package.`

5. Info.plist와 entitlements(직접 쓴 XML plist)
   - iOS 앱 `Info.plist`: `CFBundleDisplayName` = `Lectern`, `CFBundleShortVersionString` = `$(MARKETING_VERSION)`, `CFBundleVersion` = `$(CURRENT_PROJECT_VERSION)`, `CFBundleIdentifier` = `$(PRODUCT_BUNDLE_IDENTIFIER)`, `CFBundleExecutable` = `$(EXECUTABLE_NAME)`, `CFBundlePackageType` = `APPL`, `UILaunchScreen` = 빈 dict, `UIApplicationSceneManifest`(`UIApplicationSupportsMultipleScenes` = false), `NSMicrophoneUsageDescription` = `강의와 회의를 녹음하려면 마이크가 필요합니다.`, `UIBackgroundModes` = `[audio]`, `NSSupportsLiveActivities` = true, `LecternServerURL` = `$(LECTERN_SERVER_URL)`, `ITSAppUsesNonExemptEncryption` = false.
   - 위젯 `Info.plist`: `NSExtension` → `NSExtensionPointIdentifier` = `com.apple.widgetkit-extension`.
   - 공유 `Info.plist`: `NSExtension` → `NSExtensionPointIdentifier` = `com.apple.share-services`, `NSExtensionPrincipalClass` = `$(PRODUCT_MODULE_NAME).ShareViewController`, `NSExtensionAttributes` → `NSExtensionActivationRule` → `NSExtensionActivationSupportsFileWithMaxCount` = 10.
   - macOS `Info.plist`: 같은 기본 키 + `LSMinimumSystemVersion` = `$(MACOSX_DEPLOYMENT_TARGET)`, `NSMicrophoneUsageDescription`(같은 문구), `LSUIElement` = false, `LecternServerURL`.
   - entitlements(네 파일 모두): `com.apple.security.application-groups` = `[group.com.qucord.lectern]`, `keychain-access-groups` = `[$(AppIdentifierPrefix)com.qucord.lectern]`. macOS 앱에는 추가로 `com.apple.security.app-sandbox` = true, `com.apple.security.device.audio-input` = true, `com.apple.security.network.client` = true.
6. 소스(최소)
   - `iOS/App/LecternApp.swift`: `@main struct LecternApp: App { var body: some Scene { WindowGroup { Text("Lectern") } } }`
   - `iOS/Widgets/LecternWidgetsBundle.swift`: `@main struct LecternWidgetsBundle: WidgetBundle`와 자리만 차지하는 `StaticConfiguration` 위젯 하나(`kind: "LecternPlaceholder"`, 표시 이름 `Lectern`, 본문 `Text("Lectern")`).
   - `iOS/Share/ShareViewController.swift`: `UIViewController` 하위 클래스. `viewDidAppear`에서 `extensionContext?.completeRequest(returningItems: nil)`.
   - `macOS/App/LecternMacApp.swift`: iOS와 같은 모양(`WindowGroup { Text("Lectern") }`).
7. `scripts/gate.sh`(실행 권한 `chmod +x`)
   ```bash
   #!/usr/bin/env bash
   # Apple gate: generate the project, test the packages, build both apps without signing.
   # Usage: bash apps/apple/scripts/gate.sh
   set -euo pipefail
   cd "$(dirname "$0")/.."

   command -v xcodegen >/dev/null || { echo "gate: xcodegen is not installed (brew install xcodegen)" >&2; exit 2; }

   for hook in scripts/pre-gate-*.sh; do   # later work packages add steps here (token sync, OpenAPI copy)
     if [ -f "$hook" ]; then bash "$hook"; fi
   done

   xcodegen generate --quiet

   for pkg in LecternKit RecorderKit LecternUI LecternIntents; do
     echo "gate: swift test $pkg"
     (cd "Packages/$pkg" && swift test)
   done

   build() {  # scheme, destination
     echo "gate: xcodebuild $1"
     xcodebuild -project Lectern.xcodeproj -scheme "$1" -destination "$2" -configuration Debug \
       CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO build -quiet
   }
   build LecterniOS 'generic/platform=iOS Simulator'
   build LecternMac 'generic/platform=macOS'

   echo "gate: apple ok"
   ```

   아래 항목은 사람이 실제 기기에서 확인한다. 확인하기 전에는 "통과"라고 적지 않는다.

9. `README.md`: 구조 그림(§6.2), 처음 실행(`cp Local.xcconfig.example Local.xcconfig` → 팀 id 입력 → `xcodegen generate` → Xcode에서 열기), 게이트 실행법, "`.xcodeproj`는 커밋하지 않는다", "기존 `apps/macos`, `apps/ios`는 그대로 둔다(D-P6-11)".

## 6. 테스트

| 테스트 | 기대 |
|---|---|
| 패키지 네 개의 `swift test` | 각각 테스트 1개 통과 |
| `bash apps/apple/scripts/gate.sh` | 마지막 줄 `gate: apple ok`, 종료 코드 0 |
| `git status --short apps/apple` (게이트 뒤) | `Lectern.xcodeproj`, `.build/`가 보이지 않는다(gitignore) |
| `git grep -n "DEVELOPMENT_TEAM = [A-Z0-9]" -- apps/apple` | 결과 없음(팀 id가 저장소에 없다) |
| `plutil -lint` 를 모든 `Info.plist`와 `.entitlements`에 | 모두 `OK` |

## 8. 하지 않는 것

- 실제 기능(API 클라이언트, 녹음, 화면). 뼈대뿐이다.
- 서명, 프로비저닝, TestFlight.
- 기존 `apps/macos`, `apps/ios`를 건드리지 않는다.
- CI 작업 추가(`P6-CI`).

## 9. 끝났다는 기준

- [ ] 게이트가 통과한다
- [ ] 생성된 프로젝트와 `Local.xcconfig`가 커밋되지 않는다
- [ ] 타깃·스킴·번들 id·App Group 이름이 이 명세와 같다
- [ ] 팀 id와 개인 값이 저장소에 없다

## 10. 명세 작성자 메모

- 이 명세를 쓴 기계에는 Xcode 27.2, XcodeGen, Swift 6.4가 있었다. `project.yml`은 실제로 생성해 보지 않았다(직접 구현하지 않는다는 조건). XcodeGen이 키를 거절하면 4단계 끝의 방법으로 고친다.
- 서명 없이(`CODE_SIGNING_ALLOWED=NO`) 빌드하면 App Group·Keychain 접근 그룹은 실제로 동작하지 않는다. 그 동작은 `MANUAL_CHECKS.md`의 항목이다.
- `swift test`는 호스트(macOS)에서 돈다. iOS 전용 API를 쓰는 코드는 `#if os(iOS)`나 `#if canImport(ActivityKit)` 안에 두어야 패키지 테스트가 깨지지 않는다(이후 명세가 반복해서 적는다).
- macOS용 위젯·공유 확장 타깃(NATIVE §3)은 넣지 않았다. 필요해지는 작업(P6-A11)이 더한다.
