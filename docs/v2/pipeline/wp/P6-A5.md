# P6-A5 LecternUI

> 등급: `basic` · 게이트: `apple` · 의존: `P6-A2` · 소유: `apps/apple/`, `packages/design-tokens/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

iOS와 macOS가 함께 쓰는 화면 부품을 만든다. 디자인 토큰(색·글자·간격)을 웹과 같은 원본에서 받고, 구조화 문서의 블록을 SwiftUI로 그리고, 출처 칩을 누르면 그 시각의 오디오로 가고, 전사 목록이 재생 위치를 따라 현재 구간을 강조한다. 규칙은 웹과 같다: 모르는 블록은 그리지 않는다.

## 2. 먼저 읽을 것

- 문서: `docs/v2/NATIVE.md` §3(렌더링 규칙은 웹과 같다), `packages/domain/README.md`(동결 규칙)
- 코드: `packages/design-tokens/dist/Tokens.swift`(이미 생성돼 커밋돼 있다), `src/emit-swift.ts`, `scripts/build.ts`, 루트 `package.json`의 `tokens:build`
- 코드(웹, 읽기만): `apps/web/src/routes/recording/DocumentPane.tsx`(블록 종류별 그리는 법), `TranscriptPane.tsx`와 `lib/segments.ts`(현재 구간 찾기), `playback.tsx`
- 코드: `Packages/LecternKit`의 `Document`, `DocumentBlock`, `SourceRef`, `Transcript`(P6-A2)
- 코드: `apps/apple/scripts/gate.sh`의 `pre-gate-*.sh` 훅

## 5. 단계

1. 토큰: `Tokens.swift`를 `packages/design-tokens/dist/`에서 `Packages/LecternUI/Sources/LecternUI/Tokens/`로 복사해 **커밋한다**(생성 코드지만 SwiftPM이 패키지 밖 파일을 못 읽는다). `scripts/pre-gate-tokens.sh`는 두 파일을 `cmp`로 비교해 다르면 `gate: Tokens.swift is out of date (run: cp packages/design-tokens/dist/Tokens.swift apps/apple/Packages/LecternUI/Sources/LecternUI/Tokens/)`를 내고 종료 코드 1로 끝난다. 게이트가 복사를 대신 해 주지 않는다(조용히 달라지는 것을 막는다).
2. `Theme.swift`: `Tokens`의 값을 쓰는 얇은 층. 색은 밝은·어두운 모드 쌍으로 `Color`를 만든다(iOS는 `UIColor { traits in … }`, macOS는 `NSColor(name:dynamicProvider:)`, `#if canImport(UIKit)`로 가른다). 글자는 `Font.system(size:weight:)`에 토큰 크기를 넣되 **`relativeTo:` 텍스트 스타일을 지정해 Dynamic Type을 따른다.** 화면 코드에 색 16진수와 글자 크기 숫자를 직접 쓰지 않는다.
3. 문서 렌더러
   ```swift
   public struct DocumentView: View { public init(document: Document, onSource: @escaping (SourceRef) -> Void) }
   ```
   블록별 규칙(웹 `DocumentPane.tsx`와 같은 뜻)
   | 블록 | 그리는 법 | VoiceOver |
   |---|---|---|
   | `heading` | 수준 1~3의 제목 글자 | `.accessibilityAddTraits(.isHeader)` |
   | `paragraph` | 본문 글자. 인라인 강조(굵게)가 있으면 반영 | 그대로 읽는다 |
   | `list` | 순서 없는·있는 목록. 항목마다 글머리 | 항목마다 "목록 항목" 없이 글만 |
   | `quote` | 왼쪽 선과 들여쓴 글 | "인용" 접두 |
   | `term` | 용어(굵게)와 뜻 | "용어 <용어>, <뜻>" |
   | `formula` | 고정폭 글자로 원문 그대로(수식 조판은 하지 않는다) | "수식" 접두 |
   | `callout` | 종류(중요·주의·참고)에 따른 배경과 **글자 라벨**(색만으로 구별하지 않는다) | 라벨 먼저 |
   | `gap` | `전사가 비어 있는 구간입니다 (<시작>–<끝>)` 회색 글 | 그대로 |
   | `unknown` | **아무것도 그리지 않는다** (`EmptyView`) | — |
   - 블록 끝에 출처 칩들: `SourceChip`은 `<분:초>`(예: `12:05`) 또는 PDF면 `p.<쪽>`을 보이는 버튼이다. 누르면 `onSource`. 접근성 레이블 `출처, 12분 5초부터 듣기` / `출처, PDF <쪽>쪽`. 누를 수 있는 크기는 44pt 이상.
   - 본문 폭은 최대 720pt, 가운데.
4. 전사
   ```swift
   public func activeSegmentIndex(startsMs: [Int], positionMs: Int) -> Int?    // binary search: last segment whose start <= position; nil before the first
   public struct TranscriptList: View { public init(transcript: Transcript, positionMs: Int, onSeek: @escaping (Int) -> Void) }
   ```
   - `LazyVStack`. 줄: 화자 이름, `<분:초>`, 글. 현재 구간은 배경과 **왼쪽 표시 막대**로 강조한다. `.accessibilityAddTraits(.isSelected)`.
   - 현재 구간이 바뀌면 그 줄로 스크롤한다(`ScrollViewReader`). 사용자가 직접 스크롤한 뒤 5초 동안은 자동 스크롤을 멈춘다. "동작 줄이기"가 켜져 있으면 애니메이션 없이 이동한다.
   - 줄을 누르면 `onSeek(start_ms)`. 접근성 레이블 `<화자>, <분>분 <초>초, <글>`, 힌트 `두 번 탭하면 이 위치부터 재생합니다`.
5. 플레이어
   ```swift
   @MainActor public final class PlayerViewModel: ObservableObject {
       public init(loadItem: @escaping () async throws -> AVPlayerItem)
       @Published public private(set) var positionMs: Int
       @Published public private(set) var durationMs: Int
       @Published public private(set) var isPlaying: Bool
       @Published public var rate: Float                   // 0.75, 1, 1.25, 1.5, 2
       public func toggle(); public func seek(toMs: Int); public func skip(bySeconds: Int)
       public static func clamp(_ ms: Int, durationMs: Int) -> Int
       public static func nextRate(after rate: Float) -> Float
   }
   ```
   `PlayerBar`: 재생·일시정지, 15초 뒤로·앞으로, 속도, 위치 슬라이더, `<현재> / <전체>`. 모든 버튼에 접근성 레이블(`재생`, `일시정지`, `15초 뒤로`, `15초 앞으로`, `재생 속도 <값>배`). 슬라이더의 `accessibilityValue`는 `<분>분 <초>초`.
6. `emit-swift.ts`는 지금 출력으로 2단계가 되면 고치지 않는다. 필요한 값이 Swift 출력에 없을 때만(예: 어두운 모드 색 쌍이 빠짐) 생성기를 고치고 `bun run tokens:build`, `packages/design-tokens`의 테스트를 통과시킨 뒤 1단계 복사를 다시 한다. 웹용 출력(`tokens.css`, `tokens-css.ts`)이 바뀌면 안 된다(`git diff --stat packages/design-tokens/dist`로 확인).
7. 미리보기: 블록 종류마다 `#Preview` 하나(밝은·어두운 모드, 가장 큰 Dynamic Type 크기 하나씩). `PreviewData`의 문서는 일반적인 예문이다(실제 강의·사람 이름 없음).

## 6. 테스트

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| `testActiveSegmentBinarySearch` | 시작 `[0, 4000, 9000]` | 위치 `-1` → `nil`, `0` → 0, `3999` → 0, `4000` → 1, `100000` → 2 |
| `testActiveSegmentEmpty` | 빈 배열 | `nil` |
| `testActiveSegmentLarge` | 구간 10,000개, 위치 1,000개 | 선형 탐색 결과와 모두 같다 |
| `testClamp` | `-5`, `500`, `999999`(전체 1000) | `0`, `500`, `1000` |
| `testNextRateCycles` | `0.75 → 1 → 1.25 → 1.5 → 2 → 0.75` | 그대로 |
| `testSourceChipLabel` | 725,000ms / PDF 3쪽 | `12:05`, `p.3`. 접근성 레이블 `출처, 12분 5초부터 듣기`, `출처, PDF 3쪽` |
| `testTimeFormatting` | 59,000 / 3,725,000 | `0:59`, `1:02:05` |
| `testUnknownBlockRendersNothing` | `.unknown` 블록만 있는 문서의 "그릴 블록" 목록(뷰가 쓰는 순수 함수 `renderableBlocks`) | 빈 배열 |
| `testCalloutHasTextLabel` | 종류 3개 | `중요`, `주의`, `참고` |
| `testTokensFileMatchesSource` | `Tokens.swift` 두 파일(테스트가 저장소 경로를 `#filePath`로 계산) | 내용이 같다 |
| `testThemeColorsExistForBothSchemes` | `Theme`의 모든 색 | 밝은·어두운 값이 다 있다 |

뷰 자체의 모양은 스냅샷 테스트하지 않는다(새 의존성 없음). 뷰가 쓰는 계산(라벨, 시간 표기, 그릴 블록 고르기)을 순수 함수로 빼서 테스트한다.

## 10. 명세 작성자 메모

- `DocumentBlock`의 실제 케이스와 필드는 P6-A2가 `packages/domain`의 블록 정의에서 만든다. 3단계 표의 블록 이름은 CATALOG에서 가져왔다. 실제 정의와 다르면 실제 정의를 따른다.
- VoiceOver·Dynamic Type의 실제 확인은 `MANUAL_CHECKS.md`에 행을 더한다("가장 큰 글자 크기에서 문서가 잘리지 않는다", "VoiceOver로 문서를 처음부터 끝까지 읽을 수 있다").
- `dist/Tokens.swift`에 어두운 모드 값이 어떻게 들어 있는지는 확인하지 않았다(사전 점검 둘째 명령으로 본다).
