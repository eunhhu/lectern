# P2-01 서버: 오디오 삭제, 문서 내보내기, 추천 질문

> 등급: `basic` · 게이트: `full` · 의존: `P2-C` · 소유: `apps/server/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

P2-C가 501 스텁으로 등록한 세 라우트를 구현한다. (1) `DELETE /recordings/{id}/audio`는 노트를 두고 오디오만 지운다. (2) `GET /documents/{id}/export?format=md`는 현재 버전을 Markdown 첨부 파일로 준다. (3) `GET /ask/suggestions`는 모델 없이 규칙으로 최대 6개 질문을 준다.

## 5. 단계

1. `recordings.ts` — `recordingsRouter`의 `deleteRecordingAudio: notImplemented`를 바꾼다. 권한은 `withRecording(..., "recording:delete")`(만든 사람, 또는 workspace 공개 녹음의 owner/admin. viewer는 403).
   ```ts
   deleteRecordingAudio: withRecording((req, recording) => {
     // 1) lecture-backed: the v1 function, then the v2 rows follow by projection
     if (recording.lecture_id && getLectureById(recording.lecture_id)) {
       deleteLectureAudioOnly(recording.lecture_id);
       // 2) any other audio asset (kind LIKE 'audio%'): unlink `file:` blobs, delete rows
     }
     // announce so the v1 SSE and v2 events show the change
     if (recording.lecture_id) announceLectures([recording.lecture_id]);
     return req.c.body(null, 204);
   }, "recording:delete"),
   ```
   - 2)는 `asset`에서 `recording_id = ? AND kind LIKE 'audio%'` 행을 읽어, `blob_key`가 `file:`로 시작하면 `assetPath(asset)`이 돌려준 파일을 `unlinkSync`(실패는 `logger.warn`, 무시)하고 `transact(() => DELETE FROM asset WHERE id = ?)`. `lecture:` 키는 v1 함수가 이미 처리했다.
   - 오디오가 이미 없어도 204다(멱등).
   - `deleteLectureAudioOnly`를 `../../db.ts` import에 추가한다. `unlinkSync`는 `node:fs`.
   - 문서·전사·노트 행은 건드리지 않는다.
2. `documents.ts` — `exportDocument`를 `withDocument`로 만든다(읽기 권한). 현재 버전의 `rendered_md`를 쓴다.
   ```ts
   exportDocument: withDocument((req, document, recording) => {
     const version = versionOf(document.id, document.current_version)!;
     const name = `${recording.title}.md`.replace(/[^\w가-힣._ -]/g, "_");
     return new Response(version.rendered_md + "\n", { headers: {
       "Content-Type": "text/markdown; charset=utf-8",
       "Content-Disposition": `attachment; filename="note.md"; filename*=UTF-8''${encodeURIComponent(name)}`,
       "Cache-Control": "private, no-store",
     } });
   }),
   ```
   `format`은 P2-C의 쿼리 스키마가 `md`만 통과시킨다. 따로 검사하지 않는다. 볼 수 없는 문서는 `withDocument`가 404.
3. `suggestions.ts` — 새 파일. 모델도 DB도 부르지 않는 순수 함수.
   ```ts
   export function buildSuggestions(input: { scope: "recording" | "folder" | "workspace"; domain?: string; sectionTitles?: string[] }): string[]
   ```
   규칙(이 문구를 그대로 쓴다):
   - `recording`, 도메인별 고정 질문(앞에서부터):
     - `lecture`: `"이 강의의 핵심 내용을 요약해 줘."`, `"시험에 나올 만한 내용은 뭐야?"`, `"중요한 용어를 정리해 줘."`
     - `meeting`/`one_on_one`/`call`: `"이 회의에서 결정된 것은 뭐야?"`, `"내가 해야 할 일은 뭐야?"`, `"다음 일정이 언급됐어?"`
     - `seminar`: `"발표의 핵심 주장은 뭐야?"`, `"질의응답에서 나온 내용을 정리해 줘."`, `"소개된 참고 자료가 있어?"`
     - `interview`: `"인터뷰 대상자의 핵심 답변을 정리해 줘."`, `"인상적인 발언을 인용해 줘."`, `"후속 질문으로 무엇을 할 수 있을까?"`
     - 그 밖(`other`, 모르는 값): `"이 녹음의 핵심 내용을 요약해 줘."`, `"할 일이나 일정이 있어?"`, `"중요한 결정이나 결론은 뭐야?"`
   - 이어서 섹션 제목마다 `"「<제목>」 부분을 자세히 설명해 줘."`(제목 앞 공백 제거, 30자 넘으면 `…`로 자름), 중복 제목은 한 번만.
   - `folder`: `"이 폴더의 녹음들을 한눈에 요약해 줘."`, `"이 폴더에서 해야 할 일을 모아 줘."`
   - `workspace`: `"최근 녹음에서 해야 할 일은 뭐야?"`, `"이번 주 일정과 관련된 내용을 찾아 줘."`, `"가장 최근 녹음을 요약해 줘."`
   - 결과는 중복 없이 앞에서 6개까지.
4. `ask.ts` — `createAskRouter`의 `listAskSuggestions`를 구현한다. `getService()`(물어보기 켜짐 여부)를 **보지 않는다**: 모델을 쓰지 않으므로 `LECTERN_ASK=0`에서도 답한다.
   - `scope_type=workspace`: `requireWorkspace(req, workspace_id)`(비멤버 403).
   - `scope_type=recording`: `scope_id` 필수(없으면 400 `"scope_id가 필요합니다."`). `loadRecording(req, scope_id)`로 읽는다(안 보이면 404). 그 녹음의 `workspace_id`가 쿼리의 `workspace_id`와 다르면 404. 도메인은 `recording.domain`. 섹션 제목은 `documentsOf`의 첫 문서가 아니라 `recording_id`의 모든 문서에서, `document_version`의 현재 버전 `body_json`(null이면 건너뜀)을 `parseJson`으로 읽어 `sections[].title`을 모은다.
   - `scope_type=folder`: `scope_id` 필수. `getFolderRow(scope_id)`가 없거나 다른 워크스페이스면 404. 멤버 확인은 `requireWorkspace`.
   - 응답: `ok(req, { suggestions: buildSuggestions(...) })`.
5. `api-v2.test.ts` 정리: `NOT_YET`에서 `"deleteRecordingAudio"`, `"exportDocument"`를 지운다. P2-C가 추가한 "추천 질문 501" 테스트를 지운다.
6. `README.md` 상태 표 갱신.

## 10. 명세 작성자 메모

- 오디오 삭제의 2단계(`file:` blob 정리)는 v2 업로드(P1)로 생긴 `audio_compact` 같은 파생 asset을 위한 것이다. `lecture:` blob만 있는 지금 코드에서는 실행되지 않을 수 있다.
- `recordings.ts` 안에 지역 함수 `deleteRecording`이 이미 있다. 같은 이름을 만들지 말고 `deleteRecordingAudio`는 핸들러 안에 쓴다.
- 추천 질문 문구는 계약에 없고 이 명세가 정했다. 변경하려면 이 명세와 테스트를 함께 고친다.
