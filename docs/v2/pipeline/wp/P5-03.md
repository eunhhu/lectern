# P5-03 네이티브 토큰 쌍

> 등급: `careful` · 게이트: `full` · 의존: `P5-C` · 소유: `apps/server/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

네이티브 앱이 이메일·비밀번호로 로그인해 access 토큰(1시간)과 refresh 토큰(60일)을 받는다. refresh는 쓸 때마다 새 쌍으로 바뀐다. 이미 쓴 refresh가 다시 오면(탈취 의심) 그 로그인에서 나온 토큰이 모두 죽는다. 비밀번호를 바꾸면 그 사용자의 네이티브 로그인이 모두 끊긴다.

## 5. 단계

1. `rate-limit.ts`: `index.ts`의 `RateLimiter` 클래스, `authRateLimits`, `RateLimitCheck`, `firstRateLimitWait`, `recordRateLimitHits`, `resetAuthRateLimits`를 **그대로** 옮기고 export한다. `authRateLimits`에 `nativeEmail: new RateLimiter(10, 15 * MINUTE_MS)`, `nativeIp: new RateLimiter(30, 15 * MINUTE_MS)`를 더한다(로그인과 같은 수치). `index.ts`는 이들을 import하고 `export { resetAuthRateLimits } from "./rate-limit.ts";`로 기존 import 경로를 지킨다. 동작은 바뀌지 않아야 한다(기존 `server.test.ts` 통과).
2. `native-auth.ts`
   ```ts
   export const ACCESS_PREFIX = "lct_at_";
   export const REFRESH_PREFIX = "lct_rt_";
   export const ACCESS_TTL_MS = 60 * 60 * 1000;
   export const REFRESH_TTL_MS = 60 * 24 * 60 * 60 * 1000;
   export interface NativePair { accessToken: string; refreshToken: string; expiresIn: number }   // expiresIn in seconds (3600)
   export function issueNativePair(p: { userId: string; deviceName?: string; platform?: string; familyId?: string }, now?: number): NativePair
   export function rotateNativePair(refreshToken: string, now?: number): { pair: NativePair; userId: string } | { error: "invalid" | "reused" | "expired" }
   export function revokeNativeFamilyByRefresh(refreshToken: string): void
   export function revokeNativeSessionsOfUser(userId: string): void
   export function findUserByAccessToken(accessToken: string, now?: number): string | null   // user id; null when unknown, revoked or expired
   ```
   - 토큰: 접두사 + `randomBytes(32).toString("base64url")`. DB에는 `sha256Hex`만 넣는다. 한 행이 한 쌍이다.
   - `issueNativePair`: `family_id`는 주어지지 않으면 `uuidv7()`.
   - `rotateNativePair`: `refresh_hash`로 행을 찾는다. 없으면 `invalid`. `revoked_at`이 있으면 `invalid`. `refresh_used_at`이 있으면 **그 `family_id`의 모든 행에 `revoked_at = now`**를 넣고 `reused`. `refresh_expires_at <= now`면 `expired`. 그 밖에는 한 트랜잭션에서 그 행에 `refresh_used_at = now`를 넣고 같은 `family_id`·`device_name`·`platform`으로 새 쌍을 만든다. 옛 행의 access 토큰은 그 순간 `access_expires_at = now`로 끝낸다.
   - `findUserByAccessToken`: `access_hash`가 맞고 `revoked_at IS NULL`이고 `access_expires_at > now`. `last_used_at`은 5분에 한 번만 쓴다.
3. `authn.ts`: 토큰이 `ACCESS_PREFIX`로 시작하면 `findUserByAccessToken` → `getUserById`(비활성 사용자는 `null`) → `{ user, via: "native" }`. `REFRESH_PREFIX`로 시작하는 토큰은 인증에 쓸 수 없다(`null`). 파일이 없으면 `P5-02` 명세 5절 2단계의 모양으로 만들고(`PAT` 부분은 빼고) `common.ts`의 인증 줄을 `authenticateV2`로 바꾼다.
4. `auth-native.ts`
   - `issueNativeToken` — `grant_type: "password"`
     1. `getClientIp`와 이메일로 `firstRateLimitWait([[nativeIp, ip], [nativeEmail, email]])`. 기다려야 하면 `429 rate_limited`, 문구는 기존 로그인의 것과 같게(로그인 처리에서 그대로 가져온다), `Retry-After` 헤더.
     2. `getUserByEmail` + `verifyPassword`. 틀리면 `recordRateLimitHits` 뒤 `401 unauthorized`, 문구 `이메일 또는 비밀번호가 올바르지 않습니다.`(계정이 없을 때와 같은 응답). 비활성·미인증 계정은 기존 로그인이 거절하는 조건을 그대로 따른다.
     3. `issueNativePair` → `{ token_type: "Bearer", access_token, refresh_token, expires_in: 3600, user: meDto(…) }`.
   - `grant_type: "refresh_token"`: `rotateNativePair`. 오류는 셋 다 `401 unauthorized`, 문구 `다시 로그인해 주세요.`(종류를 구별해 알려 주지 않는다). `reused`는 `logger.warn`에 `family_id`만 남긴다.
   - `revokeNativeToken`: `revokeNativeFamilyByRefresh` → 항상 204(모르는 토큰도 204).
   - 응답에 `Cache-Control: no-store`.
5. 비밀번호 변경·재설정 뒤(`updateUserPassword`를 부르는 곳마다) `revokeNativeSessionsOfUser(userId)`.

`native-auth.test.ts`

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| "password grant" | 맞는 이메일·비밀번호 | 200, `access_token`이 `lct_at_`, `refresh_token`이 `lct_rt_`, `expires_in === 3600`, `user.id` |
| "access token authenticates v2" | `Authorization: Bearer <access>`로 `GET /api/v2/me` | 200 |
| "refresh token does not authenticate" | refresh로 `GET /api/v2/me` | 401 |
| "wrong password" | 틀린 비밀번호 | 401, 없는 계정과 본문이 같다 |
| "rate limited like login" | 틀린 비밀번호 11번 | 11번째가 429와 `Retry-After` |
| "rotation" | refresh로 새 쌍 | 새 access 200, 옛 access 401, 새 refresh가 옛 것과 다르다 |
| "reuse kills the family" | 옛 refresh를 다시 씀 | 401. 그 뒤 **새** access와 새 refresh도 401 |
| "expired access" | `access_expires_at`을 과거로 | 401 |
| "expired refresh" | `refresh_expires_at`을 과거로 | 401 |
| "revoke" | `revokeNativeToken` | 204, access와 refresh 둘 다 401. 모르는 토큰도 204 |
| "password change signs native sessions out" | 발급 뒤 비밀번호 재설정 흐름 | access 401, refresh 401 |
| "no plaintext in the database" | 발급 뒤 `native_session` 전체 문자열 | 두 원문이 없다 |
| "does not open v1" | access 토큰으로 `GET /api/lectures` | 401 |

## 8. 하지 않는 것

- OAuth로 로그인한 사용자의 네이티브 로그인(Google·Apple 토큰 교환)은 만들지 않는다. 비밀번호가 없는 계정은 네이티브 로그인이 안 된다(STATUS에 적는다).
- 네이티브 세션을 `/me/devices`에 넣지 않는다.
- 앱 쪽 코드(`P6-A2`).

## 10. 명세 작성자 메모

- `P5-02`와 이 작업은 둘 다 `apps/server/`를 소유하므로 동시에 돌지 않는다. 어느 쪽이 먼저든 `authn.ts`가 생기게 5절 3단계에 두 경우를 적었다.
- 회전 때 옛 access 토큰을 바로 끝내는 것은 계약에 없는 이 명세의 결정이다(앱은 새 쌍을 받은 뒤 옛 것을 쓸 일이 없다).
- 기존 로그인의 429 문구와 미인증 계정 처리 조건은 `index.ts`의 `/api/auth/login` 처리를 읽고 그대로 옮긴다.
