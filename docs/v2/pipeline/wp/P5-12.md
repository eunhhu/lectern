## 1. 목표

운영자가 새 웹 앱의 `/app/admin`에서 서비스 상태를 본다: 개요, 사용자, 작업(단계별 시간·비용과 재시도), 사용량과 쿼터. 데이터는 지금 있는 관리자 API를 그대로 쓴다. 운영자가 아닌 사람에게는 "찾을 수 없음" 화면이 보인다. 옛 콘솔(`/admin`)은 그대로 둔다.

## 5. 단계

1. `api/admin.ts`
   ```ts
   export interface AdminApi {
     overview(): Promise<AdminOverview>;                 // GET /api/admin/overview
     users(): Promise<AdminUser[]>;                      // GET /api/admin/users
     updateUser(id: string, patch: Record<string, unknown>): Promise<void>;   // the method and body the old console sends
     jobs(q: { state?: string; kind?: string; cursor?: string }): Promise<JobPage>;   // GET /api/v2/admin/jobs
     job(id: string): Promise<AdminJobDetail>;           // GET /api/v2/admin/jobs/{id}
     retryJob(id: string): Promise<void>;                // POST /api/v2/admin/jobs/{id}/retry
     usage(period?: string): Promise<UsageLedgerPage>;   // GET /api/v2/admin/usage
     setQuota(workspaceId: string, q: WorkspaceQuota): Promise<WorkspaceQuota>;
   }
   ```
   - v1 응답 타입(`AdminOverview`, `AdminUser`)은 이 파일 안에 `interface`로 적는다. **필드는 서버 코드에서 읽은 그대로 쓰고, 지어내지 않는다.** 화면에 쓰지 않는 필드는 타입에 넣지 않아도 된다.
   - v1 관리자 API는 쿠키 인증이다(`credentials: "same-origin"`). 변경 요청에 옛 콘솔이 보내는 헤더(CSRF용 헤더가 있으면)를 똑같이 보낸다.
   - 403·404는 `ApiClientError`로 던진다.
2. 운영자 판별: `getMe()` 응답에 운영자 표시 필드가 있으면 그것을 쓴다. 없으면 `overview()`를 한 번 불러 200이면 운영자, 403·404면 아닌 것으로 보고 결과를 세션 동안 기억한다.
3. 라우트(모두 `authedRoute` 아래): `/admin`(개요), `/admin/users`, `/admin/jobs`, `/admin/jobs/$jobId`, `/admin/usage`. `AdminLayout`이 운영자가 아니면 `페이지를 찾을 수 없습니다.` 화면을 그린다(관리자 메뉴가 있다는 것도 드러내지 않는다). 왼쪽(좁은 화면에서는 위) 탭: `개요`, `사용자`, `작업`, `사용량`. `RootLayout`의 내비게이션에 운영자에게만 `관리` 링크.
4. `DataTable.tsx`
   ```ts
   export interface Column<T> { key: string; header: string; cell: (row: T) => React.ReactNode; sortValue?: (row: T) => string | number | null; align?: "left" | "right" }
   export function DataTable<T>(p: { caption: string; columns: Column<T>[]; rows: T[]; rowKey: (row: T) => string; empty: string }): JSX.Element
   export function sortRows<T>(rows: T[], col: Column<T>, dir: "asc" | "desc"): T[]   // nulls last, stable
   ```
   - 진짜 `<table>`과 `<caption>`(시각적으로 숨겨도 된다), `<th scope="col">`. 정렬 가능한 머리글은 `<button>`이고 `aria-sort`를 `ascending`/`descending`/`none`으로 둔다. Enter·Space로 정렬이 바뀐다.
   - 숫자 열은 오른쪽 정렬, `font-variant-numeric: tabular-nums`.
5. 화면
   - **개요**: 옛 콘솔 개요가 보여 주는 수치를 카드로(사용자 수, 녹음 수, 저장 용량, 대기·실행·실패 작업 수 등 응답에 있는 것). 실패 작업 수는 `/app/admin/jobs?state=failed` 링크.
   - **사용자**: 표(이메일, 이름, 가입일, 상태, 녹음 수 등 응답에 있는 것). 옛 콘솔에 있는 동작(예: 사용 중지·해제, 운영자 지정, 삭제)을 같은 요청으로 낸다. 되돌릴 수 없는 동작(삭제)은 확인 대화상자에 대상 이메일을 다시 입력하게 한다.
   - **작업**: 필터 `상태`(전체, 대기, 실행 중, 실패, 완료, 취소)와 `종류`. 표(종류, 상태, 워크스페이스, 녹음, 만든 시각, 걸린 시간, 비용). 더 보기 버튼(`next_cursor`). 줄을 누르면 상세.
   - **작업 상세**: 단계 타임라인 — 단계마다 한 줄(이름, 상태, 시작 시각, 걸린 시간, 시도 횟수, 비용, 오류 코드). 막대 길이는 걸린 시간 비례(글자로도 시간을 쓴다). AI 호출 표(모델, 입력·출력 토큰, 오디오 초, 비용, 지연, 상태). 버튼 `다시 시도`(실패·취소 작업에만. 확인: `이 작업을 다시 시도할까요?`). 501이면 토스트 `준비 중입니다.`
   - **사용량**: 기간 선택(이번 달 기본, 이전 6개월). 표(워크스페이스, 녹음 시간, AI 비용, 저장 공간). 줄마다 `한도 설정` 버튼 → 대화상자(세 입력: 월 녹음 시간(시간 단위), 월 AI 비용(달러), 저장 공간(GB). 비우면 제한 없음) → `setQuota`. 토스트 `한도를 저장했습니다.`
   - 시간은 `Asia/Seoul`, 비용은 `$0.0123` 형식(마이크로달러 ÷ 1e6, 유효 숫자 3자리 이상).
6. fixture: 사용자 5명, 작업 12개(상태 섞음, 하나는 단계 6개와 AI 호출 4개), 원장 3행.

## 6. 테스트

| 종류 | 테스트 이름 | 준비 | 기대 |
|---|---|---|---|
| unit | admin-table "sortRows" | 숫자·문자·`null` 섞음 | 오름·내림 모두 `null`이 끝, 같은 값은 원래 순서 |
| e2e | "non-admin sees not found" | fixture 일반 사용자, `/app/admin` | `페이지를 찾을 수 없습니다.`, 내비게이션에 `관리` 없음 |
| e2e | "overview cards" | 운영자 | 카드 수치가 fixture와 같다 |
| e2e | "sort by keyboard" | 사용자 표의 `가입일` 머리글에 포커스 → Enter 두 번 | `aria-sort`가 `ascending` → `descending`, 첫 줄이 바뀐다 |
| e2e | "failed jobs filter from the overview" | 실패 카드 링크 | 주소에 `state=failed`, 표에 실패 작업만 |
| e2e | "job timeline" | 작업 상세 | 단계 6줄, 각 줄에 시간과 비용 글자 |
| e2e | "retry asks first" | `다시 시도` | 확인 뒤 요청 1회 |
| e2e | "set a quota" | 한도 대화상자에 `10`(시간) | `setQuota`가 `audio_ms_month: 36000000`으로 불린다. 토스트 |
| e2e | "delete user needs the e-mail" | 삭제 대화상자 | 이메일을 넣기 전에는 버튼이 꺼져 있다 |
| server e2e | "admin overview renders against the real server" | `e2e/server/accounts.ts`의 운영자 계정 | `/app/admin`에 개요 카드, `/app/admin/users`에 자기 이메일 |
| e2e | a11y "admin overview/users/jobs/job detail/usage" | 각 화면 | axe 위반 0건 |

## 10. 명세 작성자 메모

- v1 관리자 API의 응답 필드는 이 명세에 적지 않았다(확인하지 않았다). 워커가 `index.ts`와 옛 콘솔 스크립트를 읽고 정한다. 읽어도 모양이 분명하지 않으면 멈추고 보고한다.
- server e2e에서 운영자 계정을 만드는 방법(`e2e/server/accounts.ts`와 서버의 운영자 지정 방식: 환경 변수 또는 첫 사용자)은 그 파일과 `isAdminUser`를 읽고 따른다.
- 작업 목록의 "비용" 열은 목록 응답에 없으면 상세에서만 보인다.
