## 1. 목표

`bun run harness eval --notes`를 만든다. 평가 세트의 참조 전사(`ref/*.md`)를 `runNotesPipeline`에 넣고, 주석 CSV(`annotations.csv`)와 비교해 다섯 지표를 낸다: 스키마 유효율, 근거 연결률, 일정 날짜 정확도, 과추출률, 녹음 1시간당 비용. 내장 합성 세트와 `ScriptedLlmProvider`로 비용 없이 결정적으로 돈다. 실제 공급자(`--provider gemini`)는 `--yes` 없이는 예상 비용만 출력하고 멈춘다. 기존 전사 평가(`--notes` 없이)는 바뀌지 않는다.

## 5. 단계

1. `notes-metrics.ts`(순수 함수, I/O 없음). 시간 일치 허용 오차 `MATCH_WINDOW_MS = 60_000`.
   ```ts
   export interface NotesItemMetrics {
     schema_valid: boolean;                     // pipeline finished, NotesResult parses, report.repaired === false
     blocks: { total: number; grounded: number };      // from report.items where kind === "block": ok = grounded
     events: { annotated: number; correct: number };   // annotated event found with the right date (and time when annotated)
     extracted: { total: number; unmatched: number };  // events + action items vs annotations of the same kind
   }
   export function evidenceStartMs(evidence: Evidence, segments: readonly { idx: number; start_ms: number }[]): number | null
   export function scoreNotes(input: { result: NotesResult; transcript: Transcript; annotations: readonly Annotation[] }): NotesItemMetrics
   ```
   - `evidenceStartMs`: `evidence.sources`에서 첫 `kind === "transcript"` 출처의 `start_idx`를 세그먼트 `idx`로 찾아 `start_ms`. 없으면 `null`.
   - `grounded` = `result.report.items.filter(i => i.kind === "block" && i.outcome === "ok").length`, `total` = `kind === "block"` 전체(`dropped` 포함).
   - 일정 날짜: 주석 `kind === "event"`마다, 시작 시각이 `|ann.start_ms - evidenceStartMs| ≤ 60_000`인 추출 일정 중 가장 가까운 것을 짝으로 삼는다(한 추출 일정은 한 주석에만). 짝의 날짜 `YYYY-MM-DD`(`Intl.DateTimeFormat("sv-SE", { timeZone: event.tz })`로 `start_at`을 푼 값)가 `ann.date`와 같고, `ann.time`이 있으면 `HH:MM`도 같을 때만 `correct`. 짝이 없으면 틀린 것(`annotated`만 늘어난다).
   - 과추출: 추출한 일정·할 일 각각에 대해 같은 종류 주석 중 시간 일치(±60초) 짝이 없으면 `unmatched`. `total`은 추출 일정 수 + 할 일 수.
   - 집계 함수 `totalsOf(items: NotesItemMetrics[], costMicrousd: number, audioHours: number)`: `schema_valid_rate = 유효 항목 / 항목 수`, `grounding_rate = Σgrounded / Σtotal`(Σtotal이 0이면 `null`), `event_date_accuracy = Σcorrect / Σannotated`(0이면 `null`), `over_extraction_rate = Σunmatched / Σtotal`(0이면 `null`), `usd_per_audio_hour = audioHours > 0 ? costMicrousd / 1e6 / audioHours : null`.
2. `notes-scripted.ts`: `export function oracleNotesLlm(set: EvalSet, options: OracleOptions = {}): ScriptedLlmProvider`.
   ```ts
   export interface OracleOptions { dropRate?: number; wrongDateRate?: number; extraRate?: number; seed?: number }  // all default 0, seed default 1
   ```
   - 응답은 항목(`item`)의 주석에서 만든다: `classify` → 항목의 `domain`·`language`, 제목은 항목 id, `confidence: 0.9`. `structure` → 템플릿의 필수 섹션마다 블록 1개, 출처는 참조 전사의 첫 세그먼트 `#0`. `extract` → 주석 `event`마다 일정 1개(`raw_expression` = 주석 `text`, 시작은 주석 `date`의 정오, 근거는 주석 시각에 가장 가까운 세그먼트 `#idx`), `action_item`마다 할 일 1개.
   - 노브: `dropRate`는 주석을 일정 비율 빼고(시드 고정 난수), `wrongDateRate`는 날짜를 하루 밀고, `extraRate`는 주석에 없는 일정을 추가한다. 난수는 `mulberry32(seed)`(`scripted.ts`의 방식).
   - **응답 JSON의 모양은 `P1-04`·`P1-06`의 `templateOutputSchema(def)`·`extractResultSchema(def)`를 따른다.** 코드를 쓸 때 그 스키마를 읽고, 만든 응답을 `schema.parse`로 확인한다. `ScriptedLlmProvider`에 응답 함수를 등록하는 방법은 `P1-01`이 만든 클래스의 시그니처를 따른다.
3. `notes-run.ts`:
   ```ts
   export interface NotesEvalRunOptions {
     set: EvalSet; provider: "scripted" | "gemini"; model?: string; oracle?: OracleOptions;
     cacheDir: string; label?: string; log?: (line: string) => void; now?: () => number;
     confirm?: (estimate: CostEstimate) => boolean | Promise<boolean>;
   }
   export interface NotesEvalRun { format: 1; kind: "notes"; created_at: string; label: string; set: { id: string; items: number };
     provider: string; model: string; estimate: CostEstimate | null; items: Array<{ id: string; status: "ok" | "failed"; error?: string; metrics: NotesItemMetrics | null; cost_microusd: number; duration_ms: number }>;
     totals: { schema_valid_rate: number | null; grounding_rate: number | null; event_date_accuracy: number | null; over_extraction_rate: number | null; cost_microusd: number; audio_hours: number; usd_per_audio_hour: number | null } }
   export function estimateNotesCost(model: string, transcriptChars: number, items: number, at?: number): CostEstimate
   export async function runNotesEval(options: NotesEvalRunOptions): Promise<NotesEvalRun>
   ```
   - 항목마다: `ReferenceTranscript.lines`를 하네스 `Transcript`로 바꾼다(`segments`: `idx` = 줄 순서, `start_ms`/`end_ms`/`speaker`/`text`, `source_chunk: 0`; `speakers`: 라벨별 집계; `gaps: []`; `duration_ms` = `reference.duration_ms ?? 마지막 end_ms`). 녹음 시각은 `reference.meta.recorded_at`(ISO 시각+오프셋)이 있으면 그것, 없으면 `2026-10-19T14:00:00+09:00`, 시간대 `Asia/Seoul`, `recorded_at_source`는 `"client"`.
   - `runEval`처럼 `openCache(cacheDir)`(이 작업이 `export`한 것)로 평가 전용 SQLite·blob을 쓰고, 항목마다 `eval_<runId>_<item>` `job` 행을 INSERT한 뒤 `harness.job({ jobId, scope: "eval:" + set.id })`로 `runNotesPipeline`을 돌린다(입력 타입은 `P1-09`의 것). 비용은 `SELECT COALESCE(SUM(cost_microusd),0) FROM ai_call WHERE job_id = ?`.
   - `provider === "scripted"`이면 `oracleNotesLlm(set, options.oracle)`, `"gemini"`이면 `new GeminiLlmProvider({...})`(키는 `resolveGeminiApiKey()`, `run.ts`의 `providerFor`와 같은 방식)와 `loadRouting()`. 실제 공급자는 먼저 `estimate = estimateNotesCost(...)`를 만들고 `await options.confirm?.(estimate)`가 거짓이면 `Error("eval stopped before any paid call (cost not confirmed)")`를 던진다(`runEval`과 같은 문구).
   - `estimateNotesCost`: 입력 토큰 = `ceil(chars / 2) * 3`(분류·구조화·추출이 각각 전사를 읽는다), 출력 토큰 = `4_000 * items`. 가격은 `priceFor(DEFAULT_PRICING, "gemini", model, at)`와 `costMicrousd`. `assumptions`에 이 가정을 한국어로 적는다.
   - 한 항목이 던지면 `status: "failed"`로 기록하고 계속한다. 끝에 DB를 닫는다.
4. `report.ts`: `formatNotesReport(run: NotesEvalRun, baseline?: NotesEvalRun): string`. 항목 표(`item status valid grounded events extra cost`)와 합계 줄(`스키마 유효율 100.0%, 근거 연결률 …`), 비용 줄, 기준 대비 줄(`+x.x%p`, `formatReport`와 같은 형식). `baseline.kind !== "notes"`이면 `Error("기준 파일이 노트 평가 결과가 아닙니다.")`.
5. `cli.ts`: `parseArgs`에 `notes: { type: "boolean", default: false }`와 `"drop-rate"`, `"wrong-date-rate"`, `"extra-rate"`를 더한다(`--notes`일 때만 의미). `USAGE`에 `[--notes]`를 적는다. `--notes`이면 `runNotesEval`을 부르고 결과를 `runs/`에 `<날짜>-notes-<label>.json`으로 쓴 뒤 `formatNotesReport(run, baseline)`을 출력한다. `confirm` 콜백과 `--yes` 처리는 기존 전사 평가와 같다. 종료 코드: 실패 항목이 있으면 1. `--notes`가 없으면 기존 경로를 한 글자도 바꾸지 않는다.
6. `eval/example/annotations.csv`에 행을 더한다: `lecture-break`에 일정 2개(날짜는 기준 `2026-10-19`로 사람이 푼 값)와 할 일 1개, `interview-2p`에 일정 1개. 기존 3행은 그대로 둔다. `eval/README.md`: "지금은 형식 검사만"을 "`bun run harness eval --notes`의 일정·할 일 평가에 쓴다"로 바꾸고 `ref/*.md` front matter의 선택 항목 `recorded_at`과 지표 표(5개)를 더한다.
7. `src/index.ts`에 `export * from "./eval/notes-metrics.ts"; export * from "./eval/notes-scripted.ts"; export * from "./eval/notes-run.ts";`.

## 10. 명세 작성자 메모

- 카탈로그는 "일정·할 일 주석 CSV를 추가"라고 하지만 `annotations.csv` 형식과 `parseAnnotations`는 이미 있다(`kind`: event, action_item, decision, concept). 새 형식을 만들지 않고 이것을 평가에 쓰도록 문서와 예시 행만 보강했다.
- `ScriptedLlmProvider`에 응답 함수를 등록하는 방법, `runNotesPipeline`의 `input` 타입, 단계별 JSON 모양(`templateOutputSchema`, `extractResultSchema`)은 `P1-01`~`P1-09`가 정한다. 이 명세는 그것을 모른 채 쓰였으므로 워커는 병합된 코드를 읽고 맞춘다. 맞지 않으면 멈추고 보고한다.
- 지표의 정확한 정의(±60초 매칭, 하루 단위 날짜 비교, 입력 토큰 추정 `chars/2*3`)는 계약에 없다. 이 명세의 선택이다.
- 합성 세트는 비용이 0인 스크립트 공급자라 `usd_per_audio_hour`가 0이다. 실제 비용은 사용자가 실제 세트로 잰다.
