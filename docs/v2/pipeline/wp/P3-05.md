# P3-05 OCR 승인 흐름

> 등급: `careful` · 게이트: `full` · 의존: `P3-03` · 소유: `packages/harness/`, `apps/server/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

스캔본(글자 층이 없는 쪽)은 사용자가 비용을 보고 승인해야만 OCR한다. `POST /assets/{id}/ocr`는 `dry_run: true`이면 모델을 부르지 않고 쪽 수와 예상 비용만 답한다. `dry_run: false`이면 OCR 작업을 큐에 넣고, 작업이 Gemini에 PDF를 보내 글자를 받아 `pdf_page`에 `ocr_source = 'model'`로 저장하고 색인 갱신을 예약한다. 업로드·`process`는 절대 OCR을 시작하지 않는다.

## 5. 단계

1. `gemini-ocr.ts` (R7을 따른다. 키는 `x-goog-api-key` 헤더, `fetch` 주입, `-latest` 금지):
```ts
export const OCR_PAGES_PER_CALL = 8;
export const OcrResult = z.object({ pages: z.array(z.object({ page_no: z.int().min(1), text: z.string() })) });
export class GeminiOcrProvider {
  readonly id = "gemini";
  constructor(readonly model: string, private opts: GeminiAdapterOptions) {}   // model passes resolveGeminiModel()
  readonly fingerprint: { prompt: string; params: unknown };                   // prompt = sha256 of the prompt text
  ocr(req: { pdf: Uint8Array; pages: number[]; signal?: AbortSignal; repair?: { issues: string } | null }):
    Promise<z.infer<typeof OcrResult> & ProviderCallResult>;
}
```
   요청: `POST {base}/models/{model}:generateContent`, `contents: [{ role: "user", parts: [{ inlineData: { mimeType: "application/pdf", data: <base64> } }, { text: <프롬프트> }] }]`, `generationConfig: { responseMimeType: "application/json", responseSchema: <OBJECT pages[ARRAY of OBJECT page_no INTEGER, text STRING], propertyOrdering, required>, maxOutputTokens: <routing.ocr.maxOutputTokens> }`. 프롬프트(한국어, 코드 상수): 지정한 쪽 번호만, 보이는 글자를 순서대로 **그대로** 옮기고 요약·번역·추측·설명을 하지 않는다, 글자가 없으면 빈 문자열. 응답 처리 순서는 R7 5번(`!res.ok` → `geminiHttpError`; 차단·`MAX_TOKENS` → `HarnessError("output_validation", …, { code, billed })`; `thought` 파트 제외; 빈 응답 `empty_response`; `malformed_json`; zod `schema`). 요청하지 않은 `page_no`는 결과에서 버린다. 사용량은 `normalizeGeminiUsage`.
   PDF가 18 MiB(`18 * 1024 * 1024`)를 넘으면 호출 전에 `HarnessError("input", …, { code: "pdf_too_large_for_ocr" })`.
2. `pdf/ocr.ts`:
```ts
export const OCR_INPUT_TOKENS_PER_PAGE = 258;
export const OCR_OUTPUT_TOKENS_PER_PAGE = 600;
export function estimateOcrCost(args: { pagesToOcr: number; pageCount: number; model: string; at?: number }): number; // microUSD
export const ocrStage: (p: GeminiOcrProvider) => StageDefinition<{ path: string; pages: number[] }, z.infer<typeof OcrResult>>;
```
   `estimateOcrCost`: 호출 수 `calls = ceil(pagesToOcr / 8)`(0쪽이면 0), 입력 토큰 = `calls * pageCount * 258`(요청마다 PDF 전체가 간다), 출력 토큰 = `pagesToOcr * 600`, 단가는 `priceFor(DEFAULT_PRICING, "gemini", model, at ?? Date.now())`, 결과 `Math.round(in*price.input + out*price.output)`. 단가가 없으면 `Error`.
   `ocrStage`: `name: "pdf_ocr"`, `version 1`, `memo: "shared"`, `retry: { maxAttempts: 3, repairs: 1 }`, `key`: `inputs: [hashFile(path), sha256Hex(JSON.stringify(pages))]`, `prompt: provider.fingerprint.prompt`, `provider: provider.id`, `model: provider.model`, `params: provider.fingerprint.params`. `run`: `ctx.meter({ provider: provider.id, model: provider.model }, () => provider.ocr({ pdf: bytes, pages, signal: ctx.signal, repair: ctx.repair }))`.
3. `pdf-ocr-job.ts`:
```ts
export const OCR_JOB_KIND = "pdf_ocr";
export function pagesNeedingOcr(assetId: string): number[]; // SELECT page_no FROM pdf_page WHERE asset_id = ? AND has_text_layer = 0 AND ocr_source IS NULL ORDER BY page_no
export async function runOcrJob(job: LeasedJob, deps?: { provider?: GeminiOcrProvider; harness?: Harness }): Promise<JobOutcome>;
```
   `runOcrJob`: `job.payload`에서 `asset_id`. 매번 `pagesNeedingOcr`를 다시 읽는다(글자 층이 있는 쪽·이미 OCR한 쪽은 대상이 아니다). 0쪽이면 `{ ok: true, result: { pages: 0 } }`. 8쪽씩 나눠 `run.run(ocrStage(provider), { path, pages: batch }, { chunkIndex })`(R5 6번의 `harness.job({ jobId, scope: workspaceId, workspaceId, signal })`). 결과 쪽마다 `UPDATE pdf_page SET text = ?, char_count = ?, ocr_source = 'model' WHERE asset_id = ? AND page_no = ? AND has_text_layer = 0 AND ocr_source IS NULL`(`char_count`는 공백 뺀 글자 수; `has_text_layer`는 0 그대로). 끝나면 `asset.meta_json`에 `ocr_pages`(OCR한 쪽 수)를 합치고, 녹음에 `lecture_id`가 있으면 `scheduleLectureIndex(lecture_id, owner_id)`. 결과(`result`)에는 쪽 수만 넣고 글자는 넣지 않는다. 실패는 `{ ok: false, error: "OCR에 실패했습니다. 잠시 뒤 다시 시도해 주세요." }`(원인 코드는 `logger.warn`의 필드로, 본문 금지). 기본 provider는 `new GeminiOcrProvider(loadRouting().ocr.model, { apiKey: () => readSecret("GEMINI_API_KEY") })`.
4. `job-handlers.ts`: `registerJobHandler(OCR_JOB_KIND, runOcrJob, { concurrency: 1 })`. `rows.ts`의 `JOB_KINDS`에 `pdf_ocr: "process"`(API에서 `kind: "process"`로 보인다).
5. `assets.ts`의 `ocrAsset`:
   - `config().pdf` 거짓이면 `notImplemented(req)`.
   - asset을 읽어 없거나 `kind !== 'pdf'`이면 404. `loadRecording(req, asset.recording_id, "recording:update")`가 `Response`면 반환.
   - `pdf_page` 행이 하나도 없으면 `apiError(req.c, 409, "conflict", "아직 PDF를 읽는 중입니다. 잠시 뒤 다시 시도해 주세요.")`.
   - `pages = pagesNeedingOcr(asset.id)`, `cost = estimateOcrCost({ pagesToOcr: pages.length, pageCount: asset.page_count ?? 총 행 수, model: loadRouting().ocr.model })`. `pages.length === 0`이면 `dry_run`과 관계없이 200 `{ pages_to_ocr: 0, estimated_cost_microusd: 0, job_id: null }`.
   - `dry_run === true`이면 200 `{ pages_to_ocr, estimated_cost_microusd, job_id: null }`. **모델도 큐도 건드리지 않는다.**
   - 아니면: `readSecret("GEMINI_API_KEY")`가 없으면 `apiError(req.c, 503, "unavailable", "AI 키가 설정되지 않아 OCR을 할 수 없습니다.")`. 있으면 `enqueueJob({ kind: OCR_JOB_KIND, ownerId: req.user!.id, subjectId: recording.id, payload: { asset_id }, budgetMicrousd: cost * 2 })`. 응답 202 `{ pages_to_ocr, estimated_cost_microusd, job_id: jobId }`(중복이어도 기존 `jobId`).
6. `README.md` 표와 `NOT_YET`에서 `ocrAsset`를 뺀다.

## 10. 명세 작성자 메모

- **충돌(비용)**: CONTRACTS D-P3-3의 추정 "쪽당 258토큰 입력"은 Gemini가 요청마다 **PDF 전체**를 읽는다는 점을 놓친다. `packages/pdf`는 쪽만 잘라 내는 런타임 도구가 없다(`pdf-lib`는 devDependency). 그래서 8쪽씩 나눈 요청마다 전체 쪽 수를 곱하는 보수적 공식을 썼다. 계약 공식(`쪽 수 × 258`)과 다르면 계약 쪽이 이긴다 — 그 경우 `estimateOcrCost`의 `calls` 곱셈만 빼면 된다.
- **한도**: PDF가 18 MiB를 넘으면 OCR을 못 한다(인라인 요청 한도). 업로드 상한 50 MiB와 어긋난다. Files API는 이 명세 범위 밖이다.
- 단계 이름 `pdf_ocr`는 도메인 `StageName` 열거에 없다. `stage_run.stage`는 문자열이라 DB에는 문제가 없지만, `packages/domain`은 소유 밖이라 열거에 더하지 못했다. 진행 이벤트를 웹이 `StageName.parse`하면 거부될 수 있다(확인 못 함).
- 큐 종류 `pdf_ocr`를 API에는 `process`로 보이게 했다(CATALOG "process 큐"). `domain` `JobKind`를 늘리지 않기 위한 선택이다.
- OCR한 쪽의 `has_text_layer`는 0으로 둔다(원래 글자 층이 없었다는 사실). 검색·정렬은 `char_count > 0`로 본다.
- `routing.ocr`·단가·`loadRouting`은 P1-01이 만든다(작성 시점에 없음).
