## 1. 목표

세 가지 API를 실제로 구현한다. (1) `reprocessRecording`의 `mode: "document"`: 저장된 전사로 노트 단계(분류 → 구조화 → 추출 → 검증 → 발행)만 다시 돌려 새 문서 버전을 만든다. (2) `cancelJob`: 대기 중이면 바로 `canceled`, 실행 중이면 다음 단계 시작 전에 멈추고 `canceled`. (3) `adminRetryJob`: 실패한 `process`·`regenerate` 작업을 같은 jobId로 다시 큐에 넣어 실패한 단계부터 이어 한다.

## 5. 단계

1. `queue.ts`: `JobOutcome`에 `canceled?: boolean`을 더한다. `JobWorker.execute`의 마무리 `UPDATE`에서 상태를 `outcome.canceled ? "canceled" : outcome.ok ? "succeeded" : "failed"`로 정한다(`error`는 `canceled`이면 그 메시지를 남긴다). `JobWorker.lease`의 서브쿼리에 `AND cancel_requested_at IS NULL`을 더하고, `tick()`의 `reclaimExpiredLeases()` 바로 뒤에서 `UPDATE job SET state = 'canceled', finished_at = ?, idempotency_key = NULL, error = '사용자가 작업을 취소했습니다.' WHERE state = 'queued' AND cancel_requested_at IS NOT NULL`을 돌린다.
2. `process-job.ts`: (a) `export const JOB_CANCELED_MESSAGE = "사용자가 작업을 취소했습니다.";` (b) 작업 시작 시 `controller`와 함께 `const cancelTimer = setInterval(checkCancel, 1000)`(`unref`, `finally`에서 `clearInterval`)을 만들고, `checkCancel()`은 `SELECT cancel_requested_at FROM job WHERE id = ?`가 null이 아니면 `controller.abort(new HarnessError("canceled", JOB_CANCELED_MESSAGE))`. `onEvent`의 `started`·`retry`와 `onStage`에서도 `checkCancel()`을 부른다. (c) 결과 처리에서 `HarnessError` `kind === "canceled"`이고 메시지가 `JOB_CANCELED_MESSAGE`이면 `{ ok: false, canceled: true, error: JOB_CANCELED_MESSAGE }`와 함께 강의를 `UPDATE lectures SET status='error', stage='error', stage_message=?, error_message=?`(같은 메시지; `failLectureRecord(id, JOB_CANCELED_MESSAGE)`)로 끝내고 `error` 이벤트를 낸다(전사·노트가 이미 발행된 `regenerate`가 아닌 `process`만). (d) `runNotesPhase` ctx에 `failure?: "partial" | "throw"`(기본 `"partial"`)를 더한다. `"throw"`이면 노트 단계 예외를 `partial`로 바꾸지 않고 그대로 던진다.
3. `regenerate-job.ts`를 만든다(`index.ts` import 금지).
   ```ts
   export const REGENERATE_JOB_KIND = "regenerate";
   export function enqueueRegenerate(lectureId: string, ownerId: string, budgetMicrousd: number): { jobId: string; deduplicated: boolean; position: number }
   export function transcriptFromRows(recordingId: string): Transcript | null   // null when there are no segments
   export async function runRegenerateJob(job: LeasedJob, deps?: ProcessJobDeps): Promise<JobOutcome>
   ```
   - `enqueueRegenerate`: `enqueueJob({ kind: REGENERATE_JOB_KIND, ownerId, subjectId: lectureId, budgetMicrousd })`.
   - `transcriptFromRows`: `SELECT idx, start_ms, end_ms, speaker_id, text, source_chunk FROM transcript_segment WHERE recording_id = ? ORDER BY idx`, `speaker`(label), `transcript_gap`을 읽어 하네스 `Transcript`(`version: 1`, `duration_ms` = `recording.duration_ms ?? 마지막 end_ms`, `speakers`는 라벨별 `{label, confidence: 1, basis: "single_chunk", segments, chars, members: [{chunk: 0, label}]}`, `failed_chunks: []`)로 만든다. 세그먼트의 `speaker`는 화자 행의 `label`(없으면 `"S1"`), `source_chunk`가 null이면 0.
   - `runRegenerateJob`: 강의·전사가 없으면 `{ ok: false, error: "다시 만들 전사가 없습니다." }`. `harness.job({ jobId: job.id, scope: workspaceId, workspaceId, signal })` → `runNotesPhase({ ..., keepTitle: true, failure: "throw" })`. 성공하면 `{ ok: true, result: { version } }`. 예외면 `{ ok: false, error }`이고 **녹음·강의·이전 문서는 건드리지 않는다**(이전 버전이 현재 버전으로 남는다). 취소는 `{ ok: false, canceled: true, error: JOB_CANCELED_MESSAGE }`.
   - 시작할 때 `UPDATE recording SET status = 'processing'`은 하지 않는다(이전 노트가 계속 보여야 한다). 진행은 `emitStage`의 `progress` 이벤트로만 알린다.
4. `job-handlers.ts`: `registerRegenerateJobHandler(deps = {})`를 내보내고 모듈 끝에서 한 번 부른다(`registerJobHandler(REGENERATE_JOB_KIND, …, { concurrency: 1, onLost })`, `onLost`는 아티팩트 삭제만).
5. `recordings.ts` `reprocessRecording`: `mode === "document"`일 때(전사 없음 409는 그대로):
   - 견적: `chars = SUM(LENGTH(text))`(전사 행), `input = ceil(chars / 2) + 4_000`, `output = 6_000`, 가격은 `priceFor(DEFAULT_PRICING, "gemini", "gemini-3.8-flash", Date.now())`와 `costMicrousd({ inputTokens: input, cachedTokens: 0, outputTokens: output }, price)`(분류 호출은 무시). `estimate = { estimated_microusd, audio_ms: 0, within_quota: true }`.
   - `dry_run`이면 `ok(req, { estimate, job: null })`.
   - 아니면 `isLectureBusy(lecture.id)`이면 409 `"이미 처리 중인 녹음입니다."`, 서버 키 권한 검사(기존 `canUseServerKey`)를 `full`과 같게, `enqueueRegenerate(lecture.id, lecture.owner_id, estimate.estimated_microusd * 3 + 200_000)` 뒤 `ok(req, { estimate, job: toJob(row) }, { status: 202 })`. `resetLectureForRetry`는 부르지 않는다.
   - `full`은 그대로(`P1-12`가 이미 `enqueueRecordingProcessing`으로 바꿨다).
6. `jobs.ts` `cancelJob`: `row = SELECT * FROM job WHERE id = ?`. 없거나 `getJob`과 같은 접근 규칙(워크스페이스 멤버, 녹음이 있으면 `loadRecording(req, recordingId, "recording:update")`가 `Response`가 아님)에 걸리면 `notFound(req, "작업")`(남의 작업은 404). `row.kind`가 `process`·`regenerate`·`distill`이 아니면 409 `"취소할 수 없는 작업입니다."`. 상태가 `succeeded`·`failed`·`canceled`이면 409 `"이미 끝난 작업입니다."`. 아니면:
   ```sql
   UPDATE job SET cancel_requested_at = ? WHERE id = ? AND state IN ('queued','running')
   UPDATE job SET state = 'canceled', finished_at = ?, idempotency_key = NULL, error = '사용자가 작업을 취소했습니다.' WHERE id = ? AND state = 'queued'
   ```
   대기 중이던 작업은 두 번째 문장으로 즉시 `canceled`가 되고, 그 강의가 `process`였다면 `failLectureRecord(lectureId, JOB_CANCELED_MESSAGE)`와 `error` 이벤트(`regenerate`는 강의를 건드리지 않는다). 응답은 다시 읽은 행의 `toJob(...)`이다. 실행 중이면 `state`가 `running`인 채로 돌아온다(핸들러가 곧 멈춘다).
7. `admin.ts` `adminRetryJob`: 행이 없으면 404. `kind`가 `process`·`regenerate`가 아니거나 `state !== 'failed'`이면 409 `"다시 시도할 수 없는 작업입니다."`. 같은 `kind:subject`의 미완료 작업이 있으면(`isLectureBusy(subject, kind)`) 409. `process`이면 강의와 오디오 파일이 있어야 하고(없으면 409 `"원본 오디오가 없어 다시 시도할 수 없습니다."`) `resetLectureForRetry(lectureId)`와 `progress` 이벤트. 그다음:
   ```sql
   UPDATE job SET state = 'queued', attempts = 0, error = NULL, error_code = NULL, result = NULL, finished_at = NULL,
     lease_owner = NULL, lease_until = NULL, cancel_requested_at = NULL, run_after = ?, idempotency_key = ? WHERE id = ? AND state = 'failed'
   ```
   (`idempotency_key`는 `"<kind>:<subject_id>"`.) 뒤에 `wakeLocalWorker`는 `queue.ts`에서 `export function wakeJobWorker(): void`로 감싸 부른다. 응답 `ok(req, toJob(row))`. 같은 jobId라서 `stage_run` 메모로 끝난 단계는 다시 하지 않는다.
8. `README.md` 표의 `cancelJob`·`adminRetryJob`을 `실제`로, `reprocessRecording` 설명에 "`document`는 저장된 전사로 노트만 다시 만든다"를 더한다. `api-v2.test.ts`의 `NOT_YET`에서 두 operationId를 지운다.

## 10. 명세 작성자 메모

- 취소된 `process`의 녹음 상태: 도메인에는 `canceled`가 있으나 `projectLecture`가 강의 상태에서 상태를 계산하므로(`packages/db/src/legacy.ts`, 소유 아님) 녹음은 `failed`(메시지 "사용자가 작업을 취소했습니다.")가 된다. 작업 행은 `canceled`다. `canceled` 녹음 상태가 꼭 필요하면 별도 작업이 `legacy.ts`를 고쳐야 한다.
- `cancelJob`은 실행 중 작업에 대해 즉시 `canceled`를 돌려줄 수 없어(핸들러가 멈춰야 한다) `running` 상태 작업을 200으로 돌려준다. 계약은 "The job, now canceled."이다.
- `JobOutcome.canceled`와 `wakeJobWorker`는 계약에 없는 `queue.ts` 내부 추가다(`D-P1-8`을 구현하는 데 필요).
- `domain`의 `Job` DTO에는 `cancel_requested_at`가 없다(추가하지 않는다, domain 동결).
- 견적 상수(입력 `chars/2 + 4000`, 출력 6000 토큰)는 추정치이며 계약이 정한 값이 아니다.
