# P1-16 웹: v2 처리 상태와 server e2e

> 등급: `careful` · 게이트: `full` · 의존: `P1-13` · 소유: `apps/web/`

## 1. 목표

웹이 새 처리 방식(`LECTERN_PIPELINE=v2`)의 상태를 제대로 보여 준다. (1) 진행 단계 이름을 한국어로 표시한다(`app/labels.ts`). (2) `partial` 녹음에 서버가 준 이유를 안내한다. (3) 한 녹음에 문서가 둘 이상일 때 구조화 문서를 legacy 문서보다 먼저 보인다(D-P1-3). (4) 실제 서버를 띄우는 e2e(`e2e/server/start.ts`)의 가짜 Gemini가 전사·`generateContent` JSON 요청에도 답하게 하고, `LECTERN_PIPELINE=v2`로 업로드 → 전사 → 문서 → 출처 이동을 확인하는 새 e2e를 더한다. "다시 만들기" 버튼은 `P2-06`이 한다.

## 5. 단계

1. `labels.ts`: `STAGE_LABEL`에 `index: "검색 색인 중"`을 더한다(`StageName`에 있고 `process`가 낸다). 나머지 이름(`ingest` … `publish`)은 이미 있으므로 문구를 바꾸지 않는다. 기존 `STAGE_LABEL`과 `progressLabel`의 출력은 그대로다(서버가 준 한국어 `message`가 먼저 쓰인다).
2. `labels.ts`에 추가:
   ```ts
   /** The note shown on a `partial` recording: the server's reason, else the generic gap sentence. */
   export function partialNote(failure: { code: string; message: string } | null | undefined): string {
     const reason = failure?.message?.trim();
     return reason ? `일부만 완료되었습니다. ${reason}` : "일부 구간을 전사하지 못했습니다. 빠진 구간은 전사와 문서에 표시됩니다.";
   }
   ```
3. `lib/documents.ts`:
   ```ts
   import type { Document } from "../api/types.ts";
   /** Structured documents (any template but `legacy-markdown`) come before the migrated or bridged Markdown; newest first within each group. */
   export function primaryDocument(docs: readonly Document[]): Document | undefined
   ```
   정렬: `template_id !== "legacy-markdown"`인 것이 먼저, 같은 묶음 안에서는 `updated_at` 내림차순(같으면 `id` 오름차순). 빈 배열이면 `undefined`. 입력 배열을 바꾸지 않는다.
4. `RecordingPage.tsx`: `const doc = useDocument(detail.documents[0]?.id);`를 `primaryDocument(detail.documents)?.id`로, 아래 `detail.documents[0] && doc.isPending`도 같은 값으로 바꾼다. `partial` 안내의 고정 문장을 `{partialNote(detail.failure)}`로 바꾼다(`<Icon name="alert" />`과 `role="note"`는 그대로).
5. `start.ts`(e2e 전용 파일; 서버 코드는 건드리지 않는다):
   - 가짜 `fetch`에 두 갈래를 더한다. `url.includes(":generateContent")`이고 본문 `contents[0].parts`에 `inlineData`가 있으면 **전사 요청**: `GEMINI_TRANSCRIBE_SCHEMA`와 `gemini-transcribe.ts`의 응답 파서가 받아들이는 JSON을 `candidates[0].content.parts[0].text`에 담아 돌려준다. 내용은 청크 길이(요청의 오디오 길이를 몰라도 되게)와 상관없이 짧은 3개 문장(한국어, 청크 상대 시간 0~2초, 2~4초, 4~6초)으로 고정한다. `usageMetadata`(`promptTokenCount`, `candidatesTokenCount`)를 붙인다. `inlineData`가 없고 `generationConfig.responseMimeType === "application/json"`이면 **LLM JSON 요청**: 단계를 `generationConfig.responseSchema`의 최상위 속성 이름으로 구분해(분류: `domain`을 가진 것, 구조화: `sections`를 가진 것, 추출: `events`를 가진 것) 아래를 돌려준다. 실제 속성 이름과 모양은 `P1-04`·`P1-06`의 `templateOutputSchema`·`extractResultSchema`를 따라 맞추고, 맞는지는 `bun e2e/server/start.ts`를 띄운 채 새 e2e를 돌려 확인한다. 응답 내용:
     - 분류: 도메인 `lecture`, 언어 `ko`, 제목 `"E2E 처리 녹음"`이 아닌 `"블록 암호 운영 모드 강의"`, 신뢰도 0.9.
     - 구조화: `summary` 섹션(제목 `핵심 요약`) 블록 1개와 `topics` 섹션 블록 1개. 각 블록의 출처는 `#0`~`#1`.
     - 추출: 일정 0개, 할 일 0개(빈 목록).
   - 단계 구분이 안 되는 JSON 요청은 `{ error: { code: 400, message: "not faked in e2e" } }`, 400.
   - 제어 경로(로컬 e2e 서버 안에서만 존재): `Bun.serve`의 `fetch`를 `(req) => controlRoute(req) ?? handleRequest(req)`로 감싼다. `controlRoute`는 `POST /__e2e/pipeline`(본문 `{ "mode": "v1" | "v2" }`)과 `GET /__e2e/info`만 처리한다.
     - `v2`: `process.env.LECTERN_PIPELINE = "v2"`, `resetConfigForTests()`(`@lectern/config`), 기다리는 작업을 모두 취소(`UPDATE job SET state='canceled', finished_at=?, idempotency_key=NULL WHERE state='queued'`), `new JobWorker({ pollMs: 200 })`를 `start()`(`apps/server/src/queue.ts`에서 동적 import, 이미 있으면 재사용).
     - `v1`: 환경 변수를 지우고 `resetConfigForTests()`, 워커 `drain(10_000)` 후 버린다.
     - `info`: `{ ffmpeg: isFfmpegAvailable() }`(`@lectern/media`).
   - 시작 기본값은 지금과 같다(`LECTERN_PIPELINE` 없음, 워커 없음, `LECTERN_WORKER_MODE=external`). 그래서 기존 e2e는 바뀌지 않는다. 헤더 주석의 "no job runs" 문장을 "no job runs until a test turns the v2 pipeline on (POST /__e2e/pipeline)"로 고친다.
6. `process.e2e.ts`: `flow.e2e.ts`의 `signIn`, `api` 도우미 모양을 이 파일 안에 다시 쓴다(공유 모듈을 만들지 않는다). 테스트 하나(`test.describe.configure({ mode: "serial" })`):
   1. `GET /__e2e/info`에서 `ffmpeg`가 거짓이면 `test.skip(true, "ffmpeg가 없어 처리 파이프라인을 돌릴 수 없습니다.")`.
   2. `POST /__e2e/pipeline {mode:"v2"}`. `afterAll`에서 `{mode:"v1"}`.
   3. 로그인 → `u` 키로 올리기 대화상자 → 20초 `wav(20)` 파일 `E2E 처리 녹음.wav` 업로드(`flow.e2e.ts`의 업로드 테스트와 같은 순서) → `녹음 1개를 올렸습니다.`.
   4. `GET /api/v2/recordings`를 최대 90초 폴링해 제목이 `블록 암호 운영 모드 강의`(AI 제목) 또는 `E2E 처리 녹음`인 항목의 `status === "ready"`를 기다린다(`expect.poll`).
   5. 녹음 화면(`/app/recordings/<id>`)을 연다. 보여야 할 것: 제목, `핵심 요약` 섹션 제목, 전사 줄에 가짜 전사 문장, `출처 1, …` 버튼.
   6. 출처 버튼을 눌러 오디오가 그 위치로 이동하고 인용한 전사 줄이 표시되는지 `keyboard.e2e.ts`가 같은 일을 확인하는 방식 그대로 단언한다.
   7. 끝에 다른 server e2e처럼 `axe`를 인자로 받아 호출한다(위반 0건).
   `partial` 안내는 e2e로 만들 수 없으므로(서버 DB를 직접 건드릴 수 없다) 6절의 `partialNote` 단위 테스트로만 확인한다.

## 10. 명세 작성자 메모

- 가짜 Gemini 응답(전사 JSON, 분류·구조화·추출 JSON)의 정확한 모양은 `gemini-transcribe.ts`(있음)와 `P1-04`·`P1-06`(아직 없음)의 스키마가 정한다. 이 명세는 속성 이름을 추측하지 않았다. 워커는 병합된 코드를 읽고 맞춘다. 단계 구분을 `responseSchema`의 최상위 속성으로 하는 것도 가정이다(`P1-01`의 요청 본문이 다르면 그 본문에서 구분할 수 있는 다른 표지를 쓴다).
- 새 e2e는 ffmpeg가 없으면 건너뛴다. 이 경우 "새 e2e 통과"는 건너뜀으로 끝난다(CI에서 ffmpeg 유무는 확인하지 못했다).
- `e2e/server/start.ts`의 제어 경로(`/__e2e/*`)는 e2e 서버 프로세스에만 있고 운영 코드에는 없다(AGENTS.md의 "운영 코드에 테스트 전용 분기 금지"에 걸리지 않는다).
- "구조화 문서가 legacy보다 먼저"의 해석: 항상 구조화 문서가 첫 문서다. v1 클라이언트가 Markdown을 고친 뒤(구조화 문서 `user_edited` 참, legacy 버전 새로 생김)에도 구조화 문서가 먼저 보인다. 사용자 편집을 우선 보이는 규칙은 계약에 없어 넣지 않았다. 필요하면 `P2` 문서 화면 작업에서 정한다.
- 완전 실패(`failed`)의 `failure_code`는 서버 쪽 투영 때문에 `legacy_error`일 수 있다(`P1-12` 메모). 웹은 코드를 쓰지 않고 `message`만 쓴다.
