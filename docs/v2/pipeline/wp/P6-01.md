# P6-01 서버: 푸시 기기, Live Activity 토큰, 마커

> 등급: `basic` · 게이트: `full` · 의존: `P6-C` · 소유: `apps/server/`, `packages/harness/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

네이티브 앱이 자기 기기를 푸시 대상으로 등록하고, 녹음별 Live Activity 토큰을 올리고, 녹음 중에 누른 "중요" 표시(마커)를 저장한다. 마커가 있는 녹음은 노트를 만들 때 그 구간이 중요하다는 힌트가 모델에 전달된다. 로그아웃하면 그 사용자의 푸시 기기가 지워진다.

## 5. 단계

1. `push-devices.ts`
   ```ts
   export function upsertPushDevice(userId: string, deviceId: string, p: { platform: "ios" | "macos"; apnsToken: string; pushToStartToken?: string | null; name?: string; appVersion?: string }): PushDeviceRow | "taken"
   export function deletePushDevice(userId: string, deviceId: string): boolean
   export function deletePushDevicesOfUser(userId: string): void          // also deletes their live_activity rows
   export function deletePushDeviceByToken(apnsToken: string): void        // used by the APNs sender on 410
   export function setLiveActivity(p: { recordingId: string; deviceId: string; pushToken: string }): void   // upsert on (recording_id, device_id), state 'active'
   export function endLiveActivity(recordingId: string, deviceId: string): boolean
   ```
   - 토큰은 소문자 16진수로 정규화해 저장한다.
   - `upsertPushDevice`: 그 `deviceId`가 다른 사용자의 것이면 `"taken"`(→ 409). 같은 `apns_token`이 다른 행(다른 `deviceId`나 다른 사용자)에 있으면 **그 옛 행을 지우고** 새로 넣는다(기기를 다른 계정으로 넘긴 경우. 토큰 하나는 한 사용자에게만 간다). 같은 행이면 값과 `last_seen_at`을 갱신한다.
   - 사용자당 기기는 20개까지. 넘으면 `last_seen_at`이 가장 오래된 것을 지운다.
2. `me.ts`: `upsertPushDevice`(200 `PushDeviceDto`. 응답에 토큰 없음), `deletePushDevice`(204, 없으면 404). 개인 액세스 토큰으로는 부를 수 없다(`tag: me` 규칙으로 이미 막힌다. P5-02).
3. `recordings.ts`
   - `setLiveActivity`: `loadRecording`으로 볼 수 있는 녹음인지 확인. `device_id`가 호출자의 푸시 기기가 아니면 404. 204.
   - `endLiveActivity`: `state = 'ended'`, `ended_at = now`. 204(없으면 404).
   - `listMarkers`: 볼 수 있으면 `at_ms` 순으로.
   - `createMarker`: 녹음을 고칠 수 있어야 한다(`can(caller, "recording:update", recording)`). 녹음당 200개까지(넘으면 `409 conflict`, `표시는 녹음 하나에 200개까지 넣을 수 있습니다.`). 같은 사용자가 같은 녹음에 ±500ms 안의 마커를 이미 넣었으면 새로 만들지 않고 그 마커를 201로 돌려준다(버튼을 두 번 누른 경우).
   - `deleteMarker`: 만든 사람 또는 녹음을 고칠 수 있는 사람. 204.
   - 녹음을 지우면 그 녹음의 `recording_marker`와 `live_activity` 행도 지운다(녹음 삭제 코드에 더한다).
4. 하네스(`packages/harness`)
   - `NotesPipelineInput`에 선택 필드 `markers?: { at_ms: number; label: string | null }[]`.
   - `StructureInput`에 선택 필드 `important?: { id: string; label: string | null }[]`(구간 id).
   - `notes/structure.ts`에 순수 함수:
     ```ts
     export function markerSegments(segments: CompactSegment[], markers: { at_ms: number; label: string | null }[]): { id: string; label: string | null }[]
     ```
     마커마다: `at_ms`를 포함하는 구간, 없으면 `at_ms` **이전에 끝난 가장 가까운** 구간(사람은 듣고 나서 누른다), 그것도 없으면 첫 구간. 그리고 고른 구간의 바로 앞 구간도 넣는다(있을 때만). 중복을 없애고 구간 순서로 정렬, 최대 40개(넘으면 앞에서부터 40개).
   - `buildStructureInstruction`: `important`가 비어 있지 않으면 끝에 덧붙인다.
     ```
     사용자가 녹음 중에 "중요"라고 표시한 구간: #<id>, #<id>(<라벨>), …
     이 구간의 내용은 빠뜨리지 말고 노트에 담는다. 표시가 없는 구간을 덜 중요하게 다루라는 뜻은 아니다.
     ```
     `#<id>`는 압축 전사가 구간에 붙이는 표기와 같은 표기다(`CompactSegment`의 id를 그대로 쓴다). 라벨은 있을 때만 괄호로.
   - `runNotesPipeline`이 `input.markers`를 `markerSegments`로 바꿔 구조화 단계 입력에 넣는다. `important`는 단계 입력의 일부라서 캐시 키에 들어간다(마커가 바뀌면 다시 만든다). 마커가 없으면 입력 객체에 `important` 키를 **넣지 않는다**(기존 캐시 키가 바뀌지 않게).
5. `process-job.ts`·`regenerate-job.ts`: `NotesPipelineInput`을 만들 때 그 녹음의 마커를 읽어 `markers`로 넘긴다(없으면 필드를 생략).
6. 로그아웃 정리: 웹 로그아웃은 푸시 기기를 지우지 않는다(웹 세션과 앱은 별개다). **네이티브 로그아웃**(`revokeNativeToken`)과 비밀번호 변경(`revokeNativeSessionsOfUser`) 때 `deletePushDevicesOfUser(userId)`를 부른다. `native-auth.ts`가 없으면 이 연결은 건너뛰고 `NEEDS`에 적는다. 계정 삭제는 P5-09의 `USER_TABLES`가 `push_device`를 이미 지운다.

## 8. 하지 않는 것

- APNs로 보내기(`P6-02`).
- 웹 화면에 마커를 보이거나 넣기(네이티브 앱만 쓴다. 웹은 `listMarkers`를 부르지 않는다).
- `extract`·`classify` 단계에 마커를 쓰지 않는다(D-P6-3은 `structure`만 말한다).

## 9. 끝났다는 기준

## 10. 명세 작성자 메모

- 마커 시각은 "원본 오디오 ms"다. 여러 파트를 이어 붙인 녹음(D-P1-9)에서는 이어 붙인 타임라인 기준이다. 앱이 그 기준으로 보낸다(P6-A4).
- "마커 바로 앞 구간도 넣는다"와 "이전에 끝난 구간"은 이 명세의 결정이다.
- `CompactSegment`의 id 필드 이름과 `#` 표기는 P1-01이 정했다. 병합된 코드를 읽고 맞춘다.
