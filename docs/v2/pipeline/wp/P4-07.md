## 1. 목표

설정에 "연동"과 "알림" 구역을 넣는다. 사용자는 Google 캘린더를 연결·해제하고, 캘린더 구독 주소(ICS)를 만들어 복사하고, 이메일 알림과 일정 자동 등록을 켠다. 일정 화면 위에 연결 상태 카드를 둔다. 서버 기능이 꺼져 있으면(501) "준비 중"으로 보인다.

## 5. 단계

1. API 클라이언트(`ApiClient`에 더하고 HTTP·fixture 둘 다 구현)
   ```ts
   listIntegrations(workspaceId: WorkspaceId): Promise<IntegrationPage>;
   startGoogleIntegration(workspaceId: WorkspaceId, returnTo: string): Promise<{ authorization_url: string }>;
   disconnectIntegration(integrationId: string): Promise<void>;
   getCalendarFeed(workspaceId: WorkspaceId): Promise<CalendarFeedInfo>;
   createCalendarFeed(workspaceId: WorkspaceId): Promise<CalendarFeedCreated>;
   deleteCalendarFeed(workspaceId: WorkspaceId): Promise<void>;
   updateWorkspaceSettings(workspaceId: WorkspaceId, settings: Partial<WorkspaceSettings>): Promise<Workspace>;  // PATCH /workspaces/{id} { settings }
   ```
   이미 있는 메서드는 다시 만들지 않는다. fixture 구현은 메모리 상태를 가진다: 연동 없음에서 시작, `startGoogleIntegration`은 `{ authorization_url: "/app/settings?google=connected#integrations" }`를 주고 연동을 `active`로 만든다. `?fixture-integration=needs_reauth` 쿼리가 있으면 `needs_reauth` 연동 하나로 시작한다(e2e용).
2. `Integrations.tsx` — 제목 "연동". 두 카드.
   - **Google 캘린더**
     - 연결 안 됨: 설명 `수락한 일정을 Google 캘린더의 "Lectern" 캘린더에 넣습니다. Lectern은 자신이 만든 캘린더만 읽고 씁니다.` 버튼 `Google 캘린더 연결`. 누르면 `startGoogleIntegration(workspaceId, "/app/settings#integrations")` 뒤 `window.location.assign(authorization_url)`.
     - 연결됨(`active`): `연결됨` 표시와 버튼 `연결 해제`. 확인 대화상자 제목 `Google 캘린더 연결을 해제할까요?`, 본문 `Lectern이 더 이상 일정을 넣지 않습니다. 이미 Google 캘린더에 들어간 일정은 지워지지 않습니다.`, 버튼 `연결 해제` / `취소`. 성공 토스트 `연결을 해제했습니다.`
     - `needs_reauth`: 경고 `Google 연결이 만료되었습니다. 다시 연결해야 일정이 동기화됩니다.` 버튼 `다시 연결`(연결과 같은 동작).
     - 주소에 `?google=connected`가 있으면 토스트 `Google 캘린더를 연결했습니다.`, `?google=error`면 `Google 캘린더를 연결하지 못했습니다. 다시 시도해 주세요.` 표시 뒤 쿼리를 지운다(`history.replaceState`).
     - 501이면 카드 본문 대신 `준비 중입니다.`
   - **캘린더 구독 주소(ICS)**
     - 없음: 설명 `Apple 캘린더, Outlook 같은 앱에서 이 주소를 구독하면 수락한 일정이 보입니다.` 버튼 `구독 주소 만들기`.
     - 만든 직후: 읽기 전용 입력에 URL, 버튼 `복사`(토스트 `주소를 복사했습니다.`), 안내 `이 주소는 지금만 볼 수 있습니다. 주소를 아는 사람은 누구나 일정을 볼 수 있으니 공유하지 마세요.`
     - 있음(원문 없음): `구독 주소가 있습니다. (<만든 날짜>)`, 버튼 `다시 만들기`(확인: `새 주소를 만들면 예전 주소는 더 이상 동작하지 않습니다.`)와 `삭제`(확인: `구독 주소를 삭제할까요? 구독 중인 캘린더 앱에서 일정이 더 이상 갱신되지 않습니다.`).
     - 501이면 `준비 중입니다.`
3. `Reminders.tsx` — 제목 "알림". 구역 id는 `reminders`(메일의 링크가 `#reminders`로 온다).
   - 체크박스 `일정과 할 일 마감을 이메일로 알려 주기`. 켜면 선택 `알림 시각`: `하루 전`(1440), `3시간 전`(180), `1시간 전`(60), `하루 전과 1시간 전`(1440, 60). 저장은 `updateWorkspaceSettings(id, { reminders: { email, lead_minutes } })`. 토스트 `알림 설정을 저장했습니다.`
   - 체크박스 `날짜가 분명한 일정은 자동으로 수락하기`, 도움말 `녹음에서 날짜가 정확히 읽힌 일정만 자동으로 수락합니다. 나머지는 제안으로 남습니다.` 저장은 `{ calendar_auto_add: { enabled, min_confidence: 0.8 } }`.
   - 권한이 없으면(역할이 `viewer`·`member`) 두 체크박스는 꺼져 있고 `워크스페이스 관리자만 바꿀 수 있습니다.`를 보인다.
4. `SettingsPage.tsx`: `SECTIONS`에 `{ id: "integrations", label: "연동" }`, `{ id: "reminders", label: "알림" }`을 기존 항목 형식대로 더한다.
5. `CalendarPage.tsx`: 목록 위에 한 줄 카드.
   - 연동 없음·feed 없음: `캘린더 앱과 연결하면 수락한 일정이 자동으로 들어갑니다.` 링크 `연결 설정`(`/app/settings#integrations`).
   - `needs_reauth`: 경고 문구(2단계와 같음)와 링크 `다시 연결`.
   - 연결됨: `Google 캘린더와 연결됨`.
   - 일정 줄에 상태 `synced`면 작은 표시 `캘린더에 있음`(시각적 표시와 함께 글자로. 색만으로 구별하지 않는다).
   - 501이면 카드를 그리지 않는다.

## 10. 명세 작성자 메모

- `updateWorkspaceSettings`는 서버가 설정을 합쳐 저장해야 안전하다(P4-04가 고친다). P4-04가 아직 병합되지 않았으면 클라이언트가 현재 `settings`를 읽어 합친 전체를 보낸다. 두 경우 모두 동작하도록 **항상 합친 전체를 보낸다.**
- `min_confidence: 0.8`은 이 명세가 정한 기본값이다.
- server e2e(실제 서버로 연결 흐름)는 넣지 않았다. Google이 필요해서다. 서버 쪽은 P4-02의 테스트가 본다.
