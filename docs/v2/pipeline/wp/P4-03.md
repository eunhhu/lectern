## 1. 목표

사용자가 수락한 일정이 연결된 Google 캘린더("Lectern")에 들어간다. 일정을 고치면 Google에서도 바뀌고, 무시하거나 녹음을 지우면 Google에서도 지워진다. 같은 동기화를 몇 번 돌려도 일정이 늘지 않는다.

## 5. 단계

1. `google/calendar.ts` (기준 URL `https://www.googleapis.com/calendar/v3`, 모든 요청에 `Authorization: Bearer <접근 토큰>`)
   ```ts
   export function eventResource(e: { id: string; title: string; startAt: number; endAt: number | null; allDay: boolean; tz: string; recordingTitle: string | null }): Record<string, unknown>
   export async function findEventByLecternId(token: string, calendarId: string, lecternId: string): Promise<{ id: string; etag: string } | null>
   export async function insertEvent(token: string, calendarId: string, resource: unknown): Promise<{ id: string; etag: string }>
   export async function patchEvent(token: string, calendarId: string, eventId: string, resource: unknown): Promise<{ id: string; etag: string }>
   export async function deleteEvent(token: string, calendarId: string, eventId: string): Promise<void>   // 404 and 410 count as success
   ```
   - `eventResource`: `summary` = 제목, `description` = `"녹음: <녹음 제목>"`(없으면 생략), `extendedProperties: { private: { lectern_event_id: id } }`.
     - 시간 일정: `start: { dateTime: <ISO 8601 UTC>, timeZone: tz }`, `end`도 같은 모양(끝이 없으면 시작 + 1시간).
     - 하루 종일: `start: { date: "YYYY-MM-DD" }`(tz 기준), `end: { date: <다음 날> }`.
   - 조회: `GET /calendars/{calendarId}/events?privateExtendedProperty=lectern_event_id%3D<id>&maxResults=2&showDeleted=false`.
   - 넣기: `POST /calendars/{calendarId}/events`. 고치기: `PATCH …/events/{eventId}`. 지우기: `DELETE …/events/{eventId}`.
   - 오류: 401 → `GoogleAuthError("unauthorized")`, 429·5xx·네트워크 → `"transient"`.
2. `calendar/sync-job.ts`
   ```ts
   export const CALENDAR_SYNC_JOB_KIND = "calendar_sync";
   export function enqueueCalendarSync(integrationId: string): void                 // subject = integration id; deduplicated while one is queued
   export function enqueueCalendarSyncForWorkspace(workspaceId: string): void       // every active google integration of the workspace
   export async function runCalendarSync(integrationId: string, signal?: AbortSignal): Promise<{ inserted: number; patched: number; deleted: number; adopted: number }>
   ```
   `runCalendarSync` 순서
   1. 연동을 읽는다. 없거나 `status !== 'active'`이거나 `calendar_id`가 없으면 아무것도 하지 않고 0을 돌려준다(Google을 부르지 않는다).
   2. 대상 일정: 그 워크스페이스의 `event_candidate` 중 `status IN ('accepted','synced')`이고, 그 연동의 사용자가 볼 수 있는 녹음의 것(`visibility = 'workspace'` 또는 `created_by = 사용자`).
   3. 대상 일정마다
      - 링크 행이 없으면: `findEventByLecternId` → 있으면 `patchEvent`(`adopted`), 없으면 `insertEvent`(`inserted`). 링크 행을 넣고 `status = 'synced'`로 한다.
      - 링크 행이 있고 `event_candidate.updated_at > last_synced_at`이면 `patchEvent`(`patched`). Google이 404를 주면 링크를 지우고 넣기부터 다시 한다.
      - 성공하면 `last_synced_at = now`, `external_etag`, `state = 'synced'`.
   4. 그 연동의 링크 행 중 일정이 대상이 아니게 된 것(`dismissed`·`suggested`이거나 행이 없음): `deleteEvent` 뒤 링크 행 삭제(`deleted`).
   5. `GoogleAuthError("unauthorized")`는 접근 토큰 캐시를 버리고 한 번만 다시 한다. `"invalid_grant"`는 `markNeedsReauth`(이미 됨) 뒤 **성공으로 끝낸다**(재시도하지 않는다). `"transient"`는 던져서 큐가 재시도하게 한다.
   - 맨 아래에서 `registerJobHandler(CALENDAR_SYNC_JOB_KIND, …, { concurrency: 1 })`로 등록한다. 핸들러의 반환 모양은 `index-job.ts`를 따른다.
3. `api/v2/calendar.ts`: `updateCalendarSuggestion`과 `batchCalendarSuggestions`가 상태나 제목·시각을 바꾼 뒤 `enqueueCalendarSyncForWorkspace(workspaceId)`를 부른다. `config().calendar`가 거짓이면 부르지 않는다.
4. 녹음 삭제: 녹음을 지우면 그 일정 행도 사라진다. 링크 행은 `event_candidate_id`만 가지므로 남는다. 삭제 뒤 `enqueueCalendarSyncForWorkspace`를 부르면 2단계 4번이 Google 일정을 지운다. 녹음 삭제 코드가 `calendar_event_link`를 지우지 **않게** 한다.
5. 핸들러 등록: `index-job.ts`가 import되는 곳을 `git grep -n "index-job" -- apps/server/src apps/worker/src`로 찾아 같은 곳에서 `calendar/sync-job.ts`를 import한다.

## 6. 테스트

`calendar-sync.test.ts` (가짜 Google, `LECTERN_CALENDAR=1`. 연동 행은 P4-02의 콜백 흐름으로 만들거나 직접 넣는다)

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| "accept inserts one event" | 일정 1개 수락 → `runCalendarSync` | 가짜 캘린더에 1개, `extendedProperties.private.lectern_event_id`가 일정 id, 링크 1행, 일정 `synced` |
| "running again adds nothing" | 위 뒤 한 번 더 | 여전히 1개, `insert` 요청 수 그대로 |
| "adopts an existing event when the link row is lost" | 링크 행을 지우고 일정을 `accepted`로 되돌림 | Google에 여전히 1개(`insert` 없음, `patch` 1회), 링크 복구 |
| "edit patches" | 제목을 바꿈(`updated_at` 증가) | `PATCH` 1회, Google의 `summary`가 새 제목 |
| "dismiss deletes" | `synced` 일정을 `dismissed`로 | `DELETE` 1회, 링크 0행 |
| "recording delete removes the event" | 녹음 삭제 뒤 동기화 | Google 0개, 링크 0행 |
| "all-day event" | 하루 종일 일정 | `start.date`와 `end.date`(다음 날), `dateTime` 없음 |
| "401 refreshes once" | `failNext(events, 401)` 한 번 | 갱신 요청 1회 뒤 성공 |
| "invalid_grant stops quietly" | 갱신이 `invalid_grant` | 던지지 않음, 연동 `needs_reauth`, 이후 `runCalendarSync`는 Google 요청 0회 |
| "429 is retried by the queue" | `failNext(events, 429)` 계속 | `runCalendarSync`가 던진다 |
| "private recordings of others are not synced" | B의 비공개 녹음 일정, A의 연동 | Google에 없다 |
| "suggestion update enqueues a sync" | `updateCalendarSuggestion`으로 수락 | `calendar_sync` 작업이 큐에 1개 |
