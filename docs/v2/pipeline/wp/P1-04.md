## 1. 목표

전사와 템플릿을 받아 템플릿이 정한 섹션·블록 구조의 문서(`TemplateOutput`, 출처는 `#12` 토큰)를 만드는 `structure` 단계를 만든다. 전사가 60,000자를 넘으면 20,000자 창으로 나눠 부분 요약(map)을 만든 뒤 최종 구조(reduce)를 만든다. 사용자가 보는 변화는 없다.

## 5. 단계

1. `src/notes/prompt.ts` (P1-06의 `extract`도 이 파일을 쓴다. 문구를 바꾸면 두 단계의 접두부가 갈라진다).
   ```ts
   export const NOTES_SYSTEM: string;   // fixed Korean text, no template/language in it
   export function notesContext(segments: readonly CompactSegment[]): ContextPart[];
   // => [{ type: "text", text: "전사:\n" + formatCompactTranscript({ segments }).text }]
   ```
   `NOTES_SYSTEM` 내용(한국어, 고정 문자열): "너는 녹음 전사를 정리하는 도구다. 전사에 있는 내용만 쓴다. 전사의 각 줄은 `#번호 [시각] 화자: 본문` 형식이다. 출처는 `#번호`로만 가리키고 시각은 쓰지 않는다." 템플릿·언어·단계 이름을 넣지 않는다.
2. `src/notes/structure.ts`
   ```ts
   export const STRUCTURE_STAGE_VERSION = 1;
   export const STRUCTURE_MAX_CHARS = 60_000;      // compact transcript above this => map-reduce
   export const STRUCTURE_WINDOW_CHARS = 20_000;
   export interface StructureInput { template: LoadedTemplate; segments: CompactSegment[]; language: string }
   export const PartialSummary = z.object({ points: z.array(z.object({ text: z.string().min(1), sources: z.array(SourceToken).min(1) })) });
   export function splitTranscriptWindows(text: string, maxChars: number): string[];
   export function structureStage(llm: LlmProvider, routing: Routing): StageDefinition<StructureInput, TemplateOutput>;
   ```
   - `splitTranscriptWindows`: `text`를 `\n`으로 줄 단위로 나눠, 지금 창 길이 + 줄 길이 + 1이 `maxChars`를 넘으면 창을 닫고 새로 시작한다. 줄 하나가 `maxChars`보다 길면 그 줄이 혼자 한 창이다. 빈 입력은 `[]`. 줄을 자르지 않는다.
   - `defineStage({ name: "structure", version: STRUCTURE_STAGE_VERSION, output: TemplateOutput, memo: "shared", retry: { maxAttempts: 3, repairs: 1 }, key, run })`. (`output`은 도메인의 일반 `TemplateOutput`. 템플릿별 엄격한 검사는 모델 요청의 `schema`로 한다.)
   - `key(input)`: `inputs: [sha256Hex(compactText)]`, `prompt: sha256Hex(NOTES_SYSTEM + "\u0000" + STRUCTURE_INSTRUCTION + "\u0000" + MAP_INSTRUCTION)`, `template: \`${def.id}@${def.version}:${template.hash}\``, `provider: llm.id`, `model: routing.structure.model`, `params: { schema: llmSchemaHash(templateOutputSchema(def)), maxOutputTokens: routing.structure.maxOutputTokens, language, windowChars: STRUCTURE_WINDOW_CHARS, maxChars: STRUCTURE_MAX_CHARS }`.
   - `run` 공통: 모델 호출은 모두 `await ctx.meter({ provider: llm.id, model: routing.structure.model }, () => llm.generate({...}))`. `signal: ctx.signal`. `system: NOTES_SYSTEM`.
   - **일반 경로**(`compactText.length <= STRUCTURE_MAX_CHARS`): 한 번 호출. `schema: templateOutputSchema(def)`, `context: notesContext(segments)`, `instruction` = `buildStructureInstruction(input, ctx.repair)`.
   - **map-reduce**(`compactText.length > STRUCTURE_MAX_CHARS`):
     1. `windows = splitTranscriptWindows(compactText, STRUCTURE_WINDOW_CHARS)`.
     2. 창마다 순서대로(병렬 아님) 한 번: `schema: PartialSummary`, `context: [{ type: "text", text: "전사(일부):\n" + window }]`, `instruction: MAP_INSTRUCTION`(한국어: "이 구간의 핵심 내용을 항목으로 요약한다. 항목마다 근거 출처(sources)를 `#번호` 또는 `#시작-#끝`으로 단다. 구간 요약만 쓴다.") + (repair 있으면 같은 repair 문구).
     3. 부분 요약을 `- <text> [<sources 공백 구분>]` 줄로 이어 붙여 `summaryText`로 만든다(창 순서).
     4. reduce 한 번: `schema: templateOutputSchema(def)`, `context: [{ type: "text", text: "구간별 요약(전사 전체를 나눠 요약한 것):\n" + summaryText }]`, `instruction: buildStructureInstruction(input, ctx.repair) + "\n출처 번호는 위 요약에 적힌 것만 쓴다."`.
   - `buildStructureInstruction(input, repair)`: `template.structurePrompt` + `\n\n출력 언어: ${language}` + 구조 섹션 목록(`def.sections`에서 `fill === "structure"`인 것만, 줄마다 `- <key> <title> (<필수|선택>) 허용 블록: <block_types 쉼표> — <instructions>`) + (repair 있으면 `\n\n이전 응답이 검증을 통과하지 못했다: <issues>\n규칙을 지켜 다시 답한다.`). `STRUCTURE_INSTRUCTION`은 이 함수가 앞에 붙이는 고정 문구("위 전사로 노트를 만든다. 아래 섹션만 JSON으로 답한다.")이고 상수로 export하지 않아도 된다(키 계산에서는 같은 문자열을 쓴다).
   - 반환값은 마지막 호출의 `value`(`TemplateOutput`).
3. `src/index.ts`에 `export * from "./notes/prompt.ts"; export * from "./notes/structure.ts";`를 더한다.

## 6. 테스트

파일: `packages/harness/test/structure.test.ts`. 준비: `testEnv()`, `env.job("job-1")`, `harness().job({ jobId: "job-1", scope: "ws" })`, `loadRouting()`, `loadTemplate("lecture")`. 세그먼트 헬퍼 `segs(n, len)`: idx 0..n-1, `start_ms = idx*1000`, 화자 `S1`, 본문 `"가".repeat(len)`. 정상 답 `okOut = { sections: [ {key:"summary", blocks:[{type:"paragraph",heading:null,text:"요약",sources:["#1"],pdf_pages:[]}]}, {key:"topics", blocks:[]} ] }`.

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| normal path | `segs(20, 30)`, 공급자 `fromList([okOut])` | `value`가 `okOut`과 같음; `calls.length === 1`; `calls[0].req.model === "gemini-3.8-flash"`; `maxOutputTokens === 16384`; `ai_call` 1행 |
| request order is system, transcript, instruction | 위 호출 | `req.system === NOTES_SYSTEM`; `req.context[0].text`가 `전사:\n#0 [00:00] S1: `로 시작; `req.instruction`에 `출력 언어: ko`와 `summary`·`topics` 섹션 줄 포함, `exam_points`도 포함(structure 섹션), `glossary`·`events`는 **포함되지 않음**(비-structure 섹션) |
| schema violation is repaired once | 첫 답 `{sections: []}`(필수 섹션 없음), 둘째 `okOut` | 성공, `calls.length === 2`, 둘째 `instruction`에 `이전 응답이 검증을 통과하지 못했다` |
| two bad answers fail | 둘 다 `{sections: []}` | `HarnessError` kind `output_validation` |
| disallowed block type is rejected | summary 섹션에 `type:"quote"` 블록 | 두 번 다 실패하면 `output_validation` (스키마가 거른다) |
| splitTranscriptWindows | `"aaaa\nbbbb\ncccc"`, max 9 | `["aaaa\nbbbb", "cccc"]`; 한 줄이 max보다 길면 혼자 한 창; `""` → `[]` |
| long transcript uses map-reduce | `segs(700, 100)`(압축 텍스트 > 60000자임을 먼저 단언), `windows = splitTranscriptWindows(text, 20000)`; 공급자 답 함수: `callIndex < windows.length`이면 `{points:[{text:"요약 "+callIndex, sources:["#"+callIndex]}]}`, 아니면 `okOut` | `calls.length === windows.length + 1`; map 호출의 `req.schema`로 `{points:[]}`가 통과; 마지막 호출 `req.context[0].text`에 `- 요약 0 [#0]`과 `- 요약 1 [#1]`이 들어 있음; 결과 `value`의 summary 블록 `sources`가 `["#1"]` |
| short transcript never uses map | `segs(20,30)` | `calls.length === 1` |
| memo hit on resume | 같은 `run`으로 같은 입력 두 번 | 두 번째 `resumed === true`, `calls.length` 늘지 않음 |
| editing a template file misses the memo | `lecture` 템플릿 디렉터리(`templates/`)를 임시 폴더로 복사하고 `prompt.structure.md`에 문장 추가 → `loadTemplate("lecture", tmp)` 로 입력 두 개 만들어 순서대로 실행 | `calls.length === 2` |
| changed language misses the memo | `language: "en"`로 두 번째 | `calls.length === 2` |
| budget stop | `env.job("job-b", {budgetMicrousd: 5})` 후 `UPDATE job SET spent_microusd = 10 WHERE id = 'job-b'` | `structure` 실행이 `HarnessError` kind `budget`으로 끝남; `calls.length === 0` |
| transient error is retried | 첫 호출 `new HarnessError("transient","503")`, 둘째 `okOut` | 성공, `calls.length === 2` |
| questions never asked | `req.instruction` | `질문`을 만들라는 문구 없음: 섹션 목록에 `questions` 키가 없음 |

## 10. 명세 작성자 메모

- `StageDefinition.output`은 정의 시점에 고정이라 템플릿별 `templateOutputSchema`를 쓸 수 없다. 단계 출력은 일반 `TemplateOutput`으로 검증하고 템플릿별 엄격 검사는 모델 요청의 `schema`(공급자가 검증 → `output_validation` → 수리)로 한다. 계약의 `structureStage(llm, routing)` 시그니처는 그대로다.
- map 호출들은 한 단계 실행 안에서 돌아서, 중간에 죽으면 map을 처음부터 다시 한다(청구도 다시). 창마다 메모하려면 단계 모델을 바꿔야 해서 하지 않았다. 또 map 도중에는 예산 검사가 없다(`JobRun.run`이 단계 시작 때만 본다). 둘 다 계약이 허용하는 범위로 보고 기록만 한다.
- map-reduce 모델은 `routing.structure`를 그대로 쓴다(map 전용 항목이 `routing.json`에 없다).
- `NOTES_SYSTEM` 문구와 `전사:` 머리말은 명세 작성자가 정했다. 계약은 순서만 고정했다.
