# P2-09 LECTERN_WEB_SHELL 기본값을 켬으로

> 등급: `careful` · 게이트: `full` · 의존: `P2-08`, `P2-07` · 소유: `packages/config/`, `docs/env.md`, `deploy/systemd/`, `apps/server/`, `docs/runbooks/`, `AGENTS.md`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

새 웹 앱(`/app`)을 기본 화면으로 만든다. `LECTERN_WEB_SHELL`의 기본값을 `1`로 바꾼다. 설정이 없는 호스트에서 `/`는 `/app`으로 302를 보낸다. `?legacy=1`로는 한 릴리스 동안 옛 화면을 연다. 되돌리려면 `LECTERN_WEB_SHELL=0`을 준다. 옛 화면 코드는 지우지 않는다(P2-10).

## 2. 먼저 읽을 것

- 계약: `CONTRACTS.md` D-0-3, D-P2-6 ①
- 레시피: `RECIPES.md` R4, R11
- 코드: `packages/config/src/index.ts` — `LECTERN_WEB_SHELL` 항목과 `Config`의 그 필드
- 코드: `apps/server/src/http.ts` — `createHttpApp`의 `/` 리다이렉트와 `legacy=1` 분기
- 코드: `apps/server/src/preflight-checks.ts` — `buildPreflightChecks`, `rootRedirectProblems` (P0-01이 만든다)
- 문서: `docs/v2/pipeline/PARITY.md` (P2-08이 만든다), `docs/runbooks/deploy-and-rollback.md`

- 둘째 명령이 **표의 행**을 하나라도 내면(새 앱에 없는 v1 기능이 남아 있다) `RESULT: BLOCKED`로 보고한다. 이 작업은 대조표가 다 채워진 뒤에만 한다.

## 5. 단계

1. `packages/config/src/index.ts`: `LECTERN_WEB_SHELL`의 스키마를 `bool(false)`에서 `bool(true)`로 바꾼다. 설명을 다음으로 바꾼다: `"1 (default): serve the v2 web app at /app and redirect / to it (?legacy=1 opens the old UI). 0: serve the old UI at /"`.
2. `packages/config/test/config.test.ts`: `loadConfig({})`의 웹 셸 필드가 `true`, `loadConfig({ LECTERN_WEB_SHELL: "0" })`이 `false`인 테스트를 넣는다. 기존에 기본값 `false`를 기대하던 줄은 `true`로 고친다(이 한 줄은 명세가 지시한 기대값 변경이다).
3. `bun run config:docs`.
4. `deploy/systemd/lectern.env.example`: `LECTERN_WEB_SHELL` 줄을 `LECTERN_WEB_SHELL=1`로 하고 위 주석을 다음으로 바꾼다: `# 새 웹 앱(/app)을 기본 화면으로 쓴다. 0으로 바꾸고 재시작하면 옛 화면(/)으로 돌아간다.`
5. `bun test apps/server`를 돌린다. 기본값이 꺼짐이라고 가정해 실패하는 테스트를 찾는다. 각 테스트가 서버를 만드는 곳에서 **꺼짐을 명시**한다(환경 변수 `LECTERN_WEB_SHELL=0`을 그 테스트의 준비에서 주거나, `createHttpApp`에 `webShellDistDir`를 주지 않는다). 기대값은 바꾸지 않는다. 켬 상태의 동작은 `apps/server/test/web-shell.test.ts`가 이미 덮는다.
6. `apps/server/test/web-shell.test.ts`에 테스트 하나를 더한다: 설정을 주지 않은 기본 구성에서 `/` → 302이고 `Location`이 `/app`으로 시작한다.
7. `docs/runbooks/deploy-and-rollback.md`의 롤백 절에 소절 "새 웹 앱을 끄기"를 더한다. 내용: ① `/etc/systemd/system/lectern.service.d/`의 drop-in에 `Environment=LECTERN_WEB_SHELL=0`을 넣는다(명령은 `printf … | sudo tee`, 편집기를 여는 명령은 쓰지 않는다) ② `sudo systemctl daemon-reload && sudo systemctl restart lectern` ③ 확인: `curl -sI https://<호스트>/`가 200이고 `/app`이 404.
8. `AGENTS.md`의 저장소 지도에서 `src/ui.ts` 줄을 "옛 웹 앱·관리자 콘솔 HTML (`?legacy=1`로만 열린다. P2-10에서 사용자 앱 화면을 지운다)"로, `apps/` 아래에 `web/  v2 웹 앱 (React, /app으로 서빙. 기본 화면)` 줄을 더한다.

## 6. 테스트

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| config "web shell defaults on" | `loadConfig({})` | 웹 셸 필드 `true` |
| config "web shell can be turned off" | `loadConfig({ LECTERN_WEB_SHELL: "0" })` | `false` |
| web-shell "default config redirects / to /app" | 설정 없이 만든 앱에 `GET /` | 302, `Location`이 `/app`으로 시작 |
| web-shell "?legacy=1 still opens the old UI" (있으면 유지) | `GET /?legacy=1` | 200, HTML |
| 기존 "docs/env.md is up to date" | — | 통과 |

## 8. 하지 않는 것

- `ui.ts`의 화면을 지우지 않는다(`P2-10`, 사용자 승인 필요).
- `?legacy=1`을 없애지 않는다(`P2-10`).
- 운영 호스트의 설정을 바꾸지 않는다(사용자 몫).

## 10. 명세 작성자 메모

- `Config`에서 웹 셸 필드의 정확한 이름은 확인하지 않았다(`webShell`로 추정). 3절의 `git grep`으로 확인하고 그 이름을 쓴다.
- 기본값이 켜지면 게이트의 "플래그 끔" preflight도 웹 셸이 켜진 채로 돈다. P0-01의 `buildPreflightChecks`가 두 경우를 모두 다루므로 통과해야 한다. 통과하지 못하면 멈추고 보고한다.
