# P6-A6 iOS 앱 셸

> 등급: `basic` · 게이트: `apple` · 의존: `P6-A3`, `P6-A5` · 소유: `apps/apple/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

iOS 앱에 기본 화면을 넣는다: 로그인, 라이브러리(폴더와 녹음 목록), 녹음 상세(문서·전사·플레이어), 설정(서버 주소, 로그아웃, 계정 삭제 안내). 서버 없이도 화면을 볼 수 있는 픽스처 모드가 있고, 그 모드로 화면에 들어가는 UI 테스트가 하나 있다.

## 2. 먼저 읽을 것

- 계약: `CONTRACTS.md` D-P6-7, D-P6-8, D-P6-9
- 문서: `docs/v2/NATIVE.md` §1(웹뷰 래퍼를 만들지 않는다), §6("앱 안에서 계정 삭제")
- 코드: `Packages/LecternKit`(`LecternAPI`, `AuthProvider`, `NativeTokenProvider`, `ApiTokenProvider`, `UploadQueue`), `Packages/LecternUI`(`DocumentView`, `TranscriptList`, `PlayerViewModel`, `PlayerBar`, `PreviewData`)
- 코드: `apps/apple/project.yml`(타깃 `LecterniOS`), `iOS/App/Info.plist`(`LecternServerURL`)

## 5. 단계

1. `LecternClient`(프로토콜): `me`, `workspaces`, `folders`, `recordings`, `recording`, `transcript`, `document`, `audioItem(for:)`, `signIn(email:password:)`, `signIn(apiToken:)`, `signOut`. 실제 구현은 `LecternAPI`를 감싼다. `FixtureClient`는 메모리의 예시 데이터를 준다(폴더 3개, 녹음 8개: 상태 `ready` 5, `processing` 1, `partial` 1, `failed` 1. 문서와 전사는 `PreviewData`). 픽스처에 실제 사람 이름·학교 이름을 쓰지 않는다.
2. `AppEnvironment`
   - 서버 주소: 설정에서 사용자가 바꾼 값(`UserDefaults` 키 `lectern_server_url`) → 없으면 `Info.plist`의 `LecternServerURL`.
   - 픽스처 모드: 실행 인자 `-LECTERN_FIXTURE 1` 또는 환경 변수 `LECTERN_FIXTURE=1`이면 `FixtureClient`를 쓰고 로그인된 것으로 시작한다.
   - 인증 방식: 서버가 `POST /api/v2/auth/native/token`에 501·404를 주면(P5-03 전) API 토큰 로그인 화면으로 바꾼다.
3. 화면
   - **로그인**: 이메일, 비밀번호, 버튼 `로그인`. 아래 접힌 영역 `서버 주소`(기본값 표시)와 `API 토큰으로 로그인`(토큰 붙여 넣기. 네이티브 토큰이 없는 서버용). 오류: 401 `이메일 또는 비밀번호가 올바르지 않습니다.`, 429 `잠시 뒤 다시 시도해 주세요.`, 연결 실패 `서버에 연결하지 못했습니다. 서버 주소와 네트워크를 확인해 주세요.` 비밀번호 필드는 `textContentType(.password)`.
   - **라이브러리**: `NavigationSplitView`(iPad는 3단, iPhone은 스택). 왼쪽: 워크스페이스 선택과 폴더 목록(`전체`, 폴더들). 가운데: 녹음 목록(제목, 날짜, 길이, 상태 표시). 상태 표기: `processing` → `처리 중`, `partial` → `전사만 준비됨`, `failed` → `실패`, `ready` → 표기 없음. 당겨서 새로 고침, 끝까지 내리면 다음 쪽. 빈 상태 `아직 녹음이 없습니다.` 위쪽에 업로드 대기열 요약 한 줄(`업로드 중 1개`, 누르면 대기열 시트: 항목별 상태, `다시 시도`, `삭제`).
   - **녹음 상세**: 위에 제목. 탭(세그먼트) `문서` / `전사`. 아래에 `PlayerBar`. 출처 칩과 전사 줄을 누르면 그 위치로 가서 재생한다. `processing`이면 `처리 중입니다. 끝나면 문서가 여기에 나타납니다.`, `failed`면 `처리하지 못했습니다.`, 문서가 없고 전사만 있으면 문서 탭에 `노트를 만들지 못했습니다. 전사는 볼 수 있습니다.` iPad 가로에서는 문서와 전사를 나란히 놓는다.
   - **설정**: 계정(이메일), 서버 주소, 앱 버전, `로그아웃`(확인: `로그아웃할까요? 올리지 못한 녹음은 기기에 남습니다.`), `계정 삭제`(설명 `계정 삭제는 웹에서 요청합니다.`와 버튼 `웹에서 열기` → `<서버>/app/settings#account`를 Safari로 연다), `개인정보처리방침`(`<서버>/privacy`), `이용약관`(`<서버>/terms`).
4. 뷰모델(`LecternUI`의 `Screens/`. `@MainActor`, `ObservableObject`). 상태는 `enum Phase { case loading, loaded, empty, failed(String) }`. 네트워크는 `LecternClient`로만 한다(테스트에서 가짜를 넣는다). 401이면 로그인 화면으로 돌아가게 `onUnauthorized`를 부른다.
5. 접근성: 모든 버튼·셀에 레이블. 목록 셀의 레이블은 `<제목>, <날짜>, <길이>, <상태>`. 글자 크기는 `Theme`의 글꼴만 쓴다.
6. UI 테스트 타깃: `project.yml`에 `LecterniOSUITests`(`type: bundle.ui-testing`, `platform: iOS`, `sources: [iOS/UITests]`, `dependencies: [{ target: LecterniOS }]`)를 더하고 스킴 `LecterniOS`의 `test` 대상에 넣는다. 테스트는 `-LECTERN_FIXTURE 1`로 앱을 띄운다. **게이트(`gate.sh`)는 UI 테스트를 돌리지 않는다**(시뮬레이터 부팅이 필요하고 느리다). 빌드만 한다(`build-for-testing`을 `gate.sh`의 iOS 빌드에 더한다: `xcodebuild … build-for-testing`). 실행 명령은 README에 적는다.
7. `MANUAL_CHECKS.md`에 행: "실제 서버에 로그인해 목록·문서·전사·재생이 된다", "VoiceOver로 로그인부터 문서 읽기까지 간다", "iPad에서 문서와 전사가 나란히 보인다".

## 8. 하지 않는 것

- 녹음과 Live Activity(`P6-A7`), 공유 확장(`P6-A8`), 푸시·위젯·Spotlight(`P6-A11`).
- 문서 편집, 물어보기, 검색, 캘린더 화면(이 단계의 앱에는 없다. STATUS에 적는다).
- 웹뷰로 화면을 대신하지 않는다(`WKWebView` 금지. 계정 삭제·방침은 Safari로 연다).
