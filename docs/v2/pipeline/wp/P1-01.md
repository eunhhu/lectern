## 1. 목표

노트 파이프라인(classify → structure → extract → verify)이 공통으로 쓰는 바닥을 만든다: 단계별 모델 설정 파일(`routing.json`), 전사를 `#idx [MM:SS] S1: 본문` 줄로 줄이는 함수와 출처 토큰 해석기, Gemini 텍스트 호출 어댑터(`GeminiLlmProvider`), 테스트용 가짜 공급자(`ScriptedLlmProvider`). 사용자가 보는 변화는 없다.

## 5. 단계

1. `routing.json`: 아래를 **그대로** 만든다.
   ```json
   {
     "classify":  { "provider": "gemini", "model": "gemini-3.5-flash-lite", "maxOutputTokens": 1024 },
     "structure": { "provider": "gemini", "model": "gemini-3.8-flash",      "maxOutputTokens": 16384 },
     "extract":   { "provider": "gemini", "model": "gemini-3.8-flash",      "maxOutputTokens": 8192 },
     "repair":    { "provider": "gemini", "model": "gemini-3.8-flash",      "maxOutputTokens": 8192 },
     "ocr":       { "provider": "gemini", "model": "gemini-3.8-flash",      "maxOutputTokens": 8192 }
   }
   ```
2. `src/routing.ts`: zod로 모양을 검사한다.
   ```ts
   export type RoutingStage = "classify" | "structure" | "extract" | "repair" | "ocr";
   export type Routing = Record<RoutingStage, { provider: "gemini"; model: string; maxOutputTokens: number }>;
   export function loadRouting(path: URL | string = ROUTING_PATH): Routing;
   ```
   - `ROUTING_PATH = new URL("../routing.json", import.meta.url)`, `readFileSync`로 읽는다(결과를 모듈 변수에 캐시하지 않는다. 테스트가 다른 경로를 넘긴다).
   - 키 5개가 모두 있어야 하고 `maxOutputTokens`는 양의 정수, `provider`는 `"gemini"`만 허용.
   - 각 `model`이 `resolveGeminiModel(model) === model`이 아니면 `Error("routing.<stage>: model <id> is not in the Gemini allowlist")`를 던진다. `-latest`로 끝나는 id도 같은 오류.
3. `src/notes/compact.ts`
   ```ts
   export interface CompactSegment { idx: number; start_ms: number; speaker: string | null; text: string }
   export function formatCompactTranscript(t: { segments: readonly CompactSegment[] }): { text: string; ids: number[] };
   export function parseSourceToken(token: string): { start: number; end: number } | null;
   export function expandSourceTokens(tokens: readonly string[], knownIds: ReadonlySet<number> | readonly number[]): { refs: SourceRef[]; dropped: string[] };
   ```
   - 줄: `#<idx> [<시각>] <speaker>: <text>`. speaker가 `null`이면 `#<idx> [<시각>] <text>`. 줄은 `\n`으로 잇고 끝에 개행 없음. `ids`는 segments 순서의 idx.
   - 시각: 1시간 미만 `MM:SS`(분 2자리 0채움: `03:05`), 1시간 이상 `H:MM:SS`(`1:02:40`). 초는 내림. 이 파일 안에 작은 `clock(ms)` 함수를 둔다(`@lectern/media`의 `formatClock`은 분을 0채움하지 않으므로 쓰지 않는다).
   - `text`의 줄바꿈은 공백 하나로 바꾼다(한 세그먼트 = 한 줄).
   - `parseSourceToken`: 정규식 `^#(\d+)(?:-#(\d+))?$`(domain `SourceToken`과 같다). `#12` → `{start:12,end:12}`, `#40-#44` → `{40,44}`. 모양이 틀리거나 `end < start`이면 `null`.
   - `expandSourceTokens`: 토큰마다 순서대로.
     - 파싱 실패 → `dropped`에 원문 그대로.
     - 범위 안에서 `knownIds`에 있는 값만 모아 **연속한 정수 묶음**마다 `{ kind: "transcript", start_idx, end_idx }` 하나.
     - 범위 안에 아는 id가 하나도 없으면 `dropped`에 토큰 원문. 일부만 없으면 없는 id마다 `"#<id>"`를 `dropped`에 넣는다.
     - 같은 ref는 한 번만(먼저 나온 순서 유지). 범위 크기는 `end - start + 1`이 100000을 넘으면 파싱 실패와 같이 취급.
4. `src/gemini-llm.ts`
   ```ts
   export interface GeminiLlmOptions extends GeminiAdapterOptions { thinkingLevel?: "low" | "medium" | "high" }
   export function geminiResponseSchema(schema: ZodType): unknown;   // see below
   export function llmSchemaHash(schema: ZodType): string;           // sha256Hex(canonicalJson(geminiResponseSchema(schema)))
   export class GeminiLlmProvider implements LlmProvider {
     readonly id = GEMINI_PROVIDER_ID;
     constructor(opts: GeminiLlmOptions);
     requestBody<T>(req: LlmRequest<T>): Record<string, unknown>;
     generate<T>(req: LlmRequest<T>): Promise<{ value: T; raw: unknown } & ProviderCallResult>;
   }
   ```
   - `geminiResponseSchema`: `z.toJSONSchema(schema)`를 Gemini `responseSchema`(OpenAPI 부분집합)로 바꾼다. **`toGeminiSchema`(gemini-ask.ts)를 쓰지 않는다**: 그것은 `anyOf`·`const`를 지워 구조 출력 스키마(판별 유니온, nullable)를 망가뜨린다. 변환 규칙: `type`은 대문자(`"object"`→`"OBJECT"`), `properties`는 재귀하고 키 순서를 `propertyOrdering`에 넣는다, `required`·`enum`·`description`·`items`·`minItems`·`maxItems` 유지, `const: x` → `enum: [x]`(+ 타입), `anyOf: [X, {type:"null"}]` → X에 `nullable: true`, 그 밖의 `anyOf`/`oneOf` → `anyOf: [변환한 항목들]`, `$schema`·`additionalProperties`·`pattern`·`format`·`minLength`·`maxLength`·`minimum`·`maximum`·`default`는 버린다. 결과는 `Object.freeze`하지 않아도 된다.
   - `requestBody(req)`: `{ systemInstruction: { parts: [{ text: req.system }] }, contents: [{ role: "user", parts: [...req.context 텍스트마다 { text }, { text: req.instruction }] }], generationConfig: { responseMimeType: "application/json", responseSchema: geminiResponseSchema(req.schema), thinkingConfig: { thinkingLevel }, maxOutputTokens: req.maxOutputTokens } }`. `temperature`는 넣지 않는다. `cacheKey`는 지금 쓰지 않는다(주석으로 남긴다). `ContextPart`가 `pdf`이면 `HarnessError("config", "PDF context is not supported yet", { code: "pdf_unsupported" })`(P3가 채운다).
   - `generate`: 모델은 `req.model`. `resolveGeminiModel(req.model) !== req.model`이면 `HarnessError("config", ..., { code: "model_not_allowed" })`. URL `${baseUrl ?? GEMINI_API_BASE}/models/${encodeURIComponent(model)}:generateContent`, 헤더 `Content-Type`·`x-goog-api-key`(키는 `geminiKeyOrThrow`), `signal: withDeadline(req.signal, opts.timeoutMs ?? 300_000)`, `fetch`는 `opts.fetch ?? fetch`.
   - 응답 처리 순서(전사 어댑터와 같다): `!res.ok` → `throw await geminiHttpError(res)`; `billed`를 만든 뒤(`usage: normalizeGeminiUsage(data.usageMetadata)`, `model: data.modelVersion ?? model`, `requestId: data.responseId ?? null`, `latencyMs`); `promptFeedback.blockReason` → 코드 `blocked`; `finishReason === "MAX_TOKENS"` → `truncated`; 그 외 STOP 아님 → `finish_reason`; `thought` 파트를 뺀 텍스트가 비면 `empty_response`; `JSON.parse` 실패 `malformed_json`; `req.schema.safeParse` 실패 `schema`(메시지에 오류 앞 200자). 전부 `HarnessError("output_validation", msg, { code, billed })`.
   - 성공: `{ value: parsed.data, raw: json, ...billed }`.
5. `src/eval/scripted-llm.ts`
   ```ts
   export const SCRIPTED_LLM_PROVIDER_ID = "scripted-llm";
   export type ScriptedAnswer = (req: LlmRequest<unknown>, callIndex: number) => unknown | Promise<unknown>;
   export class ScriptedLlmProvider implements LlmProvider {
     readonly id = SCRIPTED_LLM_PROVIDER_ID;
     readonly calls: Array<{ callIndex: number; req: LlmRequest<unknown> }> = [];
     constructor(answer: ScriptedAnswer);
     static fromList(values: unknown[]): ScriptedLlmProvider;  // call n returns values[n]; past the end throws HarnessError("config", "scripted llm: no answer for call n")
     generate<T>(req: LlmRequest<T>): Promise<{ value: T; raw: unknown } & ProviderCallResult>;
   }
   ```
   - 호출마다 `calls`에 `{callIndex, req}`를 먼저 넣는다. `answer`가 던지면 그대로 던진다(`HarnessError`를 던져 5xx·타임아웃을 흉내 낸다).
   - 반환값이 `Error` 인스턴스면 던진다. 아니면 `req.schema.safeParse`: 실패하면 `HarnessError("output_validation", ..., { code: "schema", billed })`, 성공이면 `{ value, raw: 반환값 }`.
   - `usage`는 결정적: `inputTokens = Math.ceil((system+모든 context 텍스트+instruction 글자 수)/3)`, `cachedTokens: 0`, `outputTokens = Math.ceil(JSON.stringify(반환값).length/3)`. `model: req.model`, `requestId: null`.
6. `src/index.ts`에 `export * from "./routing.ts"; "./gemini-llm.ts"; "./notes/compact.ts"; "./eval/scripted-llm.ts";`를 더한다(알파벳 순서 구역에 맞춰). 이름 충돌이 나면 멈추고 보고한다.
7. `packages/harness/package.json`의 `exports`에 `"./routing.json": "./routing.json"`을 더한다.

## 10. 명세 작성자 메모

- `LlmProvider`의 메서드 이름은 코드에서 `generate`다(계약의 "`generateContent`"는 REST 이름으로 해석했다).
- `toGeminiSchema`(gemini-ask.ts)는 `anyOf`·`const`를 버려서 `templateOutputSchema` 같은 판별 유니온 스키마에는 쓸 수 없다. 그래서 `gemini-llm.ts`에 전용 변환기를 둔다. 계약에 없는 추가이며, 실제 Gemini가 `anyOf`/`nullable`을 받아들이는지는 확인하지 못했다(사용자 실측 필요). 결과는 항상 `req.schema`로 다시 검증하므로 변환이 느슨해도 안전하다.
- 계약의 압축 형식은 시각을 `[MM:SS]`로만 적었다. 분 0채움(`03:05`)은 `docs/v2/AI_HARNESS.md` 예(`[14:03]`)에서 추정한 선택이다.
- `formatCompactTranscript`의 입력 타입은 하네스 `Transcript`(화자 라벨 필수)와 도메인 `Transcript`(화자 id) 둘 다 받을 수 있도록 구조 타입 `CompactSegment`로 열었다. 호출자(P1-09)가 변환한다.
- `resolveGeminiModel`은 모듈 로드 시점의 환경 변수로 허용 목록을 만든다. 테스트에서 `LECTERN_GEMINI_ALLOWED_MODELS`를 바꿔도 반영되지 않는다.
