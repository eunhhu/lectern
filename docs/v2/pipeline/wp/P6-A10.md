# P6-A10 macOS 시스템 오디오와 회의 감지

> 등급: `careful` · 게이트: `apple` · 의존: `P6-A9` · 소유: `apps/apple/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

Mac에서 화상 회의를 녹음할 때 내 마이크와 함께 상대방 소리(시스템 오디오)도 담는다. 파일은 2채널이다: 왼쪽이 마이크, 오른쪽이 시스템 오디오. 그리고 Zoom 같은 회의 앱이 실행되면 "녹음할까요?" 알림을 띄운다. 둘 다 설정에서 켜야 동작한다(기본 꺼짐). 캘린더는 읽지 않는다.

## 5. 단계

1. `RingBuffer`: `Float` 샘플의 고정 용량 FIFO. `write(_:)`가 용량을 넘으면 **가장 오래된 것을 버린다**(녹음을 멈추지 않는다). `read(count:)`는 있는 만큼 주고 모자란 부분은 호출자가 채운다. `available`. 스레드 안전(락 하나).
2. `ChannelMixer`
   ```swift
   public struct ChannelMixer {
       public init(sampleRate: Double, maxLagSeconds: Double = 0.5)
       public mutating func pushMic(_ samples: [Float])
       public mutating func pushSystem(_ samples: [Float])
       public mutating func pull(frames: Int) -> (left: [Float], right: [Float])   // always exactly `frames` each
       public mutating func drain() -> (left: [Float], right: [Float])            // what is left at stop, padded to equal length
       public private(set) var droppedMicFrames: Int
       public private(set) var droppedSystemFrames: Int
   }
   ```
   규칙
   - 왼쪽 = 마이크, 오른쪽 = 시스템. 두 입력은 같은 샘플레이트의 모노여야 한다(변환은 입력 쪽에서 한다).
   - `pull`은 한쪽이 모자라면 **0으로 채운다**(무음). 시스템 소리가 없을 때(아무것도 재생되지 않음) 탭은 버퍼를 주지 않을 수 있다. 그때도 마이크는 끊기지 않고 기록된다.
   - 한쪽이 다른 쪽보다 `maxLagSeconds` 넘게 앞서 쌓이면 뒤처진 쪽을 0으로 채워 따라잡는다(두 채널의 시간이 0.5초 넘게 어긋나지 않는다).
   - 값은 `-1...1`로 자른다.
3. `SystemAudioTap`(`#if os(macOS)`)
   - `CATapDescription`으로 **이 앱 자신을 뺀** 전체 시스템 출력의 모노 믹스 탭을 만든다(자기 소리를 다시 녹음하지 않는다). 탭은 `muteBehavior`를 음소거 없음으로 둔다(사용자는 소리를 그대로 듣는다).
   - 탭을 넣은 비공개 집합 장치(aggregate device)를 만들고 IO 프록으로 버퍼를 받는다. 받은 버퍼를 모노 `Float`로 바꿔(여러 채널이면 평균) `onSamples`로 넘긴다. 샘플레이트가 마이크 쪽과 다르면 `AVAudioConverter`로 맞춘다.
   - `start()`가 실패하는 경우를 구별한다: 권한 거부 → `SystemAudioError.permissionDenied`(`"시스템 오디오 녹음 권한이 필요합니다. 시스템 설정 > 개인정보 보호 및 보안 > 화면 및 시스템 오디오 녹음에서 Lectern을 켜 주세요."`), 그 밖 → `.unavailable(OSStatus)`.
   - `stop()`은 IO 프록, 집합 장치, 탭을 만든 순서의 반대로 없앤다. 두 번 불러도 안전하다.
4. `DualInput: AudioInput`: 마이크 입력(P6-A4의 실제 입력)과 `SystemAudioTap`을 `ChannelMixer`에 넣고, 4096프레임마다 2채널 `AVAudioPCMBuffer`를 만들어 `onBuffer`로 준다. `format`은 2채널이다. 싱크(`AVAudioFile`)는 채널 수 2로 연다(비트레이트는 채널당 같은 값). 탭이 `permissionDenied`나 `unavailable`로 실패하면 **마이크만으로 녹음을 계속하고**(오른쪽 채널 무음) 뷰모델에 경고 `시스템 오디오를 녹음하지 못해 마이크만 녹음합니다.`를 알린다.
5. 설정(`SettingsView`): 토글 `회의 소리도 함께 녹음(시스템 오디오)`, 도움말 `화상 회의에서 상대방 목소리를 함께 담습니다. 처음 켤 때 macOS가 권한을 묻습니다.` 켜져 있으면 `MacRecordingViewModel`이 `DualInput`을, 꺼져 있으면 마이크 입력을 쓴다. `Info.plist`에 `NSAudioCaptureUsageDescription` = `회의에서 상대방의 소리를 함께 녹음하려면 시스템 오디오 접근이 필요합니다.`
6. 회의 감지
   ```swift
   public struct MeetingApp: Sendable, Equatable { public let bundleID: String; public let name: String }
   public let knownMeetingApps: [MeetingApp]     // zoom.us "us.zoom.xos", Microsoft Teams "com.microsoft.teams2" and "com.microsoft.teams", Webex "com.cisco.webexmeetingsapp" and "Cisco-Systems.Spark", FaceTime "com.apple.FaceTime"
   public struct MeetingPrompter: Sendable {
       public init(cooldownSeconds: Double = 1800)
       public mutating func shouldPrompt(launchedBundleID: String, isRecording: Bool, enabled: Bool, now: Date) -> MeetingApp?
   }
   ```
   - `shouldPrompt`가 `nil`을 주는 경우: 설정이 꺼짐, 이미 녹음 중, 목록에 없는 앱, 같은 앱에 대해 `cooldownSeconds` 안에 이미 물어봄.
   - `MeetingWatcher`(macOS 앱): `NSWorkspace.shared.notificationCenter`의 `didLaunchApplicationNotification`을 듣고 `shouldPrompt`가 앱을 주면 알림을 띄운다. 제목 `<앱 이름> 회의를 녹음할까요?`, 본문 `Lectern이 마이크와 회의 소리를 녹음합니다.`, 액션 `녹음 시작` / `이번에는 안 함`. `녹음 시작`을 누르면 `MacRecordingViewModel.toggle()`. 알림을 그냥 닫으면 아무것도 하지 않는다.
   - 설정 토글 `회의 앱이 실행되면 녹음할지 묻기`(기본 꺼짐). **자동으로 녹음을 시작하지 않는다.** 항상 묻는다.
   - 브라우저 회의(Meet)는 감지하지 않는다(브라우저 실행만으로는 회의인지 알 수 없다).
7. `MANUAL_CHECKS.md`에 행(실제 Mac)
   - 시스템 오디오 권한을 처음 물을 때의 문구가 보인다
   - 음악을 틀고 말하며 녹음한 파일: 왼쪽에 목소리, 오른쪽에 음악
   - 아무 소리도 재생하지 않을 때도 마이크가 끊기지 않는다
   - 권한을 거부하면 마이크만 녹음되고 경고가 보인다
   - 30분 녹음에서 두 채널의 어긋남이 0.5초 이내다
   - Zoom을 실행하면 알림이 오고, `녹음 시작`을 누르면 녹음이 시작된다
   - 녹음한 회의 파일을 올려 서버 전사가 양쪽 목소리를 담는다

## 8. 하지 않는 것

- 캘린더(EventKit) 읽기로 회의를 감지하지 않는다(CATALOG: "캘린더 읽기는 넣지 않는다").
- 앱별 탭(특정 앱의 소리만), ScreenCaptureKit, 화면 녹화.
- 서버가 두 채널을 화자 구분에 쓰게 하는 것(평가가 필요하다. STATUS "사용자 필요").
- iOS에는 해당 없음.

## 9. 끝났다는 기준

- [ ] 6절의 테스트가 통과한다
- [ ] 게이트가 통과한다
- [ ] 탭이 실패해도 마이크 녹음이 이어진다(코드 경로와 경고 문구)
- [ ] 두 기능 모두 기본 꺼짐이다
- [ ] `MANUAL_CHECKS.md`에 7단계의 행이 있다

## 10. 명세 작성자 메모

- 프로세스 탭 API의 정확한 호출 순서와 속성 이름은 이 명세가 확인하지 않았다. SDK 헤더와 Apple의 샘플("Capturing system audio with Core Audio taps")을 기준으로 한다. 컴파일은 되지만 실제로 소리가 들어오는지는 기기 확인으로만 알 수 있다.
- 샌드박스 앱에서 프로세스 탭이 되는지, 추가 entitlement가 필요한지는 기기 확인 항목이다. 안 되면 사용자가 샌드박스 정책을 정한다(STATUS).
- 서버의 전사 파이프라인이 2채널 파일을 어떻게 다루는지(모노로 내려 섞는지)는 확인하지 않았다. 점검표 마지막 행이 그것을 본다.
- 회의 앱의 번들 id는 기억에 의존했다. 워커는 고치지 말고 그대로 쓰되, 틀린 것은 기기 확인에서 드러난다.
