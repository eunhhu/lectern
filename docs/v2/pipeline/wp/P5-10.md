## 5. 단계

1. API 클라이언트
   ```ts
   listAccessTokens(): Promise<AccessTokenPage>;
   createAccessToken(body: CreateAccessTokenRequest): Promise<CreatedAccessToken>;
   revokeAccessToken(tokenId: string): Promise<void>;
   listIdentities(): Promise<IdentityPage>;
   unlinkIdentity(identityId: string): Promise<void>;
   listExports(): Promise<DataExportPage>;
   createExport(body: CreateExportRequest): Promise<DataExport>;
   exportContentUrl(exportId: string): string;                     // "/api/v2/me/exports/<id>/content"
   getAccountDeletion(): Promise<AccountDeletionInfo>;
   requestAccountDeletion(password?: string): Promise<AccountDeletionInfo>;
   cancelAccountDeletion(): Promise<AccountDeletionInfo>;
   oauthProviders(): Promise<{ google: boolean; apple: boolean }>;
   ```
   `oauthProviders`: `fetch("/api/v2/auth/<provider>/start", { method: "GET", redirect: "manual" })`로 본다. 응답이 리다이렉트(`type === "opaqueredirect"` 또는 3xx)면 켜진 것, 404·501이면 꺼진 것이다. 결과는 세션 동안 기억한다. fixture는 `{ google: true, apple: true }`(쿼리 `?fixture-oauth=off`면 둘 다 `false`).
2. `Devices`: 줄마다 `device_name ?? "알 수 없는 기기"`, `마지막 사용 <상대 시각>`(기존 날짜 포맷 도우미를 쓴다), 현재 기기에는 `이 기기` 표시. 버튼 `로그아웃시키기`(현재 기기에는 없음).
3. `Tokens.tsx` — 제목 "액세스 토큰". 설명 `스크립트나 다른 앱에서 Lectern API를 쓸 때 사용하는 토큰입니다.`
   - 목록: 이름, `prefix…`, 권한(`읽기` / `읽기·쓰기`), 만료(`만료 없음` 또는 날짜), 마지막 사용. 버튼 `회수`(확인: `이 토큰을 회수할까요? 이 토큰을 쓰는 앱은 더 이상 접속할 수 없습니다.`).
   - `새 토큰` 대화상자: 이름(필수), 권한 선택 `읽기 전용`(`["recordings:read"]`) / `읽기·쓰기`(둘 다), 만료 선택 `30일` / `90일` / `1년` / `만료 없음`.
   - 만든 직후: 읽기 전용 입력에 `secret`, 버튼 `복사`, 안내 `이 토큰은 지금만 볼 수 있습니다. 안전한 곳에 보관하세요.` 대화상자를 닫으면 다시 볼 수 없다(상태에서 지운다).
   - v1 토큰 항목(`name === "API 토큰"`, id가 `tok_`로 시작)은 `회수` 버튼 없이 보인다.
4. `Identities.tsx` — 제목 "연결된 로그인".
   - Google·Apple 한 줄씩: 연결됨이면 이메일과 `연결 해제`, 아니면 `연결`(`window.location.assign("/api/v2/auth/<provider>/start?next=/app/settings%23account")`). 공급자가 꺼져 있고 연결도 없으면 그 줄을 그리지 않는다.
   - 해제 확인: `<Google|Apple> 로그인 연결을 해제할까요?` 409면 토스트 `마지막 로그인 수단은 연결을 해제할 수 없습니다. 먼저 비밀번호를 설정해 주세요.`
   - 주소의 `?identity=linked` → 토스트 `로그인 수단을 연결했습니다.`, `?identity=taken` → `이미 다른 계정에 연결된 로그인입니다.` 표시 뒤 쿼리를 지운다.
5. `Exports.tsx` — 제목 "데이터 내보내기". 설명 `워크스페이스의 녹음과 노트를 zip 파일로 받습니다. 파일은 7일 동안 내려받을 수 있습니다.`
   - 체크박스 `오디오와 PDF 원본 포함(용량이 커집니다)`, 버튼 `내보내기 만들기`. 202 뒤 토스트 `내보내기를 만들고 있습니다. 준비되면 여기에서 내려받을 수 있습니다.`
   - 목록(상태 표기): `queued`·`running` → `만드는 중`, `ready` → 링크 `내려받기`(`exportContentUrl`, `download` 속성)와 크기·만료일, `failed` → `실패` + `error`, `expired` → `만료됨`.
   - `만드는 중`인 항목이 있으면 10초마다 목록을 다시 읽는다(없으면 멈춘다).
6. `DeleteAccount.tsx` — 제목 "계정 삭제".
   - 예약 없음: 설명 `계정을 삭제하면 7일 뒤에 모든 녹음과 노트가 지워집니다. 7일 안에는 취소할 수 있습니다.` 버튼 `계정 삭제 요청`. 대화상자: 비밀번호 입력(OAuth로만 가입한 사용자에게는 보이지 않는다 — 판별은 `listIdentities`가 비어 있지 않고 서버가 `password` 없이 받는지로 하지 않고, 입력란을 "비밀번호(비밀번호로 가입한 경우)"로 선택 입력으로 둔다), 확인 문구 입력란 `삭제합니다`를 정확히 입력해야 버튼 `삭제 요청`이 켜진다.
   - 오류: 403은 서버 문구 그대로, 409(유일한 owner)도 서버 문구 그대로 토스트가 아니라 대화상자 안에 보인다.
   - 예약됨: 경고 `<날짜>에 계정이 삭제됩니다.`와 버튼 `삭제 취소`(토스트 `계정 삭제를 취소했습니다.`).
7. `SettingsPage.tsx`: 구역 id `account` 아래에 기기, 토큰, 연결된 로그인, 데이터 내보내기, 계정 삭제 순으로 놓는다. 501을 주는 기능(서버에서 꺼짐)은 그 구역 본문 대신 `준비 중입니다.`
8. `OAuthButtons.tsx`: `oauthProviders()` 결과에 따라 버튼을 그린다. 문구 `Google로 계속하기`, `Apple로 계속하기`. 누르면 `window.location.assign("/api/v2/auth/<provider>/start?next=" + encodeURIComponent(next))`(`next`는 로그인 화면이 이미 쓰는 돌아갈 경로, 없으면 `/app`). 둘 다 꺼져 있으면 구분선도 그리지 않는다. 로고 이미지는 인라인 SVG로 넣는다(외부 URL 금지, CSP). `LoginPage`와 `SignupPage`에서 폼 아래에 놓는다.
   - 로그인 화면이 주소의 `?error=`를 읽어 안내한다: `oauth` → `로그인하지 못했습니다. 다시 시도해 주세요.`, `email_unverified` → `이메일이 인증되지 않은 계정으로는 로그인할 수 없습니다.`, `no_email` → `이메일 주소를 받지 못해 로그인할 수 없습니다.`, `inactive` → `사용이 중지된 계정입니다.`

## 6. 테스트

| 종류 | 테스트 이름 | 준비 | 기대 |
|---|---|---|---|
| unit | http-client "account calls" | 가짜 `fetch` | `POST /api/v2/me/tokens` 본문, `DELETE /api/v2/me/identities/<id>`, `POST /api/v2/me/exports`, `POST /api/v2/me/deletion` 본문 `{ password }` |
| unit | http-client "oauthProviders" | start가 opaqueredirect / 404 / 501 | `true` / `false` / `false` |
| e2e | "token secret is shown once" | fixture, 토큰 만들기 | `lct_pat_`로 시작하는 값과 `이 토큰은 지금만 볼 수 있습니다.` → 닫기 → 목록에 접두사만, 원문 없음 |
| e2e | "revoke a token" | 회수 확인 | 목록에서 사라진다 |
| e2e | "device names" | fixture 기기 2개 | `Mac의 Chrome`, `이 기기` |
| e2e | "export lifecycle" | 만들기 → fixture가 10초 뒤 `ready` | `만드는 중` → `내려받기` 링크(`/content`로 끝나는 href) |
| e2e | "delete needs the phrase" | 대화상자 | `삭제합니다`를 넣기 전에는 버튼이 꺼져 있다. 넣고 요청 → 경고와 `삭제 취소` → 취소 |
| e2e | "sole owner message" | fixture가 409 | 대화상자 안에 서버 문구 |
| e2e | "oauth buttons hidden when off" | `?fixture-oauth=off` | 두 버튼이 없다 |
| e2e | "oauth error message" | `/app/login?error=email_unverified` | 해당 문구 |
| e2e | "keyboard only: create a token" | Tab·Enter·화살표만 | 토큰이 만들어진다 |
| e2e | a11y "settings account" / "login with oauth buttons" | 각 화면 | axe 위반 0건 |

## 10. 명세 작성자 메모

- 서버에 "어떤 로그인 수단이 켜져 있는지"를 알려 주는 라우트가 없다. 그래서 start 주소를 `redirect: "manual"`로 찔러 본다. 이 요청은 서버에 `oauth_state` 행을 하나 만든다(10분 뒤 사라진다). 깔끔하지 않지만 계약을 늘리지 않는다. 설정 라우트가 생기면 바꾼다(STATUS에 적는다).
- 계정 삭제 대화상자의 비밀번호 입력을 선택 입력으로 둔 것은 "OAuth로만 가입했는지"를 웹이 알 방법이 없어서다.
