# P5-04 Google 로그인

> 등급: `careful` · 게이트: `full` · 의존: `P5-C`, `P4-02` · 소유: `apps/server/`
> (이 줄은 `pipeline.json`의 값과 같아야 한다.)

## 1. 목표

로그인 화면의 "Google로 계속하기"로 들어올 수 있다. 같은 (인증된) 이메일의 계정이 이미 있으면 그 계정으로 들어가고, 없으면 새 계정이 생긴다. 설정에서 연결된 로그인 수단을 보고 뗄 수 있다. `LECTERN_GOOGLE_LOGIN=0`이면 라우트는 404다. 테스트는 가짜 Google만 쓴다.

## 5. 단계

1. `oauth/jwt.ts` (WebCrypto만 쓴다. 새 의존성 없음)
   ```ts
   export interface JwtClaims { iss: string; aud: string | string[]; sub: string; exp: number; iat?: number; email?: string; email_verified?: boolean | string; nonce?: string; [k: string]: unknown }
   export class JwtError extends Error { constructor(readonly reason: "malformed" | "signature" | "issuer" | "audience" | "expired" | "nonce" | "keys") }
   export async function verifyJwt(token: string, opts: { jwksUrl: string; issuers: string[]; audience: string; nonce?: string; now?: number }): Promise<JwtClaims>
   export function clearJwksCache(): void   // tests
   ```
   - 헤더의 `alg`는 `RS256`(Google)과 `ES256`(Apple)만 받는다. `none`과 그 밖의 값은 `malformed`.
   - JWKS는 `fetch(jwksUrl)`로 받아 URL마다 1시간 캐시한다. 헤더의 `kid`가 캐시에 없으면 한 번만 다시 받는다. 그래도 없으면 `keys`.
   - 서명 검증: `crypto.subtle.importKey("jwk", …)` + `crypto.subtle.verify`. RS256은 `{ name: "RSASSA-PKCS1-v1_5", hash: "SHA-256" }`, ES256은 `{ name: "ECDSA", namedCurve: "P-256" }` / `{ name: "ECDSA", hash: "SHA-256" }`(JWT의 ES256 서명은 r‖s 64바이트 그대로다).
   - 검사 순서: 모양 → 서명 → `iss`가 `issuers` 안 → `aud`가 `audience`와 같거나 배열에 포함 → `exp > now`(60초 여유) → `nonce`가 주어졌으면 일치.
2. `oauth/login.ts`
   ```ts
   export function safeNext(next: string | null | undefined): string   // "/app" unless next starts with "/" and not with "//" or "/\\"; max 512 chars
   export function completeOAuthLogin(p: { provider: "google" | "apple"; subject: string; email: string | null; emailVerified: boolean; displayName?: string | null }):
     { userId: string; created: boolean } | { error: "email_unverified" | "no_email" | "inactive" }
   export function sessionCookieHeader(token: string, req: Request): string   // same name and attributes as the password login
   export function linkIdentity(userId: string, p: { provider: "google" | "apple"; subject: string; email: string | null }): "linked" | "taken"
   ```
   `completeOAuthLogin` 규칙(D-P5-1)
   1. `(provider, subject)`의 `oauth_identity`가 있으면 그 사용자다.
   2. 없으면: `email`이 없으면 `no_email`, `emailVerified`가 거짓이면 `email_unverified`.
   3. `getUserByEmail(email)`이 있으면 그 사용자에 identity를 연결한다. 없으면 `createUser`로 새 사용자를 만든다(이메일 인증됨, 비밀번호는 누구도 모르는 무작위 64바이트 값의 해시, 표시 이름은 `displayName` 또는 이메일의 `@` 앞) 뒤 연결한다.
   4. 사용자가 비활성이면 `inactive`.
3. `auth-google.ts`
   - `GET /auth/google/start?next=<경로>`: `config().googleLogin`이 거짓이면 404. `googleClient()`가 `null`이면 404. PKCE와 state(`purpose: "google_login"`, `userId`는 지금 로그인돼 있으면 그 id — "계정에 연결" 흐름 —, 아니면 `null`, `redirectAfter: safeNext(next)`)를 만들고 `302`로 Google에 보낸다. 범위는 `openid email profile`, `access_type`은 넣지 않는다. state 값 자체를 `nonce` 파라미터로도 보낸다.
   - `GET /auth/google/callback`: 플래그가 꺼지면 404. `error`가 있거나 `code`·`state`가 없거나 `consumeOAuthState(state, "google_login")`이 `null`이면 `302 /app/login?error=oauth`. `exchangeCode` → `id_token`이 없으면 오류 → `verifyJwt(id_token, { jwksUrl: "https://www.googleapis.com/oauth2/v3/certs", issuers: ["https://accounts.google.com", "accounts.google.com"], audience: clientId, nonce: state })`.
     - state에 `userId`가 있으면(연결 흐름): 지금 세션의 사용자와 같아야 한다. `linkIdentity` → `302 /app/settings?identity=linked#account`(`taken`이면 `?identity=taken`).
     - 없으면(로그인 흐름): `completeOAuthLogin`. 오류면 `302 /app/login?error=<email_unverified|no_email|inactive>`. 성공이면 `createSession` → (있으면) `recordSessionMeta` → `Set-Cookie` → `302 <redirectAfter>`.
   - 모든 실패는 같은 화면(`/app/login?error=…`)으로 간다. `code`, 토큰, state, ID 토큰을 로그에 남기지 않는다.
4. `index.ts`: `v2.all("*")` 앞에 `v2.get("/auth/google/start", googleLoginStart)`, `v2.get("/auth/google/callback", googleLoginCallback)`.
5. `me.ts`
   - `listIdentities`: 그 사용자의 `oauth_identity` 목록.
   - `unlinkIdentity`: 자기 것만(아니면 404). **마지막 로그인 수단은 못 뗀다**: 남는 identity가 0개이고 사용자가 스스로 정한 비밀번호가 없으면 `409 conflict`, `마지막 로그인 수단은 연결을 해제할 수 없습니다. 먼저 비밀번호를 설정해 주세요.` "스스로 정한 비밀번호가 있는지"는 판별할 열이 없으므로 다음으로 정한다: OAuth로 **만들어진** 사용자(가장 오래된 identity의 `created_at`이 사용자 `created_at`과 5초 이내)는 비밀번호 재설정을 한 번이라도 하기 전에는 없는 것으로 본다. 재설정 여부를 알 수 없으면 보수적으로 409를 준다.
6. 가짜 Google 확장(`test/fakes/google.ts`)
   ```ts
   issueCode(code: string, opts?: { refreshToken?: string | null; idToken?: { sub: string; email?: string; email_verified?: boolean; aud?: string; iss?: string; exp?: number; nonce?: string; name?: string } }): void;
   rotateSigningKey(): void;   // new kid; the JWKS endpoint serves only the new key
   ```
   가짜는 시작할 때 RSA-2048 키 쌍을 `crypto.subtle.generateKey`로 만들고, `https://www.googleapis.com/oauth2/v3/certs`에 공개 JWK(`kid` 포함)를 답하고, 토큰 응답의 `id_token`을 그 키로 RS256 서명한다. `nonce`를 주지 않으면 인가 요청에서 받은 `nonce`(= state)를 쓴다.

## 6. 테스트

`oauth-jwt.test.ts`: 직접 만든 키로 "valid RS256", "valid ES256", "alg none rejected", "bad signature", "wrong issuer", "wrong audience", "expired", "nonce mismatch", "unknown kid refetches once", "JWKS cached for an hour"(요청 수로 확인).

`google-login.test.ts` (`LECTERN_GOOGLE_LOGIN=1`, 가짜 시크릿)

| 테스트 이름 | 준비 | 기대 |
|---|---|---|
| "start redirects to Google" | `GET /api/v2/auth/google/start?next=/app/ask` | 302, `scope=openid email profile`, `code_challenge_method=S256`, `nonce`가 `state`와 같다 |
| "new user" | 없는 이메일의 ID 토큰 | 302 `/app/ask`, `Set-Cookie: lectern_session=…`, `users` 1행 추가, `oauth_identity` 1행, 그 쿠키로 `GET /api/v2/me` 200 |
| "existing verified e-mail links" | 같은 이메일의 기존 사용자 | 새 사용자 없음, 기존 사용자에 identity 연결 |
| "second login reuses the identity" | 같은 `sub`로 다시 | 사용자·identity 수 그대로 |
| "email_verified=false is refused" | `email_verified: false` | 302 `/app/login?error=email_unverified`, 사용자·쿠키 없음 |
| "aud mismatch is refused" | `aud: "other-client"` | 302 `/app/login?error=oauth` |
| "state replay is refused" | 같은 `state`로 두 번 | 두 번째 `error=oauth` |
| "nonce mismatch is refused" | ID 토큰의 `nonce`를 다른 값으로 | `error=oauth` |
| "next must be a local path" | `next=https://evil.example`, `next=//evil.example` | `Location`이 `/app` |
| "link flow" | 로그인한 채 start → callback | `/app/settings?identity=linked#account`, `listIdentities`에 1개 |
| "identity already used by someone else" | 다른 사용자에 연결된 `sub`로 연결 | `?identity=taken`, 연결 없음 |
| "unlink keeps the last sign-in method" | OAuth로 만든 사용자가 유일한 identity를 뗌 | 409 |
| "unlink with a password" | 비밀번호 가입 사용자가 연결 뒤 뗌 | 204 |
| "flag off" | `LECTERN_GOOGLE_LOGIN=0` | start·callback 404 |
| "no secrets in logs" | 위 흐름의 로그 출력 | `code`, `id_token`, `state` 값이 없다 |

## 8. 하지 않는 것

- Apple 로그인(`P5-05`. `oauth/jwt.ts`와 `oauth/login.ts`를 가져다 쓴다), 웹 버튼(`P5-10`).
- Google 캘린더 연동의 토큰과 섞지 않는다(로그인은 `refresh_token`을 받지도 저장하지도 않는다).
- v1 로그인 엔드포인트를 고치지 않는다.

## 10. 명세 작성자 메모

- `createUser`의 입력(이메일 인증 표시, 비밀번호 필수 여부)은 확인하지 않았다. 함수를 읽고 맞춘다. 인증됨 표시를 넣을 방법이 없으면 멈추고 보고한다(v1 테이블을 고치는 일이 된다).
- "스스로 정한 비밀번호" 판별은 불완전하다. 정확히 하려면 `users`에 열이 필요한데 v1 테이블이라 못 넣는다. 보수적으로(뗄 수 없는 쪽으로) 틀리게 했다.
- 실제 Google 로그인 확인과 OAuth 동의 화면 검수는 사용자 몫이다(`docs/runbooks/google-oauth-verification.md`).
