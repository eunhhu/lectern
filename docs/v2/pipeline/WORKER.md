# 워커 규칙 (WORKER)

너는 작업 패키지(WP) **하나**를 맡은 워커다. 이 문서의 규칙에는 예외가 없다. 규칙과 명세가 부딪히면 규칙이 이기고, 너는 멈추고 보고한다.

## 1. 시작하기 전에 읽는다 (이 순서대로)

1. `AGENTS.md` (저장소 규칙)
2. 이 문서
3. `docs/v2/pipeline/wp/<ID>.md` (네 작업 명세)
4. 명세가 가리키는 `docs/v2/pipeline/CONTRACTS.md`의 절과 결정 번호(`D-P1-3` 같은 것)
5. 명세가 가리키는 `docs/v2/pipeline/RECIPES.md`의 레시피(`R3` 같은 것)
6. 명세의 "먼저 읽을 것"에 있는 코드 파일

읽지 않고 시작하지 않는다. 명세에 없는 것을 추측으로 만들지 않는다.

## 2. 절대 하지 않는 것

| # | 금지 | 이유 |
|---|---|---|
| 1 | `git push`, `main` 브랜치 건드리기, 통합 브랜치에 직접 커밋 | `main`은 운영이다. 병합은 오케스트레이터가 한다 |
| 2 | 명세의 **소유** 경로 밖 파일 고치기 | 다른 작업과 충돌한다. 필요하면 멈추고 보고한다 |
| 3 | 실제 외부 호출(Gemini, Google, Apple, Resend 등), `~/local.env` 읽기, 실제 API 키 쓰기 | 비용과 개인정보. 테스트는 가짜로 한다(RECIPES R7, R12) |
| 4 | 기본 데이터 디렉터리로 서버 띄우기 | 기본 경로는 실제 DB다. 서버를 띄워야 하면 `LECTERN_DATA_DIR`, `LECTERN_LECTURES_DIR`, `HOME`을 임시 디렉터리로 준다 |
| 5 | 기존 테스트를 지우기, `skip`/`todo`/`failing`으로 바꾸기, 기대값을 느슨하게 고치기 | 게이트를 속이는 것이다. 테스트가 틀렸다고 생각하면 멈추고 보고한다. **예외는 하나다**: 명세가 파일과 테스트 이름을 적어 지시한 변경·삭제·`skip`(CONTRACTS S-31) |
| 6 | 운영 코드에 테스트 전용 분기 넣기 | AGENTS.md 규칙 |
| 7 | `docs/v2/pipeline/CONTRACTS.md`, `CATALOG.md`, `pipeline.json`, 다른 WP의 명세 고치기 | 설계는 워커가 바꾸지 않는다 |
| 8 | 명세에 없는 의존성 추가(`bun add`), `bun.lock` 변경 | 계약 WP만 한다 |
| 9 | 시크릿·실제 이메일·실명·녹음 내용을 코드, 테스트, 커밋에 넣기 | 공개 저장소다. 예시는 `user@example.com` 같은 값을 쓴다 |
| 10 | DB 컬럼·테이블 삭제나 이름 변경, 기존 API 필드의 의미 변경 | 추가만 한다(CONTRACTS D-0-4, D-0-5) |
| 11 | 인라인 `<script>`/`<style>`, `on*` 속성, 외부 오리진 리소스, `localStorage` 토큰, `console.log` | AGENTS.md 웹 보안 규칙 |
| 12 | 커밋 메시지에 작성자 표시(attribution) 줄 넣기 | 저장소 규칙 |

## 3. 작업 순서

1. **사전 점검**: 명세 3절의 명령을 돌린다. 명세가 가리키는 파일·심볼이 없으면 `git grep`으로 찾는다. 그래도 없으면 4절대로 멈춘다.
2. **기준선**: 고치기 전에 `bash scripts/pipeline/gate.sh quick`을 돌린다. 실패하면 네 잘못이 아니다. 멈추고 보고한다.
3. **테스트 먼저**: 명세 6절의 테스트를 먼저 쓴다. 지금은 실패해야 한다.
4. **구현**: 명세 5절의 단계를 번호 순서대로 한다. 한 단계가 끝날 때마다 관련 테스트 파일만 돌린다(`bun test <파일>`).
5. **게이트**: 명세 7절의 명령을 돌린다. 통과할 때까지 **네 코드**를 고친다(테스트를 고치지 않는다).
6. **자기 점검**: `git status`로 바뀐 파일이 전부 소유 경로 안인지 본다. 명세 9절의 체크리스트를 하나씩 확인한다.
7. **커밋**: `type(scope): 요약` 형식, 본문에 무엇을 왜. 작업 브랜치(`wp/<ID>`)에만 커밋한다.
8. **보고**: 5절 형식으로만 답한다.

문구 규칙: 사용자에게 보이는 글은 한국어, 코드 주석은 영어, 로그는 `logger`(RECIPES R17).

## 4. 막혔을 때

다음 중 하나면 **즉시 멈춘다.** 우회하지 않는다.

- 명세나 계약이 실제 코드와 맞지 않는다(없는 함수, 다른 시그니처, 다른 테이블).
- 소유 경로 밖 파일을 고쳐야만 끝낼 수 있다.
- 같은 테스트를 3번 고쳐도 통과하지 못한다.
- 게이트가 네가 건드리지 않은 곳에서 실패한다.
- 명세가 두 가지로 읽힌다.

멈출 때는 지금까지 한 일을 작업 브랜치에 커밋하고(`wip(<ID>): …`), `RESULT: BLOCKED`로 보고한다. 무엇이 맞지 않는지 파일 경로와 심볼 이름으로 적는다.

## 5. 보고 형식 (마지막 답은 이것만)

```
RESULT: DONE | BLOCKED
WP: <ID>
BRANCH: wp/<ID>
COMMITS: <짧은 해시들>
GATE: <돌린 명령> → pass | fail (테스트 수)
FILES: <바뀐 파일 목록>
DEVIATIONS: none | <명세와 다르게 한 것과 이유>
NEEDS: none | <다른 소유자에게 필요한 변경, 사용자가 해야 할 일>
BLOCKED_REASON: <BLOCKED일 때만. 경로·심볼·오류 메시지>
```

통과하지 않은 것을 통과했다고 쓰지 않는다. 돌리지 않은 명령을 돌렸다고 쓰지 않는다.
