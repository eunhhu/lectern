# ADR-0009: 물어보기(RAG): 하이브리드 검색, 검증하는 인용, 비용 상한

- 상태: 채택(설계와 백엔드 골격). 답변 모델의 최종 선택([D13](../v2/ROADMAP.md#결정-필요-사항))과 월 한도 기본값(D14)은 평가와 사용자 결정으로 정한다.
- 날짜: 2026-10-19
- 관련: [ARCHITECTURE.md §12](../v2/ARCHITECTURE.md#12-검색물어보기), [AI_HARNESS.md §3.12, §12](../v2/AI_HARNESS.md#312-index--검색-색인), [ADR-0006](0006-harness-provider-abstraction-eval-routing.md)(공급자 추상화·평가), 코드: `packages/ask`, `packages/db/migrations/0001_search_ask.sql`·`0002_search_fts.sql`, `packages/domain/src/api/ask.ts`

## 맥락 (Context)

웹 셸을 보고 방향을 바꿨다.
- Lectern은 범용 노트 앱이다. 강의용 복습 기능(질문 카드, Active Recall)은 맞지 않는다.
- 대신 "이 노트에 물어보기"(노트 하나)와 "전반적으로 물어보기"(폴더·워크스페이스 전체)를 RAG로 제대로 넣는다.

제약은 다음과 같다.
- **AI 토큰 비용 최소화가 최우선이다.** 처리 비용 목표는 오디오 1시간당 $0.25(D11)이고, 질문 하나는 그 1%를 넘지 않는 것을 목표로 잡는다.
- 운영은 Raspberry Pi 5(aarch64) 한 대와 bun:sqlite다(ADR-0003). Bun은 Linux에서 자체 SQLite 3.53.4를 정적 링크하며, FTS5가 켜져 있고 확장 로드가 된다. 개발 Mac은 시스템 SQLite를 쓰는데 `OMIT_LOAD_EXTENSION`이라 확장을 로드하지 못한다(직접 확인).
- 데이터는 워크스페이스 단위다(ADR-0004). 다른 워크스페이스나 남의 비공개 녹음 조각이 문맥에 섞이면 안 된다.
- 한국어가 주 언어다. 조사가 붙고(`시험은`, `시험을`) 띄어쓰기가 흔들리며(`운영 모드`/`운영모드`), 핵심 명사 상당수가 두 음절이다(`시험`, `과제`, `마감`).
- 이전 설계(ARCHITECTURE §12)는 FTS5 `trigram` 토크나이저로 정했고 임베딩은 보류했다.

## 결정 (Decision)

### 1. 색인 단위(조각)

검색과 답변은 같은 조각(`search_chunk`)을 쓴다. 조각마다 인용에 필요한 출처를 함께 둔다. 그래서 인용을 만들 때 다른 테이블을 다시 조회하지 않는다.

| 종류 | 단위 | 출처(인용으로 쓰는 값) |
|---|---|---|
| `transcript` | 연속 세그먼트 묶음. 목표 350토큰(약 2분), 최대 600토큰. 화자가 바뀌거나 2초 이상 쉬면 자르고, 1분 이상 시간이 뛰면(잘린 휴식) 반드시 자른다. 세그먼트는 쪼개지 않는다 | `start_idx..end_idx`, 원본 오디오 `start_ms..end_ms`, 세그먼트별 글자 범위(`spans_json`) |
| `document` | 문서 블록 하나(`gap` 블록은 제외). 600토큰이 넘는 블록은 줄·문장 단위로 나눈다. 레거시 Markdown 노트는 제목 아래 문단을 목표 크기로 묶는다 | `document_id`, `version`, `block_id`(레거시는 null), 블록의 `SourceRef[]`, 시작 시각(블록 출처의 첫 세그먼트, 레거시는 `[MM:SS]`) |
| `pdf_page` | PDF 페이지(긴 페이지는 나눔). P3에서 켠다 | `asset_id`, `page` |

- 조각 id는 `(워크스페이스, 녹음, 종류, 위치, 내용 해시)`의 해시다. 같은 내용을 다시 색인하면 id가 같으므로 행과 임베딩을 그대로 쓴다.
- 녹음 1시간에 조각은 약 60개(전사 30, 문서 30)다. 평균 40분 노트 1만 개면 약 40만 개다.

### 2. 색인 단계(`index`)

- 하네스의 `publish` 뒤에 `index` 단계를 둔다(StageName, JobKind에 `index` 추가). 전사가 먼저 공개될 때, 문서가 발행될 때, 사용자가 문서를 고칠 때, 레거시 노트를 백필할 때 돈다.
- 처리 순서: 결정적 청킹 → `search_chunk`와 FTS 행을 한 트랜잭션으로 차분 동기화 → 임베딩이 없는 내용 해시만 묶어서(요청당 100개) 임베딩한다. 임베딩 호출은 모두 `ctx.meter`를 거쳐 `ai_call`에 남는다.
- 메모이제이션 키(AI_HARNESS §4.4): 입력(전사·문서·PDF 내용 해시), `CHUNKER_VERSION`, 청킹 규칙, 임베딩 공급자·모델·차원.
- 키가 빗나가도 임베딩은 `(workspace, model, dim, content_sha256)` 키로 저장되므로 같은 글을 두 번 임베딩하지 않는다.
- `publish`는 색인을 기다리지 않는다. 임베딩이 실패하거나 임베딩 모델이 설정되지 않으면 BM25만으로 검색·물어보기가 동작한다.

### 3. 검색: 한국어 바이그램 FTS5 + 벡터, RRF 결합

- **토크나이저는 `trigram`을 쓰지 않는다.** trigram은 3글자 미만 질의를 색인으로 찾지 못한다(sqlite.org/fts5). 그런데 한국어 핵심 명사는 두 음절이 많다.
- 대신 코드가 본문을 **문자 바이그램**으로 바꿔 넣고 FTS5는 `unicode61`로 공백만 나눈다.
  - 한글·한자·가나 연속 구간은 겹치는 바이그램으로 만든다. 공백 하나는 건너서 이어 만든다.
  - 라틴 문자·숫자는 단어 그대로 넣는다.
  - FTS 테이블은 contentless(`content=''`, `contentless_delete=1`)이고 원문은 `search_chunk.text`에만 둔다.
- 질의 처리
  - 단어 끝의 조사·어미를 두 번까지 떼고(`어디까지야` → `어디`), 의문사·요청어는 버린다.
  - 단어마다 바이그램 구(phrase)로 바꿔 OR로 묶는다. 띄어쓰기를 무시하는 부분 일치가 되고, 사용자 입력의 FTS 연산자는 모두 따옴표 안에 들어가 효력이 없다.
  - 한 글자 질의만 `LIKE`로 범위를 제한해 찾는다.
- 질의 시간은 BM25가 순위를 매기는 일치 조각 수에 비례한다. M3에서 조각당 약 6µs, Pi 5에서 약 25µs다. 그래서 순위 매길 양을 제한한다.
  - **작은 범위(녹음 20개 이하)**는 전역 색인을 쓰지 않고, 그 범위의 조각에 대해 코드에서 BM25를 계산한다. 띄어쓰기를 무시한 부분 일치로, 색인과 같은 의미다. 노트 하나는 1ms 안이다.
  - **넓은 범위**에서는 질의어를 드문 순서로 넣되, 일치 수 합이 2만(순위 예산)을 넘거나 전체 조각의 20% 넘게 나오는 질의어는 뺀다. 문서 빈도는 `fts5vocab`에서 읽는다.
  - 가장 드문 질의어 하나만으로도 예산을 넘으면 BM25 순위 없이 최신 일치 2,000개 안에서 고르고, 순서는 벡터 쪽에 맡긴다.
  - 이 문서 빈도와 전체 조각 수는 워크스페이스를 가리지 않은 색인 전체의 값이다. 순위를 매길 양(속도)을 정하는 데만 쓰고, 관련도 판단에는 쓰지 않는다. 관련도는 BM25와 근거 판정이 맡는다.
- **결합은 RRF**(k=60)다. BM25와 코사인은 척도가 달라 점수를 섞지 않고 순위만 섞는다.
  - 범위가 여러 녹음이면 녹음 하나에서 조각을 최대 3개만 쓴다.
  - 벡터가 없으면 BM25 순위만 쓴다.
- **근거 판정(모델 호출 전)**: 다음 둘 중 하나를 만족하는 조각이 없으면 모델을 부르지 않고 "모름"으로 답한다. 비용은 0이다. 기준값은 평가로 맞춘다.
  - 질의어의 절반(두 개면 충분) 이상을 담은 조각
  - 코사인 0.55 이상인 조각

### 4. 벡터 저장: 프로세스 안 전수 비교, int8 + 이진 사전 필터

조건은 768차원, 조각 40만 개(노트 1만 개)다. 측정은 Apple M3 단일 스레드이고, Pi 5는 ×4로 잡았다. Pi 수치는 추정이며 P7 부하 시험에서 잰다.

| 방식 | 메모리 | 조각 4만(노트 1천) | 조각 40만(노트 1만) | 비고 |
|---|---|---|---|---|
| float32 전수 비교 | 1,229MB | — | — | 메모리 때문에 제외 |
| int8 전수 비교(JS) | 307MB | 39ms (Pi 약 155ms) | 420ms (Pi 약 1.7초) | 작은 범위에만 |
| **이진(부호 비트) 해밍 → 상위 400개 int8 재채점(JS)** | **38MB**(+int8은 디스크) | 4ms (Pi 약 17ms) | 23ms (Pi 약 95ms) | **채택** |
| 같은 방식, 256차원(MRL) | 13MB | — | 10ms | 품질 확인 전에는 쓰지 않는다 |
| sqlite-vec v0.1.9 `vec0`(C, int8/bit, 파티션 키) | 디스크 | 미측정 | 미측정 | 1.0 이전이라 깨는 변경이 예고돼 있다. Mac 개발·테스트에서 확장을 로드할 수 없다. 운영에 네이티브 바이너리가 하나 는다 |
| ANN(HNSW 등) | 수백 MB | — | — | 이 규모에는 필요 없다 |

- 임베딩은 `search_embedding`에 int8(L2 정규화 뒤 벡터별 스케일)로 저장한다. 1개에 768바이트다.
- API 프로세스는 워크스페이스별로 부호 비트를 메모리에 올리고, 색인 세대(`search_index_state.generation`)가 바뀌면 다시 읽는다.
  - 범위 안 벡터가 2만 개 이하면 int8로 정확히 비교한다.
  - 그보다 많으면 해밍 거리로 후보 400개를 고르고, 그 후보의 int8만 읽어 다시 채점한다.
  - 워크스페이스 벡터가 5만 개를 넘으면 int8 코드는 메모리에 두지 않는다.
- `VectorIndex` 인터페이스 뒤에 두었으므로 sqlite-vec로 바꿀 수 있다. 다시 볼 신호는 다음과 같다.
  - Pi에서 벡터 검색 p95가 150ms를 넘을 때
  - 워크스페이스 조각이 100만 개를 넘을 때
  - sqlite-vec 1.0이 나올 때

### 5. 임베딩 모델: `gemini-embedding-2`, 768차원

| 모델(고정 ID) | 1M 토큰당(일반/배치) | 차원 | 다국어 지표 | 공급자 |
|---|---|---|---|---|
| **`gemini-embedding-2`**(GA 2026-04-22) | $0.20 / $0.10 | 3072, MRL 128~3072(권장 768) | MTEB Multilingual 69.9 | Google(이미 처리 위탁 중) |
| `gemini-embedding-001` | 가격 페이지에서 내려감(출시 당시 $0.15) | 3072 | 68.4 | Google |
| `text-embedding-3-small` | $0.02 / — | 1536 | MTEB 62.3%(영어 기준이라 직접 비교 불가) | OpenAI(새 위탁처) |
| `voyage-4-lite` | $0.02 | 1024 | 다국어 지원을 명시하지 않음 | Voyage(새 위탁처) |
| `embeddinggemma-2`(로컬) | $0(Pi CPU) | 768, MRL | MTEB multilingual 61.36 | 없음(Apache 2.0). Pi CPU 지연 공개 수치 없음 |

- 결정: **`gemini-embedding-2`를 `output_dimensionality=768`로 쓴다.**
  - 새 처리 위탁처가 생기지 않고 다국어 점수가 가장 높다.
  - 비용은 처리 비용의 1% 수준이라 가장 싼 후보와의 차이가 작다.
    - 녹음 1시간 = 약 1.4만 토큰 = **$0.0028**(배치 $0.0014). D11 목표의 1.1%다.
    - 질문 하나의 질의 임베딩은 약 20토큰이라 $0.000004다.
- 이 모델은 `task_type`을 받지 않는다. 질의와 문서의 구분은 공식 문서의 텍스트 접두어 규칙으로 한다(어댑터에서 구현).
- 새 녹음은 바로 임베딩하고, 레거시 노트 백필처럼 급하지 않은 대량 색인은 배치 API(50% 할인)를 쓴다.
  - 노트 1만 개(평균 40분) 전체 백필은 약 9,300만 토큰이다. 일반 단가로 $19, 배치로 $9다. 지금 운영 규모(수백 건)는 $1 안쪽이다.
- 모델을 바꾸면 임베딩 공간이 호환되지 않아 전부 다시 임베딩해야 한다. `search_embedding` 키에 모델과 차원이 들어 있으므로 옛 벡터와 새 벡터를 함께 두고 옮긴다.
- 로컬 임베딩(EmbeddingGemma 2)은 보류한다. 다시 볼 신호는 임베딩 비용이 월 AI 비용의 10%를 넘을 때다.

### 6. 답변 생성

- **문맥 구성**
  - 노트 범위: 노트 전체(문서 블록 → 전사 순)가 6,000토큰 이하이면 통째로 넣는다(`full_note`). 검색이 놓칠 수 없다. 6,000토큰은 발화로 약 25분이다.
  - 노트가 그보다 길거나 범위가 폴더·워크스페이스이면 검색 결과를 3,500토큰 안에서 넣는다(`retrieval`). 노트별로 묶고 노트 안에서는 읽는 순서로 놓는다.
  - "요약해줘"처럼 아무 조각에도 맞지 않는 노트 질문에는 그 노트의 문서 블록을 넣는다.
  - 후속 질문: 직전 답이 인용한 조각을 최대 3개 이어서 넣는다. 질문이 짧으면(질의어 2개 미만) 직전 질문의 질의어를 더해 검색한다. 질문을 다시 쓰는 모델 호출은 하지 않는다.
  - 이전 대화: 최근 3턴, 800토큰까지 넣는다.
- **프롬프트 순서는 고정**한다: 시스템 → 조각 → 이전 대화 → 질문. `full_note`에서 접두부가 같으므로 공급자 프롬프트 캐시가 후속 질문에 맞는다(Gemini 3.8 Flash 암묵 캐시는 4,096토큰 이상, Claude는 512토큰 이상 `cache_control`).
- **인용 강제**
  - 조각은 `[c1]`, `[c2]`처럼 짧은 표지로 넣는다. 모델은 사실 문장마다 이 표지를 단다. 시간은 쓰지 않는다(코드가 붙인다).
  - 답할 수 없으면 `[[모름]]`으로 시작한다.
  - 출력 상한은 700토큰이다.
- **결정적 인용 검증**(하네스 verify와 같은 원칙, LLM 판정 없음)
  1. 참조: 이번 턴에 준 표지만 남긴다. 스트리밍하면서 지운다.
  2. 범위: 조각이 스레드의 접근 범위 안인지 다시 확인한다.
  3. 뒷받침: 표지가 붙은 문장의 토큰이 조각에 30% 이상 있으면 `supported`, 아니면 `weak`(UI 경고)다.
  4. 좁히기: 전사 인용은 문장과 가장 잘 맞는 세그먼트로 좁힌다. 플레이어가 창 시작이 아니라 그 초로 이동한다.
  5. 결과: `[[모름]]`이면 `no_answer`, 살아남은 인용이 없으면 `unsupported`(UI는 접어서 경고와 함께 보인다), 그 밖에는 `answered`다.

### 7. 에이전트 도구

- **기본은 한 번의 호출이다.** 검색은 코드가 먼저 하고 모델은 답만 만든다. 노트 범위는 항상 이 경로다.
- **도구 루프는 폴더·워크스페이스 범위에서만** 열고 최대 2회로 제한한다. 다음 라운드까지 질문 상한 안에 들어갈 때만 도구를 준다.

| 도구 | 하는 일 | 필요한 경우 |
|---|---|---|
| `search_notes(query)` | 같은 범위를 다른 말로 다시 검색해 새 조각(최대 3개, 1,200토큰)을 받는다 | 비교 질문의 한쪽이 첫 검색에서 빠졌을 때, 후속 질문이 다른 주제로 넘어갈 때 |
| `read_more(label, before\|after)` | 조각 바로 앞뒤를 읽는다 | 답이 조각 경계에서 잘렸을 때 |
| `list_items(kind, from, to)` | 추출해 둔 일정·할 일을 기간으로 조회한다(P2·P4에서 연결) | "이번 주 마감 전부"처럼 모아 보는 질문 |

- 도구를 줄 때는 앞부분 80자를 붙잡아 둔다. 그 사이 도구 호출이 오면 버리고, 그렇지 않으면 그대로 스트리밍한다.

### 8. 스트리밍과 비용 통제

- **SSE**: `POST /ask/threads/{id}/turns`가 `text/event-stream`으로 답한다.
  - 이벤트 순서: `turn.started` → `retrieval` → (`tool`) → `answer.delta`·`citation` → `turn.completed` | `error`
  - 끊겨도 서버는 끝까지 만들어 저장한다. 이미 낸 토큰을 버리지 않기 위해서다. 클라이언트는 스레드를 다시 읽는다.
  - 재개 가능 스트림은 만들지 않는다.
- **질문 1회 상한**: $0.02(20,000µ$)다.
  - 호출마다 들어갈 예상 입력과 출력 상한으로 미리 계산하고, 넘으면 `budget_exceeded`로 멈춘다.
  - 단가를 모르는 모델은 호출하지 않는다.
- **캐시**: 같은 범위, 정규화한 같은 질문, 같은 이전 대화, **같은 조각 집합**(조각 id + 내용 해시), 같은 모델·프롬프트 버전이면 저장된 답을 비용 0으로 다시 보낸다(30일).
  - 검색은 매번 다시 하므로(싸다) 관계없는 노트가 추가돼도 캐시가 깨지지 않는다.
  - 질의 임베딩은 프로세스 안 LRU에 둔다.
- **쿼터**
  - 워크스페이스 월 물어보기 한도(기본 $2, D14)를 넘으면 스트림을 열기 전에 429 `quota_exceeded`로 답한다.
  - 한 스레드에 동시에 도는 턴은 하나다(409).
  - 사용자당 10분에 30회로 제한한다(HTTP 계층).
  - `Idempotency-Key`로 재전송해도 두 번 과금하지 않는다.
- **질문 1회 예상 비용**: 입력은 시스템 300 + 조각 3,500 + 이전 대화 약 200 ≈ 4,000토큰, 출력은 평균 250토큰으로 잡았다.

| 경우 | `gemini-3.5-flash-lite` ($0.30/$2.50) | `claude-haiku-5-5` ($0.10/$0.50) | `gemini-3.8-flash` ($0.75/$3.75, 2027-01부터 2배) |
|---|---|---|---|
| 검색 1회 호출 | **$0.0018** | $0.0005 | $0.0039 (2027: $0.0079) |
| 노트 전체(입력 6,000) | $0.0024 | $0.0007 | $0.0054 |
| 도구 1라운드 추가 | +$0.0022 | +$0.0006 | +$0.0049 |
| 근거 없음 / 캐시 적중 | $0 | $0 | $0 |

- 기본 답변 모델은 **`gemini-3.5-flash-lite`**다.
  - 새 처리 위탁처가 없고 하네스의 Gemini 어댑터를 같이 쓴다.
  - 새 프로젝트가 쓸 수 있는 가장 싼 GA Gemini 모델이다. 2.5 계열은 2026-09-18부터 신규 프로젝트에 닫혔다.
- `claude-haiku-5-5`는 질문당 약 3.5배 싸다. 평가에 넣고, 품질 게이트를 통과하면 바꾼다(D13). 바꾸려면 Anthropic을 처리 위탁처로 개인정보처리방침에 추가해야 한다.

### 9. 권한과 개인정보

- **접근 범위는 기본 거부**다. 스레드의 범위에서 이 사용자가 읽을 수 있는 녹음 id 목록을 먼저 만든다. 모든 질의는 `workspace_id`와 이 목록으로 함께 거른다.
  - 녹음 범위는 그 녹음만, 폴더 범위는 하위 폴더 포함 여부를 따르고, 워크스페이스 범위는 전부다.
  - `private` 녹음은 만든 사람만 읽는다. 워크스페이스 owner·admin도 남의 비공개 노트는 읽지 않는다.
  - 처리 중인 녹음은 뺀다.
  - 보이지 않는 녹음·폴더를 범위로 주면 403이 아니라 404로 답해 id 존재를 숨긴다.
- 모델에 넣기 전(`labelPassages`)과 인용을 만들 때(`verifyAnswer`) 범위를 다시 확인한다. 범위 밖 조각이 있으면 예외로 끝낸다.
- 물어보기는 비용이 드는 쓰기 행동이므로 `owner`·`admin`·`member`만 쓸 수 있다. `viewer`는 쓰지 못한다.
- 스레드는 만든 사람만 본다(남에게는 404).
- 답변 캐시는 같은 워크스페이스 안에서만 공유하며 **같은 조각 집합**일 때만 맞는다. 따라서 다른 사람이 볼 수 없는 내용이 섞일 수 없다.
- 공유 링크로 보는 사람은 물어보기를 쓸 수 없다.
- 노트를 지우면 다음을 함께 지운다.
  - 그 노트의 조각, FTS 행, 다른 곳에서 쓰지 않는 임베딩(`deleteRecordingIndex`)
  - 노트 범위 스레드(`deleteRecordingThreads`)
  - 다른 스레드에 남은 그 노트 인용은 `available: false`로 보이고 발췌문을 숨긴다.
- 외부로 보내는 것: 질문, 최근 대화 일부, 관련 조각(전사·문서 일부)을 Gemini API(유료 계층, 학습에 쓰지 않음)로 보낸다. 조각 본문은 임베딩용으로 보낸다. [개인정보처리방침](../../apps/server/static/legal/privacy.html)에 반영했다.

### 10. 평가

평가 세트 v0(AI_HARNESS §8)의 녹음마다 질문을 붙인다.
- 녹음마다 5~8개: 질문, 범위(노트·전체), 짧은 정답, 정답 근거(세그먼트 범위·블록 id)
- 그중 약 20%는 노트에 답이 없는 질문이다.

| 지표 | 정의 | 잠정 기준 |
|---|---|---|
| 검색 재현율@12 | 정답 근거와 겹치는 조각이 문맥 12개 안에 든 비율. BM25만 / 하이브리드를 나눠 재서 임베딩의 몫을 확인한다 | ≥ 0.85 |
| 인용 정밀도 | 좁힌 인용 범위가 정답 근거와 겹치는 비율 | ≥ 0.90 |
| 표지 규율 | 모델이 낸 표지 중 준 조각을 가리킨 비율(필터 전) | ≥ 0.98 |
| `unsupported` 비율 | 답이 있는 질문에서 인용 없이 답한 비율 | ≤ 5% |
| 오답률(답 없는 질문) | 답 없는 질문에 `answered`로 답한 비율 | ≤ 10% |
| 거절률(답 있는 질문) | 답 있는 질문에 "모름"으로 답한 비율(근거 판정이 막은 것 포함) | ≤ 10% |
| 비용·지연 | 질문당 µ$ p50·p95, 첫 토큰까지와 완료까지 시간 | p95 ≤ 질문 상한 |

- 정답 일치는 사람이 보거나, 생성 모델과 다른 모델로 LLM 판정한다(평가에서만).
- 근거 판정 기준값(`minTermCoverage`, `minCosine`)과 뒷받침 기준(`SUPPORT_MIN`)은 이 세트로 맞춘다.
- CI에서는 결정적 부분(청킹, 바이그램, 범위 필터, 스트림 필터, 인용 검증, 러너의 녹화 응답 재생)만 매번 테스트한다.

### 11. API 계약(`packages/domain/src/api/ask.ts`, 하위 호환 추가)

| 메서드·경로 | 요청 | 응답 |
|---|---|---|
| `POST /ask/threads` | `{workspace_id, scope}`. scope는 `{kind:"recording", recording_id}`, `{kind:"folder", folder_id, include_subfolders}`, `{kind:"workspace"}` 중 하나 | 201 `AskThread` |
| `GET /ask/threads?workspace_id&recording_id?` | 커서 페이지 | `AskThreadPage`(내 스레드, 최근 순) |
| `GET /ask/threads/{id}` | — | `AskThreadDetail {thread, turns[]}` |
| `DELETE /ask/threads/{id}` | — | 204 |
| `POST /ask/threads/{id}/turns` | `{question}`(1~2,000자), `Idempotency-Key` | 200 `text/event-stream`. 각 메시지가 `AskStreamEvent`다. 스트림 전 오류는 400·403·404·409·429 `ApiError` |
| `GET /ask/usage?workspace_id` | — | `AskUsage {period, turn_count, spent_microusd, limit_microusd, per_turn_cap_microusd}` |

- 인용 `AskCitation`은 `kind`로 나뉜다.
  - `transcript`: `start_idx`, `end_idx`, `start_ms`, `end_ms`
  - `document`: `document_id`, `document_version`, `block_id`, `section_title`, `start_ms`, `sources[]`
  - `pdf_page`: `asset_id`, `page`
  - 공통: `label`(`c3`), `chunk_id`, `recording_id`, `recording_title`, `snippet`, `support`(스트리밍 중 null), `available`
- 답변 `answer`는 가벼운 Markdown(문단, `-` 목록, `**굵게**`)에 `[c3]` 표지가 들어간 텍스트다. 클라이언트가 표지를 출처 칩으로 바꾼다.
- `EventSource`는 POST를 못 하므로 웹은 `fetch` 스트림을 읽는다.

### 12. 복습·질문 기능을 뺀다

- 파이프라인은 질문을 기본으로 만들지 않는다. 실제 템플릿의 `extract.questions`는 꺼 둔다.
- 사용자가 원하면 물어보기 답이 그 자리에서 만든다("필요할 때 에이전트가 만드는 것").
- `Question` 엔티티, `QuestionKind`, `/recordings/{id}/questions`는 동결 계약이라 지우지 않는다. 설명에만 폐기 예정으로 표시했다. 지우려면 별도 ADR이 필요하다.
- 웹 셸의 "복습" 화면은 "물어보기"로 바꾼다(웹 흐름 소유).

이 ADR이 정하지 않는 것
- 답변 모델의 최종 선택(D13): 위 평가로 정한다.
- 월 한도 기본값(D14).
- 공급자 어댑터 구현: Gemini 스트리밍·임베딩 어댑터는 하네스 공급자와 함께 만든다.

## 결과 (Consequences)

- 좋아지는 것
  - 두 음절 한국어 질의와 띄어쓰기 차이를 색인으로 찾는다. 확장(SQLite extension) 없이 Mac 테스트와 Pi 운영이 같은 코드를 쓴다.
  - 답할 수 없는 질문과 같은 질문의 반복은 모델 비용이 0이고, 나머지는 질문당 약 $0.002(Flash-Lite)다.
  - 모든 인용은 실제로 준 조각을 가리키고, 접근 범위 안이며, 문장과 겹치는 정도가 표시된다. 전사 인용은 해당 세그먼트 시각으로 이동한다.
  - 공급자·모델은 인터페이스(`AskModel`, `Embedder`, `VectorIndex`) 뒤에 있어 평가로 바꿀 수 있다.
- 감수하는 것
  - 색인이 원문을 한 번 더 저장한다. 조각 본문, 바이그램 색인(합성 한국어에서 원문 바이트의 약 1.2배), int8 임베딩이다. 노트 1만 개면 DB가 약 2GB 늘어난다(조각당 약 5KB).
  - 바이그램은 어간·동의어를 모른다. 동의어와 다른 표현은 벡터 쪽이 맡는다.
  - 응답 전체가 스트림이라 재개되지 않는다. 끊기면 다시 읽어야 한다.
  - 근거 판정·뒷받침 기준은 잠정값이다. 평가 전에는 거절이 너무 많거나 적을 수 있다.
  - 임베딩 모델을 바꾸면 전부 다시 임베딩한다(노트 1만 개 기준 배치 $9).
- 다시 검토할 신호
  - Pi에서 검색 p95가 200ms(P3 기준)를 넘을 때. 노트 1만 개 워크스페이스는 추정상 넘을 수 있다. 그때는 순위 예산을 줄이거나 워크스페이스 토큰으로 색인을 나눈다
  - 평가에서 BM25만으로도 재현율이 같을 때(임베딩을 끈다) 또는 형태소 분석이 필요할 때
  - 물어보기 비용이 월 AI 비용의 30%를 넘을 때
  - sqlite-vec 1.0이 나올 때
