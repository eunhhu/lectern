# 평가 세트 형식

`bun run harness eval`이 읽는 세트의 형식이다([AI_HARNESS.md §8](../../../docs/v2/AI_HARNESS.md)). 실제 세트는 사람이 주석을 달아야 해서 아직 없다. 이 디렉터리의 `example/`은 형식을 보여 주는 **합성 세트**다(톤 오디오, 지어낸 문장).

## 넣는 위치

녹음과 전사는 개인정보라서 **저장소 밖**에 둔다. 저장소에는 이 형식 문서와 합성 예제만 커밋한다.

```
~/lectern-eval/                 평가 루트 (아무 경로나 가능, 저장소 밖)
  sets/
    v0/                         세트 하나 = 디렉터리 하나
      items.csv
      ref/<id>.md               교정 전사
      annotations.csv           (선택) 일정·할 일·결정·핵심 개념
      audio/<id>.m4a            원본 녹음 (상대 경로 또는 절대 경로)
  runs/                         실행 결과 <날짜>-<라벨>.json (CLI가 만든다)
  .cache/v0/                    전사 캐시 (CLI가 만든다)
```

`--set`이 `sets/` 아래의 디렉터리면 `runs/`와 `.cache/`는 평가 루트에 생기고, 아니면 세트 디렉터리 안에 생긴다.

## items.csv

| 열 | 필수 | 뜻 |
|---|---|---|
| `id` | 예 | 소문자·숫자·`-`·`_`. 참조 파일 이름과 맞춘다 |
| `audio` | 예 | 녹음 경로(세트 기준 상대 경로 가능). 합성 세트만 `synth` |
| `reference` | 예 | 교정 전사 Markdown 경로 |
| `consent` | 예 | `yes`: **녹음 속 모든 화자가 평가 사용에 동의함**. 동의하지 않은 화자가 있는 녹음은 넣지 않는다. 합성 데이터는 `synthetic` |
| `language` | | BCP 47(`ko`, `en`). 전사 힌트와 언어 검사에 쓴다 |
| `domain` | | `lecture`, `meeting`, `seminar`, `interview`, `general` |
| `notes` | | 자유 메모(쉼표가 있으면 큰따옴표로 감싼다) |

## 교정 전사 Markdown (`ref/<id>.md`)

```markdown
---
duration: 1:12:30
language: ko
speakers: S1 강사, S2 학생
reviewed: 0:00-10:00, 50:00-1:00:00
---
# 메모는 제목이나 > 인용으로 쓴다 (채점하지 않음)

[0:03] S1: 오늘은 대칭키 암호의 운영 모드를 보겠습니다.
[0:21-0:26] S2: 질문 있는데요, ECB가 왜 위험한가요?
[1:02:03] S1: 다음 주 화요일까지 과제를 제출하세요.
```

- 한 줄이 한 발화다: `[시작] 화자: 텍스트` 또는 `[시작-끝] 화자: 텍스트`. 시간은 **원본 녹음 기준**(휴식을 자르기 전)이고 `M:SS`, `MM:SS`, `H:MM:SS` 모두 된다. 끝을 안 쓰면 다음 줄 시작까지로 본다.
- 화자는 `S1`, `S2`…로 쓰고 이름은 front matter `speakers`에만 적는다(익명화).
- `reviewed`: 일부 구간만 교정했다면 그 구간들(원본 시간). 그 안에 중심이 있는 줄과 세그먼트만 채점한다. 없으면 전체를 채점한다.
- `duration`: 합성 항목에 필수(오디오를 만들 길이). 실제 녹음에는 선택.
- `recorded_at`: (선택) 녹음 시각, 오프셋을 붙인 ISO 형식(`2026-10-19T14:00:00+09:00`). 노트 평가가 "다음 주 화요일" 같은 상대 날짜를 이 시각 기준으로 푼다. 없으면 `2026-10-19T14:00:00+09:00`.
- 들리는 대로 쓴다. 말더듬·반복도 실제로 말했으면 쓰고, 알아들을 수 없는 부분은 `[불명확]`.
- 작업량: 녹음 1시간당 2~3시간(일부 구간만 교정하면 1시간).

## annotations.csv (`bun run harness eval --notes`의 일정·할 일 평가용)

| 열 | 필수 | 뜻 |
|---|---|---|
| `item` | 예 | `items.csv`의 `id` |
| `kind` | 예 | `event`(일정), `action_item`(할 일), `decision`(결정), `concept`(핵심 개념) |
| `start` | 예 | 원본 시간에서 그 말이 나온 곳 |
| `end` | | 끝 시간 |
| `text` | 예 | 일정 제목, 할 일, 결정, 개념 이름 |
| `date` | event면 예 | 정답 날짜 `YYYY-MM-DD`(녹음 시각과 사용자 시간대 기준으로 사람이 푼 값) |
| `time` | | `HH:MM` |
| `owner` | | 할 일 담당자(말한 그대로) |
| `notes` | | 자유 메모 |

`event`와 `action_item`만 채점한다(`decision`, `concept`는 아직 형식 검사만). 항목의 템플릿이 그 종류를 추출하지 않으면(예: 강의 템플릿의 할 일, 인터뷰 템플릿의 일정) 놓친 것으로 치지 않고 `skipped`로 센다.

## 지표

| 지표 | 계산 |
|---|---|
| CER | 문자·숫자만 남긴 글자(NFKC, 소문자, 공백·구두점 제거)의 편집 거리 ÷ 참조 글자 수. 한국어 기본 지표 |
| WER | 공백으로 나눈 단어의 편집 거리 ÷ 참조 단어 수. 띄어쓰기 차이도 오류로 센다 |
| 누락·삽입 비율 | 삭제된 참조 글자, 참조에 없는 글자 ÷ 참조 글자 수 |
| 화자 오류(근사) | 참조와 결과를 글자 단위로 정렬하고, 라벨을 1:1로 가장 잘 맞춘 뒤 화자가 다른 정렬 글자의 비율. 무음과 겹친 발화는 보지 않는다 |
| 타임스탬프 오차 | 참조 줄의 첫 글자와 정렬된 결과 글자의 시간 차(중앙값, p90) |
| 비용 | 원장(`ai_call`)에 남은 이번 실행의 실제 비용, 녹음 1시간당 환산 |

## 노트 지표 (`--notes`)

`bun run harness eval --notes`는 참조 전사(`ref/*.md`)를 노트 파이프라인(분류 → 구조화 → 추출 → 검증)에 넣고 `annotations.csv`와 비교한다. 기본은 내장 예시 세트와 주석에서 답을 만드는 스크립트 공급자라 비용이 없다. `--drop-rate`, `--wrong-date-rate`, `--extra-rate`(0~1)로 일부러 틀리게 해 지표가 움직이는지 볼 수 있다. `--provider gemini`는 예상 비용을 먼저 보여 주고 `--yes`가 있어야 실제로 호출한다.

| 지표 | 계산 |
|---|---|
| 스키마 유효율 | 파이프라인이 끝났고 결과가 스키마에 맞으며 수리(repair)가 필요 없었던 항목 ÷ 전체 항목 |
| 근거 연결률 | 검증 보고서에서 출처가 확인된(`ok`) 블록 ÷ 전체 블록(버린 블록 포함) |
| 일정 날짜 정확도 | 주석 일정마다, 근거 시각이 ±60초 안인 추출 일정 중 가장 가까운 것을 짝으로 삼아 날짜(주석에 시각이 있으면 시각까지)가 맞은 비율 |
| 과추출률 | 같은 종류 주석과 ±60초 안에서 짝을 못 찾은 추출 일정·할 일 ÷ 전체 추출 |
| 녹음 1시간당 비용 | 원장(`ai_call`)에 남은 이번 실행의 실제 비용 ÷ 참조 전사 길이(시간) |
